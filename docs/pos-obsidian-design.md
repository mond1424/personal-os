# pOS–Obsidian 연동 설계

## 0. 문서 구조

- 층: 불변식(§2)은 ADR 없이 바꾸지 않는다. 계약(§4 볼트 구조, §5 투영 계약)은 스키마 버전과 함께 바꾼다. 구성 요소(§6)와 절차(§8)는 계약 안에서 자유롭게 바꾼다.
- ID: INV(불변식), C(구조 규칙), DEC(결정), OPEN(미결), CHK(확인 항목), P(절차), S(단계). 티켓과 ADR은 이 ID로 참조한다. 같은 사실은 한 곳에만 쓰고, 다른 곳에서는 ID로 가리킨다.
- pOS 쪽 테이블·함수 이름은 개념 참조다. 정확한 이름과 현재 상태는 저장소의 `STATE.md`, `docs/schema-current.sql`, `docs/api-surface.md`가 정본이다.
- 삼성 노트 저장소의 테이블·파일 이름(§5.7)은 2026-09에 관찰한 구조다. 앱 업데이트로 바뀌면 §5.7을 고친다.

## 1. 목적과 범위

일정·자기관리(pOS)와 학업(필기)을 Obsidian 볼트에서 엮는다. Obsidian이 생각하는 공간의 중심이 되고, pOS는 그 감각기관과 반사를 맡는다.

| 역할 | 담당 | 하는 일 |
|---|---|---|
| 뇌 | Obsidian 볼트 | 학업 노트, 과목 허브, 일기, 회고, 분석 |
| 감각기관 | pOS | 일정·과제·마감·상태 기록·밤 화면 사용·장소를 감지해 원장에 남김 |
| 척수 반사 | pOS Guard | 밤 개입. 볼트를 거치지 않음 |
| 구심 신경(pOS) | pOS 내보내기 API + Obsidian 플러그인 | pOS 원장을 볼트의 `pOS/`에 투영 |
| 원심 신경 | 명령(pOS API 호출) | 볼트에서 pOS로 가는 유일한 경로 |
| 필기 입력 | 삼성 노트 | S펜 필기 원본 |
| 구심 신경(필기) | 필기 투영기(PC) | 삼성 노트 PC 앱의 저장소를 읽어 강의 필기를 수업 날짜 단위 PDF로 볼트의 `삼성노트/`에 투영 |
| AI 복습 | Gemini 노트북 | 과목별 복습 대화. 볼트와 동기화하지 않음 |

범위 밖: AI 자동화(에이전트의 자동 편집·자동 요약), 볼트에서 pOS로의 파일 동기화, Gemini 노트북 자동 연동, 강의 필기 노트 밖의 삼성 노트 노트(교재 등) 투영. 과제 노트는 OPEN-12.

용어

- 주인: 어떤 데이터의 진실을 가진 쪽. 데이터마다 하나다.
- 투영: 주인의 데이터를 다른 곳에 읽기 전용으로 비춘 사본. 조건은 INV-7.
- 귀속일: pOS가 하루 경계 설정에 따라 사건을 붙이는 날짜. 경계 이전의 새벽 사건은 전날에 속한다.
- 정본 과목명: pOS 시간표에 입력된 과목명. 과목을 가리키는 모든 이름의 기준이다. 학기마다 쌓이고, 한 번 생긴 정본은 사라지지 않는다(DEC-27).
- 허브 노트: 과목 폴더 안에서 정본 과목명과 같은 이름을 가진 노트. 과목에 관한 링크가 모이는 곳이다.
- 투영기: 투영을 만드는 구성 요소. pOS 투영은 서버 렌더러와 플러그인(§6.1, §6.2), 필기 투영은 필기 투영기(§6.5)다.
- 훼손: 투영 파일이 그 투영기 외의 손으로 바뀐 상태. pOS 투영은 자기 검증 해시(§5.2), 필기 투영은 투영기의 해시 기록(§5.7)으로 판정한다.
- 강의 필기 노트: 삼성 노트에서 과목마다 하나 두고, 수업마다 그날 만든 페이지에 이어 쓰는 노트(C-8).
- 수업 날짜: 강의 필기 페이지가 만들어진 날. 페이지 ID(UUIDv1)에 든 시각을 한국 시간 달력 날짜로 읽는다. 강의 노트와 필기 PDF의 키다.
- 개념 노트: 과목과 학기를 넘어 남는 지식 하나를 다루는 볼트 노트. `06 Concepts`에 둔다(C-9).
- 지금: 오늘을 포함하는 기간과 학기의 과목, 진행 중인 프로젝트의 모임. 파일로 두지 않고 조회로 만든다(DEC-25).

## 2. 불변식

- **INV-1** 모든 데이터는 주인이 하나다.
- **INV-2** pOS가 주인인 데이터는 pOS DB가 진실이다. 볼트의 `pOS/`는 그 투영이다.
- **INV-3** 볼트가 주인인 데이터는 볼트가 진실이다. pOS(서버·앱)는 볼트를 읽지 않는다. pOS에 볼트 데이터가 필요한 기능이 제안되면, 기능을 만들기 전에 그 데이터의 주인을 다시 정한다.
- **INV-4** 흐름을 거스르는 경로는 명령(pOS API 호출)뿐이다. 볼트를 감시하는 프로세스와 양방향 동기화는 두지 않는다.
- **INV-5** 주인이 바뀌는 것은 한 번의 명시적 이전으로만 한다. 이전 뒤 원래 쪽은 보관 전용이 된다.
- **INV-6** 반사(Guard 개입)의 경로는 pOS 안에서 닫힌다. 볼트를 거치지 않는다.
- **INV-7** 투영(`pOS/`, `삼성노트/`)은 세 조건을 만족한다.
  - 결정적: 같은 원천 상태와 같은 렌더러면 같은 바이트가 나온다. 렌더러는 현재 시각을 읽지 않는다.
  - 폐기 가능: 투영 폴더를 지우고 다시 만들면 같은 내용으로 돌아오고, 잃는 것이 없다.
  - 비입력: 투영의 어떤 내용도 원천으로 되돌아가지 않는다.
- **INV-8** pOS 투영의 문장과 링크는 pOS 서버의 렌더러 한 곳이 만든다. 플러그인은 받아 쓰기만 한다.
- **INV-9** `pOS/`에는 플러그인만 쓴다. 사람, 에이전트, 다른 플러그인은 쓰지 않는다.
- **INV-10** 전달이 끊기면 보인다. pOS 경로는 양쪽에 보인다(pOS: 마지막 수신 시각, 볼트: `pOS/_상태.md`). 필기 경로는 볼트에 보인다(`삼성노트/_상태.md`: 마지막 동기화 시각, 마지막 투영 시각). 투영 훼손은 볼트에 보인다. 어느 쪽도 조용히 넘어가지 않는다.
- **INV-11** 강의 필기는 삼성 노트가 진실이다. 볼트의 `삼성노트/`는 그 투영이며, 필기 투영기만 쓴다. 필기 투영기는 삼성 노트 저장소를 읽기만 한다.

## 4. 볼트 구조

```

├── AGENTS.md                         ← 에이전트용 규칙 (§6.4)
├── CLAUDE.md                         ← "@AGENTS.md" 한 줄
├── 지금.base                         ← 지금 조회 (DEC-25)
├── 00 Inbox
├── 01 Me
├── 02 Education
│    └── 양자물리및연습2              ← 정본 과목명
│         ├── 양자물리및연습2.md      ← 허브 노트
│         └── 양자물리및연습2 2026-09-23.md  ← 강의 노트
├── 03 Projects
├── 04 Journal
│    └── 2026-09-23.md                ← 귀속일
├── 05 Analysis
├── 06 Concepts
│    └── 푸리에 급수.md               ← 개념 노트
├── 90 Templates
├── pOS                               ← pOS 투영 전용
│    ├── _상태.md
│    ├── days/       2026-09-23 pOS.md
│    ├── tasks/      task-123 pOS.md
│    ├── courses/    양자물리및연습2 pOS.md
│    ├── periods/    period-7 pOS.md
│    └── analysis/   analysis-42 pOS.md
└── 삼성노트                          ← 필기 투영 전용
     ├── _상태.md
     └── 양자물리및연습2/   양자물리및연습2 2026-09-23.pdf
```

- **C-1** 과목 폴더와 허브 노트의 이름은 정본 과목명과 글자 그대로 같다. 링크는 폴더가 아니라 파일 이름으로 풀리므로, 허브 노트가 폴더와 같은 이름을 가진다.
- **C-2** 강의 노트는 `<정본 과목명> <수업 날짜>.md`, 그 필기 PDF는 `삼성노트/<정본 과목명>/<정본 과목명> <수업 날짜>.pdf`다. 수업 날짜는 `YYYY-MM-DD`로 쓴다(DEC-20). 과목명 없이 날짜만으로 이름을 짓지 않는다(같은 날 두 과목이 부딪친다).
- **C-3** Journal 파일 이름은 귀속일(`YYYY-MM-DD.md`)이다.
- **C-4** pOS 투영 파일 이름은 `<키> pOS.md`다. 사람이 만드는 노트는 ` pOS`로 끝나는 이름을 쓰지 않는다. 필기 투영 파일과 같은 이름의 PDF를 볼트의 다른 곳에 두지 않는다. 이것으로 볼트 전체에서 파일 이름이 겹치지 않는다.
- **C-5** 투영 파일의 키는 바뀌지 않는 값이다. days는 귀속일, tasks·periods·analysis는 pOS id, courses는 정본 과목명, 필기는 정본 과목명과 수업 날짜다. 제목처럼 바뀌는 값은 키로 쓰지 않는다.
- **C-6** C-1~C-5와 C-8의 경로·이름 형식은 계약이다. 사람 노트가 이 경로로 링크·임베드하므로, 바꾸려면 ADR과 링크 이전 절차가 필요하다.
- **C-7** 최상위 폴더의 번호 접두사(00~06, 90)는 정렬용이다. 새 최상위 폴더는 비어 있는 번호를 쓴다. 투영 폴더(`pOS`, `삼성노트`)는 번호 없이 원천의 이름을 쓴다.
- **C-9** 개념 노트는 `06 Concepts`에 하위 폴더 없이 둔다. 이름은 개념 이름 하나이고, 다른 표기(영문 이름, 약어)는 `aliases`에 둔다. 과목명, 날짜, ` pOS`로 끝나는 이름은 개념 노트 이름으로 쓰지 않는다(C-4).
- **C-10** 속성 값으로 링크를 쓸 때는 값 전체가 링크 하나다(예: `course: "[[양자물리및연습2]]"`). 목록 속성이면 항목마다 링크 하나다. 글과 섞인 링크는 링크로 인식되지 않는다(CHK-15).

### 4.1 층

볼트의 노트는 네 층으로 읽는다(DEC-24). 층은 폴더가 아니라 링크의 방향으로 정해진다.

| 층 | 바뀌는 방식 | 자리 | 주인 |
|---|---|---|---|
| 나 | 몇 년에 걸쳐 조금씩 바뀐다 | `01 Me`. S3 전에는 pOS의 Me | pOS → 볼트(P-2) |
| 지금 | 학기·기간마다 열리고 닫힌다 | `지금.base`가 모으는 기간·과목 투영과 프로젝트 허브 | 기간·과목은 pOS, 프로젝트 허브는 볼트 |
| 지식 | 계속 쌓인다 | `06 Concepts` | 볼트 |
| 기록 | 날짜가 붙고, 지난 것은 고치지 않는다 | `04 Journal`, 강의 노트, `05 Analysis`, `pOS/days` | 볼트, pOS |

- 링크는 기록에서 위쪽(개념, 허브, 기간, 나)으로 건다. 위쪽 노트에는 기록의 목록을 손으로 적지 않는다. 위쪽은 백링크와 조회로 채워진다. 허브의 절에는 과목 전체에 대한 자기 글을 쓴다.
- 이해 상태는 개념 노트의 `stuck` 속성으로 둔다. 언제 막히고 언제 풀렸는지는 그날의 기록에 남는다.
- 학기나 기간이 끝나도 파일을 옮기거나 지우지 않는다. 날짜가 지나면 `지금.base`에서 빠진다(P-8).

## 5. 투영 계약

5.1~5.6은 pOS 투영, 5.7은 필기 투영의 계약이다.

### 5.1 공통 속성

`_상태.md`를 제외한 모든 투영 파일의 frontmatter는 다음을 가진다.

| 속성 | 뜻 |
|---|---|
| `pos_type` | `day` · `task` · `course` · `period` · `analysis` |
| `pos_id` | C-5의 키 |
| `pos_schema` | 투영 스키마 버전(정수) |
| `pos_hash` | 자기 검증 해시(§5.2) |

### 5.2 자기 검증 해시

`pos_hash`는 파일 전체에서 `pos_hash:` 줄을 뺀 내용을 UTF-8·LF로 정규화한 뒤 계산한 SHA-256의 16진수 앞 16자다. 서버가 계산해 넣는다. 파일이 스스로 무결성을 증명하므로, 플러그인은 기기마다 상태를 들고 있을 필요가 없고 여러 기기가 각자 가져와도 안전하다.

플러그인의 처리 규칙:

| 상황 | 처리 |
|---|---|
| 파일 없음 | 쓴다 |
| 자기 해시 유효, 서버 해시와 같음 | 건너뛴다 |
| 자기 해시 유효, 서버 해시와 다름 | 덮어쓴다 |
| 자기 해시 무효 | 쓰지 않는다. 훼손으로 보고한다 |
| 서버 목록에 없는 파일 | 자기 해시가 유효하면 지우고, 무효면 보고한다 |

검증은 덮어쓰기·삭제 직전에 반드시 한다. 전체 검증은 명령으로 돌린다.

### 5.3 렌더 규칙

- 날짜·시각은 절대값만 쓴다. "D-5", "3일 전" 같은 상대 표현은 쓰지 않는다(INV-7).
- 귀속일과 달력 날짜가 다른 시각에는 날짜를 붙인다(예: 2026-09-23 파일의 `09-24 01:12`).
- 체크박스(`- [ ]`)는 쓰지 않는다. 볼트에서 체크해도 pOS 상태는 바뀌지 않기 때문이다. 상태는 기호로 쓴다: ✓ 완료, ✗ 못 함, → 미룸.
- 과목은 대응된 경우 `[[정본|표시 이름]]`, 대응되지 않은 경우 원문 텍스트로 쓴다. 대응되지 않은 이름은 링크로 만들지 않는다.
- 투영 파일끼리의 링크는 해당 `pos_schema`에 존재하는 종류로만 건다.
- Guard 사건과 새벽 기록은 귀속일의 day 파일에 넣는다.
- 가져온 시각은 어떤 투영 파일에도 넣지 않는다. 시각이 필요하면 DB에 있는 값(예: 마지막 변경 시각)만 싣는다.

### 5.4 종류별 내용

| 종류 | 속성(공통 외) | 본문 |
|---|---|---|
| day | 날짜, 마감 방식, 마감 수치 전부(현재 스키마의 항목 이름 그대로), 과제 완료·못 함·미룸 수, 밤 개입 수, 관련 과목 링크 목록 | 한 일·못 한 일·미룸 / 일정 / 밤 / 기록(상태 기록 원문, 로그, memo) |
| task | 제목, 상태, 과목 링크, 생성일, 예정일 이력, 미룸 횟수, 종료일, DB 기준 마지막 변경 시각 | 이력 |
| course | 정본 과목명, 마지막 학기와 그 시작일·종료일 | 시간표 / 마감 목록 / 열린 과제 링크 |
| period | 이름, 종류, 시작일, 종료일, 관련 과목 | 기간의 목표 |
| analysis | 작성일, 종류 | 분석 본문(불변) |

day는 닫힌 날만 만든다(DEC-9). 오늘은 pOS 앱에서 다룬다.

시작일·종료일과 학기 범위는 날짜 속성으로 싣는다. 오늘이 그 안에 드는지는 투영이 아니라 조회가 판단한다(DEC-25).

### 5.5 전송

엔드포인트 이름은 제안이다. 최종 이름은 구현 시 `docs/api-surface.md`에 기록한다. 인증은 pOS의 기존 API 토큰을 쓰며, 내보내기 전용 읽기 토큰을 둘지는 OPEN-17이다.

- `GET /api/export/manifest` — 투영 파일 목록 `[{path, pos_hash}]`를 돌려준다. 호출될 때 서버는 마지막 수신 시각을 기록한다.
- `POST /api/export/files` — `{paths}`를 받아 `[{path, content}]`를 돌려준다.
- 귀속일 조회 — 오늘의 귀속일을 돌려주는 기존 응답이 있으면 그것을 쓰고, 없으면 추가한다.
- 정본 과목 목록 — 필기 투영기(§6.5)가 삼성 노트 과목 폴더를 대조할 때 쓴다. 지난 학기를 포함해 학기마다 과목명과 그 학기의 시작일·종료일을 준다(DEC-27). 기존 응답이 있으면 그것을 쓰고, 없으면 추가한다.
- 목록을 매번 전부 렌더하지 않는 변경 감지 방식은 OPEN-1.

### 5.6 스키마 변경

- 내용·형식 변경: 렌더러 수정 → `pos_schema` 증가 → 전체 재생성(P-4). 투영은 폐기 가능하므로 별도 이전 절차가 필요 없다.
- 경로·이름 형식 변경: C-6에 따라 ADR과 링크 이전 절차가 필요하다.

### 5.7 필기 투영

원천은 삼성 노트 Windows 앱의 로컬 저장소 `%LOCALAPPDATA%\Packages\SAMSUNGELECTRONICSCoLtd.SamsungNotes_wyx1vj98g3asy\LocalState\`다.

| 항목 | 자리 |
|---|---|
| 노트 목록 | `Storage.sqlite`의 `NoteDB`(제목, 폴더, 생성·수정 시각, 본문 경로) |
| 폴더 트리 | `Storage.sqlite`의 `CategoryTreeDB` |
| 노트 본문 | `wdoc\<노트 ID>\`. SDOCX 압축을 푼 구조(`note.note`, `<페이지 ID>.page`, `pageIdInfo.dat`, `media\`, `end_tag.bin`) |

- **C-8** 삼성 노트에서 학기 폴더 아래 과목 폴더의 이름은 정본 과목명과 글자 그대로 같다(NFC로 정규화해 비교한다, DEC-30). 과목 폴더마다 강의 필기 노트를 하나 두고, 제목은 `<정본 과목명> 필기`다. 수업 필기는 그 수업 날 만든 새 페이지에 쓴다. 예: 학기 폴더 `<학년>/<학기>`, 과목 폴더 `양자물리및연습2`, 강의 필기 노트 `양자물리및연습2 필기`.

투영 규칙:

- 대상: 필기 투영기 설정에 든 학기 폴더들 아래, C-8을 따르는 강의 필기 노트. 다른 노트는 투영하지 않는다.
- 이름: 삼성 노트의 폴더·노트 이름은 NFC로 정규화한 뒤 정본과 비교한다. 볼트에 쓰는 이름은 삼성 노트의 이름이 아니라 정본에서 만든다(DEC-30).
- 페이지: `pageIdInfo.dat`에 있는 페이지만 그 순서대로 쓴다. 내용이 없는 페이지는 뺀다.
- 묶음: 수업 날짜가 같은 페이지를 노트 안 순서대로 모아 PDF 하나로 만든다(DEC-19). 예: `양자물리및연습2 필기`에서 2026-09-23에 만든 페이지들은 `삼성노트/양자물리및연습2/양자물리및연습2 2026-09-23.pdf` 하나로 묶인다.
- 이름과 자리: C-2.
- 렌더: 변환기(DEC-21) 하나가 만든다. 필기는 벡터 획으로, 가져온 PDF 페이지는 원본 글자 층을 가진 채로, 붙인 이미지는 그대로 들어간다. 손글씨에는 글자 층이 없다.
- 판: 변환기 버전이나 이 절의 규칙이 바뀌면 `삼성노트/`를 전체 재생성한다.

필기 투영기의 처리 규칙(DEC-23):

| 상황 | 처리 |
|---|---|
| 파일 없음 | 쓴다 |
| 파일 해시가 기록과 같고, 새 결과와 같음 | 건너뛴다 |
| 파일 해시가 기록과 같고, 새 결과와 다름 | 덮어쓴다 |
| 파일 해시가 기록과 다름 | 쓰지 않는다. 훼손으로 보고한다 |
| 기록이 없는 파일 | 새 결과와 같으면 기록하고 건너뛴다. 다르면 보고한다 |
| 대상 목록에 없는 파일 | 기록과 같으면 지우고, 다르면 보고한다 |

## 6. 구성 요소

### 6.1 pOS 서버

- 렌더러: 투영 전부를 만드는 모듈 하나. 현재 시각을 인자로도 받지 않는다.
- 내보내기 라우트: §5.5.
- 과목 대응표: 수집한 학사 마감의 과목 분류 문자열을 정본 과목명에 대응시킨다. 자동 규칙(괄호·분반 표기 제거 등)과 수동 지정을 둔다. 대응되지 않은 문자열 수를 센다.
- 시간표 이력: 새 학기 시간표는 학기 범위가 겹치는 규칙만 바꾸고, 다른 학기의 규칙은 남긴다. 지난 날짜의 수업은 그 학기의 규칙으로 전개된다. 과목명은 NFC로 저장한다(DEC-27, DEC-30).
- 상태 표시: 마지막 수신 시각과 과목 미대응 수를 pOS 설정의 상태 줄에 보인다.
- 테스트(smoke):
  - 결정성: 서로 다른 시계를 주입해 같은 DB를 두 번 렌더하면 결과가 같다.
  - 자기 해시: 렌더 결과의 `pos_hash`가 §5.2 규칙으로 재계산한 값과 같다.
  - 귀속일: 경계 전 새벽 Guard 사건이 전날 day 파일에 들어간다.
  - 과목: 대응되지 않은 문자열은 링크가 아닌 텍스트로 나온다.
  - 정본 이력: 새 학기 시간표를 넣어도 지난 학기의 과목이 정본 목록에 남고, 지난 날짜의 수업이 그대로 전개된다.

### 6.2 Obsidian 플러그인

- 모바일 호환: Node API를 쓰지 않는다. HTTP는 Obsidian의 `requestUrl`로 한다. 데스크톱 전용 표시를 하지 않는다.
- 실행 시점: 볼트를 열 때, 명령을 받았을 때. 열려 있는 동안의 주기 실행은 선택이다.
- 명령:
  - pOS 가져오기: §5.2 규칙으로 `pOS/`를 맞춘다.
  - 전체 검증: 모든 투영 파일의 자기 해시를 검사해 보고한다.
  - 전체 재생성: `_상태.md`를 뺀 `pOS/`를 지우고 다시 가져온다. 훼손 파일이 있으면 먼저 보고하고 확인을 받는다.
  - 오늘 일기 열기: 서버에서 귀속일을 받아 `04 Journal/<귀속일>.md`를 열고, 없으면 템플릿으로 만든다.
  - 과목 허브 만들기: 이번 학기 정본 과목 중 허브가 없는 것만 템플릿으로 만든다. 이미 있는 노트는 건드리지 않는다.
- 보고: `pOS/_상태.md`와 알림. `_상태.md`에는 마지막 수신 시각, 결과, 쓴·건너뛴·훼손 파일 수와 목록, 서버 스키마 버전을 쓴다. 이 파일은 투영이 아니라 플러그인 자신의 기록이며 INV-7의 대상이 아니다.
- 하지 않는 것: 문장 만들기, 볼트 노트를 읽어 pOS로 보내기, `pOS/` 밖 파일 수정. 예외는 "오늘 일기 열기"와 "과목 허브 만들기"의 새 파일 생성뿐이다.
- 토큰은 플러그인 설정 파일에 저장된다. 볼트는 공개 저장소에 두지 않는다.

### 6.3 볼트 설정

- 코어 Daily Notes는 끈다. 달력 날짜로 노트를 만들어 C-3과 어긋난다. 일기는 "오늘 일기 열기"로 연다.
- 코어 Templates의 폴더를 `90 Templates`로 한다.
- 서식을 자동 정리하는 플러그인은 `pOS/`와 `삼성노트/`를 제외한다.
- `pOS/`와 `삼성노트/`를 검색·그래프 제외 목록에 넣지 않는다. 엮기의 대상이다.
- 내부 링크 자동 갱신을 켠다. 새 볼트에서는 꺼져 있다. 과목명 변경은 P-3의 순서를 따른다.
- 새 노트의 기본 위치는 `00 Inbox`다. 링크를 눌러 만든 개념 노트도 여기 생기며, 사람이 `06 Concepts`로 옮긴다(C-9).

### 6.4 볼트 규칙 파일

`AGENTS.md`에 에이전트가 지킬 규칙을 둔다(부록 C). `CLAUDE.md`는 `@AGENTS.md` 한 줄이다. AI 비중이 작아도, 에이전트가 볼트를 열 때 생길 수 있는 INV-9·INV-11 위반을 거의 비용 없이 막는다.

### 6.5 필기 투영기

- 자리: 삼성 노트 앱이 설치된 Windows PC 하나. 작업 스케줄러로 돈다. PC가 꺼져 있으면 돌지 않으며, 그 공백은 상태 파일의 시각으로 보인다.
- 동기화: 삼성 노트 동기화를 12시간을 넘기지 않는 간격으로 내린다(DEC-22). 내리는 방법은 OPEN-11.
- 투영 주기: `Storage.sqlite`의 수정 시각으로 저장소 변화를 확인하고, 바뀐 노트만 다시 만든다. 동기화를 내린 뒤에도 한 번 돈다.
- 읽기: 삼성 노트 저장소는 읽기만 한다(INV-11). `Storage.sqlite`는 WAL 모드라 사본을 떠서 읽는다. 노트 폴더 안의 삼성 무결성 해시가 모두 맞는 노트만 변환한다. 맞지 않으면 앱이 쓰는 중으로 보고 다음 회차로 미루며, 두 회차 연속이면 보고한다.
- 정본 대조: 정본 과목 목록(§5.5, 모든 학기)을 받아 학기 폴더 아래 과목 폴더 이름과 NFC로 정규화해 대조한다(DEC-27, DEC-30). 맞지 않는 폴더는 투영하지 않고 보고한다.
- 쓰기: 볼트에서는 `삼성노트/`만 읽고 쓴다. 쓴 파일의 해시를 PC의 자기 기록에 남긴다.
- 상태 파일 `삼성노트/_상태.md`는 투영이 아니라 투영기 자신의 기록이며 INV-7의 대상이 아니다. 다음을 쓴다.
  - 마지막 동기화 명령 시각과 결과
  - 저장소 마지막 갱신 시각(`Storage.sqlite` 수정 시각)
  - 반영된 강의 필기 노트의 최신 수정 시각
  - 마지막 실행 시각과 결과, 쓴·건너뛴·훼손·실패 파일 수와 목록
  - 정본과 맞지 않는 과목 폴더, 강의 필기 노트가 둘 이상인 과목 폴더(오류)
  - 강의 필기 노트가 없는 과목 폴더(정보. 필기하지 않는 과목이 있다)
  - 변환기 버전
- 설정: 학기 폴더 목록(학기마다 더하고, 지난 학기는 빼지 않는다), 볼트 경로, pOS API 주소와 토큰, 변환기 경로. 설정과 기록은 PC에 두고 볼트에 두지 않는다.
- 테스트(smoke):
  - 결정성: 같은 노트를 두 번 투영하면 같은 바이트가 나온다.
  - 묶음: 수업 날짜가 셋인 노트에서 PDF가 셋 나오고, 각 PDF의 쪽 수가 그 날짜의 내용 있는 페이지 수와 같다.
  - 가져온 PDF: 가져온 PDF 페이지가 든 노트에서, 그 쪽의 글자를 PDF에서 추출할 수 있다.
  - 훼손: 기록과 다른 파일은 덮이지 않고 보고된다.
  - 쓰는 중: 무결성 해시가 맞지 않는 노트는 건너뛴다.
  - 이름 정규화: NFD로 저장된 과목 폴더가 NFC 정본과 맞고, 볼트에 쓴 파일 이름은 NFC다.
  - 지난 학기: 정본 목록에 남은 지난 학기 과목 폴더가 계속 투영되고, 그 PDF가 지워지지 않는다.

## 7. 학업 필기

### 7.1 역할

- 삼성 노트: 필기 원본. 고칠 수 있는 원본은 여기 하나다. 과목마다 강의 필기 노트 하나에 수업 날짜별로 페이지를 이어 쓴다(C-8).
- 필기 PDF: 강의 필기 노트의 투영(§5.7). 볼트의 `삼성노트/`에 수업 날짜 단위로 생긴다.
- Gemini 노트북: 과목별 AI 복습 공간. 볼트와 동기화하지 않고 이름과 주소로만 연결한다(DEC-12).
- 개념 노트: 강의 노트가 가리키는 지식. 과목과 학기를 넘어 남는다(C-9, DEC-26).

### 7.2 이름 하나로 묶기

삼성 노트 과목 폴더, 볼트 과목 폴더, `삼성노트/`의 과목 폴더, Gemini 노트북의 이름을 모두 정본 과목명으로 한다. 허브 노트 속성 `gemini_notebook`에 노트북 주소를 둔다.

### 7.3 저장 단위

수업 하나가 PDF 하나다. 페이지는 `[[양자물리및연습2 2026-09-23.pdf#page=3]]`처럼 링크한다. 페이지마다 파일을 나누지 않는다(DEC-11). 노트북 소스 형식은 OPEN-8에서 정한다.

### 7.4 원본 수정

삼성 노트에서 지난 수업의 페이지를 고치면 다음 투영에서 그 날짜의 PDF가 다시 만들어진다. 파일 이름이 링크 계약이므로(C-6) 링크는 그대로다. 노트북 소스는 필요할 때만 교체한다.

## 8. 절차

**P-1 강의 뒤 필기**

1. 수업 중 강의 필기 노트에 그날 새 페이지를 만들어 쓴다(C-8).
2. 필기 투영기가 다음 동기화 뒤 `삼성노트/<과목>/<과목> <수업 날짜>.pdf`를 만든다. 바로 필요하면 PC의 삼성 노트에서 동기화를 누른다.
3. 같은 파일을 Gemini 노트북에 소스로 추가한다.
4. 템플릿으로 강의 노트를 만든다(과목 링크, PDF 임베드, 정리 칸).
5. 노트북에서 복습한 뒤 남길 것만 강의 노트에 자기 말로 옮기고, 나오는 개념에 링크를 건다(DEC-26).

5단계는 자동화하지 않는다. 노트북 대화는 노트북에 남고, 볼트에는 소화한 것만 들어간다.

**P-2 Me 소유권 이전** (S3)

1. pOS에서 Me 편집을 잠근다.
2. Life Model의 현재 상태를 볼트 소유 노트로 내보낸다(`01 Me/`). 학업 항목(과목, 성적, 학점, 상태)은 허브 노트 속성으로 옮긴다. 내보낸 파일은 투영이 아니므로 `pos_*` 속성을 달지 않는다.
3. 사람이 내용을 확인한다.
4. pOS의 Life Model 테이블은 보관 전용으로 두고, 주간 제안 파이프라인을 멈추고, Me 탭을 뺀다.

**P-3 과목명 변경**

1. pOS 시간표에서 정본을 바꾼다.
2. pOS 가져오기를 한다. 투영이 새 이름으로 링크한다.
3. 삼성 노트의 과목 폴더와 강의 필기 노트 제목을 바꾼다(C-8). 다음 투영에서 `삼성노트/`의 PDF가 새 이름으로 생기고 옛 이름은 지워진다.
4. 볼트의 과목 폴더, 허브, 강의 노트 이름을 바꾸고, 강의 노트 안의 PDF 임베드를 새 이름으로 고친다. Gemini 노트북 이름도 맞춘다.

순서를 거꾸로 하면 Obsidian의 링크 자동 갱신이 `pOS/` 파일을 고쳐 훼손 보고가 뜬다. 그때는 전체 재생성으로 복구한다.

**P-4 투영 스키마 변경**: §5.6.

**P-5 훼손 복구**

1. `_상태.md`에서 훼손 파일을 확인한다.
2. 사람이 쓴 내용이 있으면 자기 노트로 옮긴다.
3. 그 파일을 지우고 가져오기를 한다. `삼성노트/`의 파일은 다음 투영에서 다시 생긴다.

**P-6 새 학기**

1. pOS 시간표를 입력한다. 이번 학기 정본 과목명이 생기고, 지난 학기 정본은 남는다(DEC-27).
2. 과목 허브 만들기를 실행한다.
3. 삼성 노트에 학기 폴더를 만들고, 그 아래 정본 이름의 과목 폴더와 강의 필기 노트를 만든다(C-8). 필기 투영기 설정의 학기 폴더 목록에 더한다.
4. Gemini 노트북을 같은 이름으로 만든다.

**P-7 맨손 운영** (S0, 1주, DEC-29)

플러그인과 투영 없이 볼트만으로 한 주를 지낸다. DEC-1의 전제(볼트를 실제로 연다)를 본다.

준비

1. Obsidian을 기기 하나에 설치하고 볼트를 만든다. 수업 직후와 밤에 실제로 손에 드는 기기를 고른다(CHK-12의 가정은 태블릿). 동기화는 OPEN-2를 정할 때까지 두지 않는다.
2. 폴더를 만든다: `00 Inbox`, `02 Education/<정본>`(수강 과목마다), `04 Journal`, `06 Concepts`, `90 Templates`. `pOS`와 `삼성노트`는 만들지 않는다.
3. 설정: 코어 Daily notes를 끄고, Templates 폴더를 `90 Templates`로, 새 노트 기본 위치를 `00 Inbox`로 한다(§6.3). 커뮤니티 플러그인은 설치하지 않는다.
4. 과목 폴더마다 허브 노트를 만든다(C-1). 템플릿은 부록 B의 맨손 판을 쓴다.
5. 삼성 노트의 이번 학기 과목 폴더와 강의 필기 노트 이름을 C-8에 맞춘다.

운영

6. 수업 뒤 과목 폴더에 강의 노트 `<정본> <YYYY-MM-DD>`를 만든다(C-2). 필기 PDF는 넣지 않는다. 나중에 필기 투영기가 같은 이름의 PDF를 만든다(C-4).
7. 밤에 `04 Journal/<귀속일>.md`에 일기를 쓴다. pOS 하루 경계 전의 새벽이면 전날 날짜다. pOS에 있는 수치·일정·과제·목표는 옮겨 적지 않는다(INV-1, DEC-17).
8. 개념에는 처음부터 링크를 건다. 같은 개념에 두 번째 링크가 생기면 노트를 만들어 `06 Concepts`로 옮긴다(DEC-26).
9. `00 Inbox/맨손 운영 기록.md`에 날마다 한 줄을 적는다: 연 기기와 때, 한 일, 다른 기기에서 열고 싶었던 순간, pOS에서 보고 싶었던 것, 불편했던 것.

확인

10. CHK-15를 확인한다. 볼트를 태블릿에 두었으면 CHK-4도 확인한다.

판정

11. 7일째에 DEC-29로 판정한다. 셀 것: 일기나 강의 노트를 만든 날 수, 강의 노트 수와 그 주의 필기하는 수업 수, 개념 노트 수와 개념으로 가는 링크 수. 9의 기록은 OPEN-2와 S1 범위의 근거로 쓴다.

**P-8 학기 끝**

1. 성적·학점·상태를 pOS의 Life Model 학업 항목에 적는다. S3 뒤에는 허브 노트 속성에 적는다(DEC-28).
2. 학기 회고는 `05 Analysis`에 쓴다.
3. 파일을 옮기거나 지우지 않는다. 학기 범위가 지나면 과목이 `지금.base`에서 빠진다(DEC-25).
4. 다음 학기는 P-6을 따른다.

## 9. 결정 기록

**DEC-1** Obsidian을 중심에 두고 pOS를 감각기관·반사로 둔다.
- 기각: pOS를 볼트로 옮긴다. 과거 기록 불변성이 DB 트리거의 '막음'에서 파일 이력의 '기록'으로 내려간다. 파일 속성에는 필수·열거 제약이 없어 스키마 검증이 사라진다. Guard가 받는 일정이 "기기 → 동기화 → 서버" 사슬을 타며 최종 일관성으로 바뀐다.
- 기각: 지금 구조를 유지한다. 일정과 학업이 엮이지 않는다.

**DEC-2** 투영을 파일로 쓴다.
- 기각: 플러그인이 pOS API를 실시간으로 그려 보여 준다. 검색·백링크·Bases는 볼트 안의 파일만 보므로 엮이지 않는다.

**DEC-3** 흐름은 한 방향, 역방향은 명령으로만 둔다.
- 기각: 양방향 파일 동기화. 주인이 둘이 되고, 충돌과 조용한 실패가 가장 잘 생기는 구조다.

**DEC-4** 플러그인이 당겨온다(pull).
- 기각: 서버가 볼트 git 저장소에 커밋한다. 모바일 git 동기화의 안정성 문제가 있고, 저장소 쓰기 권한을 서버에 둬야 한다. AI 비중이 작아 git이 주는 에이전트 접근 이점도 작다.

**DEC-5** 문장과 링크는 서버 렌더러 한 곳이 만든다.
- 기각: 플러그인에서 렌더한다. 렌더러가 둘이 되고 서버 테스트 밖으로 나간다.

**DEC-6** 정본 과목명을 pOS에 둔다.
- 기각: 볼트 노트의 aliases로 이름을 맞춘다. Obsidian은 `[[별칭]]`을 그 별칭을 가진 노트로 해석하지 않는다. 미해결 링크가 되고, 누르면 빈 노트가 생긴다.
- 기각: 별칭을 해석하는 서드파티 플러그인. 실험적이다.

**DEC-7** 자기 검증 해시를 파일 안에 둔다.
- 기각: 플러그인이 기기별로 마지막으로 쓴 해시를 저장한다. 기기가 둘 이상이면 다른 기기가 쓴 정상 파일을 훼손으로 오판한다.

**DEC-8** 투영 파일 이름에 고정 접미사를 붙인다.
- 기각: 날짜·과목명만 쓴다. Journal·허브와 이름이 겹쳐 링크가 모호해진다.

**DEC-9** day는 닫힌 날만 투영한다.
- 기각: 열린 날도 기록으로 투영한다. 파일이 하루 종일 바뀌고, 운영(pOS 앱)과 기록(볼트)이 섞인다.

**DEC-10** 일기 파일 이름은 귀속일로 하고, 여는 경로는 플러그인 명령으로 한다.
- 기각: 코어 Daily Notes. 달력 날짜를 써서 새벽에 쓴 일기가 다음 날 노트에 붙는다.

**DEC-11** 필기는 수업 단위 PDF로 투영한다. 노트북 소스 형식은 OPEN-8에서 정한다.
- 기각: 페이지 단위 이미지. 노트북 소스 상한을 빠르게 채우고 파일이 흩어진다.
- 기각: 강의 필기 노트 전체를 PDF 하나로. 노트가 학기 내내 자라서, 수업 하나를 가리키려면 쪽 번호를 알아야 하고 노트북 소스를 매번 통째로 바꿔야 한다.

**DEC-12** Gemini 노트북은 이름과 주소로만 연결한다.
- 기각: 비공식 API로 동기화한다. 문서화되지 않은 내부 API와 세션 쿠키 인증을 쓰므로 예고 없이 끊길 수 있다.
- 기각: Gemini API로 노트북 기능을 직접 만든다. AI 비중을 작게 가져가는 범위를 벗어난다.

**DEC-13** pOS 축소는 마지막 단계에서 한다.
- 기각: 먼저 축소한다. 볼트가 정착했는지 확인하기 전에 기능을 잃는다.

**DEC-14** `pOS/guard` 폴더를 두지 않는다. 밤 기록은 day에 넣는다.
- 기각: Guard 전용 투영 폴더. 밤 사건은 귀속일의 day와 키가 같아서, 같은 사건이 두 파일에 산다. 월 단위 집계가 필요해지면 그때 스키마 변경으로 더한다.

**DEC-15** 분석은 둘로 나눈다. 지난 분석은 `pOS/analysis`에 투영해 보관하고, 앞으로의 분석은 `05 Analysis`(볼트 소유)에 쓴다.
- 기각: 지난 분석을 `05 Analysis`로 옮긴다. 폴더 하나에 주인이 둘이 된다.

**DEC-16** pOS 앱의 최종 탭은 Today · Calendar · Works · Guard다. Analysis와 Me는 뺀다. Me 탭에 있던 Guard 기록 화면은 Guard 탭으로 옮긴다.
- 기각: Me 탭을 남겨 이전된 내용을 보여 준다. pOS가 볼트를 읽어야 한다(INV-3).

**DEC-17** 하루 기록의 경계를 나눈다. pOS에는 그 순간의 측정(수치, 상태 기록, 로그)을 쓰고, Journal에는 해석을 쓴다.
- 기각: 일기 본문을 pOS와 Journal 양쪽에 쓴다. 같은 내용을 두 번 쓰게 되고, 결국 한쪽을 버린다.

**DEC-18** 필기 PDF는 사람이 내보내지 않고, 필기 투영기가 삼성 노트 PC 앱의 로컬 저장소를 읽어 만든다(INV-11).
- 기각: 사람이 수업마다 PDF로 내보낸다. 단계가 하나 늘고, 태블릿에서 저장 위치와 덮어쓰기를 따로 맞춰야 한다. 삼성 노트가 내보내는 PDF는 필기를 이미지로 넣는다는 보고가 있다.
- 기각: 태블릿 앱 저장소를 읽는다. 루팅 없이는 접근할 수 없다.
- 기각: 삼성 클라우드를 직접 읽는다. 공개 API가 없다.
- 기각: OneNote 연동. 노트가 Outlook의 OneNote 피드에 읽기 전용으로 보일 뿐, 읽어 올 공개 API를 찾지 못했다.

**DEC-19** 강의 필기 노트의 페이지를 수업 날짜로 묶어 수업을 가른다. 페이지 ID가 UUIDv1이라 만든 시각이 들어 있고, 강의 필기 노트 네 개에서 페이지 순서대로 날짜를 묶었을 때 묶음이 과목마다 일정한 요일에 모였다(2026-09).
- 위험: 페이지를 만든 날과 쓴 날이 다르면 잘못 묶인다. 한 페이지에 두 수업을 이어 쓴 경우가 이미 있다(2026-09). 수업 필기를 그날 만든 새 페이지에 쓰는 규칙(C-8)으로 받아들인다.
- 기각: 수업마다 새 노트를 만든다. 필기 방식을 바꿔야 한다.
- 기각: 페이지 첫머리에 손으로 쓴 날짜를 인식한다. 필기 인식 결과는 PC 앱에서 연 노트에만 생기고, 인식이 틀리면 조용히 잘못 묶인다.

**DEC-20** 강의 노트와 필기 PDF의 이름 키는 수업 날짜다.
- 기각: 회차 번호(`<NN>강`). 번호는 원천에 없어 세는 규칙이 필요하고(휴강·보강), 앞 수업의 필기가 사라지면 뒤 번호가 밀려 바뀌지 않는 키(C-5)가 되지 못한다.

**DEC-21** 변환기는 sdocx2pdf를 버전을 고정해 쓴다. 시험한 후보 중 가져온 PDF 페이지를 글자 층과 함께 그리는 것은 이것뿐이다. 2026-09 기준 최신판(0.4.0)은 현재 형식의 `end_tag.bin` 끝 4바이트에서 멈추므로, 이를 건너뛰는 한 줄 패치를 얹어 빌드하고 노트 폴더를 zip으로 묶어 넣는다(폴더를 그대로 넣으면 가져온 PDF를 찾지 못한다). 이 구성은 시험한 강의 필기 노트 두 개에서 필기·가져온 PDF·붙인 이미지를 모두 그렸고, 같은 입력에 같은 바이트를 냈다. 역설계 도구라 형식이 바뀌면 다시 깨질 수 있으며, 실패는 상태 파일에 보인다(INV-10). 업스트림에 수정이 들어가면 패치를 걷는다.
- 기각: sdocx(twangodev/sdocx) CLI. 현재 형식을 패치 없이 읽고 Windows 실행 파일도 있지만, 가져온 PDF 페이지를 그리지 않는다(0.6.0). 강의 자료를 가져와 필기한 페이지의 내용이 빠진다.
- 기각: 삼성 노트 앱의 PDF 내보내기를 화면 조작으로 부른다. 필기가 이미지로 들어가고, 화면 조작은 앱 업데이트에 쉽게 깨진다.

**DEC-22** 삼성 노트 동기화는 필기 투영기가 12시간을 넘기지 않는 간격으로 내리고, 마지막 동기화 시각을 상태 파일에 보인다(§6.5).
- 기각: 앱의 백그라운드 동기화에 맡긴다. 앱을 열지 않은 채 들어온 변경의 지연이 1분에서 41시간까지였고, 앱을 열어 동기화를 누르기 전까지 13시간 넘게 들어오지 않은 변경도 있었다(2026-09 관측).

**DEC-23** 필기 투영의 훼손은 투영기가 PC에 남긴 파일 해시 기록으로 판정한다.
- 기각: pOS 투영처럼 파일 안에 자기 해시를 둔다. PDF에는 frontmatter가 없어 파일 형식을 건드려야 한다. 쓰는 기기가 PC 하나이므로 DEC-7의 기각 사유(여러 기기가 각자 쓴다)가 없다.

**DEC-24** 볼트의 노트를 나·지금·지식·기록의 네 층으로 읽고(§4.1), 층 사이는 링크로 잇는다. 링크는 기록에서 위쪽으로 걸고, 위쪽 노트는 백링크와 조회로 채운다.
- 기각: 층을 폴더 트리로 만든다(`나/학업/학기/과목/개념`). 한 개념이 여러 수업과 과목에 걸쳐 나오면 트리의 한 자리에 둘 수 없다. 폴더는 §4처럼 노트의 종류와 주인으로 나눈다.
- 기각: 위쪽 노트(허브, 개념)에 관련 기록의 목록을 손으로 적는다. 목록은 적는 대로 낡고, 백링크가 같은 것을 저절로 보여 준다.

**DEC-25** 지금(활성 작업 집합)은 파일로 두지 않고 조회로 만든다. `지금.base`(코어 Bases)가 시작일 ≤ 오늘 ≤ 종료일인 기간 투영, 학기 범위가 오늘을 포함하는 과목 투영, `status`가 진행인 프로젝트 허브를 모은다. 기간이나 학기가 끝나면 아무것도 옮기지 않아도 조회에서 빠진다.
- 조회는 볼트 쪽 보기라 오늘 날짜를 읽는다. 투영 파일은 절대 날짜만 싣고(§5.3), 오늘과의 비교는 조회가 한다. 그래서 INV-7과 어긋나지 않는다.
- 기각: `지금` 폴더를 두고 학기마다 노트를 들이고 내보낸다. 옮길 때마다 무엇을 어디로 보낼지 정해야 하고, 빠뜨린 노트가 남는다.
- 기각: 지금 노트에 이번 기간·목표·과목을 적는다. 기간과 목표의 주인은 pOS라서 주인이 둘이 된다(INV-1). 기간의 목표는 기간 투영이 싣는다(§5.4).
- 기각: 과목 허브의 상태를 학기마다 손으로 바꿔 지금을 정한다. 날짜로 정해지는 것을 손으로 따라가게 되고, 상태는 P-2 전에는 pOS에 있다(DEC-28).

**DEC-26** 개념 노트는 `06 Concepts` 한 곳에 하위 폴더 없이 둔다(C-9). 링크는 처음부터 걸고, 같은 개념에 두 번째 링크가 생기면 노트를 만든다. 막힘 같은 이해 상태는 개념 노트의 속성으로 둔다(§4.1).
- 근거: 한 개념이 여러 수업에 걸쳐 나온다. 한 과목의 이어진 두 수업 필기가 같은 개념을 다루는 것을 확인했다(2026-09). 과목을 넘는 경우는 필기로 아직 확인하지 않았지만, 개념을 과목 아래 두면 그 경우를 받을 자리가 없다.
- 기각: 과목 폴더 아래 개념 폴더. 과목을 넘는 개념이 과목마다 따로 생긴다.
- 기각: 처음부터 개념 목록을 만든다. 쓰이지 않는 빈 노트가 먼저 쌓인다.

**DEC-27** 정본 과목명은 학기마다 쌓이고 사라지지 않는다. pOS 시간표는 새 시간표를 저장할 때 학기 범위가 겹치는 규칙만 바꾸고, 다른 학기의 규칙은 남긴다. 정본 과목 목록(§5.5)은 모든 학기를 준다.
- 근거: 지금의 시간표 저장은 전체 교체다. 다음 학기 시간표를 넣으면 이번 학기 규칙이 지워지고, 다음이 함께 일어난다.
  - pOS에서 지난 날짜를 열면 그날의 수업이 사라진다. 수업은 규칙에서 전개하기 때문이다.
  - 지난 학기 과목이 정본 목록과 과목 투영에서 빠져, 허브의 임베드가 깨진다.
  - 필기 투영기의 정본 대조가 지난 학기 폴더를 거부하고, §5.7 처리 규칙("대상 목록에 없는 파일")에 따라 그 PDF를 지운다. 강의 노트의 임베드가 깨진다.
  - P-4로 전체 재생성하면 지난 day 투영의 과목 링크가 텍스트로 바뀐다.
- 기각: 필기 투영기가 한 번 맞았던 정본을 기억한다. 기록을 잃으면 같은 투영을 다시 만들 수 없어 INV-7(폐기 가능)이 깨진다. pOS 쪽 문제도 그대로 남는다.
- 기각: Life Model 학업 항목을 정본의 원천으로 쓴다. P-2로 볼트에 이전되므로 그 뒤에는 pOS가 볼트를 읽어야 한다(INV-3).

**DEC-28** 과목 성적·학점·상태는 P-2 전까지 pOS의 Life Model 학업 항목에만 적는다. 허브 템플릿에는 이 속성을 두지 않고, P-2가 허브에 더한다. 지금 듣는 과목인지는 과목 투영의 학기 범위로 판단한다(DEC-25).
- 근거: 허브 템플릿에 상태·학점·성적이 있으면 S2와 S3 사이에 같은 사실을 pOS와 볼트에 따로 적게 된다(INV-1).
- 기각: 학업 항목만 S2에서 먼저 이전한다. 볼트가 자리 잡았는지 확인하기 전에 pOS의 학업 편집을 잠그게 된다(DEC-13).

**DEC-29** S0에서 플러그인 없이 볼트만으로 1주 운영한다(P-7). 판정은 S1을 멈출지 정하는 데만 쓴다. 7일 중 일기나 강의 노트를 만든 날이 4일 이상이면 S1로 가고, 2일 이하면 S1을 멈추고 DEC-1의 전제를 다시 본다. 3일이면 1주 더 운영한다.
- 기각: 맨손 운영 없이 S1로 간다. Obsidian을 써 본 적이 없어, DEC-1의 전제(볼트를 실제로 연다)를 확인하지 않은 채 서버와 플러그인을 만든다.
- 기각: 2주 운영. 판정의 용도는 거의 쓰지 않는 경우를 거르는 것뿐이다. 필기하는 수업이 한 주에 여러 번 있어 강의 노트 흐름을 한 주 안에 여러 번 겪는다.

**DEC-30** 삼성 노트의 폴더·노트 이름은 NFC로 정규화한 뒤 정본과 비교하고, 볼트에 쓰는 이름은 정본에서 만든다. pOS는 시간표 과목명을 NFC로 저장한다.
- 근거: 한 저장소 안에서 폴더 이름이 NFC와 NFD로 섞여 있다(2026-09 관찰: 학년·학기 폴더와 과목 폴더 일부가 NFD). 정규화하지 않고 비교하면 화면에서 같아 보이는 이름이 어긋난다. NFD 이름을 그대로 파일 이름에 쓰면 NFC로 입력한 링크와 글자가 다르다.
- 기각: 폴더 이름을 다시 입력해 NFC로 맞춘다. 어느 기기와 입력기가 NFD를 만드는지 모르므로 다시 생길 수 있다.

| CHK-15 | 속성 값 전체가 링크일 때 백링크에 잡히는가 | 값 전체가 링크면 인식되고 글과 섞이면 인식되지 않는다는 포럼 보고와 운영진 답변이 있다(1.4.16). 공식 문서에는 없다 | 보고 | C-10, 부록 B 강의 노트 |
| CHK-16 | `지금.base`가 투영의 날짜 속성으로 걸러지는가 | Bases는 `today()`와 날짜 비교를 지원한다(공식 도움말). 투영 속성이 날짜 타입으로 읽히는지는 모른다 | 일부 확인 | DEC-25. S2에서 확인 |

확인된 전제(다시 확인하지 않음):

- Obsidian은 `[[별칭]]`을 그 별칭을 가진 노트로 해석하지 않는다. 별칭은 `[[이름|별칭]]` 형식의 표시 텍스트로 쓰인다.
- Obsidian 모바일은 백그라운드에서 플러그인을 실행하지 않는다.
- Gemini 노트북에는 개인 계정용 공식 API가 없다(2026-05 자료 기준). 비공식 라이브러리는 문서화되지 않은 내부 API를 쓴다.
- 코어 플러그인에 폴더 노트가 없다(코어 플러그인 목록, 2026-09). C-1은 그대로다.
- 코어 Daily notes의 설정은 새 파일 위치, 날짜 형식, 템플릿이며 하루 경계 설정이 없다(2026-09). DEC-10은 그대로다.
- 내부 링크 자동 갱신은 새 볼트에서 꺼져 있다(Android 앱, 2026-09). §6.3에 따라 켠다.
- Bases는 코어 플러그인이다. 속성과 폴더(`file.inFolder`)로 거르고, `today()`로 날짜를 비교하며, 코드 블록으로 노트에 임베드된다(공식 도움말, 2026-09).
- PDF 임베드는 `#page=N`으로 쪽을, `#height=N`으로 높이를 정한다(공식 도움말).
- 코어 Templates는 `{{title}}`, `{{date}}`, `{{time}}`만 채우고, 날짜와 시각에는 형식 문자열(`{{date:YYYY-MM-DD}}`)을 붙일 수 있다(공식 도움말).

## 부록 B. 템플릿

`{{…}}` 자리표시는 해당 명령을 실행하는 플러그인이 채운다. 강의 노트는 OPEN-10에 따른다. 속성 안의 자리표시는 따옴표로 감싼다. Live Preview의 속성 패널이 따옴표 없는 자리표시를 고쳐 쓸 수 있다.

```markdown
## 
```
