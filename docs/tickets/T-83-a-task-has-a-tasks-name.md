# T-83 — 할 일은 할 일의 이름을 갖고, 움직이면 어디로 갔는지 말한다

**발행** Cowork · 2026-09-22 · **담당** Claude Code · **보통**
**근거** 2026-09-22 사용자 실측 — *"이름을 '중간고사대체과제, 학기과제' 라고만 했었어야 해"* ·
*"날짜를 정했더니 사라졌다"* · [T-78](T-78-accepted-homework-becomes-a-task.md)(event ≠ task) ·
[T-74](T-74-categories-knows-the-course.md)(`summary` 원문) · ADR-048
**프런트 + 서버 · 마이그레이션 없음 · APK 무관**

---

## ★★★ 명제 둘. 둘 다 *수락한 뒤*의 자리다

```
①  할 일의 이름이 할 일이 아니다      "학기과제 기한" 을 하는 게 아니다
②  움직였는데 어디로 갔는지 안 말한다   대기에서 빠지고, 간 곳은 화면 밖이다
```

---

## ① 제목 — `event`는 마감이고 `task`는 할 일이다

```
event.title   "학기과제 기한"    ★ 맞다. 마감 그 자체이고, 그것이 사실이다
task.title    "학기과제 기한"    ⚠️ "기한을 한다" 가 된다
```

★★★★ **T-78이 event와 task를 가른 것과 같은 자리다** — *"마감은 고정이고 할 일은 이동한다."*
**같은 문자열을 쓰면 둘 중 하나가 반드시 틀린다.**

⚠️ **T-74의 *"제목을 고치지 마라"* 는 `summary` 저장과 `events` 의 규칙이다.**
근거가 *"사용자가 uclass 에서 그 제목으로 찾는다"* 였고, **찾는 자리는 달력이다.**
★ **`task.title` 은 자유 변경 칸이라**(`CLAUDE.md` §아키텍처 원칙 — *id 불변 / title 자유*)
**만들 때 한 번 다듬는 것은 되돌릴 수 있는 해석이다.**

### 규칙 — ⚠️ 끝의 `기한` 하나만 뗀다

```
"학기과제 기한"                    →  "학기과제"
"중간고사대체과제 기한"             →  "중간고사대체과제"
"벡터대수학 2주차 연습문제 제출 기한" →  "벡터대수학 2주차 연습문제 제출"
"기한" 으로 안 끝나는 제목          →  ★ 그대로 둔다
떼고 나서 빈 문자열                 →  ★ 원문을 쓴다
```

⚠️ **그 이상 다듬지 마라** — *"제출"·"문제"* 를 떼는 것은 해석이고, 근거가 없다.
⚠️ **`summary` 저장은 원문 그대로다**(T-74). **`events.title` 도 그대로다.**

---

## ② 움직임 — 날짜를 정하면 **어디로 갔는지 말한다**

**대기에서 날짜를 정하면 대기 목록에서 빠진다. 간 곳은 예정 *"이후"* 구간이고,
먼 날짜일수록 스크롤 밖이다** — T-81 ①이 Works 구조를 *"오늘 / 이번 주 / 이후"* 로 쟀다.

★★ **화면이 아무 말도 안 하므로 *"사라졌다"* 가 맞는 관찰이다.**
⚠️ **ADR-048 계열이다** — *"모르는 버튼은 없는 버튼"* 이 여기서는
***"간 곳을 안 말하면 안 간 것이다."***

### 처방 — 토스트가 **날짜를 말한다**

```
"11월 30일로 옮겼어요"       ★ 그 날짜를 담는다
"옮겼어요"                   ⚠️ 고정 문구는 아무것도 안 말한다
```

⚠️ **스크롤로 따라가게 하지 마라** — `scrollIntoView` 는 금지이고(함정 1),
`scrollTop` 으로 먼 날짜까지 끌고 가면 **지금 보던 맥락을 잃는다.**
★ **말해 주는 것으로 충분하다.**

⚠️ **검사가 이 토스트를 *"끝났다"* 의 신호로 쓰지 마라**(함정 14 · T-53).
**뜬다는 것과 그 안에 날짜가 있다는 것만 센다.**

## 범위

```
src/services/collected.ts   ① accept 가 task 제목을 만들 때
src/services/tasks.ts       ①이 거기가 맞으면 (⚠️ 기존 경로를 쓴다)
public/app.js               ② 날짜를 정하는 핸들러 · 토스트
test/smoke.ts · front.mjs   검사
docs/api-surface.md         응답이 바뀌면 재생성
```

**APK 무관 · `guard/` 안 건드린다 · 마이그레이션 없다.**
⚠️ **①을 어디에 두느냐가 판단이다** — `accept` 안이면 **수집에서 온 것만** 다듬고,
`createTask` 안이면 **손으로 만든 task 도** 다듬는다. ★ **수집분만이다.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| **`events.title` 을 다듬는다** | ⚠️ **달력엔 "…기한"이 맞다.** 마감 그 자체다 |
| `summary` 저장을 다듬는다 | **원문 그대로**(T-74). 사용자가 uclass 에서 그 제목으로 찾는다 |
| `"제출"·"문제"` 까지 뗀다 | ★ **해석이다. 근거가 없다** |
| `createTask` 안에서 전부 다듬는다 | 손으로 만든 task 까지 바뀐다. **수집분만** |
| 고정 문구 토스트 | ⚠️ *"옮겼어요"* 는 **어디로** 를 안 말한다. 지금과 같다 |
| 먼 날짜로 스크롤한다 | `scrollIntoView` 금지(함정 1) · 맥락을 잃는다 |
| 이미 만들어진 task 를 소급해 고친다 | ⚠️ **사용자가 고친 제목을 덮는다.** 자유 변경 칸이다 |
| 기존 `deferTask`·날짜 경로를 새로 짠다 | 대기 판정·`wait_anchor_at` 이 거기 한 곳에 있다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
★ ①을 어느 함수에 뒀는지와 그 이유가 §보고에 있다
```

**검사**

```
1  ★ 수락하면 task.title 에 끝의 "기한" 이 없다              ← ①의 본체
2  ★ 그런데 event.title 은 그대로 "…기한" 이다               ← 1의 짝. ⚠️ 제일 중요
3  ★ collected_items.summary 는 원문 그대로다                 ← T-74 회귀
4  ★ "기한" 으로 안 끝나는 제목은 한 글자도 안 바뀐다          ← 경계
5  ★ 떼면 빈 문자열이 되는 제목은 원문을 쓴다                  ← 방어
6  ★ 손으로 만든 task 는 안 다듬어진다                         ← 수집분만
7  ★ 대기에서 날짜를 정하면 토스트가 뜬다                      ← ②의 본체
8  ★ 그 토스트가 정한 날짜를 담는다 (고정 문구가 아니다)        ← 7의 짝
```

⚠️⚠️ **2가 이 티켓에서 제일 중요한 검사다.** *"둘 다 다듬는"* 구현이 1을 초록으로 통과하고,
**달력에서 마감이 마감처럼 안 읽히게 된다.** 화면에서는 오히려 깔끔해 보인다.
⚠️ **4가 없으면 *"아무 데서나 '기한'을 지우는"* 구현이 통과한다** — 지금 표본이
전부 `"…기한"` 으로 끝나서 1·2·3이 전부 초록이다(T-74 실측 5/5).
⚠️ **8이 없으면 7이 *"옮겼어요"* 로도 통과한다** — 그게 지금과 같은 상태다.
⚠️ **픽스처에 고정 날짜를 쓰지 마라**(함정 12).

**변이**

```
제목을 안 다듬는다                → 1 만 죽는다
★★ event.title 도 다듬는다        → 2 만 죽는다 (1은 초록)
summary 저장도 다듬는다            → 3 만 죽는다
문자열 아무 데서나 "기한" 을 지운다 → ★ 4 만 죽는다 (1·2·3 초록 — 표본이 전부 끝에 있다)
빈 문자열 방어를 뺀다              → 5 만 죽는다
createTask 안으로 옮긴다           → 6 만 죽는다
토스트를 안 띄운다                 → 7 · 8 이 함께 죽는다 (필연)
토스트를 고정 문구로 한다           → ★ 8 만 죽는다 (7은 초록 — 뜨니까)
```

★★ **둘째·넷째·마지막이 짝의 존재 이유다.**
★★★ **변이가 *붙었는지*와 *되돌아갔는지*를 둘 다 본다**(함정 16).
⚠️ **그리고 검사가 *저절로 참*이 되지 않았는지 본다**(`AGENT-CHAIN` §8 다섯 기제).

## ★ 이 티켓이 안 하는 것

- **`events` 를 한 글자도 안 바꾼다.**
- **소급 수정 없음** — 이미 만들어진 task 의 제목은 그대로다.
- **날짜 고르는 UI 를 안 바꾼다** — *"정한 뒤에 말한다"* 까지다.
- **먼 예정의 회색 표시(T-80 ④)를 안 만진다** — 같은 화면이지만 다른 명제다.
- **Guard · 캘린더 쪽은 한 줄도 안 건드린다.**
