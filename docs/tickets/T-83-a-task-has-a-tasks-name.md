## ① 제목 — `event`는 마감이고 `task`는 할 일이다

```
event.title   "학기과제 기한"    ★ 맞다. 마감 그 자체이고, 그것이 사실이다
task.title    "학기과제 기한"    ⚠️ "기한을 한다" 가 된다
```

★★★★ **T-78이 event와 task를 가른 것과 같은 자리다** — *"마감은 고정이고 할 일은 이동한다."*
**같은 문자열을 쓰면 둘 중 하나가 반드시 틀린다.**

⚠️ **T-74의 *"제목을 고치지 마라"* 는 `summary` 저장과 `events` 의 규칙이다.**
근거가 *"사용자가 uclass 에서 그 제목으로 찾는다"* 였고, **찾는 자리는 달력이다.**
★ **`task.title` 은 자유 변경 칸이라**(`CLAUDE.md` §아키텍처 원칙 — *id 불변 / title 자유*)
**만들 때 한 번 다듬는 것은 되돌릴 수 있는 해석이다.**

### 규칙 — ⚠️ 끝의 `기한` 하나만 뗀다

```
"학기과제 기한"                    →  "학기과제"
"중간고사대체과제 기한"             →  "중간고사대체과제"
"벡터대수학 2주차 연습문제 제출 기한" →  "벡터대수학 2주차 연습문제 제출"
"기한" 으로 안 끝나는 제목          →  ★ 그대로 둔다
떼고 나서 빈 문자열                 →  ★ 원문을 쓴다
```

⚠️ **그 이상 다듬지 마라** — *"제출"·"문제"* 를 떼는 것은 해석이고, 근거가 없다.
⚠️ **`summary` 저장은 원문 그대로다**(T-74). **`events.title` 도 그대로다.**

---

## ② 움직임 — 날짜를 정하면 **어디로 갔는지 말한다**

**대기에서 날짜를 정하면 대기 목록에서 빠진다. 간 곳은 예정 *"이후"* 구간이고,
먼 날짜일수록 스크롤 밖이다** — T-81 ①이 Works 구조를 *"오늘 / 이번 주 / 이후"* 로 쟀다.

★★ **화면이 아무 말도 안 하므로 *"사라졌다"* 가 맞는 관찰이다.**
⚠️ **ADR-048 계열이다** — *"모르는 버튼은 없는 버튼"* 이 여기서는
***"간 곳을 안 말하면 안 간 것이다."***

### 처방 — 토스트가 **날짜를 말한다**

```
"11월 30일로 옮겼어요"       ★ 그 날짜를 담는다
"옮겼어요"                   ⚠️ 고정 문구는 아무것도 안 말한다
```

⚠️ **스크롤로 따라가게 하지 마라** — `scrollIntoView` 는 금지이고(함정 1),
`scrollTop` 으로 먼 날짜까지 끌고 가면 **지금 보던 맥락을 잃는다.**
★ **말해 주는 것으로 충분하다.**

⚠️ **검사가 이 토스트를 *"끝났다"* 의 신호로 쓰지 마라**(함정 14 · T-53).
**뜬다는 것과 그 안에 날짜가 있다는 것만 센다.**

## ① 어느 함수에 뒀는가 — **`collected.taskTitleOf`, `accept` 가 부른다**

```ts
// src/services/collected.ts
const DEADLINE_SUFFIX = "기한";
export function taskTitleOf(summary: string): string {
  const s = summary.trim();
  if (!s.endsWith(DEADLINE_SUFFIX)) return summary;                 // 끝이 아니면 한 글자도 안 바꾼다
  return s.slice(0, -DEADLINE_SUFFIX.length).trim() || summary;     // 떼면 비는 제목은 원문을 쓴다
}
```

**`createTask` 가 아닌 이유 셋:**

```
① 다듬는 근거가 "수집한 마감에서 왔다" 하나다   손으로 만든 task 엔 그 근거가 없다(§금지)
② createTask 는 대기 판정·wait_anchor_at 을 진다  제목 해석을 거기 얹으면 층이 섞인다
③ task.title 은 자유 변경 칸이다                 만들 때 한 번 다듬는 것은 되돌릴 수 있다
```

⚠️ **`events.create` 는 `row.summary` 를 그대로 받는다** — 한 함수 안에서 두 문자열이
갈리는 것이 이 티켓의 전부다. `stAcceptCollected` 도 `summary` 를 안 건드린다.

제대로 붙여 다시 돌리자 **6만** 이 나왔다.

⚠️ **원인은 셸 heredoc 이 `\` 를 한 겹 먹은 것**이다(함정 17). 이 세션에서 **두 번** 났고
(검사 삽입 한 번 · 변이 도구 한 번), **둘 다 `Write` 로 파일에 쓰자 사라졌다.**
★ **`\n` 같은 홑 백슬래시는 살아남는다 — 죽는 것은 `\` 다.** 그래서 앞서 T-82 의 `\r` 걷기는
멀쩡했고 여기만 물렸다: **도구가 먹은 것이 무엇인지 먼저 가르지 않으면 못 본다**(함정 18).

## ★ 안 한 것

- **`events` 를 한 글자도 안 바꿨다** · **`summary` 저장도 그대로다.**
- **소급 수정 없음** — 이미 만들어진 task 제목은 그대로다(사용자가 고친 제목을 안 덮는다).
- **날짜 고르는 UI 를 안 바꿨다** — *"정한 뒤에 말한다"* 까지다. `openDay(k)` 도 그대로.
- **먼 예정의 회색 표시(T-80 ④) · Guard · 캘린더를 안 만졌다.**
