# T-88 — 과제 재촉 ② 기기: 그 시각에 울리고, [완료] 한 번으로 끝난다

**발행** Cowork · 2026-10-02 · **담당** Claude Code · **보통**
**상태** ✅ 닫힘 · 2026-10-08 설계층 — **① 서버 보정 구현 완료 · ② 기기 구현은 사용자 결정으로 취소**
**근거** [ADR-050](../../APP-ADR.md#adr-050) · [T-87 §보고](T-87-nudge-points-from-the-deadline.md)(Cowork 결정 셋 · 계약) ·
ADR-031(알림 액션) · ADR-004(쓰기 큐 없음) · 함정 13
**서버 보정 셋 + APK · 마이그레이션 없음**
**현재 결정:** 과제 알림은 Tasks.org(uclass-tasks)가 맡는다(사용자 · 2026-10-08 · ADR-050 개정).
**②에는 착수하지 않는다.** 아래 범위·완료 조건·배포/APK/폰 확인 절차는 종전 계획의 이력이며 재개 지시가 아니다.
남은 서버/웹 정리는 T-94, ①-d 발견 둘은 T-95·T-96으로 넘긴다. 기기 구현 완료로 닫는 것이 아니다.

---

## 무엇을 하나

T-87 이 서버에서 재촉 시각을 계산해 싣는다. **이 장은 기기가 그것을 받아 울리고, 알림에서 끝낼 수 있게 한다.**

```
계약 (T-87 · docs/api-surface.md)
  nudges: [ { at, items: [ { task_id, course, title, due } ] } ]
```

★ **그 앞에 서버 보정 셋을 먼저 한다** — T-87 §보고가 올린 Cowork 결정이다. verify 로 잴 수 있어서 먼저 닫는다.

## ① 서버 보정 — 먼저. 따로 커밋해도 된다

### ①-a "1시간 미만" 이다 — 정각 1시간은 안 합친다

T-87 은 *"1시간 안"* 을 **이하(≤)** 로 읽었다. ⚠️ **그러면 무너진다:**

```
11:00 마감    08:00 (3시간 전) · 09:00 (아침) · 10:00 (1시간 전)  ← 정확히 1시간씩
이하로 합치면  08→09 합침, 09→10 합침  →  10:00 하나만 남는다
```

★ **합치는 규칙은 *거의 같은 시각의 중복*을 없애려는 것이지 간격을 줄이려는 것이 아니다**(ADR-050 ② 개정).
**미만(<)으로 바꾸고, 검사가 그 경계를 정한다** — 지금 검사는 정각 1시간을 안 정한다(T-87 §보고).

### ①-b 마감 시각 이후의 점은 뺀다

```
08:00 마감 → "당일 아침 09:00" 은 마감 뒤다 → 빼야 한다
09:00 마감 → "당일 아침 09:00" 은 마감과 같다 → "마감까지 0분" — 빼야 한다
```

★ **이미 빼고 있으면 검사만 확인한다.** 안 빼고 있으면 넣는다(ADR-050 ② 개정 — 규칙이 넷이 됐다).

### ①-c 수집 일정(마감)을 고치면 기기를 깨운다

T-87 §보고 결정 ②: **일정 수정은 깨우고, 하루 경계·오프셋 변경은 안 깨운다.**

```
마감 일정의 날짜·시각을 고친다   →  ★ nudge_changed  (그날 재촉이 틀리면 아프다 · 사용자가 앱에 있다)
하루 경계·오프셋을 바꾼다         →  안 깨운다 — 드물고, 하루 동기화가 그물이다
```

### ①-d 읽기만 — 둘

```
□ uclass 에서 과제 마감이 바뀌면, 이미 수락된 일정의 시각이 따라 바뀌나
   (수집 원장은 갱신되는데 수락 때 복사한 일정은 안 바뀔 수 있다 — 그러면 재촉이 옛 마감을 본다)
□ 수집에서 온 할 일에 삭제를 누르면 사용자는 무엇을 보나 (409 → 화면에 뭐라고 뜨나)
```

⚠️ **둘 다 보고만 한다. 고치지 않는다** — 고칠지는 Cowork 가 정한다.
★ 두 번째의 배경: ADR-050 ⑤ 개정 — **수집분 할 일은 지울 수 없고 취소가 그 자리다.**
**연결을 비워 삭제를 열지 않는다**(비어 있는 연결은 이미 *"이미 했어요"* 의 뜻이다 · T-80 ③).
**그런데 삭제 버튼이 보이고 누르면 오류만 뜬다면 그건 ADR-048 의 *"모르는 버튼"* 이다** — 그래서 본다.

## ② 기기 — 취소 (아래는 종전 계획)

### 받기

```
GuardSync 가 nudges 를 읽어 예약한다
동기화마다 통째로 갈아 끼운다     (서버가 안 싣는 것 = 끝난 것 → 취소)
부팅하면 되살린다                 (GuardAlarmStore · restoreAll 을 쓴다)
```

★ **보관 껍데기(GuardAlarmStore)는 쓰고, 종류를 가를 칸이나 id 구간을 둔다**(T-87 전 담당 실측 — 지금은 종류 칸이 없다).

### 예약 방식 — ⚠️ 알람시계가 아니다

```
시스템 "다음 알람" 에 뜨면 안 된다     → setAlarmClock 을 쓰지 않는다
정각일 필요는 없다                    → 몇 분 늦는 것은 괜찮다
몇 시간 늦으면 안 된다                → 기기가 잠들어도(Doze) "1시간 전" 은 1시간 전 근처에 와야 한다
```

★ **방식은 담당이 고른다. 고른 이유를 §보고에 적는다**(정확 알람 권한이 필요한가 · 지금 앱에 있는가 포함).

### 울리는 길 — ⚠️ 밤 개입 경로를 안 탄다

T-87 전 담당 실측이 짚은 다섯을 전부 피한다:

```
GuardNotifications.fire()   안 탄다     cause 기본값 "protect" 로 기록된다
GuardNight.note()           안 부른다   밤 방해 횟수에 섞인다 — ADR-049 의 수가 오염된다
GuardEventQueue             안 넣는다   guard_events 0행 (ADR-050 ⑥)
밤 채널                     안 쓴다     새 채널 하나 — 배너가 뜨는 정도
레벨 기반 알림 id            안 쓴다     같은 레벨끼리 덮어쓴다
```

### 알림 — 문구 · id · 묶음

**문구는 울리는 순간 만든다**(서버가 준 `due` 와 `now` 의 차 — ADR-047):

```
전자기및연습1 · 3주차 연습문제 — 마감까지 3시간 (23:59)
전자기및연습1 · 3주차 연습문제 — 마감까지 40분 (23:59)      ← 1시간 미만이면 분
학기과제 — 마감까지 2시간 (23:59)                           ← 과목이 없으면 제목만
```

⚠️ *"빨리 하세요"* 같은 매번 같은 말을 붙이지 않는다(ADR-050 ④).

**알림 id 는 과제마다 하나다** — ★ **같은 과제의 다음 재촉이 앞 재촉을 덮는다.**
알림함에 같은 과제가 넷 쌓이지 않고, 늘 *"지금 남은 시간"* 한 줄만 있다.

**같은 시각의 과제 여럿 — OS 알림 그룹으로 묶는다:**

```
겉      과제 2개 — 마감까지 3시간
펼치면   과제마다 한 줄 · 과제마다 [완료]
```

★ **ADR-050 ②의 "알림 하나로" 와 ⑤의 "[완료] 한 번" 을 둘 다 지키는 모양이 이것이다.**
⚠️ **그룹이 안 되면 멈추고 보고해라** — 한 알림에 [완료] 를 여럿 달거나, 묶음 전체를 한 번에 완료하는 것은
*"어느 것을 끝냈나"* 를 흐린다.

### [완료] — 알림에서 한 번

```
누른다  →  POST /api/tasks/:id/complete   (GuardSync 의 baseUrl · token · 기존 HTTP 패턴)
성공    →  그 알림을 지우고, 그 과제의 남은 재촉을 기기에서 바로 취소한다
실패    →  앱을 연다 (409 · 네트워크 — ADR-031 의 폴백)
```

⚠️ **실패를 쌓아 두고 나중에 다시 보내지 않는다**(ADR-004 — 쓰기 큐를 두지 않는다).
⚠️ **기존 complete 엔드포인트를 쓴다** — 새 경로를 만들지 않는다(ADR-031 · 도메인 규칙이 한 곳에 산다).

### 콘솔 시험 — 실 마감을 기다리지 않게

```js
await Capacitor.Plugins.Guard.testNudge({ task_id, title, course, due })   // 지금 바로 울린다
```

★★ **같은 문구 함수 · 같은 알림 경로 · 같은 [완료] 를 탄다.** 시험용 문구를 따로 짜면 **사본을 시험하는 것**이다.
★ `testNotify` 와 달리 **원장에 아무것도 안 남는다**(재촉은 기록하지 않으므로).

| 하지 말 것 | 왜 |
|---|---|
| **`setAlarmClock` 으로 예약** | 시스템 "다음 알람" 에 재촉이 뜬다 |
| **밤 개입 경로(`fire`·`GuardNight.note`·`GuardEventQueue`)를 탄다** | ADR-049 의 수가 오염된다 · guard_events 는 지울 수 없다 |

| 새 complete 경로 | 기존 엔드포인트 하나 |
| testNudge 용 문구를 따로 짠다 | 사본을 시험하게 된다 |
| ①-d 둘을 고친다 | 보고만 — Cowork 가 정한다 |

## 완료 조건

```
① typecheck 통과 · smoke ±N · front ±N · 실패 0 · verify exit 0
② assembleRelease 통과 (함정 13) · 소스 스캐너 검사 초록
★ ①-d 둘의 읽은 결과가 §보고에 있다
★ 예약 방식을 무엇으로 골랐고 왜인지가 §보고에 있다
```

**검사 — ① 서버**

```
1  ★ 정각 1시간 간격의 점은 합치지 않는다 (11:00 마감 → 08·09·10시 셋 다 남는다)
2  ★ 1시간 미만이면 늦은 쪽 하나 (10:00 마감 → 아침과 1시간 전이 하나)       ← 1의 짝
3  ★ 마감 시각 이후·같은 시각의 점은 없다 (08:00 · 09:00 마감)
4  ★ 수집 일정의 시각을 고치면 응답이 "바뀌었다" 를 단다
5     손으로 만든 일정을 고치면 안 단다                                        ← 4의 짝
```

**검사 — ② 기기 (소스 스캐너 · `\r` 를 먼저 걷는다 — 함정 16)**

```
6  ★ 재촉 경로가 GuardNight.note 를 안 부른다
7  ★ 재촉 경로가 GuardEventQueue 에 안 넣는다
8  ★ 재촉 예약에 setAlarmClock 이 없다
9  ★ 재촉 채널 id 가 밤 채널 id 와 다르다
10 ★ GuardSync 가 nudges 를 읽는다 (T-87 검사 12 의 키 스캐너가 이것을 새로 집는가도 본다)
```

⚠️ **스캐너마다 물어야 하는 것 하나를 먼저 먹인다**(함정 17·18) — `0건` 이 *없다* 인지 *못 봤다* 인지 가른다.
⚠️ **스캐너는 *"이 이름이 소스에 있나"* 만 안다** — 경로를 따라가지 못한다. 6·7은 **재촉 경로의 파일·함수 안에서**
세어야 한다. 파일 전체에서 세면 밤 경로의 호출이 섞여 *"있다"* 로 거짓 빨간불이 되거나, 반대로 섞여 가려진다.
⚠️ **②는 기기 실측이 진짜 판정이다** — 스캐너는 *"안 하기로 한 것을 안 했나"* 까지만 잰다.

**변이**

```
①  "미만" 을 "이하" 로                 → 1 만 (2 는 초록)
   1시간 규칙을 뺀다                   → 2 만
   마감 뒤 점을 안 뺀다                 → 3 만
   일정 수정에 표시를 안 단다            → 4 만
   모든 일정 수정에 표시를 단다          → 5 만
②  재촉 경로에서 GuardNight.note 를 부른다 → 6 만
   GuardEventQueue 에 넣는다            → 7 만
   setAlarmClock 으로 예약한다          → 8 만
   밤 채널 id 를 쓴다                   → 9 만
```

★★★ **변이가 *붙었는지*와 *되돌아갔는지*를 둘 다 본다**(함정 16).
⚠️ **②의 변이 뒤에도 `assembleRelease` 를 돌려 *빌드가 깨진 것*을 *검사가 죽인 것*으로 읽지 마라.**

## 이 티켓이 안 하는 것

- **재촉을 기록하지 않는다**(ADR-050 ⑥).
- **①-d 둘을 고치지 않는다** — 보고만.
- **마감이 지난 뒤 재촉하지 않는다**(ADR-050 ⑤).
- **밤 Guard 의 문구·게이트·채널을 안 건드린다.**
- **[미루기] 버튼은 안 단다** — ADR-031 의 표에는 있지만 재촉의 끄는 법은 완료 하나다(ADR-050 ⑤).

  **바꾸기 전후로 견줘** 달라졌을 때만 `nudge_changed: true`. 라우트가 `t` 를 넘기게 했다.
  ★ *"수집 일정이면 단다"* 가 아니라 *"재촉이 달라졌는가"* 다 — **제목만 고친 마감**(재촉이 싣는 이름은 할 일의 제목) ·
