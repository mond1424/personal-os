지금도 빠듯한 자리라 간격보다 **구분선이 안전하다.**

### 검사 경계값을 어떻게 비율에 묶었나

**10% 시절 좌표가 하나도 안 남았다.** 전부 페이지에서 읽은 상수에서 계산된다:

```js
const gestureWidth     = gestureScreen.clientWidth || 380;   // jsdom은 0 — 함정 2
const gestureEdgeWidth = gestureWidth * ev("SWIPE_EDGE_RATIO");
const centerGestureX    = gestureLeft + gestureWidth / 2;
const leftEdgeGestureX  = gestureLeft + gestureEdgeWidth - 1;
const rightEdgeGestureX = gestureLeft + gestureWidth - gestureEdgeWidth + 1;
```

사라진 것: `gestureLeft + 190` · `+ 10` · `+ 370` · 폭 0 폴백의 `37/39/341/343`.
`ev("SWIPE_EDGE_RATIO")`는 **구현이 실제로 쓰는 그 변수**를 읽는다 — 검사가 자기 사본을 두지 않는다.

**티켓 검사 2("가운데 좌표가 새 가운데 구간 안에 있다")를 검사가 스스로 단언한다:**

```js
&& centerGestureX - gestureLeft > gestureEdgeWidth
&& centerGestureX - gestureLeft < gestureWidth - gestureEdgeWidth
```

가운데를 눌렀는데 그게 사실은 가장자리였으면 **달이 안 넘어가는 것이 정상 동작이 되어
검사가 거짓으로 초록**이 된다. 이 두 줄이 그 경우를 이름을 달고 빨간불로 만든다.
폭이 0.5에 닿으면 가운데가 사라지므로 여기서 먼저 걸린다.

**폭 0 폴백도 비율에서 양쪽을 누른다** — `edge∓1` · `width-edge∓1` 넷.
`isSwipeEdge`가 `<=`/`>=`이므로 경계값 자신은 가장자리이고, 프로브는 그 바깥/안쪽 1px이다.

### 행 구분: 선인가 간격인가 · 총높이 영향

**선이다.** 티켓 2부가 "지금도 빠듯한 자리라 간격보다 구분선이 안전하다"고 한 쪽.

```css
- .cal-row{position:relative;height:99px;border-top:3px solid var(--card)}
+ .cal-row{position:relative;height:99px;border-top:1px solid var(--line)}
```

| | 옛 | 새 |
|---|---|---|
| 행 총높이 | 99px | **99px (불변)** |
| 셀 안쪽 | 96px | **98px (늘었다)** |
| 무엇으로 갈랐나 | 3px 배경색 띠(`--card`) | 1px 선(`--line`) |

`*{box-sizing:border-box}`(style.css:15)라 **경계가 99px 안에 든다** — 캐러셀 총높이 불변(함정 11).
`.cells`는 `position:absolute;inset:0`이라 padding box를 따라가므로 셀 내용 공간은 **줄지 않고 2px 늘었다.**
`--line`은 `:root` · `@media prefers-color-scheme:dark` · `[data-theme="dark"]` **셋 다 정의돼 있다**(함정 5).
`.calpane .wkdays + .cal-row{border-top:none}`는 그대로 — 첫 주 위에는 선이 없다.

**3px 띠 → 1px 선은 물리적 분리를 줄이고 대비로 갚는 교환이다.** 갈리는지는 폰에서만 정해진다
(확인 절차 3번). **Cowork 판단: 실측 항목이다.**

### 설계와 어긋난 점

없다. 서버·마이그레이션 무변경, `SWIPE_EDGE_RATIO`는 여전히 한 자리,
`AXIS_LOCK`·`FLICK_V`·`VEL_*`·`dragBlockUntil`·`setPointerCapture`는 **바뀐 줄에 하나도 없다**
(`app.js` diff가 정확히 한 줄이다).

### 실제로 돌린 것 둘

**① 이식성 — `SWIPE_EDGE_RATIO`를 `0.25`로 바꿔 `npm run front`.** **257/0.**
읽지 않고 "비율에서 계산되니 되겠지"로 넘기면 이 티켓의 요점을 놓친다 —
§완료 조건이 "1·2가 이 티켓의 전부"라고 못 박은 자리다.

**② T-25가 남긴 함정 — `isSwipeEdge`의 `|| 380` 폴백 제거.** **254/3**
(가운데 · 왼쪽 가장자리 · 폭 0). T-25 때의 253/3과 **같은 셋**이고,
**오른쪽 가장자리 검사가 거짓으로 초록인 것도 그대로다** — 폭이 0이면 전 구간이 가장자리라
"탭이 바뀐다"가 우연히 맞아떨어진다. **T-25가 이미 기록해 둔 성질이고 이번 재작성이
악화시키지도 개선하지도 않았다.** 좌표를 비율로 갈아 끼우면서 감도를 잃지 않았다는 뜻이다.

### 검사 하나가 늘어난 자리 (front 256 → 257)

증가분은 **행 구분 검사 1건**이다. 제스처 검사 여섯은 **다시 쓴 것이지 늘린 것이 아니다** —
같은 여섯이 이제 비율에서 좌표를 얻는다. `.cal-row` 6행 · `height:99px` ·
`border-top:1px solid var(--line)` · 첫 주 `border-top:none`을 함께 본다.
