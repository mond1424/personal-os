# T-62 — 기상 시각을 정하는 곳은 하나다

**발행** Cowork · 2026-09-06 · **담당** Claude Code · **작음**
**근거** [ADR-047 ①](../../APP-ADR.md#adr-047) 우선순위 셋 · T-61이 올린 판단 · **APK 무관 · 마이그레이션 없음**

---

## 무엇이 어긋났나 — T-61 담당이 찾아 올렸다

> `protectAxis`의 폴백(`DEFAULT_PREP_MIN`)은 설정이 안 덮는다.
> 지금은 기본값의 합을 같게 맞춰 안 갈라지지만 **설정을 넣는 순간 갈라진다.**

```
protect_prep_min 이 붙은 일정   그 값        ✓ 문구와 알람이 같다
안 붙은 보호 일정               상수 폴백    ← 알람이 여기 걸린다
수업 · 일반 일정                설정         ← 문구가 여기 걸린다
```

**사용자가 이동 1시간을 적으면 문구는 그것을 반영하고 알람은 무시한다.**
**같은 날 알람이 07:30을 전제하는데 문구는 *"8시 기상"* 이라 쓰는 밤**이 생기고,
⚠️ **그 밤은 아무 검사도 안 잡는다.**

⚠️ **지금 안 갈라지는 것은 우연이다** — 기본값의 합이 상수와 같게 맞춰져 있을 뿐이다.
**두 시각이 아무도 모르게 공존하는 것**이 이 리포가 기준선·배포 상태·하루 경계에서
세 번 물린 그 모양이다.

## 할 일 — 순서를 셋으로 만든다

```
①  그 일정의 protect_prep_min      가장 구체적이다 — 이긴다      (지금도 그렇다)
②  설정 (이동 + 준비)              ★ 새로 끼운다
③  상수 폴백                       아무것도 모를 때만
```

**`protectAxis`가 ②를 읽게 한다.** ①은 그대로 이기고, ③은 설정이 없을 때만 남는다.

⚠️ **①의 자리를 바꾸지 마라.** 일정마다 다른 값을 붙일 수 있는 것이 그 컬럼의 뜻이다.
**②가 ①을 덮으면 그 컬럼이 죽는다.**

## ★ 알람 시각이 움직인다 — 그것이 뜻이다

**이 티켓은 보호 일정의 취침 데드라인을 실제로 옮긴다.**

```
설정 없음   안 움직인다 (③ 그대로)      ← 회귀. 지금 쓰는 사람이 안 놀란다
설정 있음   ★ 그만큼 일찍 자야 한다      ← 이것이 설정의 뜻이다
```

⚠️ **안 움직이는 쪽이 틀린 것이다.** 사용자가 *"이동 1시간"* 을 적었으면
**보호 일정도 그만큼 일찍 자야 한다** — 안 그러면 그 설정은 문구에만 사는 장식이다.

⚠️ **밤에 울리는 것을 옮기는 티켓이다.** 검사가 **두 방향을 다 세야 한다**(아래 1·2).

## 범위

```
src/services/guard.ts     protectAxis 가 설정을 읽는다 · ★ 위임 금지 영역
test/smoke.ts             검사
```

**마이그레이션 없음 · APK 무관 · 프런트 무변경** — 설정 UI는 T-61이 이미 만들었다.

⚠️ **`wakePoints`(T-61)를 고치지 마라.** 그쪽은 이미 ①→②를 본다. **이 티켓은 `protectAxis`뿐이다.**
⚠️ **상수를 지우지 마라.** ③은 설정이 없을 때의 답이고, 지우면 그 경우가 미정이 된다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| ②가 ①을 덮게 하기 | `protect_prep_min` 컬럼이 죽는다. **구체적인 것이 이긴다** |
| 상수 제거 | 설정이 없을 때의 답이 사라진다 |
| `wakePoints` 손대기 | T-61의 몫이다. 이 티켓은 `protectAxis`뿐 |
| 알람이 안 움직이게 막기 | **움직이는 것이 뜻이다.** 막으면 설정이 장식이 된다 |
| 값을 코드·티켓에 박기 | 설정값이다(T-61 ②와 같은 이유) |

## 완료 조건

```
typecheck 통과 · smoke +N · front(변화 없음) · 실패 0 · verify exit 0
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**
⚠️ **`front`가 움직이면 프런트를 건드린 것이다** — 그때는 멈추고 보고한다.

**검사**

```
1  ★ 설정이 있으면 protectAxis 의 데드라인이 그만큼 옮겨진다
2  ★ 설정이 없으면 옛 상수 그대로다                      ← 1의 짝. 회귀
3  ★ protect_prep_min 이 붙은 일정은 설정을 무시한다      ← ①이 이기는가
4  ★ 같은 날 wakePoints 의 leaveBy 와 protectAxis 의 기상이 일치한다
5  상수가 아직 있다 (스캐너 — 지우지 않았는가)
```

**4가 이 티켓의 본체다** — 두 곳이 같은 시각을 말하는지 **한 검사가 직접 잰다.**
지금까지는 *"각자 맞다"* 만 셌고 **둘이 같다는 것은 아무도 안 셌다.**

⚠️ **4를 `wakePoints` 쪽 값으로만 계산하지 마라** — 그러면 `protectAxis`를 안 보고
자기 자신과 비교하게 된다(§8의 *"남의 결과를 기준으로 삼는 검사는 남과 함께 죽는다"*).
**두 함수를 각각 불러 비교한다.**

⚠️ **fixture 에 고정 시각을 쓰지 마라**(함정 12).

**변이**
- `protectAxis`가 설정을 안 읽는다 → **1·4** 죽는다 (포함 관계 — 4는 1이 있어야 성립)
- 설정이 없어도 새 경로를 탄다 → **2만** 죽는다
- ②가 ①을 덮는다 → **3만** 죽는다
- 상수를 지운다 → **5만** 죽는다

⚠️ **첫 변이가 둘을 죽이는 것은 예상이다** — 4는 *"둘이 같은가"* 인데
한쪽이 설정을 안 보면 애초에 다를 수밖에 없다. **2·3이 각각 하나씩 죽는 것이
검사들이 서로 다른 것을 센다는 증거다.**

## 확인 절차 (사용자)

```powershell
npm run deploy
```

```

□ ★ 그 일정의 취침 알람이 설정만큼 일찍 잡힌다

```

**★★ 셋째 줄이 판정이다** — 두 곳이 같은 시각을 말하는가.
