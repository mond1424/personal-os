# T-62 — 기상 시각을 정하는 곳은 하나다

**발행** Cowork · 2026-09-06 · **담당** Claude Code · **작음**
**근거** [ADR-047 ①](../../APP-ADR.md#adr-047) 우선순위 셋 · T-61이 올린 판단 · **APK 무관 · 마이그레이션 없음**

---

## 무엇이 어긋났나 — T-61 담당이 찾아 올렸다

> `protectAxis`의 폴백(`DEFAULT_PREP_MIN`)은 설정이 안 덮는다.
> 지금은 기본값의 합을 같게 맞춰 안 갈라지지만 **설정을 넣는 순간 갈라진다.**

```
protect_prep_min 이 붙은 일정   그 값        ✓ 문구와 알람이 같다
안 붙은 보호 일정               상수 폴백    ← 알람이 여기 걸린다
수업 · 일반 일정                설정         ← 문구가 여기 걸린다
```

**사용자가 이동 1시간을 적으면 문구는 그것을 반영하고 알람은 무시한다.**
**같은 날 알람이 07:30을 전제하는데 문구는 *"8시 기상"* 이라 쓰는 밤**이 생기고,
⚠️ **그 밤은 아무 검사도 안 잡는다.**

⚠️ **지금 안 갈라지는 것은 우연이다** — 기본값의 합이 상수와 같게 맞춰져 있을 뿐이다.
**두 시각이 아무도 모르게 공존하는 것**이 이 리포가 기준선·배포 상태·하루 경계에서
세 번 물린 그 모양이다.

## 할 일 — 순서를 셋으로 만든다

```
①  그 일정의 protect_prep_min      가장 구체적이다 — 이긴다      (지금도 그렇다)
②  설정 (이동 + 준비)              ★ 새로 끼운다
③  상수 폴백                       아무것도 모를 때만
```

**`protectAxis`가 ②를 읽게 한다.** ①은 그대로 이기고, ③은 설정이 없을 때만 남는다.

⚠️ **①의 자리를 바꾸지 마라.** 일정마다 다른 값을 붙일 수 있는 것이 그 컬럼의 뜻이다.
**②가 ①을 덮으면 그 컬럼이 죽는다.**

## ★ 알람 시각이 움직인다 — 그것이 뜻이다

**이 티켓은 보호 일정의 취침 데드라인을 실제로 옮긴다.**

```
설정 없음   안 움직인다 (③ 그대로)      ← 회귀. 지금 쓰는 사람이 안 놀란다
설정 있음   ★ 그만큼 일찍 자야 한다      ← 이것이 설정의 뜻이다
```

⚠️ **안 움직이는 쪽이 틀린 것이다.** 사용자가 *"이동 1시간"* 을 적었으면
**보호 일정도 그만큼 일찍 자야 한다** — 안 그러면 그 설정은 문구에만 사는 장식이다.

⚠️ **밤에 울리는 것을 옮기는 티켓이다.** 검사가 **두 방향을 다 세야 한다**(아래 1·2).

## 범위

```
src/services/guard.ts     protectAxis 가 설정을 읽는다 · ★ 위임 금지 영역
test/smoke.ts             검사
```

**마이그레이션 없음 · APK 무관 · 프런트 무변경** — 설정 UI는 T-61이 이미 만들었다.

⚠️ **`wakePoints`(T-61)를 고치지 마라.** 그쪽은 이미 ①→②를 본다. **이 티켓은 `protectAxis`뿐이다.**
⚠️ **상수를 지우지 마라.** ③은 설정이 없을 때의 답이고, 지우면 그 경우가 미정이 된다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| ②가 ①을 덮게 하기 | `protect_prep_min` 컬럼이 죽는다. **구체적인 것이 이긴다** |
| 상수 제거 | 설정이 없을 때의 답이 사라진다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front(변화 없음) · 실패 0 · verify exit 0
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**
⚠️ **`front`가 움직이면 프런트를 건드린 것이다** — 그때는 멈추고 보고한다.

**검사**

```
1  ★ 설정이 있으면 protectAxis 의 데드라인이 그만큼 옮겨진다
2  ★ 설정이 없으면 옛 상수 그대로다                      ← 1의 짝. 회귀
3  ★ protect_prep_min 이 붙은 일정은 설정을 무시한다      ← ①이 이기는가
4  ★ 같은 날 wakePoints 의 leaveBy 와 protectAxis 의 기상이 일치한다
5  상수가 아직 있다 (스캐너 — 지우지 않았는가)
```

**4가 이 티켓의 본체다** — 두 곳이 같은 시각을 말하는지 **한 검사가 직접 잰다.**
지금까지는 *"각자 맞다"* 만 셌고 **둘이 같다는 것은 아무도 안 셌다.**

⚠️ **4를 `wakePoints` 쪽 값으로만 계산하지 마라** — 그러면 `protectAxis`를 안 보고
자기 자신과 비교하게 된다(§8의 *"남의 결과를 기준으로 삼는 검사는 남과 함께 죽는다"*).
**두 함수를 각각 불러 비교한다.**

⚠️ **fixture 에 고정 시각을 쓰지 마라**(함정 12).

**변이**
- `protectAxis`가 설정을 안 읽는다 → **1·4** 죽는다 (포함 관계 — 4는 1이 있어야 성립)
- 설정이 없어도 새 경로를 탄다 → **2만** 죽는다
- ②가 ①을 덮는다 → **3만** 죽는다
- 상수를 지운다 → **5만** 죽는다

⚠️ **첫 변이가 둘을 죽이는 것은 예상이다** — 4는 *"둘이 같은가"* 인데
한쪽이 설정을 안 보면 애초에 다를 수밖에 없다. **2·3이 각각 하나씩 죽는 것이
검사들이 서로 다른 것을 센다는 증거다.**

### ① `protectAxis`가 설정을 어디서 읽나 — **인자로 받는다. 같은 함수를 쓴다.**

`protectAxis`는 동기 함수이고 `rows.map()` 안에서 일정마다 불린다. 안에서 읽게 하면
**일정 수만큼 질의가 나간다.** 그래서 `schedule()`이 한 번 읽어 넘긴다.

```
schedule()   settingsMap(env) 한 번  →  protectAxis(e, offset, s)
record()     스냅샷 경로 — 보호 일정이 붙은 발동에서만 읽는다
```

⚠️ **`record()`에도 넣었다.** 스냅샷의 `deadline_min`은 12월에 *"데드라인 얼마 전에
발동했나"* 를 세는 재료다. **예약과 다른 시각에서 재면 그 수가 거짓이 된다** —
범위표엔 없지만 같은 함수를 부르는 자리라 안 넣으면 그 자리에서 다시 갈라진다.

### ② 우선순위 셋은 **한 곳에 있다** (`wakeLeadMin`)

```
wakeLeadMin(prepMin, s)
  ①  prepMin != null        → 그 값
  ②③ nonNegInt(commute, DEFAULT_COMMUTE_MIN) + nonNegInt(prep, DEFAULT_PREP_MIN)
```

**②와 ③은 항끼리 붙어 있다** — 한쪽만 넣어도 나머지는 자기 상수로 채우고, 둘 다 없으면
합이 `DEFAULT_PREP_MIN`이 된다. 그래서 **설정을 안 쓰는 사람에게는 아무것도 안 움직인다**(검사 2).

⚠️ **`wakePoints`를 한 군데 건드렸다 — 티켓 §금지와 어긋난다. 근거를 적는다.**

```
지운 것   const lead = nonNegInt(...) + nonNegInt(...)   ← T-61이 인라인으로 적어 둔 그 순서
넣은 것   const lead = wakeLeadMin(null, s)
          ... put(..., wakeLeadMin(e.protect_prep_min, s))
```

**동작은 한 글자도 안 바뀐다**(같은 식을 함수 안으로 옮겼을 뿐이다). 그렇게 한 이유는
**이 §보고가 묻는 *"한 곳에 있나"* 가 안 건드리면 대답이 안 되기 때문**이다 — 안 옮기면
`wakePoints`에 같은 순서가 그대로 남아 **두 곳에 두 벌**이 되고, 그건 이 티켓이 없애려는 것과
같은 모양이다. **검사 4는 그때 둘을 묶는 유일한 끈이 되는데, 끈 하나보다 자리 하나가 낫다.**

⚠️ **일부러 안 한 것 하나** — `wakePoints`는 여전히 `settings`를 **자기가 읽는다**(한 요청 안이라
값은 같다). 인자를 하나 더 다는 것은 질의 하나를 줄일 뿐 정합성을 안 바꾸므로 범위 밖으로 뒀다.

### ④ 두 값이 같다는 것을 어떻게 재나 — **두 함수의 출력을 각각 집는다**

```
protectAxis  →  events[].start · events[].prep_min      기상 = start − prep_min
wakePoints   →  wake[].leaveBy
```

기대값을 **`plan` 쪽에서만** 만든다 — `wake.at`으로 계산하면 `wakePoints`가 자기 자신과
비교하게 되고, `protectAxis`가 틀려도 초록이다.

★ **세 자리에서 전부 잰다**: 설정 없음(③) · 설정 둘(②) · 일정에 붙은 값(①).
한 자리에서만 재면 **①에서만 맞는 구현**이 통과한다 — T-61이 정확히 그 상태였다.

### 변이 넷

```
M1 protectAxis 가 설정을 안 읽는다   →  1 · 4        ★ 티켓이 예고한 포함 관계
M2 설정이 없으면 새 가지로 빠진다     →  2 (+ 옛 검사 하나)
M3 ②가 ①을 덮는다                   →  3
M4 상수를 지운다 (값을 인라인)        →  5
```

★ **M1이 둘을 죽인 것은 예상대로다** — 4는 *"둘이 같은가"* 인데 한쪽이 설정을 안 보면
애초에 다를 수밖에 없다. **2·3·5가 각각 하나씩 죽는 것이 검사들이 서로 다른 것을 센다는 증거다.**

⚠️ **M2가 T-62 밖의 검사 하나를 함께 죽였다** — `데드라인 = 일정시각 − 준비(90) − 수면(360)`.
**그게 맞다.** 그 검사가 T-62 이전부터 같은 상수를 지키고 있었고, 폴백을 바꾸면 그것도 거짓이 된다.
*"고쳐야 할 검사"* 가 아니라 **같은 사실을 세는 둘째 눈**이다 — 그대로 뒀다.

⚠️ **M2를 다르게 쓰면 5도 죽는다** — 폴백을 `DEFAULT_PREP_MIN`에서 다른 상수로 **바꾸면**
그 이름이 함수에서 사라져 스캐너가 문다. **그것도 맞다**: 이름이 사라지는 것은 5가 세는
*"지웠는가"* 의 한 모양이다. 위 표는 **상수 이름을 남긴 채** 가지만 늘린 쪽을 적었다.
