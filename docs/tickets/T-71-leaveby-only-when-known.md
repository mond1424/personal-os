# T-71 — 갈 곳을 모르면 기상 시각을 말하지 않는다

**발행** Cowork · 2026-09-12 · **담당** Claude Code · **작음**
**근거** [ADR-047 §기상 시각을 정하는 순서](../../APP-ADR.md#adr-047) · 2026-09-12 서버 실측 ·
**APK 무관 · 마이그레이션 없음 · 서버 층만**

---

## 무엇이 어긋났나 — 마감에 이동 시간을 뺀다

**오늘 `GET /api/guard/schedule`의 `wake[]` 첫 칸:**

```
2026-09-12   at 23:59   leaveBy 21:59   "1주차 과제 문제 기한"   source: event
```

**23:59 마감에 이동 60분 + 준비 60분을 빼고 *"21:59 기상"* 이라고 말한다.**

⚠️ **마감은 가는 곳이 아니다.** 이동 시간이 뜻이 없고, 준비 시간도 뜻이 없다.
T-61이 그 뺄셈을 넣은 근거는 *"10시 수업에 가려면 8시엔 일어나야 한다"* 였고,
**그 근거가 마감에는 없다.**

★ **같은 뿌리로 한 번 더 봤다** — 2026-09-08의 `wake[]`:

```
2026-09-08   at 20:00   leaveBy 18:00   "성범이 군바 오후 8시"   source: event
```

**저녁 8시 약속에 *"18시 기상"*.** 이것도 같은 자리다.
⚠️ **`wakePoints`가 모든 일정을 *"거기 가야 하는 아침 약속"* 으로 읽는다.**

## ★ 그러면 앱은 "가는 곳"을 어떻게 아는가 — **아는 것만 쓴다**

```
source: class              ★ 안다. 시간표는 학교로 간다
protect_from 이 붙었다     ★ 안다. 사용자가 "이 시각에 있어야 한다"고 선언했다
  └ protect_prep_min 있음     그 값을 쓴다 (ADR-047 ① — 가장 구체적)
  └ 없음                      ★ 설정값을 쓴다. 알람이 이미 그렇게 한다 (아래)
그 밖의 event              ⚠️ 모른다
```

### ⚠️ ★ 정정 (2026-09-12 · 담당 실측이 잡았다) — 보호 일정의 경계

**이 티켓이 처음 적은 *"보호 일정은 `protect_prep_min`이 붙어 있으므로 이미 안다 쪽"* 은 틀렸다.**
`protect_prep_min`은 nullable이고, `protectAxis`(`guard.ts:318`)가 **안 붙은 보호 일정을
명시적으로 다룬다** — T-62의 픽스처 자체가 그것이다.

**표대로 구현했더니 T-62 검사 4가 죽었다:**

```
✗ T-62 #4  예약이 전제하는 기상과 문구가 말할 기상이 같다
```

```
protectAxis (알람)   설정값으로 기상을 전제하고 울린다
wakePoints  (문구)   "모른다"며 입을 닫는다
                     ★ 두 기상이 아무도 모르게 공존한다 — T-62 가 없앤 바로 그것
```

★★ **그러므로 규칙은 이렇다: "모른다"는 양쪽이 함께 몰라야 한다.**
**문구가 입을 닫는 것은 알람도 안 울릴 때만 옳다.** 한쪽만 침묵하면 겸손이 아니라 **갈라진 것**이다.

★ **`protect_from`이 붙었다는 사실 자체가 "안다"의 근거다** — 값이 아니라 **선언**이 신호다.
**마감에 보호를 거는 사람은 없다.** 보호는 *"이 시각에 있어야 한다"* 는 뜻이고,
그것이 이 티켓이 찾던 *"갈 곳인가"* 에 대한 사용자 자신의 답이다.

⚠️ **제목에서 읽지 마라.** *"기한"·"마감"* 같은 낱말로 가르는 것은 **해석**이고
**ADR-037 §실측이 그것을 금지했다** — *"이름을 믿는 순간 그것이 해석이고, 개강 첫날 틀린다."*
⚠️ **시각으로도 가르지 마라.** *"저녁이면 안 뺀다"* 도 같은 부류의 추측이다.

## 할 일 — 모르면 안 싣는다

```
지금   모든 wake 칸에 leaveBy 를 싣는다
바꿈   ★ 갈 곳을 아는 칸에만 싣는다. 모르면 leaveBy 를 안 싣는다
```

★ **기기는 이미 그 경우를 안다.** T-61 §보고 ④의 셋째 가지가
*"`leaveBy`가 없으면 약속까지를 말한다"* 로 이미 있다(옛 서버 대비로 만든 것).
**그래서 이 티켓은 APK가 안 든다** — 서버가 안 실으면 기기가 그 가지를 탄다.

⚠️ **그 가지의 문구가 완벽하지는 않다.** 23:59 마감이면 *"지금 자면 20시간 — 23:59 과제 기한"*
같은 말이 된다. **그래도 *"21:59 기상"* 보다 덜 틀리다** — 없는 기상 시각을 지어내지 않는다.
★ **더 나은 문구는 다음 티켓이다**(아래 §안 하는 것). 이 티켓은 **거짓을 없애는 데까지**다.

## 범위

```
src/services/guard.ts    wakePoints — leaveBy 를 싣는 조건
test/smoke.ts            검사
```

**마이그레이션 없음 · APK 무관 · 프런트 무변경.**

⚠️ **`wakeLeadMin`을 고치지 마라** — 그 함수의 우선순위 셋(T-62)은 옳다.
**이 티켓이 바꾸는 것은 *"그 함수를 부를 것인가"* 이지 그 안의 계산이 아니다.**
⚠️ **`protectAxis`를 고치지 마라** — **알람 시각이 움직이면 안 된다.**
★ 그리고 **`protectAxis`가 무엇을 전제하는지가 이 티켓의 기준이다**:
그것이 기상을 전제하고 울리는 일정은 `wakePoints`도 같은 기상을 말해야 한다(위 §정정).
⚠️ **`at`은 늘 싣는다** — 약속 자체는 언제나 말한다(T-61 §금지 4행).
⚠️ **기기(`android/`)를 열지 마라.** 폴백 가지가 이미 있다 — **없으면 멈추고 보고해라.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 제목의 낱말로 가르기 | **해석이다.** ADR-037 §실측 — *"이름을 믿으면 개강 첫날 틀린다"* |
| 시각으로 가르기 (저녁·심야) | 같은 부류의 추측. 새벽 약속도 있다 |
| `wakeLeadMin`의 우선순위 손대기 | T-62가 한 곳으로 모은 것이다 |
| `protectAxis` 손대기 | 보호 일정은 이미 "안다" 쪽. 알람 시각이 움직인다 |
| `at`을 빼기 | 약속 자체는 늘 말한다 |
| `leaveBy`에 `null` 대신 `at`을 넣기 | **그러면 기기가 "기상 = 약속 시각"으로 읽는다.** 안 싣는 것과 다르다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front(변화 없음) · 실패 0 · verify exit 0
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**
⚠️ **`front`가 움직이면 프런트를 건드린 것이다** — 멈추고 보고한다.

**검사**

```
1  ★ source: class 칸에는 leaveBy 가 실린다 (설정만큼 이르다)
2  ★ protect_prep_min 이 붙은 칸에도 실린다 (그 값만큼)           ← ADR-047 ① 회귀
2b ★ protect_from 만 붙은 칸에도 실린다 (설정만큼)                ← §정정. 알람과 갈라지지 않는가
3  ★ 보호도 시간표도 아닌 event 칸에는 leaveBy 가 없다            ← 본체
4  ★ 그 칸에도 at·title·date 는 그대로 있다                      ← 3의 짝. 약속은 말한다
5  ★ leaveBy 자리에 at 이 들어가 있지 않다 (null 이거나 없다)     ← 조용한 대체 금지
6  wakeLeadMin 의 세 갈래가 그대로다 (스캐너 — 살아 있는 값)
7  ★ T-62 검사 4가 살아 있다 (예약과 문구가 같은 기상을 말한다)   ← ★ 이 티켓의 안전핀
```

★ **7이 이 티켓을 안전하게 만든다.** T-62가 만든 그 검사가 **이 티켓의 잘못된 전제를
실제로 잡았다**(§정정). **그것이 계속 초록이어야 이 티켓이 T-62를 안 깬 것이다.**

**3이 본체이고 4가 그 짝이다** — *"없는 기상을 지어낸다"* 가 결함이었으므로
**안 지어내는 것과 약속은 여전히 말하는 것이 둘 다 세어져야** 한다.

⚠️ **fixture 에 고정 날짜를 쓰지 마라**(함정 12) — `t.d`에서 상대로 잡는다.
⚠️ **개수를 세지 말고 자리를 세라**(`AGENT-CHAIN` §8) — *"leaveBy 가 몇 개냐"* 가 아니라
**그 칸 하나에 있느냐 없느냐**를 본다.
⚠️ **훑기가 0건을 내면 되먹임을 확인해라**(함정 17).

**변이**
- 모든 칸에 `leaveBy`를 싣는다 → **3만** 죽는다
- `class` 칸에서도 뺀다 → **1만** 죽는다
- `protect_prep_min`을 무시한다 → **2만** 죽는다
- ★ `protect_from`만 붙은 칸에서 뺀다 → **2b + 7** 죽는다 (§정정이 실제로 본 그 모양)
- 그 칸의 `at`까지 뺀다 → **4만** 죽는다
- `leaveBy`에 `at`을 넣는다 → **5만** 죽는다 (3은 초록 — 값이 있으니)
- `wakeLeadMin`의 갈래를 지운다 → **6만** 죽는다

⚠️ **다섯째 변이가 3을 안 죽이는 것이 5의 존재 이유다** — *"실렸다"* 만 세면
**약속 시각을 기상이라 부르는 구현이 통과한다.**

## ★ 이 티켓이 안 하는 것 — 다음 자리

**마감·저녁 약속에 *무엇을* 말할지**는 정하지 않는다.

```
이 티켓   없는 기상 시각을 지어내지 않는다      ← 거짓을 없앤다
다음      마감에는 무엇을 말해야 하는가          ← 무엇을 말할지 정한다
```

⚠️ **마감은 *"자고 일어나서 가는 것"* 이 아니라 *"그 전에 해야 하는 것"* 이다.**
*"지금 자면 N시간"* 이라는 틀 자체가 마감에는 안 맞을 수 있다 — **그건 설계 질문이고
Cowork가 정한다.** 재료는 이 티켓이 배포된 뒤 그런 밤이 한 번 오면 쌓인다.

### 고친 자리

```
src/services/guard.ts   wakePoints — put() 의 leadMin 이 number | null 이 되고,
                        null 이면 leaveBy 키를 **아예 안 싣는다**
                        event 의 문은 e.protect_from != null 하나다
test/smoke.ts           [T-71] 절 8건
docs/api-surface.md     wake[] 의 모양과 조건
```

⚠️ **`wakeLeadMin`·`protectAxis`는 한 글자도 안 고쳤다.** 바뀐 것은 *"그 함수를 부를 것인가"* 뿐이다.
★ **`android/`는 열지 않았다.** 폴백 가지가 있는지만 읽어서 확인했다 —
`GuardWatch.kt:259` `if (w.leaveBy <= 0L) return "지금 자면 … — $at ${w.title}"`,
받는 쪽은 `GuardSync.kt:94` `parseIso(o.optString("leaveBy")) ?: 0L` 이라
**키가 없으면 `""` → 파싱 실패 → `0L`** 로 그 가지를 탄다.
⚠️ 그래서 **`null`보다 "키 없음"이 안전하다** — Android `org.json`의 `optString`은 JSON `null`을
**`"null"` 문자열**로 준다(`JSON.toString(JSONObject.NULL)`). 여기선 어차피 파싱 실패라 결과가 같지만,
**같은 값이 되는 경로가 하나뿐인 쪽**을 골랐다.

### ★ §정정의 전제를 실측이 한 번 더 좁혔다 — 문이 하나로 끝난다

`protect_prep_min`은 **`protect_from` 없이 설 수 없다**(`src/services/events.ts:60·82` —
`stSetProtect`가 넷을 함께 쓰고, 해제는 넷을 함께 `null`로 만든다).
그래서 §정정의 트리가 **조건 하나**로 접힌다:

```ts
e.protect_from != null ? wakeLeadMin(e.protect_prep_min, s) : null
```

★ ①/②→③ 갈래는 `wakeLeadMin`이 그대로 정한다 — **여기서 다시 적지 않았다**(T-62).

### 변이 — 일곱 중 다섯이 하나씩만 죽었다. 겹친 둘은 필연이고 증명이 있다

| 변이 | 티켓 예측 | 실측(T-71 검사) | 그 밖 |
|---|---|---|---|
| 모든 칸에 `leaveBy` | 3만 | **3만** ✅ | 없음 |
| `class` 칸에서도 뺀다 | 1만 | **1만** ✅ | T-61 #1·#2 |
| `protect_prep_min` 무시 | 2만 | ⚠️ **2 + 7** | T-62 #4 |
| `protect_from`만 붙은 칸에서 뺀다 | 2b + 7 | **2b + 7** ✅ | T-62 #4 |
| 그 칸의 `at`까지 뺀다 | 4만 | **4만** ✅ | 없음 |
| `leaveBy`에 `at`을 넣는다 | 5만 (3은 초록) | **5만 · 3 초록** ✅ | 없음 |
| `wakeLeadMin`의 갈래를 지운다 | 6만 | ⚠️ **2 + 6** | T-62 #3 |

★ **겹친 둘은 좁힐 수 없다 — 검사가 눈이 멀어야만 안 겹친다.**

```
protect_prep_min 무시 → 7 도 죽는다
  7 이 세는 명제가 "예약과 문구가 같은 기상을 말한다" 인데,
  그 변이가 만드는 상태가 정확히 그 둘이 갈린 상태다(protectAxis 는 95, wakePoints 는 설정합).
  ★ 7 이 안 죽으면 7 이 눈먼 것이다.

wakeLeadMin 갈래 지움 → 2 도 죽는다
  2 가 세는 명제가 "①의 값이 그 값만큼 반영된다" 인데, 그 변이가 ①을 지운다.
  6 은 원문을, 2 는 결과를 센다 — 같은 사실의 두 층이라 함께 움직인다.
```

⚠️ **그 변이에서 7은 살아 있다 — 그리고 그것이 6의 존재 이유다.**
두 함수가 **같은 `wakeLeadMin`** 을 부르므로 갈래가 사라지면 **함께 틀리고 여전히 일치한다.**
**동작만 보는 검사는 이 결함을 영원히 못 잡는다**(T-62가 한 곳으로 모은 값이자 대가다).

### ★ 3과 5를 가른 것이 이 검사들의 날이다

티켓이 *"다섯째 변이가 3을 안 죽이는 것이 5의 존재 이유"* 라고 못 박았으므로 **둘을 겹치지 않게** 썼다:

```
3   그 칸에 leaveBy 가 있고 at 보다 **이르다**      ← 지어낸 기상
5   leaveBy 가 있고 at **이상**이다 (전수)          ← 조용한 대체
```

**둘을 합쳐야 *"leaveBy 가 없다"* 가 되고, 어느 쪽이 깨졌는지도 갈린다.**
3을 그냥 *"`leaveBy == null`"* 로 쓰면 다섯째 변이가 3·5를 함께 죽여 **`at` 대체와 지어내기가 한 빨간불**이 된다.

### 안 한 것

- **`protectAxis`는 그대로다.** 마감에 보호를 걸면 알람은 여전히 역산해 울린다 —
  그것이 옳은지는 **이 티켓의 물음이 아니다**(티켓 §안 하는 것).
- **마감·저녁 약속에 무엇을 말할지**는 안 정했다. 기기의 폴백 문구가 그대로 나간다.

### 🌙 판정

**마감·저녁 약속만 있는 밤이 취침 창에 걸릴 때** ★ *"N시 기상"* 이 안 나오는가.
회귀 축은 **수업 있는 날 밤** — *"8시 기상 · 10시 <과목>"* 이 그대로여야 한다.
⚠️ `npm run deploy` 만 필요하다. **APK·마이그레이션 불필요.**
