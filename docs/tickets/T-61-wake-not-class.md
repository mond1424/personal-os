# T-61 — 재는 것은 수업까지가 아니라 기상까지다

**발행** Cowork · 2026-09-06 · **담당** Claude Code · **작음**
**근거** [ADR-047 ①](../../APP-ADR.md#adr-047) 정정 · T-60의 미완 · **APK 필요 · 마이그레이션 없음**

---

## 무엇이 어긋났나 — 문구가 틀린 사실을 말한다

**2026-09-06 사용자:**

> 집에서 학교 가는 데 1시간 걸리고 준비도 얼추 한 시간이라,
> **강의 시작 두 시간 전에는 적어도 일어나야 해**

```
10시 수업 · 지금 새벽 4시 30분
지금 뜨는 것   "지금 자면 5시간 30분"     ← 10시까지. 그때 자고 있으면 수업에 없다
사실           "지금 자면 3시간 30분"     ← 8시엔 일어나야 한다
```

⚠️ **1~2시간을 부풀려 말하는 문구는 사실이 아니라 위안이다.**
ADR-047이 명령을 사실로 바꾼 이유가 *"매일 같은 말은 서약을 소모한다"* 였는데,
**틀린 사실은 그보다 빨리 신뢰를 깎는다.**

## ★ T-60이 이것을 뺀 근거는 옳았다 — 자리만 틀렸다

**T-60 §보고:**

> 준비 시간은 안 뺀다 — 빼려면 `prep`을 기기에도 둬야 하고 **그러면 역산이 두 벌이 된다**

**그 걱정은 기기가 계산할 때의 이야기다. 서버가 빼서 보내면 역산은 여전히 한 곳이다.**

## 할 일

### ① 서버가 기상 시각을 함께 싣는다

```
지금   wake: { at, date, source, title }
바꿈   wake: { at, date, source, title, ★ leaveBy }
```

**`leaveBy = at − (이동 + 준비)`.** 기기는 **`leaveBy − now`** 만 잰다 — T-60 ①이
*"서버가 몇 시간까지 접으면 새벽 3시의 문구가 저녁 6시 기준으로 굳는다"* 고 한 것은 그대로다.
**접는 것은 시각이고, 남은 시간은 여전히 기기가 그 자리에서 잰다.**

⚠️ **`at`을 빼지 마라.** 문구가 *"…— 10시 전자기및연습1"* 로 **약속 자체**를 말하려면 둘 다 필요하다.

### ② 빼는 값은 설정이다

```
이동 시간 · 준비 시간   →  settings
```

⚠️ **이 티켓에 분도 시간도 적지 않는다**(`CLAUDE.md` §아키텍처 원칙 — 하루 경계와 같은 이유).
사용자가 준 값은 **§무엇이 어긋났나의 인용 안에만** 있고, 그것은 근거이지 기본값의 출처가 아니다.

⚠️ **둘로 나눌지 하나로 합칠지는 담당이 고르고 근거를 적는다.** 합치면 화면이 단순하고,
나누면 *"오늘은 학교에서 자고 간다"* 같은 경우에 이동만 0으로 둘 수 있다.

### ③ ★ `protectAxis`의 `prep`과 같은 것인가 — 확인하고 답을 적어라

**`protectAxis`가 이미 보호 일정의 역산에 `prep`을 쓴다.**

```
같은 것이면   그 값을 읽는다 — 두 벌을 만들지 않는다
다른 것이면   왜 다른지 보고에 적는다
```

⚠️ **읽지 않고 새로 만들면 두 벌이 된다.** 이 리포가 기준선·배포 상태·하루 경계에서
차례로 물린 그 모양이다. **먼저 `protectAxis`를 읽어라.**

### ④ 문구가 무엇을 말하는지 바뀐다

```
지금   "지금 자면 5시간 30분 — 10시 전자기및연습1"
바꿈   "지금 자면 3시간 30분 — 8시 기상 · 10시 전자기및연습1"
```

⚠️ **기상 시각을 보이는 것이 이 티켓의 값이다.** *"3시간 30분"* 만 말하면 **왜 그 숫자인지**
모르고, 사용자가 **틀렸다고 느낄 때 고칠 자리를 못 찾는다**(설정이 어디 있는지도 모른다).

⚠️ **`leaveBy`가 이미 지났으면** — 새벽 4시에 자려는데 기상이 3시였다면 —
**그 사실을 말한다.** 음수를 *"0시간"* 으로 뭉개면 T-54가 없앤 그 부류가 돌아온다.

## 범위

```
src/services/guard.ts          wakePoints 에 leaveBy
src/db/index.ts                (필요하면) 설정 읽기
android/.../guard/GuardWatch.kt   문구 · ★ 위임 금지 영역
public/app.js · index.html     설정 UI 두(또는 한) 칸
test/smoke.ts · test/front.mjs
```

**마이그레이션 없음** — `settings`는 키·값 표다.

⚠️ **`guard/`는 위임 금지 영역**(`AGENT-CHAIN` §4). 직접 한다.
⚠️ **L2 게이트 조건을 건드리지 마라** — *"띄울까 말까"* 는 T-60이 정했고 이 티켓은 **문구만** 바꾼다.
⚠️ **`protectAxis`를 고칠 것 같으면 멈추고 보고해라** — 보호 일정 예약이 거기 걸려 있다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 시간 값을 코드·티켓에 박기 | 설정값이다. 사람마다 학기마다 다르다 |
| 기기에서 역산 | **두 벌이 된다.** T-60이 옳게 걱정한 자리 |
| 서버가 "몇 시간"까지 접기 | 새벽 3시의 문구가 저녁 6시 기준으로 굳는다(T-60 ①) |
| `at`을 `leaveBy`로 대체 | 문구가 약속 자체도 말해야 한다 |
| `protectAxis`의 `prep`을 안 보고 새로 만들기 | ③. 두 벌이 갈라진다 |
| 음수를 0으로 뭉개기 | ④. *"이미 지났다"* 와 *"딱 맞다"* 는 다르다 |
| 게이트 조건 손대기 | T-60의 몫이다. 이 티켓은 문구만 |

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**

**검사**

```
1  wake[] 에 leaveBy 가 실린다 — at 보다 설정만큼 이르다
2  ★ 설정을 바꾸면 leaveBy 가 따라 바뀐다        ← 코드에 안 박혔는가
3  ★ 문구에 기상 시각과 약속이 둘 다 들어간다
4  ★ leaveBy 가 지났으면 그 사실을 말한다 (0으로 안 뭉갠다)
5  ★ 남은 시간은 기기가 잰다 (서버 응답에 "몇 시간"이 없다 · 스캐너)
6  ★ 5의 스캐너가 살아 있는가
7  게이트 조건은 T-60 그대로다 (없는 것을 세는 검사)
```

**2가 ②를 지킨다** — 값을 박은 구현은 여기서 죽는다.

**5·6이 T-60 ①의 회귀다.** 서버가 시간까지 접으면 **문구가 받은 시각에 굳고**,
그것은 밤새 안 바뀌는 숫자가 된다 — 이 ADR이 없애려던 바로 그 모양이다.

**7이 회귀 검사다.** 문구를 고치다 게이트를 건드리면 **T-60이 산 침묵이 사라진다.**

⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).
⚠️ **fixture 에 고정 시각을 쓰지 마라**(함정 12) — 설정값도 상대로 잡는다.

**변이**
- `leaveBy` 를 안 싣는다 → **1만** 죽는다
- 값을 코드에 박는다 → **2만** 죽는다
- 문구에서 기상 시각을 뺀다 → **3만** 죽는다
- 음수를 0으로 뭉갠다 → **4만** 죽는다
- 서버가 "몇 시간"을 접는다 → **5만** 죽는다
- 스캐너를 눈멀게 → **5는 초록 · 6만** 죽는다
- 게이트에 `leaveBy` 조건을 건다 → **7만** 죽는다
