# T-60 — Level 2가 밤마다 다른 말을 한다

**발행** Cowork · 2026-09-05 · **담당** Claude Code · **보통**
**근거** [ADR-047](../../APP-ADR.md#adr-047) · **APK 필요 · 위임 금지(guard/) · 마이그레이션 없음**

---

## 무엇이 어긋났나 — 사용자가 한 문장으로 말했다

```
8/26 ~ 8/31   L2 여섯 밤 전부 ignored      L3 는 전부 accepted
```

> **항상 뜨는 게 내가 맨날 대충 넘겼었어** (2026-09-05)

⚠️ **반응 실패가 아니라 설계 결함이다.** L2의 조건은 *"화면이 N분 이상 켜져 있다"* 하나뿐이고,
**그 시각에 그것은 거의 언제나 참이다. 항상 참인 신호는 아무것도 말하지 않는다.**

**그리고 무시가 습관이 되면 L3까지 같은 취급을 받기 시작한다** — ADR-026이 경고한
도구 이탈의 앞 단계다. **지금 L2는 관측도 개입도 아니다.**

## ★ 어제까지는 못 고쳤다 — T-58이 재료를 넣었다

```
내일 10시 수업이 있다     지금 자면 N시간
내일 공강이다 (화요일)     늦게 자도 마찬가지다
```

**같은 시각의 같은 화면 켜짐이 두 밤에 다른 뜻을 갖는다.** 그 차이를 이제 말할 수 있다.

## 할 일

### ① 문구가 사실을 말한다 — 명령이 아니라

```
지금   "지금 자야 합니다"                          ← 매일 같다
바꿈   "지금 자면 5시간 30분 — 10시 전자기및연습1"   ← 밤마다 다르다
```

⚠️ **명령이 아니라 사실이다**(ADR-047 ①). 설계 §6.2가 개입의 정당성을 사전 서약에 두는데,
**매일 같은 명령은 서약을 소모하고 사실은 그렇지 않다.**

**내일 첫 일정과 거기까지 남는 시간**을 함께 보인다. 그 값은 **시간표 전개와 `events`가 준다.**

### ② ★ 내일 아침에 아무것도 없으면 안 뜬다

**공강 전날 밤의 L2는 소음이다.** 늦게 자는 것이 판단이 흐려서가 아니라
**늦게 자도 되기 때문**일 수 있고, 앱이 그것을 모르면서 개입하면 신뢰를 깎는다.

⚠️ **L3·L4는 이 조건을 타지 않는다.** 그것들은 데드라인·보호 일정이 근거다.
**이 티켓은 L2만 다룬다** — L3 경로를 한 줄도 건드리지 마라.

### ③ ★ 조용히 안 뜨는 것과 못 뜨는 것을 가른다

```
내일 일정이 없어서 안 띄웠다      →  정상 · 그렇게 기록된다
일정을 못 읽어서 안 띄웠다        →  ★ 그건 결함이다. 구별돼야 한다
```

⚠️ **T-54·T-55·T-57이 세 번 배운 자리다.** 안 뜬 이유가 기록에 남지 않으면
**다음에 시간표가 깨져도 "조용한 밤"으로 보인다.**

### ④ 무시가 쌓이면 끄는 선택지를 준다

**더 세게 하지 않는다**(ADR-047 ③). 연속 무시가 임계를 넘으면 화면이 그 사실을 말한다:

```
"이 알림이 N번 그냥 지나갔어요 — 꺼 둘까요? [끄기 / 그대로]"
```

⚠️ **끌 수 없는 알림은 무음 처리되고, 그러면 관측도 잃는다.** 임계값은 설정값이다 —
**이 티켓에 숫자를 적지 않는다**(`CLAUDE.md` §아키텍처 원칙).

## 범위

```
android/.../guard/GuardWatch.kt      L2 조건 · ★ 위임 금지 영역
android/.../guard/  (문구 조립)
src/services/guard.ts · src/db/index.ts   내일 첫 일정 조회
public/app.js · index.html           ④의 카드
test/smoke.ts · test/front.mjs
```

**마이그레이션 없음.** 무시 횟수는 `guard_events`에서 세면 나온다 — **파생을 저장하지 않는다**(원칙 1).

⚠️ **`guard/`는 위임 금지 영역이다**(`AGENT-CHAIN` §4). 직접 한다.
⚠️ **`cal/`·시간표 전개를 고치지 마라** — 읽기만 한다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| L3·L4에 같은 조건 걸기 | 근거가 다르다. **데드라인은 내일 일정과 무관** |
| 무시 횟수로 자동 강화 | ②와 충돌 — 공강 무시가 시험 전날 과잉이 된다 |
| 소리·진동을 키운다 | 원인이 강도가 아니라 **정보 없음**이다. 이탈이 빨라진다 |
| 안 뜬 이유를 안 남기기 | ③. 시간표가 깨져도 조용한 밤으로 보인다 |
| 임계값을 코드·문서에 박기 | 설정값이다 |
| 무시 횟수를 컬럼에 저장 | 파생이다. `guard_events`를 세면 나온다 |
| 끄는 선택지를 안 주기 | 끌 수 없으면 무음 처리되고 관측을 잃는다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**

**검사**

```
1  내일 첫 일정이 있으면 L2 문구에 그 시각과 남은 시간이 들어간다
2  ★ 내일 일정이 없으면 L2 가 안 뜬다                      ← 1의 짝
3  ★ 안 뜬 이유가 기록에 남는다 (일정 없음 / 못 읽음이 갈린다)
4  ★ L3 는 내일 일정과 무관하게 뜬다                        ← 없는 것을 세는 검사
5  연속 무시가 임계를 넘으면 끄기 카드가 뜬다
6  ★ 임계 아래면 안 뜬다                                    ← 5의 짝
7  ★ 무시 횟수가 컬럼에 없다 (조회로 계산 · 스캐너)
```

**2가 이 티켓의 본체다** — *"항상 뜨는 것"*이 결함이었으므로 **안 뜨는 밤이 있어야 고쳐진 것이다.**

**4가 회귀 검사다.** L2를 고치다 L3까지 조건을 태우면 **시험 전날 밤에 Guard가 통째로 조용해진다.**

⚠️ **Kotlin 쪽은 jsdom 이 못 본다** — 1·2는 스캐너 또는 서버 층이고 **진짜 판정은 밤 실측이다.**
⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).
⚠️ **fixture 에 고정 날짜를 쓰지 마라**(함정 12) — *"내일"* 도 상대로 잡는다.

**변이**
- 남은 시간을 안 싣는다 → **1만** 죽는다
- 일정 없어도 띄운다 → **2만** 죽는다
- 안 뜬 이유를 안 남긴다 → **3만** 죽는다
- L3 에도 같은 조건 → **4만** 죽는다
- 끄기 카드를 안 띄운다 → **5만** 죽는다
- 항상 띄운다 → **6만** 죽는다
- 무시 횟수를 컬럼에 저장 → **7만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

**밤 실측이다. 이틀이 필요하다:**

```
□ 평일 밤 (내일 수업 있음)
   ★ L2 가 "지금 자면 N시간 — 10시 <과목>" 으로 뜬다
□ 월요일 밤 (내일이 화요일 = 공강)
   ★★ L2 가 아예 안 뜬다                          ← 이 티켓의 판정
□ 두 밤 다 L3 는 평소대로 뜬다
```

**★★ 둘째 줄이 판정이다** — *"항상 뜨는 것"*이 사라졌는가.

⚠️ **L2 가 뜬 밤에 `adb screencap` 을 한 장 남겨라**(담당). 문구가 실제로
읽히는 크기인지는 화면이 답하고, 여섯 밤을 무시하게 만든 것 중에
**안 보이는 것**이 섞여 있었는지도 그때 갈린다.

마이그레이션: 없음. 무시 횟수는 guard_events 를 세면 나온다 (원칙 1)

**⚠️ ③을 티켓과 다르게 만들었다 — 못 읽은 밤은 *막지 않고 띄운다*.**

티켓 ③은 두 경우를 *"둘 다 안 띄우되 기록으로 가른다"* 로 적었다. **가르는 것은 그대로 했지만
행동을 갈랐다:**

```
재료를 받았고 다가올 약속이 없다   no_wake   →  침묵한다 (정상)
한 번도 못 받았다                 no_data   →  ★ 띄운다 (옛 문구로)
받은 지 오래됐다                  stale     →  ★ 띄운다 (옛 문구로)
```

근거는 티켓 자신의 걱정이다 — *"안 뜬 이유가 기록에 남지 않으면 다음에 시간표가 깨져도
조용한 밤으로 보인다."* **결함일 때 개입을 없애면 결함이 조용해진다.** 둘 다 막으면 동기화가
며칠 실패한 밤에 감지 경로가 통째로 사라지고, 그 침묵은 공강 밤과 화면에서 구별되지 않는다.
띄우면 최소한 *"오늘 밤 뭔가 이상하다"* 가 사용자에게 닿는다. `stale`을 따로 둔 것도 같은 이유다:
목록의 항목이 전부 과거가 된 것을 *"일정이 없다"* 로 읽으면 **낡음이 침묵으로 번역된다.**

**① 남은 시간은 기기가, 발동 그 자리에서 잰다** (`GuardWatch.wakeSentence`).
서버(`guard.wakePoints`)는 **하루에 하나, 그 날 가장 이른 약속**을 `wake[]`로 내려보내고
(`GET /api/guard/schedule`에 얹었다 — 새 왕복을 만들지 않았다), 기기는 `at - now`를 그 순간 계산한다.
서버가 미리 접으면 **새벽 3시의 문구가 저녁 6시 기준으로 굳는다.**
재료는 **시간표 전개(T-58)와 `events`** 둘이고, `classesIn`을 읽기만 한다.
⚠️ **준비 시간은 안 뺀다** — 재는 것이 *약속까지 남은 시간*이라고 문구가 말한다. 빼려면 `prep`을
기기에도 둬야 하고 그러면 역산이 두 벌이 된다(`protectAxis`가 유일한 자리인 이유와 같다).

**② 안 띄우는 판정은 네이티브다. 서버는 재료까지만 말한다.**
근거 둘: **발동 경로엔 네트워크가 없고**(ADR-021) 판정에 `now`가 들어간다 — 하루 1회 pull한
응답에 *"띄울까"* 를 접어 두면 그 답은 받은 시각의 답이지 발동 시각의 답이 아니다.
★ **날짜로 *"내일"* 을 계산하지 않았다.** 취침 창이 `00:30~06:00`이라 발동 시각이 이미 그 아침의
달력 날짜다 — *"내일"* 로 잡으면 하루 건너뛴 날을 본다. **`now` 이후 첫 약속까지의 거리**로 가른다
(`wakeLookaheadHours`). 그 아침의 수업은 몇 시간 뒤, 다음 날은 하루 더 뒤라 둘이 넓게 벌어진다.

**③ 무엇이 가르나 — `GuardSync.WakeState` 넷 하나가 정한다.** 기기 prefs에 마지막 판정이
`watch_l2_gate`로 남고(`{at, state, fired, wakeAt, title}`) `Guard.watchStatus()`가 그대로 준다.
**띄운 밤도 그 자리를 지난다** — 안 띄운 것만 남기면 *"왜 떴나"* 를 못 읽는다(T-54의 `noteTry` 모양).

**④ L3가 안 걸린다는 것을 두 검사가 양쪽에서 센다.**
smoke 4는 **행동** — 종일 시험은 `wake`에 안 실리는데(3) 같은 응답의 `fires[]`에 Level 3이 그대로 있다.
smoke 5는 **원문** — 게이트가 `if (level == 2)` 가지 안에 있고, 알람 경로(`GuardAlarms`·`AlarmReceiver`)에
`nextWake|WakeState|wakeLookahead`가 하나도 없다.
⚠️ **`/wake/i`로 세다가 `RTC_WAKEUP`에 걸렸다** — 구현과 무관하게 늘 빨간불이었다. 겨누는 것은
낱말이 아니라 **아침 재료를 보는 이름 셋**이다.

**변이 일곱 — 여섯은 하나씩만, 하나는 기능을 통째로 없애 넷을 죽였다**
(기준 M0 = smoke 413/0 · front 413/0)

| | 변이 | 결과 | 표의 예상 |
|---|---|---|---|
| M1 | 남은 시간을 안 싣는다 | smoke 412/1 — **8만** | ✓ |
| M2 | 일정이 없어도 띄운다 | smoke 412/1 — **6만** | ✓ |
| M3 | 안 뜬 이유를 안 남긴다 | smoke 412/1 — **7만** | ✓ |
| M4 | L3에도 같은 조건 | smoke 412/1 — **5만** | ✓ |
| M5 | 끄기 카드를 안 띄운다 | front 409/4 — 카드 + 버튼 셋 | *5만* ✗ |
| M6 | 항상 띄운다 | front 412/1 — **6만** | ✓ |
| M7 | 무시 횟수를 저장한다 | smoke 412/1 — **13만** | ✓ |

⚠️ **M5가 넷을 죽인 것은 검사가 겹쳐서가 아니라 변이가 크기 때문이다.** *"그대로 누르면
기록을 지난다"* · *"네이티브가 없으면 껐다고 말하지 않는다"* 는 **카드가 떠야 누를 것이 있다.**
검사들이 서로 다른 것을 센다는 증거는 M1~M4·M6·M7이 하나씩만 죽인 것이 준다.

⚠️ **검사가 서로의 몫을 먹던 자리 둘을 좁혔다.**
① 처음엔 *"이유가 갈린다"* 와 *"모든 출구가 기록을 지난다"* 를 한 검사에 뒀는데,
M2와 M3가 **같은 검사 하나만** 죽여 둘을 구별하지 못했다 — 6과 7로 갈랐다.
② `none과 error` 검사가 *"안 뜬다"* 를 **6의 관측값**과 비교하고 있었다. M6이 6과 이 검사를
함께 죽여, 이 검사가 자기 몫(*실패가 이름을 갖는가*)을 못 셌다. 계약값(`"none"`)과 비교하게 좁혔다.

⚠️ **변이 하나가 배터리를 통째로 죽일 뻔했다** — M5에서 `#td-nag-keep`의 `onclick`이 없어
`null is not a function`으로 러너가 죽고 **요약을 잃었다.** 배터리가 그것을 *"아무도 안 죽었다"* 로
읽는 것이 T-55·T-56·T-58에서 물린 그 칸이라, **핸들러가 없으면 그 검사만** 빨간불이 되게 고쳤다.

⚠️ **M7을 처음엔 놓쳤다.** *"조회를 두 번 부르고 `settings`를 비교"* 로 짰는데 물화하는 구현도
두 번째엔 **같은 값을 쓰므로 차이가 안 났다.** 연속이 실제로 **한 칸 올라가는 순간**에 재도록 고쳤다.

**범위 밖으로 안 나갔다** — `cal/`·시간표 전개는 읽기만 했고, `guard/`의 예약·알람 경로와
L3·L4 판단은 한 줄도 안 건드렸다. 마이그레이션 없음.

**⚠️ 진짜 판정은 밤 실측이다.** 위 숫자는 *"게이트가 옳은 자리에 있고 문구가 재료를 싣는다"* 까지고,
**여섯 밤을 무시하게 만든 것이 정말 사라졌는가**는 §확인 절차의 두 밤이 답한다.
