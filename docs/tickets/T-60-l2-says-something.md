# T-60 — Level 2가 밤마다 다른 말을 한다

**발행** Cowork · 2026-09-05 · **담당** Claude Code · **보통**
**근거** [ADR-047](../../APP-ADR.md#adr-047) · **APK 필요 · 위임 금지(guard/) · 마이그레이션 없음**

---

## 무엇이 어긋났나 — 사용자가 한 문장으로 말했다

```
8/26 ~ 8/31   L2 여섯 밤 전부 ignored      L3 는 전부 accepted
```

> **항상 뜨는 게 내가 맨날 대충 넘겼었어** (2026-09-05)

⚠️ **반응 실패가 아니라 설계 결함이다.** L2의 조건은 *"화면이 N분 이상 켜져 있다"* 하나뿐이고,
**그 시각에 그것은 거의 언제나 참이다. 항상 참인 신호는 아무것도 말하지 않는다.**

**그리고 무시가 습관이 되면 L3까지 같은 취급을 받기 시작한다** — ADR-026이 경고한
도구 이탈의 앞 단계다. **지금 L2는 관측도 개입도 아니다.**

## ★ 어제까지는 못 고쳤다 — T-58이 재료를 넣었다

```
내일 10시 수업이 있다     지금 자면 N시간
내일 공강이다 (화요일)     늦게 자도 마찬가지다
```

**같은 시각의 같은 화면 켜짐이 두 밤에 다른 뜻을 갖는다.** 그 차이를 이제 말할 수 있다.

## 할 일

### ① 문구가 사실을 말한다 — 명령이 아니라

```
지금   "지금 자야 합니다"                          ← 매일 같다
바꿈   "지금 자면 5시간 30분 — 10시 전자기및연습1"   ← 밤마다 다르다
```

⚠️ **명령이 아니라 사실이다**(ADR-047 ①). 설계 §6.2가 개입의 정당성을 사전 서약에 두는데,
**매일 같은 명령은 서약을 소모하고 사실은 그렇지 않다.**

**내일 첫 일정과 거기까지 남는 시간**을 함께 보인다. 그 값은 **시간표 전개와 `events`가 준다.**

### ② ★ 내일 아침에 아무것도 없으면 안 뜬다

**공강 전날 밤의 L2는 소음이다.** 늦게 자는 것이 판단이 흐려서가 아니라
**늦게 자도 되기 때문**일 수 있고, 앱이 그것을 모르면서 개입하면 신뢰를 깎는다.

⚠️ **L3·L4는 이 조건을 타지 않는다.** 그것들은 데드라인·보호 일정이 근거다.
**이 티켓은 L2만 다룬다** — L3 경로를 한 줄도 건드리지 마라.

### ③ ★ 조용히 안 뜨는 것과 못 뜨는 것을 가른다

```
내일 일정이 없어서 안 띄웠다      →  정상 · 그렇게 기록된다
일정을 못 읽어서 안 띄웠다        →  ★ 그건 결함이다. 구별돼야 한다
```

⚠️ **T-54·T-55·T-57이 세 번 배운 자리다.** 안 뜬 이유가 기록에 남지 않으면
**다음에 시간표가 깨져도 "조용한 밤"으로 보인다.**

### ④ 무시가 쌓이면 끄는 선택지를 준다

**더 세게 하지 않는다**(ADR-047 ③). 연속 무시가 임계를 넘으면 화면이 그 사실을 말한다:

```
"이 알림이 N번 그냥 지나갔어요 — 꺼 둘까요? [끄기 / 그대로]"
```

⚠️ **끌 수 없는 알림은 무음 처리되고, 그러면 관측도 잃는다.** 임계값은 설정값이다 —
**이 티켓에 숫자를 적지 않는다**(`CLAUDE.md` §아키텍처 원칙).

## 범위

```
android/.../guard/GuardWatch.kt      L2 조건 · ★ 위임 금지 영역
android/.../guard/  (문구 조립)
src/services/guard.ts · src/db/index.ts   내일 첫 일정 조회
public/app.js · index.html           ④의 카드
test/smoke.ts · test/front.mjs
```

**마이그레이션 없음.** 무시 횟수는 `guard_events`에서 세면 나온다 — **파생을 저장하지 않는다**(원칙 1).

⚠️ **`guard/`는 위임 금지 영역이다**(`AGENT-CHAIN` §4). 직접 한다.
⚠️ **`cal/`·시간표 전개를 고치지 마라** — 읽기만 한다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| L3·L4에 같은 조건 걸기 | 근거가 다르다. **데드라인은 내일 일정과 무관** |
| 무시 횟수로 자동 강화 | ②와 충돌 — 공강 무시가 시험 전날 과잉이 된다 |
| 소리·진동을 키운다 | 원인이 강도가 아니라 **정보 없음**이다. 이탈이 빨라진다 |
| 안 뜬 이유를 안 남기기 | ③. 시간표가 깨져도 조용한 밤으로 보인다 |
| 임계값을 코드·문서에 박기 | 설정값이다 |
| 무시 횟수를 컬럼에 저장 | 파생이다. `guard_events`를 세면 나온다 |
| 끄는 선택지를 안 주기 | 끌 수 없으면 무음 처리되고 관측을 잃는다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**

**검사**

```
1  내일 첫 일정이 있으면 L2 문구에 그 시각과 남은 시간이 들어간다
2  ★ 내일 일정이 없으면 L2 가 안 뜬다                      ← 1의 짝
3  ★ 안 뜬 이유가 기록에 남는다 (일정 없음 / 못 읽음이 갈린다)
4  ★ L3 는 내일 일정과 무관하게 뜬다                        ← 없는 것을 세는 검사
5  연속 무시가 임계를 넘으면 끄기 카드가 뜬다
6  ★ 임계 아래면 안 뜬다                                    ← 5의 짝
7  ★ 무시 횟수가 컬럼에 없다 (조회로 계산 · 스캐너)
```

**2가 이 티켓의 본체다** — *"항상 뜨는 것"*이 결함이었으므로 **안 뜨는 밤이 있어야 고쳐진 것이다.**

**4가 회귀 검사다.** L2를 고치다 L3까지 조건을 태우면 **시험 전날 밤에 Guard가 통째로 조용해진다.**

⚠️ **Kotlin 쪽은 jsdom 이 못 본다** — 1·2는 스캐너 또는 서버 층이고 **진짜 판정은 밤 실측이다.**
⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).
⚠️ **fixture 에 고정 날짜를 쓰지 마라**(함정 12) — *"내일"* 도 상대로 잡는다.

**변이**
- 남은 시간을 안 싣는다 → **1만** 죽는다
- 일정 없어도 띄운다 → **2만** 죽는다
- 안 뜬 이유를 안 남긴다 → **3만** 죽는다
- L3 에도 같은 조건 → **4만** 죽는다
- 끄기 카드를 안 띄운다 → **5만** 죽는다
- 항상 띄운다 → **6만** 죽는다
- 무시 횟수를 컬럼에 저장 → **7만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

**밤 실측이다. 이틀이 필요하다:**

```
□ 평일 밤 (내일 수업 있음)
   ★ L2 가 "지금 자면 N시간 — 10시 <과목>" 으로 뜬다
□ 월요일 밤 (내일이 화요일 = 공강)
   ★★ L2 가 아예 안 뜬다                          ← 이 티켓의 판정
□ 두 밤 다 L3 는 평소대로 뜬다
```

**★★ 둘째 줄이 판정이다** — *"항상 뜨는 것"*이 사라졌는가.

⚠️ **L2 가 뜬 밤에 `adb screencap` 을 한 장 남겨라**(담당). 문구가 실제로
읽히는 크기인지는 화면이 답하고, 여섯 밤을 무시하게 만든 것 중에
**안 보이는 것**이 섞여 있었는지도 그때 갈린다.
