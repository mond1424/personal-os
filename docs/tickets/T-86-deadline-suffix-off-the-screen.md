# T-86 — "기한"은 과제 이름이 아니다. 화면 어디에서도 뗀다

**발행** Cowork · 2026-10-01 · **담당** Claude Code · **보통**
**근거** 2026-10-01 사용자 — *"'기한'은 왜 아직 붙어있는거지? … 앱의 '일정'에도 기한이 붙어있다"* ·

## 무엇이 어긋났나 — T-83이 절반만 뗐다

```
할 일(task)     "학기과제"           ★ T-83 이 뗐다
일정(event)     "학기과제 기한"      ⚠️ 원문 그대로 뒀다
들어온 것 목록   "학기과제 기한"      ⚠️ 원문 그대로 보여 준다
```

**T-83이 일정을 그대로 둔 근거는 둘이었다 — 둘 다 약하다:**

```
"마감 그 자체다"             날짜 상세는 이미 23:59 와 "일정" 칸으로 그것을 말한다
"uclass 에서 그 이름으로 찾는다"  "학기과제" 로 찾아도 똑같이 나온다
```

★★ **그리고 "기한"은 교수가 쓴 글자가 아닌 것으로 보인다.** 수집된 과제가 과목·교수와 무관하게
**전부 같은 꼬리 `" 기한"` 으로 끝난다** — Moodle이 과제 마감 일정에 자동으로 붙이는 꼬리다.
⚠️ **T-74의 *"제목을 고치지 마라"* 는 교수가 틀리게 지은 이름을 우리가 고쳐 쓰지 말라는 규칙이다.**
Moodle 의 꼬리를 떼는 것은 그 규칙에 안 걸린다.

## 명제 — 원문은 원장에만. 화면은 이름만

```
collected_items.summary   ★ 원문 그대로 (T-74 — 바뀌지 않는다)
events.title              "학기과제"      ← 이 티켓
tasks.title               "학기과제"      ← T-83 그대로
들어온 것 목록             "학기과제"      ← 이 티켓 (보여 줄 때만)
```

## 할 일

### ① 먼저 센다 — ⚠️ 전제다

```
□ ★ collected_items 전수 — summary 가 " 기한" 으로 끝나지 않는 행이 있나 (몇 건 · 무엇)
□ 이미 수락된 수집분 — event·task 중 제목이 아직 원문 그대로인 것 몇 건
    (collected_items.event_id · task_id 로 잇는다. 제목으로 찾지 마라)
□ ★ 그중 마감된 날(daily.status='closed')에 걸린 행 — 동결 트리거가 UPDATE 를 막는가
```

⚠️ **" 기한" 으로 안 끝나는 행이 있으면 적고 계속한다** — 규칙이 그것은 안 건드린다(T-83 §규칙).
★ **훑기가 0건을 내면 스캐너에 물어야 하는 것 하나를 먹여 보고 넘어간다**(함정 17·18).

### ② 새로 들어오는 것 — `accept` 가 일정 제목도 같은 함수로 만든다

```ts
events.create(env, t, { title: taskTitleOf(row.summary), ... })   // 지금은 row.summary
```

★★ **`taskTitleOf` 하나를 쓴다. 일정용을 따로 짜지 마라** — 두 벌이면 한쪽만 바뀐다.
(이름이 이제 할 일 전용이 아니니 바꾸고 싶으면 바꿔도 된다. 함수는 하나다.)

### ③ 들어온 것 목록 — 보여 줄 때만 뗀다

`pending` · `list` 응답에 **서버가 같은 함수로 만든 표시용 제목**을 싣고, 시트가 그것을 쓴다.
⚠️ **`summary` 칸은 그대로 둔다.** 프런트에 같은 규칙을 다시 짜지 마라(두 벌).

### ④ 이미 들어간 것 — 소급한다. **손대지 않은 제목만**

```
event.title = 원문 그대로   →  뗀다
task.title  = 원문 그대로   →  뗀다
그 밖 (사용자가 고친 제목)  →  ★ 안 건드린다
마감된 날에 걸려 막히는 행  →  건너뛰고 §보고에 적는다
```

★ **마이그레이션으로 한다** — 원격 원장을 바꾸는 일이고, 기록이 남고 `--local → --remote` 순서를 탄다.
⚠️ **SQL 이 `taskTitleOf` 와 같은 규칙을 한 번 더 쓰게 된다** — 한 번만 도는 일이라 받아들인다.
**그 사실을 마이그레이션 주석에 적는다.** 새 파일은 `test/smoke.ts` 스키마 목록에도 넣는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| **`collected_items.summary` 를 다듬는다** | ★ 원문은 원장에 남는다(T-74) |
| **사용자가 고친 제목을 소급이 덮는다** | 자유 변경 칸이다 — 원문과 같을 때만 고친다 |

### 한 것

- **② `accept`** — `titleOf(row.summary)` 를 **한 번** 만들어 `events.create` 와 `createTask` 에 같이 쓴다.
  `taskTitleOf` → **`titleOf` 로 이름을 바꿨다**(할 일 전용이 아니다 · 함수는 하나).
- **③ `pending`·`list`** — 응답에 `title`(표시용 이름)을 싣는다. **`summary` 는 원문 그대로.**
  시트(`renderCollected`)는 `r.title` 을 쓴다. **프런트엔 규칙이 없다.**
- **④ `0026_collected_title_backfill.sql`** — `event_id`·`task_id` 로 잇고 · **제목 = 원문일 때만** ·
  마감된 날의 일정은 `WHERE` 에서 거른다. 새 제목은 **자기 제목에서** 만든다(조건이 제목 = 원문이라 같은 값).
  ⚠️ **SQL 이 규칙을 한 번 더 쓴다는 것과, 공백(`' '`)만 걷어 JS `trim()` 보다 좁다는 것**을 주석에 적었다 —
  좁은 쪽으로 어긋나면 *안 고치는* 쪽이라 안전하다(실측 끝 공백 0). `test/smoke.ts` 스키마 목록에 넣었다.
- 주석 셋을 사실에 맞췄다 — `db/index.ts` `calEntries` · `app.js` 짝 합치기(*"T-83이 갈라 놓은 구별"* 이 이제 없다 —
  **남은 이유는 사용자가 고친 제목과, 소급에서 원문으로 남은 마감된 날의 일정**이다).

### ⚠️⚠️ 티켓이 안 적은 것 — **Guard 문구가 바뀐다** (Cowork 자리 · 사용자 확인 후 진행)

**`guard/` 는 한 줄도 안 열었다. 그런데 출력이 바뀐다** — Guard 가 `events.title` 을 그대로 읽는다:

```
guard.ts wakePoints   put(e.date, e.time, e.title, …)   → /api/guard/schedule 의 wake[]
GuardWatch.kt:317     "지금 자면 ${span} — $at ${w.title}"   (보호 없는 일정 = leaveBy 없음 = 이 가지)

전   지금 자면 20시간 — 23:59 수리물리 과제 1 기한
후   지금 자면 20시간 — 23:59 수리물리 과제 1
```

**그 밤의 다음 약속이 수집한 마감일 때만** 뜬다 — 수업이 없는 날의 23:59 마감, 즉 **토요일 마감의
금요일 밤**이 그 자리다(09-12 · 09-19 · 09-26 이 전부 토요일이었다). ADR-047 §T-71 이 이 폴백을
*"'21:59 기상'보다 덜 틀리다"* 로 남겨 뒀고, **그 문장에서 "기한"은 23:59 가 마감이라는 유일한 단서였다.**
Guard 는 제목의 낱말로 가르지 않으므로(ADR-047) 지금 그 단서는 **어디에도 없다.**
★ **판단은 Cowork 의 것이다** — *마감에 무엇을 말할 것인가* 는 ADR-047 이 아직 안 정했다고 적은 그 자리다.
