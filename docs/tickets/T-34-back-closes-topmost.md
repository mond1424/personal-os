# T-34 — 뒤로가기가 맨 위 하나만 닫는다

**발행** Cowork · 2026-08-11 · **담당** Claude Code · **작음**
**상태** ✅ **실측 완료 (2026-08-17 낮)** · 최종 검토 합격 (수정 없음) 2026-08-11 · **이번 APK에 묶였다**
실측: `FIELD-TEST-DAY.md` ① 다섯 줄 — **Today에서 뒤로가기로 앱이 나간다**(갇히지 않는다).
⚠️ **짝의 뒤쪽(③ 마지막 줄 — 개입 화면에서는 아무 일도 없다)은 보고에 명시되지 않았다.**
검토가 *"둘 다 통과해야 이 티켓의 경계가 지켜진 것"*이라 적어 둔 그 줄이다. Level 4는 `cap`에
막혔지만 **Level 3 개입 화면은 떴으므로 그 자리에서 확인된다** — 안 봤으면 밤 실측에서 함께 본다.

---

## 무엇이 어긋났나

`BACKLOG-0806` 5번. **시트가 열려 있어도 뒤로가기를 누르면 앱이 그냥 닫힌다.**

웹에 그 이벤트를 받는 자리가 **하나도 없다** — `public/`에 `backButton`·`popstate` 0건.
Capacitor는 하드웨어 뒤로가기를 `@capacitor/app`의 `backButton` 이벤트로 넘기는데
**그 플러그인이 설치돼 있지 않다**(`package.json`에 `@capacitor/android`·`core`·`cli`뿐).

**그래서 APK가 필요하다.** 웹만으로는 안드로이드 하드웨어 키를 받을 방법이 없다.

## 왜 지금인가

**APK를 몇 시간 뒤에 설치한다.** 이번에 안 묶으면 **다음 유선 연결까지 기다린다** —
그게 언제일지는 정해져 있지 않고, 실제로 T-28은 넷이 밀려 하루를 기다렸다.

작은 것이고, 늦출 이유가 시간뿐이라면 지금이 그 시간이다.

## 할 일

### ① 무엇을 닫을지 정하는 함수를 분리한다

**리스너와 판단을 나눈다.** 판단이 순수하면 `front.mjs`가 직접 부를 수 있다 —
jsdom에는 Capacitor가 없으므로 **리스너 안에 판단을 넣으면 검사가 0이 된다**(T-33의 그 자리).

```
handleBack()  →  무엇을 닫았는지 / 아무것도 안 닫았는지를 돌려준다
리스너        →  그것을 부르고, 아무것도 안 닫았으면 기본 동작에 맡긴다
```

### ② 순서 — 맨 위 하나만

```
① 시트가 열려 있다        → 맨 위 하나만 닫는다        (겹쳐 있으면 한 번에 하나)
② 날짜 선택 모드다        → cancelPick — 원래 탭으로
③ Today 탭이 아니다       → Today로
④ Today 탭이다            → 앱을 나간다               ★ 막지 않는다
```

**④를 반드시 남긴다.** 뒤로가기로 앱을 못 나가면 사용자가 갇히고,
그건 이 티켓이 고치려는 것보다 나쁘다. **"두 번 누르면 종료" 같은 것도 넣지 않는다** —
실수로 나가도 다시 열면 그만이고, 마찰은 Guard가 쓰는 도구이지 앱 전체가 쓰는 것이 아니다.

`closeSheet`·`cancelPick`·`switchTab`이 이미 있다. **새 닫기 경로를 만들지 않는다.**

## ★ 개입 화면의 뒤로가기 차단은 건드리지 않는다

`GuardAlertActivity`가 `OnBackInvokedDispatcher`로 뒤로가기를 **의도적으로 막고 있다**
(`:255~269` — targetSdk 35+는 예측형 뒤로가기가 기본이라 `onBackPressed()`가 아예 안 불린다).

**그것이 ADR-026의 Override 마찰이다.** 뒤로가기로 개입 화면을 빠져나갈 수 있으면
60초·180초 대기가 통째로 무의미해지고, **Guard가 무력해진다.**

이 티켓은 **메인 액티비티의 웹 화면**만 다룬다. 둘은 다른 액티비티다.

## 범위

```

public/app.js               handleBack() + boot()에서 리스너 하나
test/front.mjs              검사
```

**서버·마이그레이션 무변경.** `GuardAlertActivity` 무변경.
**`npx cap sync android` 후 재빌드가 필요하다** — 플러그인이 하나 는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| `GuardAlertActivity`의 뒤로가기 차단 손대기 | ADR-026의 마찰이다. **다른 액티비티다** |
| 뒤로가기로 앱을 못 나가게 만들기 | 사용자가 갇힌다. ④는 기본 동작에 맡긴다 |
| "두 번 누르면 종료" | 마찰은 Guard의 도구다. 앱 전체가 쓰지 않는다 |
| 한 번에 여러 개 닫기 | 겹쳐 있으면 하나씩. 사용자가 어디까지 닫았는지 알아야 한다 |
| 판단을 리스너 안에 넣기 | jsdom에 Capacitor가 없다 → **검사가 0이 된다**(T-33) |
| 새 닫기 경로 만들기 | `closeSheet`·`cancelPick`·`switchTab`이 이미 있다 |
| 다른 Capacitor 플러그인 함께 추가 | 이 티켓은 `backButton` 하나다 |

## 완료 조건

```

Kotlin 빌드 통과 · npx cap sync android 성공
```

검사 — `handleBack()`을 직접 부른다.

1. 시트가 열려 있으면 **그 시트만** 닫고 탭은 그대로다
2. 시트 둘이 겹치면 **한 번에 하나만** 닫힌다
3. 피커 모드면 원래 탭으로 돌아온다 · 시트는 안 열려 있었다
4. Today가 아닌 탭이면 Today로
5. **Today에서 아무것도 안 열려 있으면 "안 닫았다"를 돌려준다** ← 앱이 나갈 수 있어야 한다

**5번이 짝이다.** 1~4만 보면 **항상 무언가를 닫는 구현**(= 앱을 영영 못 나감)도 통과한다.

## 확인 절차 (사용자) — APK 설치 후

```
□ 시트를 열고 뒤로가기 → 시트만 닫힌다 (앱은 살아 있다)
□ 날짜 선택 중 뒤로가기 → 원래 탭으로
□ 캘린더 탭에서 뒤로가기 → Today로
□ Today에서 뒤로가기 → 앱이 닫힌다          ← 갇히지 않는다
□ 개입 화면(testNotify)에서 뒤로가기 → 아무 일도 없다   ← 마찰이 살아 있다
```

**마지막 둘이 이 티켓의 경계다.** 하나는 "막지 않는다", 하나는 "막는다" — 반대 방향이고
둘 다 지켜져야 한다.

### 판단과 리스너를 어떻게 나눴나

```js
function handleBack() { ... return "sheet" | "pick" | "tab" | null; }   // 순수 — 검사가 직접 부른다
capApp?.addListener?.("backButton", () => { if (!handleBack()) capApp.exitApp?.(); });
```

**리스너는 잇기만 한다.** jsdom엔 Capacitor가 없으므로 판단을 리스너 안에 넣었으면
**검사가 통째로 0**이 됐다 — T-33이 방금 고친 그 자리와 같은 종류다.
`front.mjs`는 `ev("handleBack()")`로 직접 부른다.

**새 닫기 경로를 만들지 않았다.** `closeSheet`·`cancelPick`·`switchTab` 그대로 쓴다.
'맨 위' 판정도 새로 정하지 않고 **`syncOverlay`와 같은 기준(DOM 순서)**을 쓴다 —
시트끼리 z-index가 같아 나중 것이 위에 그려진다. 두 벌 두면 갈라진다.

⚠️ **`exitApp()`이 없으면 사용자가 갇힌다.** Capacitor는 `backButton` 리스너를 달면
**기본 동작을 꺼 버린다** — 그래서 ④를 "안 막는다"로 두려면 나가는 것도 우리가 해야 한다.
티켓의 *"기본 동작에 맡긴다"*를 글자 그대로 구현하면(= 아무것도 안 함) **앱이 안 닫힌다.**
`handleBack()`이 `null`을 주면 `exitApp()`을 부른다.

브라우저(PWA)에는 `Capacitor`가 없어 리스너가 안 걸린다 — 그 환경엔 하드웨어 키도 없으므로 맞다.

### 개입 화면이 무변경인가 (전수)

**무변경이다.** `git diff -- android/.../guard/` 가 **비어 있다** — `GuardAlertActivity`를 포함해
`guard/` 아래 17개 파일 전부 손대지 않았다. `android/`에서 바뀐 것은 `cap sync`가 만드는
**생성 파일 둘뿐**이고(`capacitor.build.gradle`에 `implementation project(':capacitor-app')` 한 줄,
`capacitor.settings.gradle`에 `include ':capacitor-app'`), 둘 다 헤더에
*"DO NOT EDIT THIS FILE! IT IS GENERATED"*라 적혀 있는 파일이다.

**`GuardPlugin` 등록도 무사하다** — `MainActivity.java`의 `registerPlugin(GuardPlugin.class)`은
소스 등록이라 `cap sync`가 건드리지 않는다. sync 로그의 *"Found 1 Capacitor plugin"*은
**npm 패키지 플러그인만 센 것**이고 로컬 플러그인은 그 목록에 원래 안 나온다.

**둘은 다른 액티비티다.** 개입 화면의 뒤로가기 차단은 ADR-026의 Override 마찰이고,
뒤로가기로 빠져나갈 수 있으면 60초·180초 대기가 통째로 무의미해진다. 그쪽은 막는 게 맞다.

### 변이 — 5번이 실제로 잡히는가

| 변이 | 결과 |
|---|---|
| ④가 `null` 대신 `"tab"`을 준다 (= **항상 무언가를 닫는다**) | **282/1** |
| 겹쳐도 `closeAll()`로 한 번에 다 닫는다 | **281/2** |

**앞이 이 티켓의 짝이다.** 딱 하나만 죽었고, `null`을 단언하는 검사는 ⑤뿐이다 —
①~④는 전부 초록이었다. 즉 **①~④만 있었으면 "앱을 영영 못 나가는 구현"이 통과한다.**
뒤는 둘이 죽었는데(②와 그 후속) 둘 다 *"다른 하나는 남아 있다"*를 보는 짝이라 함께 죽는 것이 맞다.

**②를 연 순서와 반대로 열었다** — `sh-log`(442줄)를 먼저 열고 `sh-day`(241줄)를 나중에 연다.
닫히는 것이 `sh-log`면 DOM 순서를 따른 것이고 `sh-day`면 '마지막에 연 것'을 따른 것이다.
**둘이 같은 결과를 내는 시나리오로 짜면 무엇을 검사하는지 알 수 없다.**

### 막힌 것

⚠️ **웹 검사가 볼 수 없는 것이 둘이다 — 감추지 않는다.**
① 리스너가 실제로 하드웨어 키에 걸리는지 ② 개입 화면에서 뒤로가기가 여전히 막히는지.
전자는 jsdom에 Capacitor가 없어서, 후자는 다른 액티비티라서다.
**둘 다 §확인 절차의 마지막 두 줄이고, 그 둘이 이 티켓의 경계다** —
하나는 "막지 않는다", 하나는 "막는다"로 **반대 방향**이라 한쪽만 봐서는 부족하다.

⚠️ **모달은 뒤로가기가 안 닫는다.** `handleBack`은 `.sheet`만 본다(티켓 §할 일 ①의 순서 그대로).
모달은 자기 배경이 따로 있어 시트와 다른 층인데, **뒤로가기 대상에 넣을지는 티켓이 정하지 않았다** —
범위를 넓히지 않고 그대로 뒀다. 실제로 걸리면 별건이다.

### 티켓이 틀렸고, 담당이 그것을 찾았다

티켓 §할 일 ①이 *"아무것도 안 닫았으면 기본 동작에 맡긴다"*라고 썼다. **Capacitor에서는 성립하지 않는다** —
`backButton` 리스너를 다는 순간 기본 동작이 꺼진다. 글자 그대로 구현했으면 **앱에 갇히고**,
그건 이 티켓이 고치려던 것보다 나쁘다(§금지 2번이 정확히 그것을 금지한다).

**§금지와 §할 일이 합쳐서 모순이었던 것이 아니라, 플랫폼 전제가 확인되지 않은 것이다.**
발행자의 실수이고, `AGENT-CHAIN.md` §5에 한 줄로 올라갔다 —
*"'아무것도 안 한다'가 '원래대로 둔다'와 같지 않을 수 있다."*

### 남은 것 — 실측 두 줄이 **반대 방향**이다

담당이 §막힌 것에 감추지 않고 적었고, 그 판단이 맞다.

| 실측 | 방향 | 어디 |
|---|---|---|
| Today에서 뒤로가기 → 앱이 닫힌다 | **막지 않는다** | `FIELD-TEST-DAY.md` ① 마지막 줄 |
