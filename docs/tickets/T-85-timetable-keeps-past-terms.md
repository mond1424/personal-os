# T-85 — 시간표는 학기마다 쌓인다

**서버만 · 마이그레이션 없음 · APK 무관 · 프런트 무변경**

## 목표

새 시간표를 저장해도 다른 학기의 규칙이 남게 한다. 저장은 학기 범위가 겹치는 규칙만 바꾸고, `GET /api/timetable`은 대표 학기 하나만 돌려준다. 과목명은 NFC로 저장한다.

**왜** — 지금 저장은 전체 교체다(`stClearTimetable`). 다음 학기 시간표를 넣는 순간 이번 학기 규칙이 지워지고, 수업은 규칙에서 전개되므로(ADR-045 ②) **지난 날짜를 열면 그날의 수업이 사라진다.** Obsidian 연동이 과목 이름의 기준으로 쓰는 정본 과목명의 이력도 함께 사라진다(설계 DEC-27).
**다음 학기 시간표를 넣기 전에 배포돼야 한다.** 그 뒤에는 이번 학기 규칙을 되살릴 수 없다.

## 먼저 확인한다

```
□ list()·replace()를 부르는 곳이 GET·PUT /api/timetable 라우트 둘뿐인가
□ classesIn()이 규칙 전부를 읽고, expand()가 규칙마다 학기 범위로 거르는가
  (그렇다면 쌓인 규칙이 다른 학기의 날짜로 새지 않는다. 전개 쪽은 고칠 것이 없다)
□ 화면(openTimetable)이 GET 응답의 rules를 편집 초안으로 쓰고,
  ttSave가 PUT 응답의 rules.length를 토스트에 쓰는가
□ smoke의 T-58 절 뒤에서 그 학기 시간표를 쓰는 절이 어디인가(아침 재료 등).
  새 검사가 그 학기를 건드리면 안 된다
```

## 할 일

① **저장 — 겹치는 학기만 바꾼다.** `stClearTimetable` 대신, 새 범위와 겹치는 규칙만 지운다.

```
겹침:  term_start <= 새 term_end  AND  term_end >= 새 term_start
```

지우기와 넣기는 지금처럼 한 batch다. 빈 규칙(`rules: []`)으로 저장하면 그 범위와 겹치는 학기만 비워진다.

② **조회 — 대표 학기 하나.** `GET /api/timetable`은 대표 학기의 규칙과 범위만 준다.

```
대표 학기 = 오늘(귀속일 t.d)을 포함하는 학기
          → 없으면 term_start가 가장 늦은 학기
          → 규칙이 없으면 { rules: [], term: null }  (지금과 같다)
```

대표 학기를 고르는 부분은 순수 함수로 뺀다. 검사가 오늘을 바꿔 가며 부른다.
라우트가 `TimeCtx`를 넘기도록 `src/index.ts` 한 줄을 고친다.

③ **저장 응답 — 방금 저장한 학기.** `PUT`은 저장한 범위의 규칙과 범위를 돌려준다. 화면 토스트("N칸")가 이 값을 쓴다.

④ **과목명 NFC.** `validate()`에서 과목명을 `trim()`한 뒤 `normalize("NFC")`한다(설계 DEC-30). 이미 저장된 행은 고치지 않는다.

⑤ `stClearTimetable`은 쓰는 곳이 없어지면 지운다. SQL은 `src/db/index.ts`에만 둔다.

## 범위 — 이 파일들만 고친다

```
src/services/timetable.ts   ①②③④
src/db/index.ts             ①⑤ 겹침 삭제 문장
src/index.ts                ② GET 라우트가 TimeCtx를 넘긴다 (한 줄)
test/smoke.ts               검사
docs/api-surface.md         재생성 (GET·PUT의 뜻이 바뀐다)
```

`public/`은 바꾸지 않는다. 바꿔야 할 것 같으면 멈추고 보고한다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 새 마이그레이션 | `timetable_rules`에 학기 범위가 이미 있다. 스키마가 필요해 보이면 멈추고 보고한다 |
| GET이 모든 학기의 규칙을 준다 | 화면이 그 규칙을 편집 초안으로 쓴다. 여러 학기가 섞인 초안을 한 범위로 저장하면 지난 학기 규칙이 이번 학기로 복제된다 |
| 겹치지 않는 학기의 규칙을 지운다 | 그것을 남기는 것이 이 티켓의 목적이다 |
| 과목명으로 학기를 가른다 | 같은 과목을 다른 학기에 다시 들을 수 있다. 학기는 범위로만 가른다 |
| 학기 범위를 코드에 박는다 | T-58 검사 8(날짜 리터럴 스캐너) · `validate()`의 주석 |
| `expand`·`classesIn`의 거르는 규칙을 바꾼다 | 이미 규칙마다 학기 범위로 거른다 |
| 전개한 수업을 저장한다 | ADR-045 ② · 원칙 1 |
| 검사가 T-58 학기를 바꾼다 | 뒤의 절이 그 시간표를 쓴다. 새 검사는 겹치지 않는 학기만 더하고 끝에 치운다 |

## 읽을 것

- ADR-045 ② — 규칙(과목·요일·시각·학기 범위)을 저장하고, 날짜는 조회할 때 전개한다
- 설계 `docs/pos-obsidian-design.md` DEC-27 · DEC-30 · §6.1(시간표 이력, 테스트 "정본 이력")
- `test/smoke.ts` §T-58 — 검사 4가 규칙 행 수 8을 센다. 새 검사는 그 절 뒤에 둔다
- 함정 12 — 검사 fixture에 고정 날짜를 쓰지 않는다. 학기 범위는 오늘(`D`)에서 상대로 잡는다

## 완료 조건

```
typecheck 통과 · smoke 497 → 497+N · front 523 그대로 · 실패 0 · verify exit 0
```

T-58 학기를 A(오늘 포함)라 한다. B는 A가 끝난 뒤의 학기, B′는 B와 겹치지만 범위가 다른 학기다.

```
1  ★ B를 저장해도 A의 규칙이 남는다 (행 수 = A + B)                  ← 본체
2  ★ A 안의 지난 날짜(/api/days/:date)에 A의 수업이 뜬다             ← 1의 짝. 행만 남고 전개되지 않으면 소용없다
3  ★ B 안의 날짜에는 B의 수업만 뜬다 (A가 새지 않는다)
4  ★ GET은 A만 준다 (칸 수 8 · 범위 A)
5  ★ B′를 저장하면 B만 B′로 바뀌고 A는 그대로다 (행 수 = A + B′)
6  ★ 대표 학기 고르기(순수 함수): 오늘을 포함하는 학기 / 없으면 가장 늦게 시작하는 학기 / 규칙이 없으면 null
7  ★ PUT 응답은 저장한 학기다 (B′를 저장하면 B′의 칸 수와 범위)
8  ★ NFD로 들어온 과목명이 NFC로 저장된다
```

검사가 끝나면 B′의 범위로 빈 규칙을 저장해 치우고, 행 수가 A(8)로 돌아왔는지 센다.

**변이**

```
전체 삭제로 되돌린다                      → 1 · 2 · 4 · 5가 죽는다
겹침 조건을 뒤집는다                      → 1 · 2 · 4 · 5가 죽는다
겹침 대신 범위가 같은 학기만 지운다        → 5만 죽는다
GET이 모든 학기를 준다                    → 4만 죽는다
대표 학기를 늘 "가장 늦게 시작"으로 고른다 → 4 · 6이 죽는다
PUT 응답을 대표 학기로 돌려준다           → 7만 죽는다
expand의 학기 거름을 뺀다                 → 3이 죽는다 (T-58 검사 7도)
NFC 정규화를 뺀다                         → 8만 죽는다
```

변이가 붙었는지와 되돌아갔는지를 둘 다 본다(함정 16).

## 이 티켓이 안 하는 것

- 정본 과목 목록 API(모든 학기). Obsidian 연동 S2에서 연다(설계 §5.5).
- 시간표 화면에서 학기를 골라 보거나 지난 학기를 고치는 UI.
- 이미 저장된 과목명을 NFC로 바꾸는 일.
