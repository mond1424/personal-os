# T-92 — T-71 픽스처가 하루 중 어느 시각에도 그날 가장 이른 약속이 된다

**발행** 설계층 · 2026-10-07 · **담당** 감독층 · **상태** ⬜ 대기
**근거** T-90 §보고(smoke 2 · 7 실패와 최소 재현) · `CONVENTIONS.md` 함정 12 · 15 · 18
**`test/smoke.ts`의 T-71 절 하나 · 동작 변경 없음 · 마이그레이션 없음 · 배포 없음**

---

## 목표

smoke의 T-71 검사 2 · 7이 **돌리는 시각과 상관없이** 같은 판정을 낸다.
왜: `t71Slot`은 그날 가장 이른 일정보다 한 시간 이르게 잡되 01:00 밑으로 내려가지 않는다. 귀속일 경계 전 00시대에 돌리면
T-71 일정의 날짜(`D + 21`)가 T-80 마감(`now + 20일`)과 같은 날이 되고, 마감이 00시대라 T-71 일정이 그날 가장 이른 약속이 못 된다.
그러면 `wakePoints`는 맞게 마감을 고르고, 검사는 `간격=NaN`으로 실패한다 — **구현이 아니라 픽스처의 전제가 깨진 것이다.**
함정 12의 *"피해야 할 시계는 오늘만이 아니다 — 그 파일이 만드는 모든 시각"* 이 앉는 자리다.

## 범위 — 이 파일만 고친다

```
test/smoke.ts    T-71 절(t71Slot · t71Make와 그 날짜 상수)
```

## 금지

| 하지 말 것 | 왜 |
|---|---|
| `src/` 고치기 | 구현은 맞게 골랐다(T-90 최소 재현) |
| T-80 픽스처 옮기기 | 다른 절의 전제를 건드린다. T-71이 자기 전제를 지킨다 |
| 검사 2 · 7의 기대값 느슨하게 하기 | 고칠 것은 전제지 판정이 아니다 |
| 시스템 시계에 기대는 확인 | 시각은 주입해서 잰다(T-23 · T-90 최소 재현의 방식) |

## 완료 조건

```
typecheck 통과 · smoke 534 → 534 + 새 검사 수 · front 526 → 526 · 실패 0
```

- **전제를 스스로 확인한다** — T-71 일정이 그날 가장 이른 약속이 아니면 *"전제 깨짐"* 으로 실패한다.
  `간격=NaN` 같은 결과 실패로 위장하지 않는다(함정 18)
- **주입한 시각 넷에서 같은 판정** — 00:30 · 02:30 · 05:59 · 12:30(KST). 주입을 smoke 안에 둘지 따로 돌릴지는 담당이 정한다.
  **00:30이 고치기 전에는 빨간불**이었음을 함께 보인다
- 고친 뒤 실제 시계로 한 번 더 — 위 기준선
