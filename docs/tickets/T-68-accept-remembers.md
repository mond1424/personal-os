# T-68 — 열한 번째 개입이 첫 번째인 척하지 않는다

**발행** Cowork · 2026-09-10 · **담당** Claude Code · **보통**
**근거** [ADR-049](../../APP-ADR.md#adr-049) · 2026-09-09 밤 실측 ·
**★ APK 필요 · 위임 금지(`guard/`) · 마이그레이션 없음**

---

## 무엇이 어긋났나 — 열한 번 수락하고 열한 번 계속 썼다

```
00:30  L2                     reaction 없음
00:45  L3  watch:bedtime      accepted
00:51  L3  recheck:accepted   accepted
00:57  L3  recheck:accepted   accepted      ← 재확인 상한. 여기서 멈춘다
01:13 · 01:40 · 02:44 · 03:00 · 03:32 · 03:48 · 04:11   전부 accepted
```

**개입은 정확했다** — 조건이 참이었다. **효과도 있었다**: 최근 60분의 화면 시간이
03:00에 52분 → 03:32에 **15분**으로 떨어졌다.

⚠️ **그리고 03:48에 31분, 04:11에 53분으로 돌아왔다.**

```
개입 하나가 사는 시간   ≈ 30분
재발동 간격             15분          ← 앱이 자기가 방금 산 30분을 다시 개입한다
```

★ **열한 번은 과한 것이 아니라 필요한 수였다.** 문제는 횟수가 아니라
**열한 번째가 첫 번째와 똑같이 생겼다**는 것이다 — **매번 첫 개입인 척한다.**

## 할 일

### ① ★ 문구가 오늘 밤 몇 번째인지 안다

```
지금   (매번 같은 문구)
바꿈   ★ 오늘 밤의 누적이 문구에 들어간다
```

⚠️ **재료는 이미 기기에 있다** — `GuardWatch`가 `firedTonight`을 prefs에 센다(`K_NIGHT_N`).
**서버를 부르지 마라**(ADR-021 — 발동 경로엔 네트워크가 없다).
⚠️ **저장하지 마라** — 밤마다 초기화되는 계수다. **컬럼을 만들면 파생 저장이다**(원칙 1).
⚠️ **문구를 이 티켓에 적지 않는다** — 담당이 쓰고 §보고에 적는다.
**다만 수(數)가 읽혀야 한다** — *"여러 번"* 같은 뭉뚱그림은 세는 것을 지우는 것이다.

⚠️ **첫 개입은 지금과 같아야 한다.** 1번째에 *"1번째예요"* 라고 말하면 소음이다 —
**언제부터 다르게 말할지는 담당이 정하고 근거를 적는다.** 임계는 설정값이다(`CLAUDE.md`).

### ② ★ 버튼에 마찰을 붙이지 않는다 — 이 티켓의 경계다

```
수락하고 잤다        →  대가 없다. 그것이 옳은 수락이다
수락하고 계속 썼다   →  다음 개입이 그 사실을 안다        ← ①이 전부다
```

⚠️ **[알겠습니다]에 대기·사유를 붙이지 마라.** **처음 한 번에 자는 밤도 함께 벌한다**
(ADR-049 §기각한 대안 1행). 막으면 OS 무음 처리로 **관측까지 잃는다**(ADR-047 ③).

### ③ [그래도 계속하기]가 무엇을 하는지 읽히는가 — **보고만 한다**

**열한 번 중 한 번도 안 쓰였고 `override_reason`은 전부 `null`이다.**

⚠️ **ADR-048이 방금 배운 것이 걸린다** — *"쓰이지 않는 길과 없는 길은 화면에서 같다."*
17일 동안 안 눌린 버튼도 화면에 떠 있었다.

```
할 것     그 버튼의 지금 문구·색·위치를 §보고에 적는다 (스크린샷 한 장이면 된다)
안 할 것  ★ 고치지 않는다
```

**고치면 ①과 섞여 판정이 안 갈린다.** 재료만 올린다 — 다음 티켓이 정한다.


**마이그레이션 없음 · 서버 무변경 · ★ APK 필요.**

⚠️ **`guard/`는 위임 금지 영역**(`AGENT-CHAIN` §4). 직접 한다.
⚠️ **`GuardAlertActivity`의 버튼 구성을 바꾸지 마라** — ③은 보고만이다.
⚠️ **`recheck` 상한을 만지지 마라** — 그 상한은 *"같은 개입을 무한히 되묻지 않는다"* 로 옳다.
**이 티켓이 메우는 것은 상한 뒤에 오는 새 발동이 앞을 모르는 것**이다(ADR-049 ③).
⚠️ **L2 게이트(T-60)를 건드리지 마라.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| [알겠습니다]에 대기·사유 붙이기 | **정직한 수락을 벌한다.** ADR-047 ③의 *"더 세게"* 그 자체 |
| 누적을 컬럼에 저장 | 파생이다(원칙 1). 밤마다 초기화되는 계수다 |
| 발동 경로에서 서버 조회 | ADR-021. 네트워크 없이 발동한다 |
| 재발동 간격·상한 조정 | 개입이 30분을 산다. 간격을 늘리면 **그 30분마저 못 산다** |
| 임계·숫자를 코드·티켓에 박기 | 설정값이다(T-51·T-60과 같은 이유) |
| [그래도 계속하기]를 고치기 | ③. 섞이면 판정이 안 갈린다 |
| 문구를 *"여러 번"* 으로 뭉개기 | 세는 것을 지우는 것이다 |

## 완료 조건

```
typecheck 통과 · smoke(±N) · front(±N) · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**
⚠️ **`verify`가 초록이어도 Android는 안 본 것이다**(함정 13). 주석의 `--`·`/*`를 조심한다.

**검사**

```
1  ★ 두 번째 이후 발동의 문구에 그 밤의 누적이 들어간다
2  ★ 첫 발동의 문구는 전과 같다                          ← 1의 짝. 소음을 안 만들었는가
3  ★ 밤이 바뀌면 수가 초기화된다 (전날 것을 안 이어 센다)
4  ★ 누적을 저장하는 컬럼·키가 없다 (스캐너 — 파생 금지)
5  ★ 발동 경로에 네트워크 호출이 없다 (스캐너 — ADR-021 회귀)
6  ★ 수락 버튼에 대기·사유가 안 붙었다 (스캐너 — ②의 경계)
```

**1이 본체이고 2가 그 짝이다** — *"매번 같다"* 가 결함이었으므로 **달라진 밤과 안 달라진 첫 번이
둘 다 세어져야** 고쳐진 것이다.

⚠️ **Kotlin 쪽은 jsdom이 못 본다**(T-60이 배운 것). **1·2·3은 스캐너 또는 서버 층이고
진짜 판정은 밤 실측이다.** 스캐너로 셀 때 **낱말 하나를 겨누지 말고 이름 셋을 겨눈다**
(T-60이 `/wake/i`로 세다 `RTC_WAKEUP`에 걸린 자리).
⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).

**변이**
- 누적을 문구에 안 싣는다 → **1만** 죽는다
- 첫 발동에도 누적을 말한다 → **2만** 죽는다
- 밤 키를 안 갈아 전날을 이어 센다 → **3만** 죽는다
- 누적을 prefs 컬럼처럼 영구 저장 → **4만** 죽는다
- 발동 경로에 조회를 넣는다 → **5만** 죽는다
- 수락에 대기를 붙인다 → **6만** 죽는다

⚠️ **하나씩 안 죽으면 좁혀라**(`AGENT-CHAIN` §8). 특히 **1과 2는 같은 문구를 본다** —
2가 *"첫 번엔 그 말이 없다"* 만 세는지 확인한다.

## 확인 절차 (사용자) — APK 설치 후

**밤 실측이다.**

```
□ 첫 개입의 문구가 전과 같다
□ ★ 두 번째 이후 개입이 오늘 밤 몇 번째인지 말한다
□ ★★ 그 밤의 reaction 이 accepted 일색이 아니다     ← 판정
□ 다음 날 밤에 수가 1부터 다시 센다
```

**★★ 셋째 줄이 판정이다 — "고쳤다"가 아니라 "무엇이 달라졌는가".**

⚠️ **`accepted` 일색이 그대로면 ①이 틀린 것이다.** 그때는 **개입이 맞는 도구인가**를 다시 묻는다
(ADR-049 §결과 — 밤을 통째로 재고 아침에 말하는 안이 다음 후보다).
⚠️ **화면 시간도 함께 본다** — `risk_snapshot`의 `screen_on_sec`가 개입 뒤 더 오래 낮게 머무는가.
**그것이 "30분짜리 도구"가 길어졌는지를 재는 유일한 수다.**

### ① 문구 — 무엇을 썼고 왜 그것뿐인가

```
1번째   (전과 한 글자도 같다)
2번째   오늘 밤 2번째예요. 취침 창(00:30~06:00) 안에서 31분째 화면을 보고 있어요. 지금 …. 내일이 무너집니다.
9번째   오늘 밤 9번째예요. …
```

★ **말하는 것은 수(數) 하나다.** *"수락하고 계속 썼다"* 는 **안 쓴다** — 기기가 발동 경로에서
아는 것은 발동 수뿐이고, 앞의 반응이 Override였던 밤에 그 문장은 거짓이 된다.
**틀린 사실은 명령보다 빨리 신뢰를 깎는다**(T-61이 `wakeSentence`에서 배운 자리).
누적이 하는 일은 판정이 아니라 **세어 보이는 것**이다(ADR-049 ② — *"세게 하는 것이 아니다"*).

⚠️ **자리는 맨 앞이다.** 한 밤 안에서 달라지는 조각이 이것 하나뿐이라 뒤에 붙이면
매번 같은 앞부분이 먼저 읽히고 그대로 넘어간다(ADR-047 ①).
접힌 알림에서도 이 줄이 먼저 보인다 — 대신 *"N분째"* 가 접힘 밖으로 밀린다.
**개입 화면(FSI)에는 전문이 그대로 뜨므로** 잃는 것은 접힌 상태 한 줄뿐이라고 봤다.

⚠️ **9/9 밤에 이 코드였다면**: 00:30 L2(1번째, 지금과 같음) → 00:45부터 04:11까지
**2번째 … 9번째**. 04:11이 밤 상한(9)이었다. **상한은 문구에 안 싣는다** —
*"여섯 번 더 버티면 조용해진다"* 를 읽히게 하는 순간 도구가 카운트다운이 된다.

### 임계를 2로 정한 근거 (티켓 §① *"담당이 정하고 근거를 적는다"*)

`GuardSettings.watchTallyFrom` · 기본 **2** · `coerceIn(2, 20)`.

**2인 이유**: *"앞이 있었다"* 가 처음 참이 되는 순간과 **문구가 달라지는 순간이 같아야 한다.**
3 이상이면 **앞이 있는데도 없는 척하는 발동**이 생기고, 그것이 이 티켓이 고치는 결함 그 자체다.

**하한이 1이 아니라 2인 이유**(이웃 `watchMinutes`·`watchMaxPerNight`는 1부터다):
1번째에 *"1번째예요"* 는 앞이 없는데 앞을 세는 말이라 알리는 것이 없는 소음이다.
★ **첫 발동의 침묵은 설정으로도 못 깨야 한다** — 그래서 검사 2가 코드 구조로 받쳐진다.

**끄기 스위치를 따로 안 만든 이유**: `watchMaxPerNight`(9)보다 크게 두면 누적을 영영 안 말한다.
손잡이 하나가 켜기·끄기·세기를 다 진다 — T-51이 `refireMinutes`에서 한 것과 같다.

### 재료 — 새로 저장한 것이 없다

`GuardWatch`가 이미 세던 `K_NIGHT_N`(밤 키가 바뀌면 0으로 돌아가는 계수)을 **읽기만** 한다.

```kotlin
val n = pr.getInt(K_NIGHT_N, 0) + 1      // 이번 발동을 포함한 순번
…
.putInt(K_NIGHT_N, n)                    // ★ 말한 수를 그대로 센다
```

★ **증가분이 같은 `n`을 쓴다.** 전엔 `pr.getInt(K_NIGHT_N, 0) + 1`을 두 번 계산했는데,
그러면 **말한 수와 센 수가 두 식**이 되어 갈라질 수 있다. 한 식으로 묶었다.

⚠️ **서버를 안 부른다**(ADR-021). `GuardWatch`에는 지금도 `HttpURLConnection`·`openConnection`·
`GuardSync.pull`·`GuardEventQueue.flush`가 하나도 없다 — 검사 5가 그 넷을 지킨다.

### 첫 발동이 늘 Level 2인 것은 **구조**다 — 검사 2가 여기 기댄다

`l2done`과 `K_NIGHT_N`은 **한 `edit()`에서 함께 쓰이고 함께 초기화된다.** 그래서

```
n == 1  ⟺  K_NIGHT_N == 0  ⟺  l2done == false  ⟺  level == 2
```

즉 **아침 한 줄(L2)과 누적 한 줄(L3~)은 같은 발동에 함께 서지 않는다.**
둘의 순서가 화면에서 다툴 일이 없고, ADR-047 ①의 *"사실이 맨 앞"* 도 그대로 남는다.

### ② 경계 — 수락 버튼은 한 글자도 안 바뀌었다

```kotlin
accept.setOnClickListener {
    finishWith("accepted", null)
    GuardRecheck.arm(this, level)
}
```

대기도 사유도 안 붙였고 레이아웃에서 버튼을 죽이지도 않았다.
`recheck` 상한(`MAX_PER_DAY = 2`)·재발동 간격·L2 게이트 **전부 안 건드렸다.**

⚠️ **재확인(`GuardRecheck`)의 문구에는 누적을 안 실었다.** `K_NIGHT_N`이 세는 것은
**감지 발동**이고 재확인은 거기 안 세어진다 — 그 수를 재확인 화면에 옮기면
**이름과 세는 것이 어긋난다**(함정 15의 사촌). 재확인은 이미 자기 앞을 말한다
(*"5분 전 [알겠습니다]를 선택했지만…"*)이라 *"첫 번째인 척"* 하지 않는다.

### ③ [그래도 계속하기] — **보고만 한다. 안 고쳤다**

스크린샷 대신 **레이아웃 원문의 실제 값**을 적는다 — 다음 티켓이 고칠 곳이 그 파일이다.
(`res/layout/activity_guard_alert.xml`)

| | [알겠습니다] `guard_accept` | [그래도 계속하기] `guard_override_open` |
|---|---|---|
| 문구 | `알겠습니다` (L1~2에선 `확인`) | **`그래도 계속하기`** |
| 배경 | `backgroundTint="#EDE7DA"` (밝게 채움) | **없음** — `borderlessButtonStyle` |
| 글자색 | `#1A1713` + `bold` | **`#A79E8D`** — 본문 `guard_body`와 **같은 색** |
| 크기 | `15sp` | **`13.5sp`** |
| 위치 | 본문 아래 `marginTop=30dp`, 폭 `match_parent` | **바로 아래 `marginTop=6dp`**, 폭 `match_parent` |

배경은 `#1A1713`(어두움). 즉 **채워진 버튼 하나 밑에, 본문과 같은 회색으로, 더 작게,
배경 없이 붙어 있는 텍스트 줄**이다.

★ **ADR-048 ①이 그대로 걸린다 — 라벨이 하는 일과 다르다.**
누르면 **계속되지 않는다.** 사유 입력창과 60초 대기(`WAIT_L3 × friction_mult`)가 열린다.
*"그래도 계속하기"* 는 **결과**를 말하는데 실제 결과는 *"사유를 적고 1분 기다리기"* 다 —
T-66이 *"일정 정하기 ›"* 에서 고친 것과 **같은 모양**이고, 그쪽은 17일 동안 안 눌렸다.
여기는 **열한 번 중 0번**이고 `override_reason`이 전부 `null`이다.

⚠️ **곁다리로 하나 더 나왔다 (역시 안 고쳤다).** 마찰 영역을 열면 처음 보이는 글자가
`guard_reason_count`의 **`0 / 20자`** 인데, **20자 하한은 이미 없다**
(`GuardAlertActivity` 주석: *"20자 하한은 마찰이 아니라 강제로 읽혔다"*, 실제 코드는
`count.text = if (n > 0) "${n}자" else ""`). 레이아웃 머리 주석도 아직 *"사유 한 문장(20자)"* 이다.
**있지도 않은 할당량을 화면이 먼저 말한다** — 안 눌린 버튼 뒤에 붙은 첫 인상이라
③과 같은 티켓에서 함께 볼 재료다.

### 변이표 — 여섯이 하나씩 죽는다

| 변이 | 죽는 검사 | front |
|---|---|---|
| M1 누적을 문구에 안 싣는다 | **1만** | 458 / 1 |
| M2 첫 발동에도 누적을 말한다 (임계 기본값 1) | **2만** | 458 / 1 |
| M3 밤 키를 안 갈아 전날을 이어 센다 | **3만** | 458 / 1 |
| M4 누적을 밤과 무관한 키에 영구 저장 | **4만** | 458 / 1 |
| M5 발동 경로에 `GuardEventQueue.flush` | **5만** | 458 / 1 |
| M6 수락에 `startWait` | **6만** | 458 / 1 |

⚠️ **처음엔 둘이 겹쳤고 좁혔다** (AGENT-CHAIN §8 — *"하나씩 안 죽으면 좁혀라"*).

- **M1이 1과 2를 함께 죽였다.** 2가 본문의 `n`을 **세고** 있었는데(`=== 2`), 누적을 통째로
  지우면 그 수가 0이 되어 2도 따라 죽었다. → **누적 줄을 뺀 나머지에 순번이 새는지**만 본다.
  M1에서는 나머지가 곧 전부이고, 거기 `n`이 없으면 통과가 맞다.
  **2가 세는 것은 *"첫 번엔 그 말이 없다"* 하나다**(티켓 §변이 마지막 줄이 겨눈 그 자리).
- **M3이 3과 4를 함께 죽였다.** 4가 *"정수 쓰기가 둘"* 을 세고 있었는데(0으로 · 이번 발동),
  초기화를 지우면 하나가 되어 4도 따라 죽었다. → **정수로 쓰이는 키가 그 계수 하나뿐인가**만 본다.
  ***"0으로 돌아가는가"* 는 3의 몫이다.**

★ **둘 다 같은 실수였다 — 검사가 개수를 셌다.** 개수는 이웃 변이가 함께 움직이고,
그러면 무엇이 틀렸는지 못 가른다. **T-64·T-67이 각각 좁힌 그 모양이고 세 번째다.**

### 검사가 문구를 복사하지 않는다 (함정 15)

스캐너가 *"정규식이 맞았는가"* 가 아니라 **Kotlin에서 뽑은 재료로 JS가 한 밤을 돌려 본다** —
`TALLY_FMT`(문구) · 비교 연산자 · `watchTallyFrom`(임계) 셋을 원문에서 뽑아
`n = 1…watchMaxPerNight`을 렌더한다. 검사에 문구를 적지 않았으므로 **구현이 틀릴 때
검사가 함께 틀리지 않는다.** 짝 셋(1·5·6)이 합성 소스로 **스캐너 자신의 눈**을 센다 —
*"안 실었다"* 와 *"파서가 낡았다"* 를 가른다.

⚠️ **`%d`가 이 검사의 칼날이다.** *"여러 번"* 처럼 뭉개면 치환이 안 되고 검사 1이 죽는다 —
티켓 §금지의 *"세는 것을 지우는 것이다"* 가 그대로 검사가 됐다.
