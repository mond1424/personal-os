## ★★★★★ 기다리는 대상이 틀렸다

```
넘기기 전   c-2  c-1  [c]  c+1  c+2          ← 다섯 다 캐시에 있다
넘긴 뒤     c-1   c  [c+1] c+2  c+3
                        ↑              ↑
                  ★ 보이는 칸       ⚠️ 기다리는 칸
                  이미 다 있다       두 칸 뒤. 화면과 무관하다
```

**`calBusy`를 푸는 것이 `c+3`의 응답이고**(`app.js:4206`), **`blocked`는 `commit`이 아니라
`pointerdown`에서 본다**(`app.js:4218`). ★★ **그래서 그동안 손가락이 아예 안 따라온다** —
*"넘어가다 말았다"* 가 아니라 **죽은 것처럼 보인다.**

```
죽은 시간 = 300ms + 왕복 + D1
왕복 바닥 0.48~0.55s (유선 · 401 = D1 닿기 전). ⚠️ 폰 + 모바일 회선이면 더 든다
```

★★★ **렌더 문제가 아니다.** T-81이 (b)(c)(d)를 수로 배제했다 —
**네이티브 전환으로도 이 왕복은 안 사라진다.**

## 할 일

### ① `calBusy`는 **화면이 끝나면** 푼다

```
지금   전환 끝 → 그래도 c+3 응답을 기다림 → 풀린다
바꿈   ★ 전환 끝 → 푼다.  프리페치는 await 없이 뒤에서 돈다
```

⚠️ **프리페치를 *지우지* 마라.** 없애면 이 티켓의 검사 하나가 더 초록이 되는데
(빨라지니까) **다음 칸이 매번 빈다.** ★ 뒤로 미루는 것이지 없애는 것이 아니다.

⚠️ **`TRACK_MS`(300ms)를 건드리지 마라** — **탭 캐러셀과 같은 상수다**(`app.js:140`).
캘린더만 줄이면 값이 두 벌이 된다. **줄일 값이 있으면 별건으로 올려라.**

### ② 프리페치가 못 따라온 칸은 **"받는 중"으로 그린다**

⚠️ **빈 칸과 *아직 안 온 칸*이 화면에서 같으면 안 된다.**
T-79가 방금 배운 것이고(*"물어볼 게 없다"* vs *"못 물어봤다"*), `AGENT-CHAIN` §5가 같은 말을 한다.

★ **모양은 담당이 정한다.** 정해진 것은 하나 — **그 상태가 DOM 에서 읽혀야 한다**(검사가 본다).

### ③ 안 읽는 `classes`를 서버가 안 보낸다

**`/api/calendar`가 만드는 `classes`를 프런트가 한 곳에서도 안 읽는다**(T-81 §덤).
**달마다 D1 질의 하나가 헛돈다**(`services/timetable.ts:187`).

⚠️ **지우기 전에 왜 있었는지 한 번 본다** — 커밋 이력이나 주석에 이유가 있으면 적고 올려라.
★ 그래도 **지금 죽은 코드인 것은 사실이다**(읽는 곳 0). 근거가 없으면 뺀다.

|---|---|
| **프리페치를 지운다** | ⚠️ 빨라 보이는데 **다음 칸이 매번 빈다.** 미루는 것이지 없애는 것이 아니다 |
| `TRACK_MS`를 줄인다 | ★ **탭 캐러셀과 공유하는 상수다.** 두 벌이 된다 |

## ① `calBusy` 를 화면이 끝나면 푼다 — **조립을 둘로 갈랐다**

`renderCalendar` 가 *"받아서 그린다"* 한 덩어리였다. 그것을 **동기 프레임**과 **채우기**로 가르고,
제스처는 앞의 것만 기다린다.

```
renderCalendarFrame(rotateDir, fill)   동기. 캐시에 있는 달로 pane을 세운다. 없는 달은 '받는 중'
  └ 돌려주는 프라미스                   빠진 달을 받아 한 번 더 그린다. ★ 기다릴 사람만 기다린다
renderCalendar(rotateDir)              그 프라미스까지 await 하는 문 — 기존 호출부 스무 곳이 쓴다
```

```js
// calGo 의 finish()
const filling = renderCalendarFrame(dir);   // 회전·재중심화가 여기서 끝난다
calBusy = false;                            // ★ 여기서 푼다
if (filling) run(() => filling);            // ⚠️ 버리지 않는다 (함정 14)
```

★★ **pane 배치를 '모양이 달라진 것만 다시 조립'으로 바꿨다.** `data-sig = 세대|귀속일|달|d나w`
하나가 그 판정을 진다. 그래서 **채우기는 '받는 중'이던 그 칸 하나만** 다시 만든다 —
`한 칸 넘기면 새로 조립하는 pane은 1개`(front.mjs:1499)가 그대로 초록인 이유다.
(플레이스홀더는 `paneBody` 를 안 지나므로 `calendarPaneBuildCount` 를 **안 올린다.**)

⚠️ **`cur` 토글을 순서가 바뀐 판에서만 돈다.** 프레임이 두 번 도니까 그냥 두면 열 번이 되고,
`cur 토글은 pane당 한 번`이 죽는다. `cur`는 **DOM 순서에만** 달렸으므로 이 쪽이 맞다.

⚠️⚠️ **채우기는 한 번이다(`fill = false`).** 다시 `fill` 을 켜면 **캐시가 안 차는 상황에서
프레임↔요청이 무한히 돈다** — 러너가 멈추는 자리이고, 화면에서는 *"검사가 튼튼하다"* 와 같아
보인다(함정 8·16). 변이 배터리를 짜다 그 모양을 먼저 만나서 구현에 상한을 뒀다.

**`TRACK_MS`(300ms)는 한 글자도 안 건드렸다** — 탭 캐러셀과 공유하는 상수다(검사 6이 센다).
