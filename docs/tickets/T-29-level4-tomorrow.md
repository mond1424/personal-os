# T-29 — 화면이 Level 4를 읽고 날짜를 튼다

**발행** Cowork · 2026-08-10 · **담당** Claude Code · **상태** ✅ 합격 (2026-08-10)
🌙 **실측은 밤 대기.** 2026-08-17 낮에 격상이 `cap`에 막혀 **날짜 게이트가 걸릴 구간이 없었다**
(T-28과 같은 이유 · `APP-BUILD.md` §낮 실측 ②). 낮에 상한을 쓰면 그 밤도 같은 귀속일이라
함께 막힌다 — **밤 실측을 하는 날 낮에는 `level: 4`를 쓰지 않는다.**
**위임 금지** 게이트 세 자리 · '내일' 계산 — **위임 가능** 문구·표시

---

## 무엇을 한다

T-28이 기기에 물어볼 곳을 냈다(`Guard.level4State()`). 이제 화면이 그것을 읽고,
**Level 4 구간에는 오늘 날짜가 붙지 않게** 한다 — ADR-035.

**막지 않는다.** 적는 것도, 대기에 담는 것도, 내일 이후 아무 날짜나 고르는 것도 전부 그대로다.
바뀌는 것은 **그것이 어느 날에 놓이는가** 하나다.

## 게이트를 어디에 거나 — 붙는 자리에 건다

여는 자리와 붙는 자리를 구별한다(AGENT-CHAIN §5). 피커를 여는 곳은 여럿이지만
**날짜가 실제로 붙는 곳**은 다음이 전부다:

| 자리 | 붙이는 것 | Level 4 중 |
|---|---|---|
| `addTaskOn` (628) | `Api.createTask({title, date:k})` | `k`가 오늘이면 **내일로 돌린다** |
| `assignDate` 비-defer (1143) | `Api.schedule(p.id, k)` | 오늘이면 붙이지 않는다 |
| `dfx-ok` (866) | `Api.defer(c.id, c.from, c.to)` | `c.to`가 오늘이면 붙이지 않는다 |

> ⚠️ **`assignDate`의 defer 분기는 붙는 자리가 아니다.** 거기서는 `openDeferSheet`가
> **열릴 뿐**이고, `Api.defer`는 시트의 확인 버튼에서 나간다. 시트가 떠 있는 동안
> 구간이 시작될 수 있으므로 **게이트는 `dfx-ok`에 건다.**

**대기(`Api.createTask({title})`, 1429)는 손대지 않는다.** 날짜가 없으니 오늘의 부담이 아니고,
*"적어두고 자자"*가 이 ADR이 원하는 형태다 — 막으면 대기의 의미가 깨진다(ADR-035 ①).

## 안내와 판정을 나눈다

`pickMinMax`(1099)의 `min`을 올리면 `pickable`·`applyPickDim`이 따라와
**오늘 칸이 흐려지고 눌리지 않는다.** 그런데 `pickMinMax`는 동기 함수이고 플러그인은 비동기다.

```
startPick 에서 한 번 물어 S 에 담는다   →  pickMinMax 가 읽는다     안내(dim)
붙는 자리 셋이 확정 직전에 다시 묻는다                              판정
```

**둘로 나누는 이유**: 피커를 03:29에 열고 03:31에 격상되면 dim은 낡는다.
이 순서면 **안내가 관대하고 판정이 엄하다** — 흘려보내는 쪽이 아니라 붙잡는 쪽으로 어긋난다.
반대(안내가 엄하고 판정이 관대)로 만들면 조용히 새는 구멍이 된다.

묻는 함수는 **하나**다. 세 자리가 각자 플러그인을 부르더라도 **판정을 각자 하지 않는다** —
`level4` 불리언은 기기가 준 그대로 쓴다(ADR-035 ②).

## 모르면 걸지 않는다

플러그인이 없으면(브라우저 PWA · 구버전 APK) **게이트는 안 걸린다.**
`globalThis.Capacitor?.Plugins?.Guard`가 `undefined`인 경로가 이미 있다(`app.js:2816`).

**이것을 fail-closed로 "고치지" 않는다.** ADR-024의 fail-closed는 *격상*을 안 하는 쪽이고
여기도 방향이 같다 — **모르면 덜 개입한다.** 발동하지도 않은 기기에서 날짜가 튀면
그것이 §6.3의 도구 이탈이다.

## 말없이 옮기지 않는다 (ADR-035 ⑤)

`toast()`가 이미 있다. 왜 내일이 됐는지 한 줄로 말한다.

**남은 시간을 시각으로 보여주지 않는다.** `level4State()`의 `until`을 화면이 쓰지 않는다:

- **카운트다운은 기다리라는 초대다.** 12분을 버티게 만드는 것은 이 ADR이 막으려던 바로 그것이다
- **그 시각은 약속이 아니다.** 발동이 이어지면 창이 갱신된다 —
  못 지킬 시각을 보여주면 도구를 못 믿게 된다

`until`은 플러그인에 그대로 둔다. 값이 틀린 것이 아니라 **화면에 넘기지 않기로** 한 것이다.

## 프롬프트에 사실을 적는다

T-28이 거짓을 지웠고, 이제 강제력이 생긴다. `VERIFY_SYSTEM`에 **실제 대가**를 적는다 —
대기가 60초에서 180초로 길어지는 것과, **격상 뒤 30분 동안 오늘 날짜가 붙지 않는 것**이다.
*"차단"*이라고 쓰지 않는다. 막지 않기 때문이다.

`guard.ts` 위의 T-28 주석도 함께 정리한다 — *"아직 적지 않는다"*가 사실이 아니게 된다.

**Kotlin을 건드리지 않는다** — T-28이 낸 것을 읽기만 한다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 대기 생성(1429)에 게이트 걸기 | 날짜가 없다. 막으면 대기의 의미가 깨진다 — ADR-035 ① |
| `assignDate`의 defer 분기에 게이트 걸기 | 거기는 시트를 **여는** 자리다. 붙는 자리는 `dfx-ok` |
| 서버가 오늘 날짜를 거부하게 만들기 | ADR-035 ② |
| 플러그인이 없을 때 막기 | 모르면 덜 개입한다. 발동 안 한 기기에서 날짜가 튀면 도구 이탈이다 |
| `until`을 시각으로 표시 | 카운트다운은 기다리라는 초대이고, 그 시각은 약속이 아니다 |
| 웹에서 창 길이를 다시 계산 | 30분이 두 곳에 생긴다. 판정은 기기가 준 불리언 그대로 |
| 마찰·확인 팝업으로 통과시키기 | "대가를 치르고 오늘로"가 기본 경로가 된다 — ADR-035 §기각한 대안 |

## 완료 조건

```
typecheck 통과 · smoke 282 → 283 이상 · front 257 → 262 이상 · 실패 0
```

검사 — **표의 자리 전부에 걸린다. 하나라도 빠지면 그 경로가 조용히 샌다.**

1. 자리마다 **Level 4일 때 오늘이 안 붙고, 아닐 때는 붙는다** — 양쪽을 각각 본다
2. **대기 생성은 Level 4에도 그대로 통과한다** (막지 않았음을 세는 검사)
3. 플러그인이 **없을 때** 오늘이 붙는다 (fail-open)
4. 옮겨졌을 때 **화면이 이유를 말한다**

**1번을 한쪽만 보면 안 된다.** "Level 4면 안 붙는다"만 검사하면
**게이트가 항상 켜져 있어도 초록**이다 — 2번이 그 짝이다(AGENT-CHAIN §5).

변이로 확인한다 — 게이트 셋을 **하나씩** 지웠을 때 **각각 다른 검사**가 빨간불이어야 한다.
셋을 지웠을 때 같은 검사가 걸리면 셋 중 둘은 검사되지 않고 있다.

### 게이트가 붙는 자리에만 걸렸나 (여는 자리와 구별했나)

**셋 전부, 붙는 자리에만.** 여는 자리에는 하나도 안 걸었다.

| 자리 | 무엇을 했나 |
|---|---|
| `addTaskOn` | 오늘이면 **내일로 돌린다** — 날짜가 생성과 함께 붙어 되돌릴 것이 없다 |
| `assignDate` 비-defer | 오늘이면 **안 붙이고** 다시 고르게 한다 — 사용자가 고른 날이라 말없이 옮기지 않는다 |
| `dfx-ok` | 오늘이면 **안 붙인다.** 시트를 먼저 닫지 않는다 — 막고 닫으면 사유를 다시 쓰게 된다 |

**`assignDate`의 defer 분기에는 걸지 않았다** — 거기는 `openDeferSheet`를 **여는** 자리다.
`startPick` 호출부 넷(`1162`·`1248`·`1336`·`1440`)도 여는 자리라 손대지 않았다.

**`k === S.today.date`를 먼저 본다.** 오늘이 아니면 플러그인을 아예 부르지 않는다 —
앞날에 넣는 것은 Level 4와 무관하고, 무관한 자리에서 왕복을 만들 이유가 없다.

**대기(1429)는 한 글자도 안 건드렸다.** 검사 ④가 그것을 **센다**.

### 안내와 판정을 어떻게 나눴나

```
startPick → askLevel4() 한 번 → S.level4 → pickMinMax → pickable/applyPickDim   안내(dim)
붙는 자리 셋 → 확정 직전에 askLevel4() 다시                                      판정
```

`S.level4`를 **항상 false로 먼저 두고** 답이 오면 좁힌다. 피커를 03:29에 열고 03:31에
격상되면 dim이 낡는데, 그 경우가 판정에서 걸린다 — **안내가 관대하고 판정이 엄하다.**
반대로 만들면 조용히 새는 구멍이 된다.

**막혔을 때 `S.level4 = true; applyPickDim()`을 그 자리에서 부른다** — 낡은 안내를 즉시 좁힌다.
안 그러면 "왜 눌리는데 안 되지"가 반복된다.

**판정은 세 자리가 각자 하지 않는다.** 묻는 함수는 `askLevel4()` 하나이고,
`level4` 불리언을 기기가 준 그대로 쓴다. **웹에 30분이 없다** — 검사가 그것도 센다
(`app.js`에 `30 * 60`·`1800000`이 없고 `level4State`는 있다).

### 변이 — 셋을 하나씩 지웠을 때 각각 다른 검사가 걸렸나

**걸렸다. 겹침 0.**

| 변이 | 결과 | 빨간불이 된 검사 |
|---|---|---|
| A `addTaskOn` 게이트 제거 | **268/3** | 내일 생성 · 서버 확인 · 이유 문구 — 전부 addTaskOn |
| B `assignDate` 게이트 제거 | **270/1** | "오늘로는 확정하지 않는다" 하나 |
| C `dfx-ok` 게이트 제거 | **268/3** | 미루기 차단 · 시트 유지 · 미루기 짝 — 전부 dfx-ok |
| **D `askLevel4`가 항상 true** | **267/4** | **짝 셋 전부 + fail-open** |

**D가 이 티켓의 핵심이다.** 게이트가 상시 ON이어도 "Level 4면 안 붙는다" 쪽은 **전부 초록**이다 —
짝이 없었으면 T-29가 통과했을 것이고, 낮에 오늘 칸이 통째로 막힌 앱이 배포됐다.
§완료 조건이 "1번을 한쪽만 보면 안 된다"고 못 박은 자리다.

### 설계와 어긋난 점

없다. 서버는 막지 않고(라우트 무변경), 판정은 기기가 하고, 웹은 창을 다시 계산하지 않는다.
마찰·확인 팝업으로 통과시키는 경로를 만들지 않았다 — 막힌 자리는 **다시 고르게** 할 뿐이다.
`until`은 플러그인에 그대로 있고 **화면이 쓰지 않는다**: 검사가 토스트에 `HH:MM` 꼴이
없는 것까지 본다.

### 막힌 것

**검사 자리를 옮겨야 했다.** 처음엔 파일 끝(부팅 복구 앞)에 뒀는데 거기는 **하루 마감 뒤**라
(`front.mjs`가 "마감은 뒤의 쓰기 검사를 막으므로 모든 쓰기 왕복을 끝낸 다음"이라고 적어 둔 자리)
`schedule`·`createTask`가 트리거에 409로 막혔다. 마감 **앞**으로 옮겼다.
증상은 "게이트는 통과했는데 목록에 없다"였고, 게이트와 무관했다.

**`Api.defer`만 기록에서 끊었다.** 미루기가 오늘로 오려면 **지난 날 entry**가 있어야 하는데
과거 날짜 task는 서버가 만들지 못하게 한다(400). 실제 defer 왕복은 앞의 [할 일 시트] 블록이
이미 태우므로, 여기서는 **게이트의 계약**(불렀나 · 어느 날짜로)만 본다.
`createTask`·`schedule`은 그대로 통과시켜 서버까지 실제로 간다.

⚠️ **APK가 아직 폰에 없다**(사용자가 원격 — 유선 연결 후). 그래서 **지금 폰에서는 게이트가
안 걸린다** — 그게 결함이 아니라 fail-open의 정의이고, 검사 ⑤가 보는 것이 정확히 그 상태다.
배포 순서는 웹 먼저·APK 나중이어도 안전하다: 웹이 원격 로드라 순서가 뒤집혀도
`Guard.level4State`가 없으면 오늘이 그냥 붙는다.

### 수정 — 프롬프트가 ADR이 구별한 것을 도로 합쳤다

초안이 *"**새 일에** 오늘 날짜가 붙지 않는다"*라고 썼는데 **구현은 둘 다 막는다.**
ADR-035 ①이 "새 일"과 "있던 부담의 이동(미루기)"을 **명시적으로 갈라 놓고**
둘 다 걸린다고 정했는데, 프롬프트가 한쪽만 적어 도로 합친 것이다.

**이 티켓 계열이 고치려던 것과 같은 종류다** — 모델이 실제와 다른 대가를 저울에 올린다.
T-28이 "없는 대가"를 지웠는데 T-29가 "절반짜리 대가"를 적을 뻔했다.

```
Level 4의 대가: Override 대기가 60초에서 180초로 늘고, 격상 뒤 30분 동안
오늘 날짜가 새로 붙지 않는다 — 새 일도, 미루던 일도 내일 이후로 간다.
```

smoke [13]의 마지막 검사가 **양쪽을 다 센다** — `새 일도` · `미루던 일도` ·
`오늘 날짜가 새로 붙지 않는다` · `180초` · `30분`. 한쪽만 적으면 빨간불이다.

### 주석 하나의 근거가 틀렸다 (행동은 그대로)

`dfx-ok`에서 시트를 안 닫는 근거를 *"사유를 다시 쓰게 된다"*로 적었는데 **성립하지 않는다** —
시트에서 `to`를 바꿀 수 없으니 결국 취소해야 하고, `openDeferSheet`가 `#dfx-reason`을
비우므로 **사유는 어차피 다시 쓴다.**

**남는 이유는 맥락이다**: 무엇을 어디로 옮기려 했는지가 토스트 한 줄만 남기고 통째로
사라지는 것과, 그대로 있는 채로 "오늘은 안 된다"를 듣는 것은 다르다.
주석과 검사 이름을 그렇게 고쳤다. **코드는 안 바꿨다** — 결론이 맞았고 근거가 틀렸다.

### 남긴 것 — 비대칭 (BACKLOG-0806)

같은 "오늘로는 안 된다"인데 단계 수가 다르다: `assignDate`는 **1단계**(피커가 떠 있고
오늘만 흐려짐 → 바로 다른 날), `dfx-ok`는 **3단계**(취소 → 피커 → 다시 고름).

**지금 바꾸지 않는다** — 새벽에 미루기가 오늘로 막히는 빈도를 모른다.
드물면 맥락 유지가 낫고 잦으면 단계 수가 이긴다. **밤 실측 뒤에 정한다.**
