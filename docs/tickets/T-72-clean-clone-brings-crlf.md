# T-72 — 클린 클론이 CRLF를 낳는다

**발행** Cowork · 2026-09-13 · **담당** Claude Code · **작음**
**근거** [함정 16](../../CLAUDE.md) (T-69가 `t46Bare`에서 실제로 물렸다) · 2026-09-13 담당 관측
**APK 무관 · 마이그레이션 없음 · 배포 무관 · 코드 무변경(검사·설정만)**

---

## 무엇이 어긋났나 — 둘이 각각은 옳고 합치면 CRLF다

**2026-09-13 담당이 본 것:**

```
git config core.autocrlf      true            체크아웃 때 LF → CRLF
.gitattributes                * text=auto     커밋 때 CRLF → LF (리포 안은 LF)
                                              ★ 둘이 합쳐지면 working tree 는 CRLF 다
```

**지금 안 터진 이유는 하나뿐이다 — 현재 working copy 가 이미 LF고 그대로 남아 있다.**
⚠️ **클린 클론은 다르다.** 그리고 클린 클론을 하는 사람은 **맥락이 가장 적은 사람**이다
(새 PC · 재설치 · 다른 층).

### ⚠️ 그 실패의 모양이 특히 나쁘다

**구현은 한 글자도 안 변했는데 소스를 문자열로 읽는 검사 여럿이 한꺼번에 빨간불**이 된다.
함정 16이 적은 그대로다 — ***"어느 검사가 틀렸나"* 가 아니라 *"왜 여럿이 한꺼번에 죽었나"* 로 보인다.**

⚠️ **변이 배터리를 돌리는 중이면 변이가 죽인 것으로 오독한다**
(`AGENT-CHAIN` §8 — *"환경이 러너를 죽여도 배터리는 똑같이 거짓말한다"*).

---

## ★★ 할 일 — 순서가 있다. **먼저 재고, 그다음 고친다**

### ① 센다 — 추측을 실측으로 바꾼다

```
임시 디렉터리에 클린 클론  →  npm ci  →  npm run verify
```

```
★ 몇 건이 죽는가 · 어느 검사인가
  그 목록이 ③의 범위다
```

⚠️ **이 수가 0이면 이 티켓은 여기서 닫는다.** 그러면 전제가 틀린 것이고,
***왜* 안 터졌는지가 그 자체로 새 관측**이다(보고에 적는다).
⚠️ **"터질 것이다"는 추측이고, 클린 클론 하나면 실측이다.** 이 리포는 추측으로 범위를 넓히지 않는다.

★ **클론 전에 `git config --get core.autocrlf`와 `.gitattributes`를 그대로 적어 온다** —
이 티켓의 전제가 사실인지부터 본다(`AGENT-CHAIN` §8 — *티켓의 전제도 변이 대상이다*).

### ② 원천 — `.gitattributes`가 working tree 를 LF로 못 박는다

```
*  text=auto  eol=lf
```

⚠️ **⚠️⚠️ 그런데 전부는 아니다. `android/gradlew.bat`은 CRLF 라야 한다.**

```
*.bat        text  eol=crlf      ← Windows 배치는 CRLF 가 아니면 깨진다
android/gradlew   text  eol=lf   ← 짝. 셸 스크립트는 LF
```

★★ **그리고 이것을 `npm run verify`가 안 잡는다 — 함정 13이 그 자리다.**
*"verify 초록 = 안 깨졌다"* 로 읽지 마라. **`assembleRelease`만이 답한다.**

⚠️ **사용자의 전역 `core.autocrlf`는 고치지 않는다** — 리포 밖이고 다른 리포에 영향이 간다.
`.gitattributes`가 리포 안에서 이긴다. **고칠 곳은 리포 안이다.**

### ③ 깊이 방어 — ①이 센 검사들이 `\r`를 걷는다

**②가 있어도 ③을 한다.** 에디터·도구 하나가 설정이 다르면 CRLF 파일은 다시 생기고,
그때 ②는 **커밋 시점에만** 정규화한다 — 그 사이의 verify 는 여전히 거짓말한다.

⚠️ **①을 건너뛰고 ③부터 하면 전수인지 모른다.** T-69가 `t46Bare` 하나를 고쳤을 때
**나머지가 몇인지 아무도 안 셌다** — 그것이 이 티켓이 ①로 시작하는 이유다.


**마이그레이션 없음 · APK 무관 · `src/`·`public/`·`android/` 무변경.**
⚠️ **`android/`는 `.gitattributes` 한 줄이 가리키는 대상일 뿐, 파일을 열지 않는다.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| **소스 파일을 일괄 변환해 커밋** | ⚠️ **전 파일 diff 가 된다.** 이력이 사실의 기록이 아니게 된다 |
| 전역 `core.autocrlf` 고치기 | 리포 밖이다. 다른 리포에 영향이 간다 |
| `*.bat`에 `eol=lf` | **`gradlew.bat`이 깨진다.** verify 는 초록인 채로 |
| ①을 건너뛰고 ③부터 | **전수인지 모른다.** T-69가 하나만 고친 자리 |
| `\r` 대신 정규식을 느슨하게 (`\s*$` 따위) | ⚠️ **다른 공백까지 먹어 검사가 무뎌진다.** 걷는 것과 눈감는 것은 다르다 |

## 완료 조건

```
typecheck 통과 · smoke ±N · front ±N · 실패 0 · verify exit 0
★ 그리고 클린 클론에서 verify exit 0          ← 이 티켓의 본체
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다.**
⚠️ **②가 `.bat`을 건드리므로 `assembleRelease`를 한 번 돌린다**(함정 13 — verify 로는 못 잰다).

**검사**

```
1  ★ 소스를 문자열로 읽는 검사 전수에 \r 걷기가 있다   (스캐너 — ①의 목록이 정답지)
2  ★ .gitattributes 에 *.bat 의 eol=crlf 가 있다        (gradlew.bat 보호)
3     .gitattributes 에 * 의 eol=lf 가 있다             (2 의 짝 — 둘이 함께라야 뜻이 있다)
```

⚠️ **1은 *개수*가 아니라 *자리*를 센다**(`AGENT-CHAIN` §8) —
*"몇 개가 `\r`를 걷나"* 가 아니라 **소스를 읽는 검사 각각이 걷는가**다.
⚠️ **1의 훑기가 0건을 내면 함정 17·18이다** — 스캐너에 물어야 하는 것 하나를 먹여 보고 넘어간다.

**변이 — ★ 이 티켓은 CRLF 자체가 변이다**

```
working tree 를 통째로 CRLF 로 바꾼다      → ③ 이후엔 아무것도 안 죽는다   ← 본체
  ⚠️ 그 상태에서 assembleRelease 도 한 번   → gradlew.bat 이 살아 있는가
스캐너 하나의 \r 걷기를 지운다 (CRLF 상태)  → 그 검사 하나만 죽는다        ← 짝
.gitattributes 에서 *.bat 줄을 뺀다        → 2 만 죽는다
```

⚠️ **첫 변이를 되돌릴 방법을 먼저 확보하고 시작한다** — working tree 전체를 만지는 변이다.
`git stash` 가 아니라 **별도 클론에서** 한다(`AGENT-CHAIN` §8 — 환경이 러너를 죽이는 자리).

## 확인 절차 (사용자)

**없다.** 배포·APK·마이그레이션 무관. **사용자가 할 것이 없다.**

---

## ★ 이 티켓이 안 하는 것

**이미 CRLF 로 저장된 파일이 리포에 있는지**는 안 본다 —
`.gitattributes`의 `text=auto`가 커밋 시점에 정규화하므로 **리포 안은 LF 라는 것이 전제**이고,
①이 그 전제를 함께 잰다(클린 클론이 CRLF 면 체크아웃 변환이고, 리포가 CRLF 면 다른 문제다).
⚠️ **①에서 그 둘이 갈리면 멈추고 보고한다.** 두 번째라면 이 티켓의 범위가 아니다.

## 보고 (담당이 채운다)

**2026-09-13 · ①에서 닫는다. 죽은 검사 0건.** ②·③으로 가지 않았다.

### ① 전제 — 사실이다. 다만 층이 예상보다 바깥이었다

```
git config --get core.autocrlf                true
git config --show-origin --get core.autocrlf  file:C:/Program Files/Git/etc/gitconfig   true
  --system  true   ·   --global  (없음)   ·   --local  (없음)
cat .gitattributes                            # 저장소에는 LF로 정규화해 저장 (…)
                                              * text=auto
```

★ **`core.autocrlf`는 global 이 아니라 *system* 층에 있다**(Git for Windows 설치 기본값).
티켓이 *"전역을 고치지 마라"* 라고 한 것보다 **한 겹 더 바깥이고, 그래서 이 PC의 모든 클론에 걸린다.**

### ① 실측 — 클린 클론은 정말 전부 CRLF 다. 그런데 아무것도 안 죽었다

```
임시 디렉터리 클린 클론 (HEAD 6dc0a3e) → npm ci → npm run verify

클린 클론 working tree   CRLF 264 / 추적 264      ← 전부
현재 개발 working tree   CRLF  43 / 추적 264      ← 이미 섞여 있었다(텍스트 16 · 바이너리 27)
리포 안(blob)            LF                       ← 체크아웃 변환이 맞다. 리포 CRLF 문제 아님
                                                    (§안 하는 것이 가르라 한 둘 중 첫째다)

typecheck 통과 · smoke 452 · front 467 · 실패 0 · verify exit 0
★ 죽은 검사 = 0건        ← verify 뒤에도 264/264 CRLF 인 것을 다시 확인했다
```

### ① 짝 변이 — *왜* 안 죽었는가. 추측하지 않고 쟀다

CRLF 클론에서 **`\r` 걷기만** 지운다(`.replace(/\r\n/g, "\n")` 3곳 — front 1 · smoke 2):

```
smoke   452 · 실패 0        ← 안 죽는다. smoke 의 두 곳은 지금 떠받치는 검사가 없다
front   466 · 실패 1        ← ★ 정확히 하나. T-69 검사 4
        ✗ 4 ★ 발동 조건이 읽는 연속 값은 안 바뀐다 … 조건줄=false
```

★★ **답: T-69 가 고친 `t46Bare` 한 곳이 유일한 민감처였고, 나머지는 0 이다.**
함정 16 이 *"아직 몇인지 아무도 안 셌다"* 로 남긴 자리가 **이제 세어졌다 — 0 이다.**
그래서 **②도 ③도 필요 없다.** `.gitattributes` 를 고치는 것은 안 아픈 곳을 여는 것이고,
전 파일 diff 의 위험(§금지)만 남는다.

⚠️ **smoke 의 두 곳(`ktBare`·`ktCode`)은 지금 아무 검사도 안 떠받친다. 그래도 지우지 않는다** —
깊이 방어이고, 지우면 다음에 민감한 검사가 들어올 때 조용히 물린다.

### ⚠️ 조사 중 함정 17·18 이 실제로 두 번 일어났다 (이것이 이 티켓의 덤)

**셸 명령 치환 `$( )` 안에서 `$'\r'` 가 빈 패턴이 됐다.** 결과는 에러가 아니라 **그럴듯한 수**였다 —
`grep -cU $'\r' public/index.html` 이 `655` 를 냈는데 그것은 CR 줄 수가 아니라 **전체 줄 수**였고,
같은 이유로 첫 집계가 *"현재 워킹도 264/264 CRLF"* 라고 말했다(실제 43).
★ **가른 것은 스캐너에 물어야 하는 것 하나를 먹인 것이다** — 알려진 LF 파일에 0,
알려진 CRLF 파일에 2 가 나오는지. 패턴을 파일로 주자(`grep -f`) 둘 다 맞았다.
**막는 법은 함정 17 그대로다: 패턴을 파일로 쓰거나 스크립트 파일로 옮긴다**(변이도 `.mjs` 로 썼다).
