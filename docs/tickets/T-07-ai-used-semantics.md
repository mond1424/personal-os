# T-07 — `ai_used`는 "판정을 받았는가"가 아니라 "모델을 불렀는가"다

**발행** Cowork · 2026-07-31 · **담당** Claude Code (위임 금지 — Guard 발동 경로) · **상태** ✅ 구현 완료 · deploy 대기

---

## 목표

`verifyLevel4`가 돌려주는 `ai_used`를 **호출이 나갔는지** 기준으로 고친다.
지금은 `timeout`·제공자 응답 실패에서 `0`이 나가고, 그만큼 **일일 상한(ADR-024 ③)이 뚫린다.**

**왜** — T-04 구현 중 드러났다. 타임아웃은 **요청이 이미 나간 뒤**다. 돈은 나갔는데 안 세어진다.
8초 타임아웃이 반복되는 밤이면 상한이 사실상 없는 것이 된다. 상한이 지키려는 것은
**판정의 수가 아니라 지출**이므로, 세는 기준도 지출이 발생하는 지점이어야 한다.

## 기준

| 상황 | `source` | `ai_used` | 왜 |
|---|---|---|---|
| 킬 스위치 off | `off` | 0 | 호출 안 함 |
| 캐시 적중 | `cache` | 0 | 호출 안 함 |
| 상한 초과 | `cap` | 0 | 호출 **전에** 막았다 |
| 키 없음 | `error` | 0 | 호출 **전에** 막혔다 |
| 판정 받음 | `ai` | 1 | |
| **타임아웃** | `timeout` | **1** | **요청이 나갔다** |
| **제공자 응답 실패** | `error` | **1** | **요청이 나갔다** |
| 응답은 왔는데 JSON 파싱 실패 | `error` | 1 | 요청도 응답도 있었다 |

**가르는 선은 하나다: `callModel`에 들어갔는가.**
들어가기 전에 막힌 것은 0, 들어간 뒤 무슨 일이 나든 1이다.

`stay3()`가 모든 실패를 한 덩어리로 다루는 것이 원인이므로, **호출 전 실패와 호출 후 실패를
구분**해야 한다. 키 확인은 `callModel` 안에 있으니(`aiConfig.keyOf` → 503) 그 경계를 넘기 전에
직접 확인하는 편이 갈라 두기 쉽다 — 다만 **`ai.ts`의 시그니처는 바꾸지 않는다**(다른 소비처가 물린다).

## 범위

```
src/services/guard.ts   verifyLevel4 — 호출 전/후 실패를 가른다
test/smoke.ts           검사
```

`android/`·`src/lib/ai.ts`·마이그레이션은 건드리지 않는다.
**기기는 서버 값을 그대로 싣는 지금 방식이 맞다** — 상한의 근거가 한 곳이어야 한다(T-04 §최종 검토).

## 금지

| 하지 말 것 | 왜 |
|---|---|
| `callModel` 시그니처 변경 | 분석 경로가 물린다 |
| 기기에서 보정 | 근거가 둘이 되면 갈라진다 |
| `ai_verdict` 매핑 변경 | `timeout`·`error`는 `unavailable`이 맞다. **판정이 아니었던 것은 사실이다** — `ai_used`와 `ai_verdict`는 서로 다른 질문에 답한다 |
| 상한 초과를 1로 세는 것 | 호출 전에 막았다. 세면 상한이 스스로를 소모한다 |

## 완료 조건

```
typecheck 통과 · smoke 233 → 236 이상 · front 193(변화 없음) · 실패 0
```

검사에 들어가는 것 — **AI를 실제로 부르지 않고** 가른다:

1. 키 없음 → `source: "error"`, **`ai_used: 0`** (호출 전 실패)
2. 상한 초과 → `source: "cap"`, `ai_used: 0`, 그리고 **캐시는 여전히 이긴다**(기존 검사 유지)
3. 호출 후 실패가 **1로 센다** — 제공자 실패나 타임아웃을 흉내 낸 경로에서
   `ai_used: 1`이 나오는 것을 본다

**3번이 이 티켓의 전부다.** 1·2만 지키는 검사는 지금 코드로도 통과한다 —
**구현을 안 고쳐도 녹색인 검사는 이 티켓을 지키지 못한다**(§8).

## 구현 메모 (Claude Code · 07-31)

락은 04:58에 걸고 커밋 직전에 풀었다.

### 가르는 선을 `ApiError.status`로 그었다

티켓이 "`callModel`에 들어갔는가"를 기준으로 삼으라 했는데, **키 확인이 `callModel` 안에도 있다**
(`ai.ts` → 503). 그래서 catch에서 그 경계를 되짚는다:

```
503(키 없음)  → 요청이 나가지 않았다 → 0
그 밖         → 요청이 나갔다       → 1   (502 제공자 실패 · fetch 거절 · 타임아웃)
파싱 실패      → 요청도 응답도 있었다 → 1
```

키는 `callModel` **앞에서 이미 확인**하므로(그때는 `source:"error"` + 0) 503이 catch까지 오는 경우는
**그 사이에 키가 지워진 경우**뿐이다. 그때도 요청은 안 나갔으니 0이 맞다 — 좁은 경합이지만
`status`로 갈라 두면 추측이 필요 없다.

### 검사 — AI를 부르지 않고 `fetch`만 갈아 끼운다

`globalThis.fetch`를 세 가지로 바꿔 **호출 후 실패**를 만든다(네트워크 0):
제공자 500 → `ApiError(502)` · fetch 거절 → `TypeError` · 200인데 JSON 아님 → 파싱 실패.
셋 다 `ai_used: 1`. 그다음 키를 비워 **같은 경로가 0으로 돌아오는 것**까지 본다 — 그 대비가 이 티켓이다.

### 검사가 옛 구현에서 빨간불이 되는지 **직접 확인했다**

티켓 §완료 조건이 "구현을 안 고쳐도 녹색인 검사는 이 티켓을 지키지 못한다"고 못 박았으므로,
`stay3`를 옛 의미(`ai_used: 0` 고정)로 되돌려 놓고 돌렸다:

```
통과 234 · 실패 3
  ✗ 제공자 응답 실패 → ai_used 1 (요청이 나갔다)
  ✗ 네트워크 거절 → ai_used 1
  ✗ 파싱 실패 → ai_used 1 · 거부가 아니라 판정 불가
```

정확히 셋만 빨간불이고 나머지는 그대로다. 확인 후 원복했다.

### 검사 위치가 불변성에 걸려 있다

처음엔 상한 검사 **뒤에** 두고 `cap-uuid-%` 행을 지워 상한을 비우려 했는데,
`guard_events`는 **삭제가 트리거로 막혀 있다**("개입 이력은 영구 보존"). 그래서 T-07 블록을
**상한을 채우기 전으로** 옮겼다 — 한 번 채운 상한은 그 실행에서 되돌릴 수 없다.
smoke가 이걸 잡아 줬다(설계가 검사 순서를 강제한 셈이다).

### 검사하지 않은 것 하나 — 타임아웃

`timeout` 분기도 `ai_used: 1`이지만 **검사에 넣지 않았다.** `AI_TIMEOUT_MS`가 8초라
실제로 태우려면 매 smoke 실행에 8초가 붙는다. 상수를 검사용으로 빼는 것은 프로덕션 모양을
검사 편의로 바꾸는 것이라 하지 않았다.

그 분기는 다른 호출 후 실패들과 **같은 결정**(`stay3(..., 1)`)을 공유하고, 위 세 검사가 그 결정을
지키고 있다. 다만 **타임아웃만 별도로 회귀할 여지는 남는다** — 8초를 감수하거나 상수를 주입 가능하게
바꾸는 것이 대안이고, 그건 판단이 필요하므로 적어 둔다.

## 범위 밖 — `test/front.mjs` 날짜 검사 (CLAUDE.md 기준선 규칙)

verify를 돌리니 front가 **193 → 192 · 실패 1**이었다. 내 변경(서버 + smoke)과 무관한데,
숫자가 안 맞으면 원인을 찾기 전에 끝내지 않는다.

```
✗ 이번 달 마지막 날 활성 true
```

**검사가 자기모순이었다.** `dim(`${이번달}31`)`이라 오늘이 31일이면 그 날짜가 곧 오늘인데,
**바로 윗줄이 "오늘은 비활성(미루기는 내일부터)"을 확인한다.** 앱이 맞고 검사가 틀렸다.

게다가 이 검사는 **31일이 있는 달의 1~30일에만** 통과한다 — 30일까지인 달·2월이면
`2026-06-31` 같은 셀이 아예 없어 `dim()`이 `null`을 준다. 오늘 처음 물린 것뿐이고
7월에 시작한 프로젝트라 아직 다른 달을 안 지났다.

실제 말일을 계산하고 그게 오늘이면 내일(= 다음 달 1일)로 옮기게 고쳤다 — 어느 쪽이든
이 줄이 지키려던 **달 경계**다. `CLAUDE.md` 기준선 규칙("검사가 옛 동작을 검사하고 있으면
검사를 고치고 그 사실을 말한다") 그대로다. 티켓 범위 밖이지만 그 규칙은 이 층의 상시 규칙이다.
