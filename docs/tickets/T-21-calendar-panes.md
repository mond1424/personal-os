# T-21 — pane을 돌려 쓴다 (매번 다시 그리지 않는다)

**발행** Cowork · 2026-08-05 · **담당** Codex CLI · **상태** ⬜ 대기 · **선행 T-20 완료**

---

## 실측 — 진단이 틀렸다

```
T-20 전   왕복 990(콜드) · renderCalendar 526
T-20 후   캐시 적중 상태에서 renderCalendar 570
```

**캐시가 걸렸는데 줄지 않았다.** 왕복이 병목이라는 T-20의 진단은 틀렸다 —
콜드 왕복 990ms에 가려져 있었을 뿐, **처음부터 DOM 조립이 지배적**이었다.

T-20이 헛되지는 않았다. 왕복은 실제로 사라졌고(콜드 990ms가 안 나간다),
**그 덕에 남은 것이 무엇인지 보이게 됐다.**

## 무엇이 낭비인가

달을 넘길 때마다 **3-pane을 전부 다시 조립한다.** 126셀(3 × 42)이다.

```
8월 → 9월    8·9·10 세 pane을 새로 만든다
             그런데 8·9는 방금 만든 것과 같은 내용이다
```

**실제로 새로 필요한 것은 pane 하나다.**

---

## 방향 — 회전 + 5-pane

```
① pane을 버리지 않고 돌려 쓴다
     오른쪽으로 넘기면 맨 왼쪽 pane을 오른쪽 끝으로 옮기고 그것만 채운다
② pane을 5개로
     데이터가 이미 5달치다(T-20). 좌우 두 번씩은 채울 것도 없다
```

현재 달은 가운데(index 2)다. 트랙은 500%.

**`WEEKS_IN_GRID`(6주)는 건드리지 않는다** — 캐러셀 높이 고정의 전제다(함정 11).
**트랙 위치는 % `transform`** — 손가락분만 px(`clientWidth||380` 폴백). 함정 2.

### 셀 요소까지 재사용하지는 않는다

`innerHTML` 한 방으로 pane을 채우는 지금 방식을 유지한다.
**이번에 줄이는 것은 "몇 개의 pane을 조립하는가"다.** 3 → 1이면 그것만으로 1/3이다.

셀 요소를 들고 내용만 갈아끼우는 방식은 상태 관리가 붙고 그 상태가 새 버그 자리가 된다.
**회전 뒤에 다시 재서** 여전히 느리면 그때 판단한다.

---

## pane과 달의 대응 — **이 티켓의 덫**

회전은 인덱스 계산이다. 어긋나면 **8월 자리에 10월이 그려진다.**

그리고 그 실패는 **아무 오류도 내지 않는다.** 화면을 봐야만 드러나고,
날짜가 하나씩 밀려 있어도 눈으로는 잘 안 잡힌다.

```
넘긴 뒤 각 pane의 달이 맞는가
연속으로 세 번 넘겨도 맞는가        ← 여기서 어긋난다
캐시가 비워진 뒤 다시 그려도 맞는가
```

**연속 스와이프가 위험하다.** `calGen`이 요청 경합을 막지만 **회전은 DOM 상태를 바꾼다** —
중간에 버려진 조립이 pane 순서를 건드리면 그 뒤가 전부 밀린다.
`calGen`을 지우지 말고, **회전이 세대 검사 뒤에 일어나게** 둔다.

## 범위

```
public/app.js       pane 회전 · 5-pane · 트랙 위치
public/style.css    트랙 폭 (300% → 500%)
test/front.mjs      검사
```

**서버를 건드리지 않는다.** T-20의 캐시도 그대로 쓴다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| `WEEKS_IN_GRID` 변경 | 6주 고정이 높이의 전제다 — 함정 11 |
| 트랙 위치를 px로 | % `transform`이다. jsdom은 `clientWidth=0` — 함정 2 |
| `calGen` 제거·회전을 세대 검사 앞으로 | 버려진 조립이 pane 순서를 밀어 놓는다 |
| 셀 요소 단위 재사용 | 상태가 붙는다. 이번 범위가 아니다 |
| `scrollIntoView` | 함정 1. 위치는 `scrollTop`만 |
| `booted` 가드 제거 | 함정 4 |
| T-20의 캐시 무효화를 건드리기 | 별개다. 캐시가 비면 5-pane을 다시 채운다 |

## 완료 조건

```
typecheck 통과 · smoke 268(변화 없음) · front 238 → 244 이상 · 실패 0
```

검사:

1. pane이 5개다
2. 한 칸 넘기면 **새로 조립되는 pane이 1개다** (3개가 아니다)
3. **오른쪽으로 세 번 연속 넘겨도 각 pane의 달이 맞다**
4. **왼쪽으로 세 번 연속 넘겨도 각 pane의 달이 맞다**
5. 캐시가 비워진 뒤 다시 그려도 pane과 달이 맞다
6. 현재 달이 가운데 pane이다

**3·4번이 이 티켓의 덫이고, 둘 다 있어야 한다.** 한 번만 넘기는 검사로는 나머지가 다 통과하고,
**연속 스와이프에서만 어긋난다.**

그리고 **한 방향만 검사하면 반대쪽이 우연히 맞는 것과 구별되지 않는다** —
오른쪽 인덱스를 틀린 변이는 잡히는데 왼쪽 변이는 통과해 버린다.
회전은 좌우가 대칭이므로 **양쪽을 각각 태운다.**
