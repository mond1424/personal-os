## 할 일

### ① 먼저 확인한다

```

□ 과목명 자르기(app.js courseOf)를 서버에서도 해야 하는가 — 하면 두 벌이 되는가
```

### ② 재촉 시각 계산 — 서버

**대상:** 수락된 수집 과제 중, 할 일이 **완료·취소되지 않았고**, 연결된 일정의 마감이 **아직 안 지난** 것.
⚠️ **잇는 칸(`collected_items.event_id`·`task_id`)으로 찾는다.** 제목으로 찾지 않는다.

**마감은 일정(event)의 시각이다** — 할 일의 예정일이 아니다.
⚠️ **T-84 의 "예정을 앞당긴 과제"** 가 바로 그 경우다 — 예정을 옮겨도 마감은 그대로다.

**점 넷 (ADR-050 ②):**

```
전날 저녁      마감 귀속일의 전날, 설정 "저녁" 시각
당일 아침      마감 귀속일, 설정 "아침" 시각
마감 3시간 전
마감 1시간 전
```

**처음 기본값: 저녁 21:00 · 아침 09:00** (사용자가 바꿀 수 있다 — 이후로는 설정이 원본이고,
이 줄을 근거로 쓰지 않는다).

★ **"전날" 과 "당일" 은 달력 날짜가 아니라 귀속일로 센다** — 하루 경계를 넘는 마감(예: 새벽 1시)이
사용자 머릿속에서는 그 전날의 일이다. 달력 날짜로 세면 "당일 아침" 이 마감 뒤로 가서 사라진다.
⚠️ **하루 경계는 설정값이다** — `guard/schedule` 의 `boundary` 를 쓴다. 상수로 박지 마라.

**정리 규칙 셋:**

```
요청 시점에 이미 지난 점       뺀다
두 점이 1시간 안              늦은 쪽 하나만
같은 시각의 과제 여럿          한 묶음으로 싣는다
```

**싣는 모양** — `/api/guard/schedule` 에 새 키 하나:

```
시각 · 마감 시각 · 묶음 [ 과목 · 과제 이름 · task_id ]
```

★★ **"마감까지 N시간" 은 서버가 안 만든다** — 기기가 울리는 순간 `now` 와의 차로 만든다.
ADR-047 이 정한 그대로다(서버가 문장을 굳히면 저녁 6시 기준 문장이 새벽에 나간다).
⚠️ **기존 키(`events · boundary · mode · friction_mult · wake`)는 한 글자도 안 바꾼다.**

### ③ 웹 — 재촉 시각이 바뀌면 기기를 깨운다

```
수락 · 완료 · 취소 · 삭제 뒤   →  재촉 시각이 바뀌었으면 Guard.sync()
```

★ **바뀌었는지는 서버가 응답으로 알려 준다** — 웹이 추측하지 않는다(어느 할 일이 수집분인지 웹은 모른다).
⚠️ **Guard 플러그인이 없는 환경(브라우저)에서는 조용히 건너뛴다.**
⚠️ **`sync()` 는 무겁다**(발동 기록 · 폰 캘린더 · 예약 pull · 재예약 넷을 다 한다) — 재촉과 무관한
동작에서는 부르지 마라. **수락은 항상 바뀐다.**

### 한 것

- **`services/nudge.ts`(신설)** — `nudges(env, t, days, taskId?)` · `hasNudges(env, t, taskId)`. 점 넷 · 정리 규칙 셋 · 묶음.
  **아무것도 저장하지 않고 `guard_events` 를 안 읽고 안 쓴다.** "마감까지 N시간" 은 안 만든다 — `due` 만 싣는다.
- **`db.nudgeTargets`** — 수락한 수집 과제 · `v_task_stats.state='not_finished'` · 일정에 시각 · `e.date` 창.
  ★ **`schedule_entries` 를 아예 안 읽는다** — 마감은 일정의 시각이다(금지 3행). ⚠️ **할 일당 한 줄**(`MIN(c2.id)`) —
  `collected_items.task_id` 엔 UNIQUE 가 없어(T-84 3 이 셀에서 잰 그 자리) 그냥 JOIN 하면 **같은 알림이 두 번** 울린다.
- **`guard.schedule`** — `nudges` 키 하나를 **끝에 더했다.** 위의 키는 한 글자도 안 바꿨다.
  ⚠️ **`events[].fires[]` 에 섞지 않았다** — 그 길은 `AlarmReceiver → fire()` 라 밤 개입으로 기록·계수된다(사실 넷 ③).
- **`nudge_changed`** — `collected.accept`(잇고 난 뒤) · `tasks.completeTask`·`cancelTask`(바꾸기 전) ·
  `uncancelTask`(바꾼 뒤 · 라우트가 `t` 를 넘기게 했다) · `me.putSetting`(재촉 키 둘만).
  ★ **판정은 `hasNudges` 하나** — 재촉 계산을 그대로 쓴다. *"수집분이면 참"* 으로 따로 짜면 마감이 지났거나
  창 밖이라 실린 적 없는 과제에서도 무거운 `sync()` 가 돈다.
- **`api.js _req`** — 응답에 `nudge_changed: true` 가 있으면 `Guard.sync()` 를 부른다(기다리지 않는다 · 플러그인 없으면 지나간다).
  ★ **자리는 `_req` 하나다** — 완료만 호출부가 넷이다. T-57 이 상한을 거기 둔 것과 같은 판단이다.
- **`app.js`** — `courseOf` 를 지우고 `r.course` 를 쓴다 · 설정 두 줄(라벨 · 설명 · 시트 머리).
  설명의 예시 시각은 **기본값이 아닌 값**으로 적었다(예시가 기본값이면 화면이 기본값을 말하는 것이 된다).
- `STATE.md` T-74 의 라이브 확인(`grep -c "courseOf"`)에 ⚠️ 를 달았다 — **T-87 배포 뒤엔 `0` 이 정상**이라
  그대로 두면 *"T-74 가 안 올라갔다"* 로 읽힌다.

- **재촉 설정 저장** — 바꾼 시각이 기기에 내일 아침에야 간다.

**안 한 것 — Cowork 자리:**
1. ⚠️⚠️ **삭제 — 수집에서 온 할 일은 이미 지울 수 없다.** `collected_items.task_id` 가 FK 로 참조해 **409**
   (*"다른 기록이 참조하고 있어 지울 수 없어요"* · `suggest` 없음). 일회 스크립트로 실측했다(수락 → 삭제 → 409).
   T-78 부터 그랬다. **ADR-050 ⑤ 의 *"할 일 취소·삭제 → 재촉 취소"* 중 삭제는 지금 일어날 수 없다** — 취소만 된다.
   그래서 `deleteTask` 엔 `nudge_changed` 를 안 달았다(참이 될 수 없는 깃발은 검사도 못 한다).
   검사 6 은 **취소**만 잰다. ★ 고치려면 *삭제가 잇는 칸을 비울 것인가* 를 정해야 한다 — T-78 이 NULL `task_id` 에
   *"이미 했어요"* 라는 뜻을 실어 두어서 **비우면 그 뜻과 섞인다.** 설계 질문이라 손대지 않았다.
2. **마감 일정의 날짜·시각을 고쳐도 안 깨운다** — `events.ts` 는 범위 밖이었다. 하루 동기화가 그물이다.
3. **하루 경계·오프셋을 바꿔도 안 깨운다** — 귀속일이 움직이면 전날·당일이 바뀐다. 드물고, 하루 동기화가 그물이다.

### ⚠️ 해석·고른 것 다섯

- **"두 점이 1시간 안" 은 경계 포함(≤ 1시간)으로 짰다.** 정각 1시간 간격의 두 알림도 잔소리로 들리는 거리라서다.
  ADR 의 예(10:00 마감의 아침 · 1시간 전 — 둘 다 09:00)는 어느 쪽이든 같다. **검사 3 은 30분 거리만 잰다** —
  정각 1시간은 검사가 안 정한다. Cowork 가 미만으로 정하면 `MERGE_MS` 비교 하나다.
- **"마감 시각" 은 묶음이 아니라 항목에 실었다** — 티켓의 모양은 `시각 · 마감 시각 · 묶음[…]` 인데,
  같은 시각에 묶인 과제들의 마감이 다를 수 있다(전날 저녁 21:00 에 *내일 10:00 마감* 과 *내일 23:59 마감* 이 함께 온다).
  묶음에 하나만 실으면 하나는 거짓이 된다. 모양: `{at, items:[{task_id, course, title, due}]}`.
- **이름은 할 일의 제목**(`tasks.title`)이다 — 일정의 제목이 아니다. [완료] 가 끄는 것이 그 할 일이라서,
  알림이 부르는 이름과 누르면 끝나는 것이 같아야 한다. 둘 다 `titleOf` 로 만들어져 처음엔 같다.
- **시각 없는(종일) 일정은 대상이 아니다** — *"3시간 전"* 이 없다. 수락이 만든 일정엔 늘 시각이 있고, 사용자가 종일로 고친 것만 빠진다.
- **마감 이후의 점은 뺀다** — ADR 의 정리 규칙 셋엔 없지만 ⑤ *"사후 재촉은 없다"* 에서 나온다(예: 07:00 마감의 *당일 아침*).
