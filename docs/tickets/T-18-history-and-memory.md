## 1부 — Me 변경 이력 축약

### 방향

```
최근 5건 표시  →  [더 보기]  →  전부
```

- **개수를 말한다.** `[더 보기]`만 있으면 얼마나 더 있는지 모른다 — `[더 보기 (23건)]`
- **5건 이하면 `[더 보기]`가 없다.** 눌러도 아무 일 없는 버튼을 두지 않는다
- 접은 상태가 기본. 펼친 뒤 다시 접을 수 있는지는 **선택** — 없어도 된다

### 넘치지 않게

**이력을 지우거나 자르지 않는다.** 축약은 표시의 문제다.
펼치면 서버가 준 전부가 나와야 한다.

`scrollIntoView` 금지 — 함정 1. 펼칠 때 위치를 잡고 싶어지는 자리다.
필요하면 `scrollTop`만.

## 2부 — Guard 메모리 조회

### 무엇을 보여주나

`Api.guardEvents()`가 이미 있다. **읽기 전용 목록 하나.**

개입 하나가 한 줄이고, 그 줄이 답해야 하는 것:

```
언제 · 몇 단계 · 왜 떴나 · 내가 뭘 했나 · 그래서 어떻게 됐나
fired_at   level   cause    reaction    outcome
```

`reaction = "override"`면 사유(`override_reason`)와 분류(`override_class`)를 함께.
**그것이 이 화면의 값어치다** — 내가 어떤 이유로 빠져나갔는지가 §6.5의 재료다.

### null의 뜻이 서로 다르다

```
reaction = null   아직 반응이 없다 (무반응 유예 중일 수 있다)
outcome  = null   반응은 했고 결과가 아직 안 정해졌다
```

**둘을 같은 "—"로 뭉치지 않는다.** 뭉치면 "무시했다"와 "아직 모른다"가 구별되지 않는다.

### 시각을 다시 계산하지 않는다

`fired_at`은 **서버가 이미 로컬 오프셋으로 정규화해서 준다**(`normalizeIso`).
프런트가 다시 만지면 어긋난다 — T-16에서 귀속일을 서버에 맡긴 것과 같은 이유.

### 빈 상태

이력 0건이면 **"아직 없음"을 명시한다.** 지금 실제로 몇 건뿐이라 이게 초기 화면이다.
아무것도 안 나오면 "없는 것"과 "안 불러온 것"이 구분되지 않는다 — T-16과 같다.

## cause 를 사람의 말로 — **이 티켓의 덫**

`cause`는 **열거형이 아니라 자유 문자열**이다. 서버는 `typeof === "string"`만 본다.
지금 코드에 있는 것만 해도:

```
watch:bedtime        recheck:accepted     protect
protect:deadline     protect:sleep-deadline    diagnostic
```

`접두사:세부` 구조이고 **세부는 계속 는다.**

그러므로 **전체 문자열 표를 만들면 안 된다.** `protect:deadline`을 넣고
`protect:sleep-deadline`을 빠뜨리면 그 줄만 빈칸이 된다.

```
① 접두사로 가른다      watch: 감지 · protect: 보호 규칙 · recheck: 재확인
② 접두사를 모르면      원문을 그대로 보여준다. 빈칸으로 두지 않는다
```

`diagnostic`처럼 콜론이 없는 것도 ②로 떨어진다 — 그래도 화면에 글자가 남는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| Guard 이력에 쓰기·삭제·수정 경로 | **개입 이력은 고칠 수 없다.** 트리거가 사후 필드를 한 번만 허용한다(0010) |
| `cause` 전체 문자열 표 | 세부가 늘면 빈칸이 된다. 접두사로 가른다 |

| `fired_at` 재계산·재파싱 | 서버가 정규화해서 준다 |

| 짧고 일반적인 새 클래스명 | 전역 충돌 **세 번**. 접두사(`.gmem-…` · `.hist-…`) |
