# T-48 — 홈에서 오늘을 찍는다

**발행** Cowork · 2026-08-26 · **담당** Claude Code · **큼**
**근거** [ADR-043](../../APP-ADR.md#adr-043) · **APK 필요 · 서버 무변경 · 마이그레이션 없음**

---

## 무엇을 만드나

**크기를 늘리면 찍을 것이 느는 위젯 하나.**

```
최소   energy · stress · focus              ●●●○○  5칸 (2·4·6·8·10)
중간   위 + ★ 요약 한 줄 + daily score
최대   위 + [ 로그 쓰기 ]                   딥링크 (앱의 로그 입력창)
```

**T-46의 "+" 위젯은 그대로 둔다.** 별개의 위젯이고, 어느 쪽이 눌리는지가 그 자체로 답이다.

## ★ 상한 — 여기서 멈춘다

```
✅  세 지표 + score 찍기 · 요약 한 줄 · 로그 딥링크 · 크기 3단계
❌  위젯 안에서 로그 타이핑        ← RemoteViews 에 EditText 가 없다. Android 가 안 준다
❌  /api/widget/* 신설            ← 화면이 쓰는 API 가 그대로 맞다
❌  오늘 할 일 목록·캘린더 그리기  ← 이 위젯은 '찍는' 물건이다
❌  잘못 누른 값 되돌리는 UI       ← 오조작이 실제로 잦은지 먼저 안다(ADR-043 §재검토)
```

## 할 일

### ① 인프라 — 이미 있는 것을 쓴다

| 필요한 것 | 어디에 |
|---|---|
| `baseUrl` · `token` | **`GuardSync`**(SharedPreferences). 웹이 `configure`로 넣는다 |
| feelings 쓰기 | `PUT /api/daily/feelings` — `{ values: { energy, stress, focus } }` |
| score 쓰기 | `PUT /api/daily/score` — `{ score }` |
| 로그 | 앱 딥링크 (T-46의 `personalos://` 대장에 한 줄) |

⚠️ **`GuardSync`를 읽기만 한다.** `guard/` 아래는 발동 경로이고 위임 금지 영역이다 —
**값을 꺼내 쓰는 것과 그 파일을 고치는 것은 다르다.** 고쳐야 할 것 같으면 멈추고 보고하라.

⚠️ **네트워크 코드를 새로 짜기 전에 `GuardEventQueue.flush()`를 본다.**
타임아웃·재시도·`Authorization` 헤더의 모양이 이미 거기 있고, **T-37이 read를 12초로 늘린 이유**도 거기 있다.

### ② 크기 3단계 — `minSdk = 24`

⚠️ **`RemoteViews(Map<SizeF,…>)`는 API 31+라 못 쓴다.**

```
레이아웃 하나에 세 블록  →  onAppWidgetOptionsChanged 에서 setViewVisibility
```

`OPTION_APPWIDGET_MIN_HEIGHT`(+ `MIN_WIDTH`)를 읽어 가른다.
**임계 dp 는 담당이 실기기에서 재서 정한다** — 여기 숫자를 적지 않는다(기준선과 같은 이유).

`resizeMode="horizontal|vertical"` · `minResizeWidth/Height` · `maxResizeWidth/Height`를 메타에 둔다.

### ③ ★ 요약과 score 는 함께 켜지고 함께 꺼진다

**한쪽만 있는 상태를 만들지 않는다.** score 만 보이면 **빈 칸에 점수를 매기는 그 모양**이고,
ADR-040이 사흘 전에 고친 자리다(ADR-043 §결정 ②).

문구는 **T-44·T-45의 `closeSummaryText`와 같은 문장**이어야 한다.
⚠️ **그 함수를 Kotlin 으로 옮겨 적지 마라 — 두 벌이 되고 갈라진다.**
서버가 이미 주는 재료(`GET /api/today`)로 **문장을 만드는 곳을 한 곳으로** 정하고,
어디로 정했든 **보고에 그 판단을 적어라.** (앱과 위젯이 같은 문장을 말하는지가 검사다.)

### ④ ★ 찍힌 것처럼 보이고 안 찍히면 안 된다 — 이 티켓의 핵심

**위젯은 토스트를 못 띄운다.**

```
성공   칠한 칸이 유지된다
실패   칠한 칸이 되돌아오고 · 그 사실이 위젯에 남는다
```

거부는 상상이 아니다 — **마감된 날에는 `feelings_frozen_ins`가 추가를 막아 409가 온다.**
**그 하루의 마지막 탭이 조용히 사라지는 것이 이 위젯의 가장 흔한 실패다.**

T-38(`none` vs `error`) · T-39 · T-40 · T-43(`0건` vs 로그인 HTML)이 **네 번** 같은 모양에 물렸다.

### ⑤ 두 곳이 같은 값을 그린다

```
앱에서 찍었다  →  위젯이 따라온다
위젯에서 찍었다 →  앱이 따라온다 (앱을 열면 최신이다)
하루 경계 06:00 →  위젯이 스스로 비워진다
```

⚠️ **경계 시각을 코드에 적지 마라.** `GET /api/guard/schedule`의 `boundary`가 준다
(`05:00`이라 적혀 있었는데 실제로는 `06:00`이었던 전례가 있다).

## 범위

```
android/.../widget/ScaleWidget.kt (신규) · res/xml · res/layout · res/values*/
android/app/src/main/AndroidManifest.xml   receiver 하나 더
public/app.js                              로그 딥링크 액션 · 위젯 갱신 알림
test/front.mjs · test/smoke.ts             검사
```

**서버 무변경 · 마이그레이션 없음.**

⚠️ **`guard/` 아래 파일을 고치지 않는다**(읽기만). **`AddTaskWidget`도 안 고친다** — 별개 위젯이다.

**Codex 위임 가능** — 다만 **`AndroidManifest.xml`·`GuardSync` 사용부·④의 실패 경로는 직접** 한다.
T-46이 *"갈라 넘기면 경계가 한 파일 안을 지나간다"*고 배운 자리다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 요약 없이 score 만 켜기 | **ADR-040을 되돌린다.** ③이 이 티켓의 설계 조건 |
| feelings 에 요약 붙이기 | 지금 몸 상태다. **매기기 전에 판단을 심지 않는다**(T-44와 같은 방향) |
| `closeSummaryText` 를 Kotlin 에 옮겨 적기 | 두 벌이 된다 — 금지어 목록·기준선에서 세운 규칙 |
| 낙관적 칠하기만 하고 실패를 안 되돌리기 | **찍은 줄 알고 넘어간다.** ④가 핵심 |
| `/api/widget/*` 신설 | 화면이 쓰는 API 가 맞다 |
| 위젯 안 텍스트 입력 시도 | `RemoteViews`에 `EditText`가 없다 |
| `guard/` 아래 고치기 | 발동 경로 · 위임 금지 영역. **읽기만** |
| `RemoteViews(Map<SizeF,…>)` | API 31+. `minSdk = 24`다 |
| 하루 경계 시각을 코드에 적기 | 설정값이다. `guard/schedule`의 `boundary`가 준다 |
| 임계 dp 를 티켓에서 받아 적기 | **실기기에서 재라.** 여기 숫자는 없다 |

## 완료 조건

```
typecheck 통과 · smoke 365(변화 없음 예상) · front 334 → 340 이상 · 실패 0 · verify exit 0
Kotlin: assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

**검사**

```
1  다섯 칸이 2·4·6·8·10 을 보낸다 (PUT 본문을 실제로 본다)
2  ★ 서버가 409 를 주면 칠한 칸이 되돌아온다                  ← ④. 마감된 날
3  ★ 2의 되돌림이 위젯에 남는가 (조용하지 않은가)             ← 2의 짝
4  크기 3단계가 각각 무엇을 켜는가
5  ★ score 가 켜진 단계에는 요약도 켜져 있다 (한쪽만인 단계가 0) ← ③. 없는 것을 세는 검사
6  ★ feelings 단계에는 요약이 꺼져 있다                       ← 5의 짝
7  위젯 문장과 앱 문장이 같다                                 ← 두 벌이 아닌가
8  ★ 하루 경계를 넘으면 위젯이 비워진다 (boundary 를 물어서)
9  ★ 크기 분기가 던져도 위젯이 빈 화면이 되지 않는다          ← 성공처럼 보이는 실패
10 ★ 9의 스캐너/검사가 살아 있는가
```

**2와 3이 짝이다.** 1·4만 보면 *"실패해도 칠한 채로 두는 구현"*과
*"되돌리긴 하는데 아무 표시가 없는 구현"*이 둘 다 통과한다 —
T-33·T-38·T-39·T-41·T-43·T-44·T-45·T-46·T-47에서 **아홉 번** 물린 자리다.

**5와 6도 짝이다.** 5만 보면 *"모든 단계에 요약을 켜는 구현"*이 통과한다.

⚠️ **Kotlin 쪽은 jsdom 이 못 본다.** 4·9는 스캐너 성격이고, **진짜 판정은 실측이다**(T-40이 배운 것).
**무엇을 검사로 세우고 무엇을 실측에 남겼는지 보고에 적어라.**

**변이**
- 409 때 칠한 채로 둔다 → **2만** 죽는다
- 되돌리되 표시를 안 한다 → **3만** 죽는다
- 요약을 모든 단계에 켠다 → **6만** 죽는다
- 요약을 어느 단계에도 안 켠다 → **5만** 죽는다
- 문장을 Kotlin 에 복제하고 한 글자 바꾼다 → **7만** 죽는다
- 경계를 `05:00`으로 박는다 → **8만** 죽는다
- 크기 분기에서 `try/catch` 를 뗀다 → **9만** 죽는다
- 그 검사를 눈멀게 한다 → **9는 초록 · 10만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

```powershell
adb -s <폰IP>:5555 install -r android\app\build\outputs\apk\release\app-release.apk
```

```
□ 위젯을 놓고 작게 → energy·stress·focus 세 줄만 있다
□ 늘리면 → 요약 한 줄과 score 가 함께 나타난다      ← 한쪽만 나오면 결함이다
□ 더 늘리면 → 로그 쓰기 버튼. 누르면 앱의 입력창
□ 칸을 눌러 찍고, 앱을 열어 같은 값이 있는지
□ ★ 마감한 뒤에 위젯에서 찍어 본다 — 칠했다가 되돌아오고, 그 사실이 보이는가
□ 다크모드에서 보이는가
```

**★ 그리고 한 주 동안 위젯으로 몇 번 찍었는지 세어 달라** — 앱에서 찍은 것과 나눠서.
그 둘의 비가 ADR-043의 재검토 트리거다. **거의 앱이면 접근성이 원인이 아니었다는 뜻이고,
그때는 위젯 계열 전체를 접는 것도 후보가 된다.**
