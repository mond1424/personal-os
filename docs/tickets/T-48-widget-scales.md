# T-48 — 홈에서 오늘을 찍는다

**발행** Cowork · 2026-08-26 · **담당** Claude Code · **큼**
**근거** [ADR-043](../../APP-ADR.md#adr-043) · **APK 필요 · 서버 무변경 · 마이그레이션 없음**

---

## 무엇을 만드나

**크기를 늘리면 찍을 것이 느는 위젯 하나.**

```
최소   energy · stress · focus              ●●●○○  5칸 (2·4·6·8·10)
중간   위 + ★ 요약 한 줄 + daily score
최대   위 + [ 로그 쓰기 ]                   딥링크 (앱의 로그 입력창)
```

**T-46의 "+" 위젯은 그대로 둔다.** 별개의 위젯이고, 어느 쪽이 눌리는지가 그 자체로 답이다.

## ★ 상한 — 여기서 멈춘다

```
✅  세 지표 + score 찍기 · 요약 한 줄 · 로그 딥링크 · 크기 3단계
❌  위젯 안에서 로그 타이핑        ← RemoteViews 에 EditText 가 없다. Android 가 안 준다
❌  /api/widget/* 신설            ← 화면이 쓰는 API 가 그대로 맞다
❌  오늘 할 일 목록·캘린더 그리기  ← 이 위젯은 '찍는' 물건이다
❌  잘못 누른 값 되돌리는 UI       ← 오조작이 실제로 잦은지 먼저 안다(ADR-043 §재검토)
```

## 할 일

### ① 인프라 — 이미 있는 것을 쓴다

| 필요한 것 | 어디에 |
|---|---|
| `baseUrl` · `token` | **`GuardSync`**(SharedPreferences). 웹이 `configure`로 넣는다 |
| feelings 쓰기 | `PUT /api/daily/feelings` — `{ values: { energy, stress, focus } }` |
| score 쓰기 | `PUT /api/daily/score` — `{ score }` |
| 로그 | 앱 딥링크 (T-46의 `personalos://` 대장에 한 줄) |

⚠️ **`GuardSync`를 읽기만 한다.** `guard/` 아래는 발동 경로이고 위임 금지 영역이다 —
**값을 꺼내 쓰는 것과 그 파일을 고치는 것은 다르다.** 고쳐야 할 것 같으면 멈추고 보고하라.

⚠️ **네트워크 코드를 새로 짜기 전에 `GuardEventQueue.flush()`를 본다.**
타임아웃·재시도·`Authorization` 헤더의 모양이 이미 거기 있고, **T-37이 read를 12초로 늘린 이유**도 거기 있다.

### ② 크기 3단계 — `minSdk = 24`

⚠️ **`RemoteViews(Map<SizeF,…>)`는 API 31+라 못 쓴다.**

```
레이아웃 하나에 세 블록  →  onAppWidgetOptionsChanged 에서 setViewVisibility
```

`OPTION_APPWIDGET_MIN_HEIGHT`(+ `MIN_WIDTH`)를 읽어 가른다.
**임계 dp 는 담당이 실기기에서 재서 정한다** — 여기 숫자를 적지 않는다(기준선과 같은 이유).

`resizeMode="horizontal|vertical"` · `minResizeWidth/Height` · `maxResizeWidth/Height`를 메타에 둔다.

### ③ ★ 요약과 score 는 함께 켜지고 함께 꺼진다

**한쪽만 있는 상태를 만들지 않는다.** score 만 보이면 **빈 칸에 점수를 매기는 그 모양**이고,
ADR-040이 사흘 전에 고친 자리다(ADR-043 §결정 ②).

문구는 **T-44·T-45의 `closeSummaryText`와 같은 문장**이어야 한다.
⚠️ **그 함수를 Kotlin 으로 옮겨 적지 마라 — 두 벌이 되고 갈라진다.**
서버가 이미 주는 재료(`GET /api/today`)로 **문장을 만드는 곳을 한 곳으로** 정하고,
어디로 정했든 **보고에 그 판단을 적어라.** (앱과 위젯이 같은 문장을 말하는지가 검사다.)

### ④ ★ 찍힌 것처럼 보이고 안 찍히면 안 된다 — 이 티켓의 핵심

**위젯은 토스트를 못 띄운다.**

```
성공   칠한 칸이 유지된다
실패   칠한 칸이 되돌아오고 · 그 사실이 위젯에 남는다
```

거부는 상상이 아니다 — **마감된 날에는 `feelings_frozen_ins`가 추가를 막아 409가 온다.**
**그 하루의 마지막 탭이 조용히 사라지는 것이 이 위젯의 가장 흔한 실패다.**

T-38(`none` vs `error`) · T-39 · T-40 · T-43(`0건` vs 로그인 HTML)이 **네 번** 같은 모양에 물렸다.

### ⑤ 두 곳이 같은 값을 그린다

```
앱에서 찍었다  →  위젯이 따라온다
위젯에서 찍었다 →  앱이 따라온다 (앱을 열면 최신이다)
하루 경계 06:00 →  위젯이 스스로 비워진다
```

⚠️ **경계 시각을 코드에 적지 마라.** `GET /api/guard/schedule`의 `boundary`가 준다
(`05:00`이라 적혀 있었는데 실제로는 `06:00`이었던 전례가 있다).

T-46이 *"갈라 넘기면 경계가 한 파일 안을 지나간다"*고 배운 자리다.

### 숫자 — smoke가 365에서 안 멈춘 이유

**의도한 +5다.** 검사 ①("PUT 본문을 실제로 본다")과 그 짝 ②의 서버 쪽을 smoke에 뒀다:
front는 **열린 날을 만들 수 없다**(T-44 절이 이미 오늘을 마감해 둔 뒤에 이 블록이 온다).
smoke에는 마감 전과 후가 한 파일에 순서대로 있어서 **같은 본문이 200과 409를 받는 것**을
한 자리에서 잴 수 있다. 그리고 `PUT /api/daily/feelings`의 **마감 후 409는 원래 검사가 없었다** —
`score`만 있었다(옛 155행). 이 위젯의 가장 흔한 실패가 바로 그 경로다.

### 크기 임계 dp — 무엇으로 정했나 · 어떻게 쟀나

⚠️ **실기기에서 재지 않았다. 못 쟀다** — 이 층에 폰이 없다. **감추지 않고 나눠 적는다.**

대신 **숫자를 아무 데도 안 적었다.** `ScaleStore.tierFor`는 `res/values/widget_scale_dims.xml`의
`h_base + h_close + h_log`를 `getDimension`으로 읽어 더한다. 그 셋은 다시 레이아웃이 쓰는
`pad · line · row`의 합이고, **front ⑥이 그 합을 검사한다** — 블록을 키우면 임계가 따라 움직인다.
즉 임계는 *"런처가 몇 칸을 주는가"* 가 아니라 *"이 블록이 그려지려면 몇 dp가 필요한가"* 다.

**실측은 §확인 절차의 셋으로 남겼다.** 값이 필요하면 이것이 실제 dp를 말한다:

```powershell
adb shell dumpsys appwidget | findstr /C:"ScaleWidget" /C:"minHeight" /C:"maxHeight"
```

작게 놨는데 요약이 이미 보이거나, 크게 늘려도 로그 버튼이 안 나오면 **그 숫자를 알려 달라** —
고칠 곳은 `widget_scale_dims.xml` 한 파일이고 Kotlin은 그대로다.

### 요약 문장을 어디서 만드나

**`public/app.js`의 `closeSummaryText` 한 곳.** 위젯은 만들지 않고 **받는다.**

서버 무변경이 조건이고 Kotlin 복제가 금지이므로 남는 선택지는 하나였다 —
**웹이 만든 문자열을 네이티브로 건넨다.** 그래서 다리(`widget/WidgetPlugin.kt`)를 하나 세웠다:
`renderToday()`가 끝날 때마다 `{date, boundary, summary, values, score}`를 밀어 넣는다.

그 결과가 이 티켓에서 가장 큰 판단이다 — **위젯이 `GET /api/today`를 아예 안 부른다.**
값·경계·문장이 전부 그 push에 실려 오므로 왕복도 배터리도 안 늘고, 위젯이 서버에 쓰는 것은
**탭 하나뿐**이다. 대가는 **앱을 한 번도 안 연 기기에서는 눈금이 비어 있다**는 것이고,
그때 요약 자리에는 `앱을 한 번 열면 오늘 요약이 와요`가 뜬다(빈 칸이 아니다).

검사는 **살아 있는 함수로** 본다: `pushWidget()`이 실제로 보내는 `summary`가
`closeSummaryText(S.today)`와 같은 글자인지(front ①), 그리고 그 문장의 조각이
Kotlin·`strings.xml` 어디에도 없는지(front ②). 뒤쪽이 없으면 *"건네주면서 복제도 해 둔"* 구현이 통과한다.

### 409 때 무엇이 되돌아오고 무엇이 남나

```
탭      pending[field] = 값        → 즉시 칠한다 (손가락은 왕복을 안 기다린다)
2xx     commit  — 확정으로 옮긴다
그 밖   reject  — pending 을 지우고(칠한 것이 되돌아온다)
                 notice 를 남긴다("마감된 날이라 안 들어갔어요")
```

**되돌림과 표시가 `ScaleStore.reject` 한 함수 안**이다. 나누면 한쪽만 지우기가 쉬워지고,
그때 생기는 것이 티켓이 말한 *"되돌리긴 하는데 아무 표시가 없는 구현"* 이다.
거부 표시는 **어느 크기 단계에도 속하지 않는다** — feelings만 있는 최소 크기에서 찍은 탭이
가장 자주 되돌아오는데 거기서 안 보이면 이 티켓이 없앤 실패가 그대로 남는다.

⚠️ **마감된 날에 실제로 눌러 보지는 못했다**(폰이 없다). 확인한 것은 둘로 나뉜다:
- **서버가 정말 거부한다** — smoke가 위젯 상수로 조립한 그 본문을 마감된 날에 쏘아 **409를 받았다**(실측).
- **위젯이 되돌린다** — front ④·⑤의 스캐너 + §확인 절차의 다섯째 줄.

`goAsync()`로 브로드캐스트를 붙잡아 왕복을 기다린다. 안 붙잡으면 `onReceive`가 끝나는 순간
프로세스가 회수 대상이 되고 **되돌림이 화면에 닿기 전에 죽는다** — 그게 정확히 이 티켓이 없애려는
"조용히 사라지는 탭"이다. 타임아웃은 **`GuardEventQueue`의 10초보다 짧은 5+5초**로 잡았다:
저기는 `Thread` 위의 flush라 여유가 있고, T-37이 `GuardVerify`의 read를 12초로 늘린 것은
**개입 판정**이 그만큼 기다려도 되기 때문이다. 손가락이 기다리는 이 경로는 반대다 —
되돌림이 늦게 오는 것은 안 오는 것과 비슷하게 나쁘다.

### GuardSync 를 읽기만 했는가

**그렇다. `guard/` 아래 파일은 한 글자도 안 고쳤다**(`git diff --stat`에 없다).
쓴 것은 `GuardSync.baseUrl(ctx)`·`GuardSync.token(ctx)` 둘뿐이고, 위젯 자신의 상태는
**별도 SharedPreferences(`widget_scale`)** 에 둔다 — guard의 prefs에 쓰지 않는다.

### 경계를 어디서 받아 오나

**`GET /api/today`의 `boundary`.** 티켓은 `guard/schedule`을 가리켰는데 **둘은 같은 `t.boundary`**이고
(`daily.assembleToday` : `guard.schedule` 둘 다 같은 `TimeCtx`에서 낸다),
`/api/today`는 **화면이 이미 부르는 응답**이라 왕복이 안 는다. 그래서 이쪽으로 정했다.

네이티브에는 시각이 한 글자도 없다(front ③이 `\d{1,2}:\d{2}` 리터럴을 0으로 센다).
경계를 **한 번도 못 받았으면 비우지 않는다** — 짐작한 시각에 지우는 것이 짐작하고 남기는 것보다 나쁘다.
비우는 것은 `ScaleStore.readFresh`가 그릴 때마다 하고, 그 시각에 스스로 깨도록 `AlarmManager`
알람 하나를 건다(`updatePeriodMillis`는 0 — 최소가 30분이라 하루 48번 깨우면서도 경계를 30분 늦게 잡는다).

⚠️ **알람을 `onUpdate`에서만 걸었다가 스스로 잡았다** — 그러면 *웹이 경계를 처음 알려 준 직후에
알람이 없다*(다음 `onUpdate`는 재부팅·앱 교체 때까지 안 온다). `refresh()`에서도 걸도록 고쳤다.

⚠️ **변이 배터리를 한 프로세스로 여덟 번 돌리다 중간에 죽어 파일이 변이된 채 남았다.**

매번 원본을 복원하는 쪽으로 바꿔 다시 쟀다 — 위 표는 그렇게 나온 숫자다.

### 범위 밖 — 한 줄

**`android/.../MainActivity.java`에 `registerPlugin(WidgetPlugin.class)` 한 줄.**
이 리포의 Capacitor 플러그인은 자동 발견이 아니라 여기서 명시 등록한다(`GuardPlugin`이 그렇다).
티켓 §범위에 이 파일이 없는데, **등록하지 않으면 `Capacitor.Plugins.Widget`이 없어서 웹이 조용히
건너뛰고 위젯이 요약도 값도 못 받는다** — 티켓 ③이 요구하는 것이 통째로 안 선다.
**티켓의 누락으로 판단**하고 넣었다(T-03이 `me.ts` 한 줄을 넣은 것과 같은 모양). **Cowork 확인 필요.**

색 파일도 나눴다(`widget_scale_colors.xml`) — T-46의 검사가 *"`widget_colors.xml`의 색 이름은
전부 그 레이아웃이 쓴다"* 를 세므로, 한 파일에 두 위젯 색을 넣으면 **T-46이 빨간불이 된다.**
