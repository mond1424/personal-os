**발행** Cowork · 2026-09-16 · **담당** Claude Code · **작음~보통**
**근거** [ADR-047 ①](../../APP-ADR.md#adr-047) — *"항상 뜨는 개입은 정보가 0이다"* ·
2026-09-16 사용자 실측(밤 L2·L3를 겪고 낸 판정) · `GuardWatch.kt` 소스 확인
**APK 필요 · 서버 무관 · 마이그레이션 없음**

---

## ⚠️ 먼저 — 이 티켓의 근거는 **전사가 아니라 소스와 판정** 둘이다

**사용자가 밤 문구를 타이핑으로 옮겨 줬고, 전사에 오타가 하나 있었다**(`06:60` → 실제 `06:00`).
**Cowork 가 그것을 "같은 값을 두 곳에서 다르게 만든다"는 결함으로 읽었다 — 틀렸다.**
문구는 `GuardWatch.kt:176` 한 곳에서 만들어지므로 **L2·L3 가 갈릴 수 없다.**

### ⚠️⚠️ ★★ 그리고 Cowork 가 그 다음에 더 크게 틀렸다

**전사에 있던 *"내일이 무너집니다"* 를 `grep` 으로 찾다가 못 찾고 *"리포에 없는 문장"* 이라고
결론냈다. 그 위에 티켓을 쓸 뻔했다.** 실제로는 **`GuardWatch.kt:178` 에 있다:**

```kotlin
if (level >= 3) append(" 내일이 무너집니다.")
```

⚠️ **원인: `grep` 을 `head_limit 15` 로 돌렸고, 15 건이 다 찬 채 `android/` 가 안 보이자 *없다*로 읽었다.**

★★★★ **0 건도 아니었다. 잘린 목록을 전수로 읽었다** —
`AGENT-CHAIN` §8 *"비율은 자기 분모를 말하지 않는다"* 와 **같은 실패를, 그 규칙을 쓴 층이 냈다.**
**가른 것은 사용자가 보낸 스크린샷 한 장이다.**

★★★ **그래서 이 티켓은 전사도 `grep` 요약도 근거로 쓰지 않는다.** 아래 §결함 둘은
**소스 줄 번호로 확인했고**, 화면은 **스크린샷으로 확인했다**. 사용자에게서 가져온 것은 **판정뿐**이다:

```
"의미 없다고 느껴짐"                        ← ★ 이건 그 사람만 아는 사실이다
"시간이 6시든 7시든 둘 다 틀렸어 — 8시에 일어나야 함"
```

★★ **전사는 틀릴 수 있어도 판정은 안 틀린다.** 문구를 잘못 기억해도 *"무의미했다"* 는 유효하다.
⚠️ **앞으로 문구는 스크린샷으로 받는다**(`OPERATIONS` §3.5 갱신 대상).

## 결함 ① — 취침 창의 **끝**이 문구에 있다. 매일 같고, 기상 시각으로 오독된다

**`GuardWatch.kt:176`:**

```kotlin
append("취침 창(${s.bedFrom}~${s.bedTo})에 들어온 뒤 ${windowMin}분 화면을 켜 두셨어요.")
```

**한 문장에 수가 셋인데 하나만 매일 같다:**

```
[N번째예요.]                       밤마다 다름   (ADR-049 ① — 그래서 맨 앞)
[지금 자면 6시간 30분 — 8시 기상…] 밤마다 다름
취침 창(00:30~06:00)에 들어온 뒤     ⚠️ 매일 같다
15분 화면을 켜 두셨어요.             ★ 다름
```

★★★ **바로 위 줄의 주석이 이미 이 원칙을 알고 있다:**

> ★ **사실이 맨 앞이다** — 밤마다 달라지는 것이 이 문장 하나뿐이라 뒤에 붙이면
> **매일 같은 앞부분이 먼저 읽히고 그대로 넘어간다**(ADR-047 ①).

⚠️⚠️ **그런데 매일 같은 조각이 *앞*이 아니라 *가운데*에 있어서 그 경계를 빠져나갔다.**
`15분`이라는 사실을 읽으려면 **매일 같은 열 몇 글자를 먼저 지나야 한다.**

### ★★ 그리고 끝은 소음보다 나쁘다 — 오독을 만든다

**사용자가 그 수를 기상 시각으로 읽었다:**

> *"시간이 6시든 7시든, 강의가 10시이고 준비 1시간 + 이동 1시간 하면 **8시에 일어나야 함. 둘 다 틀렸어**"*

★★★ **같은 문장 안에 `8시 기상`과 `~06:00`이 나란히 있으니 비교하게 되고, 안 맞는다.**
`bedTo`는 *"이 시각 이후엔 감시를 안 한다"* 는 **앱 내부 사정**이지 사용자의 기상이 아니다.

⚠️ **이것이 T-69가 고친 것과 같은 모양이다** — 거기선 *발동 횟수*의 두 수가 서로를 반박했고,
**여기선 시각이다.** **같은 결함이 다른 축에서 다시 났다.**

### 바꿈

```
지금   취침 창(00:30~06:00)에 들어온 뒤 15분 화면을 켜 두셨어요.
바꿈   ★ 00:30 이후 15분 화면을 켜 두셨어요.
```

★ **시작은 남긴다.** `15분`이 **무엇 이후의 15분인지**를 말해야 사실이 완성되고,
`windowMin`이 재는 것이 정확히 `windowStartMs(bedFrom, bedTo)` 이후이기 때문이다.
⚠️ **끝은 그 사실에 아무 기여도 안 한다.**

⚠️ **"지금까지 15분" 으로 바꾸지 마라** — `windowMin`은 *창 시작 이후*를 재지 *지금까지*가 아니다.
**문구는 값이 실제로 재는 것을 말해야 한다.**

## 결함 ② — L3 제목이 ADR-047 ①이 **L2에서 없앤 그 문장**이다

**`GuardWatch.kt:126`:**

```kotlin
val title = if (level == 2) "아직 깨어 있네요" else "지금 자야 합니다"
```

**ADR-047 ① 원문:**

```
지금  "지금 자야 합니다"           ← 매일 같다. 정보 0
바꿈  "지금 자면 5시간 30분 — 10시 전자기및연습1"   ← 밤마다 다르다
```

★★★★ **그 문장을 L2에서 빼면서 L3에는 그대로 뒀다.** ADR-047이 *명령을 사실로* 바꾼
이유가 *"매일 같은 명령은 서약을 소모한다"* 였는데, **더 센 개입이 그 명령을 계속 쓰고 있다.**

★★ **그리고 사용자 판정이 정확히 그것이다** — *"짜증까지는 아닌데 의미 없다고 느껴짐."*
**짜증이 아니라 무의미**라는 것이 ADR-047의 언어로 **정보가 0**이고,
**L2가 겪었던 바로 그 자리에 L3가 와 있다.**

⚠️ **다만 무엇으로 바꿀지는 ①만큼 자명하지 않다.** 그래서 순서를 나눈다(아래).

## ① 창의 끝을 문구에서 뺐다 — 닫음

**`GuardWatch.kt:194`** (옛 176. 위에 붙인 주석 18줄만큼 내려갔다):

```kotlin
전   append("취침 창(${s.bedFrom}~${s.bedTo})에 들어온 뒤 ${windowMin}분 화면을 켜 두셨어요.")
후   append("${s.bedFrom} 이후 ${windowMin}분 화면을 켜 두셨어요.")
```

**렌더 결과** — 검사가 표식을 먹여 실제로 만들어 낸 문장이다(아래 §검사):

```
L2   오늘 밤 8번째예요. <WAKE>. <FROM> 이후 <WIN>분 화면을 켜 두셨어요. 지금 <APP>.
L3   오늘 밤 8번째예요. <FROM> 이후 <WIN>분 화면을 켜 두셨어요. 지금 <APP>. 내일이 무너집니다.
```

`bedTo`는 **코드에서 안 지웠다** — 바로 위 `windowStartMs(s.bedFrom, s.bedTo)`(155~157)와
`inWindow`(81)가 창 계산에 쓴다. **문구에서만 뺐다**(§금지 5행).

### 검사 — front +3 (스캐너가 아니라 **렌더**다)

⚠️ **티켓이 경고한 구멍이 실재했다.** *"소스에 `s.bedTo`가 없다"* 로 쓰면
**`06:00`을 박아 넣는 구현이 통과한다.** 그래서 `val body = buildString { … }` 블록을
**Kotlin 본문 그대로 옮겨 돌리고**(T-69의 3·4·5와 같은 방식 · 함정 15),
재료마다 서로 다른 표식을 먹여 **완성된 문구에 무엇이 실렸는지**를 본다.
문구도 조건도 임계도 검사에 다시 적지 않았다 — **옮기다 막히면 셋이 함께 빨간불**이다.

```
1 ★ 밤 문구에 취침 창의 끝이 없다 — 보간으로도, 박아 넣은 시각으로도   ← 본체
2 ★ 창의 시작은 남아 있다 — N분의 기준이다                            ← 1의 짝
3    문구가 싣는 분이 그대로다 — 창 안의 시간이지 게이트의 연속 시간이 아니다  ← T-69 회귀
```

★ **`append`는 고쳐 쓰지 않고 JS 함수로 뒀다** — 옮기는 자리가 하나 줄면 조용히 어긋날 곳도 준다.

### 변이 — 넷 다 돌렸다

```
bedTo 를 다시 넣는다        → 473 → 472 · ✗1 만            ✅ 예상대로
bedFrom 까지 뺀다           → 473 → 472 · ✗2 만            ✅ 예상대로
windowMin 을 usedMin 으로   → 473 → 471 · ✗3 + ★ T-69 ✗3   ✅ 아래 참조
★ 끝을 06:00 으로 박아 넣기 → 473 → 472 · ✗1 만            ★ 티켓에 없던 넷째
```

★ **변이 3이 둘을 죽인 것이 맞다.** T-69 검사 3(*"문구의 분이 창에 들어온 뒤를 잰다"*)이
**같은 결함을 이미 지키고 있었다** — 내 검사 3이 그 자리를 렌더로 한 번 더 덮은 것이고,
둘이 함께 죽는 것이 *"장치가 둘 다 살아 있다"* 는 뜻이다. 예상 밖이 아니다.

★★ **넷째 변이는 검사 1의 *나머지 절반*이 살아 있는지를 물은 것이다.** 티켓의 변이 셋은
전부 보간을 건드리므로 **`\d{1,2}:\d{2}` 절반을 한 번도 안 태운다** — 태워 보니 이렇게 갈렸다:

```
끝표식=false   ← ★ 표식 절반은 못 잡았다. 티켓이 경고한 바로 그 구멍이다
시계모양=true  ← ★ 시계 절반이 잡았다
```

**두 절반이 서로 다른 것을 잡는다 — 겹치는 장치가 아니다.**
(*"훑기가 0건을 내면 물어야 하는 것 하나를 먹인다"* — `AGENT-CHAIN` §8 · 함정 17.)

## ② L3 가 실제로 말하는 것 — **소스로 확인했다. 아무것도 안 고쳤다**

⚠️ **아래는 전부 `GuardWatch.kt` 현재 줄 번호다**(①의 주석 18줄 반영). 전사도 요약도 안 썼다.

### L3 title (126)

```kotlin
val title = if (level == 2) "아직 깨어 있네요" else "지금 자야 합니다"
```

**조건 없음.** `level`은 107줄이 **2 아니면 3으로만** 만든다(`if (!l2done) 2 else 3`) —
그래서 `else` 가지는 **L3 전용이고 무조건이다.** 다른 재료를 안 읽는다.

### L3 body 조각 — **전수 다섯**

| # | 줄 | 조각 | 조건 | **L3에서** |
|---|---|---|---|---|
| 1 | 171 | `오늘 밤 N번째예요. ` | `n >= s.watchTallyFrom` | 조건부 |
| 2 | 174 | `<기상 한 줄>. ` | `wakeLine != null` | ★ **절대 안 붙는다** |
| 3 | 194 | `HH:MM 이후 N분 화면을 켜 두셨어요.` | **없음** | 항상 |
| 4 | 195 | ` 지금 <패키지명>.` | `app != null` | 조건부 |
| 5 | 196 | ` 내일이 무너집니다.` | `level >= 3` | ★ **항상** |

### ★ 물은 것 셋에 대한 답

**(a) `178`의 *" 내일이 무너집니다."* 는 `level >= 3` 무조건인가 → 예. 무조건이다.**
107줄이 level을 2·3으로만 만들므로 `level >= 3` ⟺ `level == 3`이고, 다른 재료를 안 읽는다.
**밤마다·발동마다 같다.**

**(b) ★★ `wakeLine`이 L3에 안 붙는 이유 → 물은 대로다. 블록 전체가 `level == 2` 안이다.**

```kotlin
113   var wakeLine: String? = null        ← 블록 밖 선언. 초기값 null
114   if (level == 2) {                   ← ★ 여기서 열린다
122       if (w.state == OK) wakeLine = wakeSentence(now, w)   ← ★ 유일한 대입. 블록 안이다
123   }                                   ← 여기서 닫힌다
```

**대입이 122 하나뿐이고 그것이 `level == 2` 안이므로, L3에서 `wakeLine`은 초기값 `null` 그대로다.**
사용자 스크린샷(L3 본문에 기상·수업 줄 없음)과 소스가 **일치한다.**

★ **그리고 이것은 결함이 아니라 ADR-047 ②의 의도다** — 110~112줄 주석이 그렇게 적어 뒀다:
*"Level 3·4는 데드라인·보호 일정이 근거이므로 여기를 타지 않는다 — 태우면 시험 전날 밤에
Guard가 통째로 조용해진다."* **②에서 이 줄을 L3로 끌어오는 것은 그 결정을 뒤집는 일이다.**

**(c) 실제 값**  (`GuardSettings.kt`)

```
watchTallyFrom    = 2    (K_WATCH_TALLY · 범위 2..20 · 117~119줄)
watchMaxPerNight  = 9    (K_WATCH_MAX   · 범위 1..20 · 101~103줄)
(참고) bedFrom 00:30 · bedTo 06:00 · watchMinutes 15 · watchRefireMinutes 15
```

⚠️⚠️ **스크린샷의 *"8번째"* 는 상한 9의 8번째가 아니다.** 두 계수가 다른 것을 센다(T-69가
일부러 갈라 놓았다 · 128~146줄 주석):

```
문구의 N        = GuardNight.count + 1   ← 방해 수. 감시 + 재확인 + 경로 A 알람
상한이 읽는 것  = K_NIGHT_N              ← ★ 감시 발동만
```

**8번 방해받은 것은 맞지만, 그중 감시가 몇 번인지는 그 수가 말하지 않는다.**
갈라서 보려면 `GuardWatch.status()`가 `firedTonight`·`interruptedTonight`를 나란히 준다(210·213).

### ★ *"다음 L3에서 더 많은 정보를 줬다"* — 무엇이 달라질 수 있나

**L3 본문에서 발동마다 달라질 수 있는 것은 셋뿐이고, 기상 줄은 그 후보가 아니다.**

```
(1) 순번 줄   n >= 2 부터 붙는다. 그 밤의 첫 방해엔 없다 → 둘째부터 생긴다
(4) 앱 줄     ★ 순번과 무관하게 붙었다 말았다 한다
(3) 분        창 시작 이후 누적이라 단조 증가 — 사라지지 않는다
```

⚠️ **(4)가 가장 자주 흔들린다.** `UsageProbe.currentApp`(46~62)은 **최근 60초**의
`MOVE_TO_FOREGROUND`/`ACTIVITY_RESUMED`만 보고, **없거나 우리 앱이면 `null`** 이다 —
**한 앱을 60초 넘게 붙잡고 있으면 그 줄이 사라진다.** 개입 직후 앱을 바꾼 발동에만 붙는다.

★★ **그래서 *"더 많은 정보"* 는 (1)이 켜졌거나 (4)가 붙은 것으로 설명된다.
기상 줄은 어떤 순번에서도 L3에 안 붙는다** — (b)가 그것을 소스로 닫았다.

⚠️ **그리고 (4)는 패키지명 그대로다.** `UsageProbe`에 라벨 변환이 **없다** — 화면에는
*"지금 com.google.android.youtube."* 로 뜬다.
★ **그 0건에 증거를 먼저 요구했다**(함정 18): 같은 스캐너에 `packageName`을 먹여 **7건**을
확인한 뒤의 `loadLabel|getApplicationLabel|PackageManager` **0건**이다. *없다*이지 *못 봤다*가 아니다.

## ★★ ②의 재료 — Cowork 에 올린다 (문구는 안 정했다)

**티켓 §결함 ②는 title 하나를 지목했는데, 매일 같은 명령/단정이 L3에 *둘*이다:**

```
126   "지금 자야 합니다"        ← ADR-047 ①이 L2에서 없앤 바로 그 문장
196   " 내일이 무너집니다."     ★ 티켓이 안 본 둘째. level >= 3 무조건이라 역시 매일 같다
```

★★★ **그래서 L3 문구에서 밤마다 달라지는 것은 (1)·(3)·(4) 셋이고, 그중 (4)는 패키지명이며
(1)은 첫 방해엔 아예 없다.** *"의미 없다고 느껴짐"* 이 놓인 자리가 이것이다 —
**여는 말(title)과 닫는 말이 둘 다 고정이고, 그 사이에 달라지는 것이 분 하나뿐인 발동이 있다.**

⚠️ **ADR-047 ①을 고치는 일이므로 여기서 정하지 않는다.** 위 표가 §할일 ②가 요구한 재료 전부다.
