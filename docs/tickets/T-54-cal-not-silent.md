# T-54 — 캘린더가 아무것도 안 했으면 그렇게 말한다

**발행** Cowork · 2026-09-01 · **담당** Claude Code · **보통**
**근거** [T-53 §②](T-53-cal-read-device.md) 의 미완 · 2026-09-01 실측 진단 · **APK 필요 · 서버 무변경**

## 무엇이 어긋났나 — 실측된 것

**T-53의 핵심은 ②였다: *"권한이 없으면 조용하지 않다."*
그런데 사용자가 `[저장하고 지금 동기화]`를 눌렀고, 아무 일도 안 일어났고, 화면은 그것을 말하지 않았다.**

```
permission true   targets []   configured true
lastOkAt null     lastError null   lastCount -1      ← 셋 다 초기값
```

**⚠️ 원인은 결함이 아니었다 — 빈 목록이 저장된 것이다.** 읽기·보내기·창·배선은 실측으로 전부 정상:
provider 26행 · 대상 `[10]` 넣으면 `sent 5 · upserted 5`.

**★ 그래서 이 티켓은 A(왜 안 왔나)가 아니라 B(왜 그것이 안 보였나)를 고친다.**
A는 고칠 것이 없고, **B를 고치면 A가 다음번에 스스로 드러난다.**

## ★ 세 겹으로 조용했다 — 그리고 넷째는 로그가 없다

### ① 빈 선택 저장이 막히지도, 말해지지도 않는다

```
save.onclick 은 ids.length === 0 을 안 본다
CalPlugin.setTargets 는 빈 배열을 정상 저장으로 처리한다
시트가 닫히는 것이 유일한 피드백이고 — 그것은 성공 신호로 읽힌다
```

⚠️ **"안 고르고 저장"과 "선택 해제"가 같은 연산이다.** 뜻이 정반대인데 화면에 가르는 말이 없다.

### ② `skipped`가 화면까지 안 온다

**네이티브는 `no_target`을 성실히 실어 보내는데** `calSyncNow`의 `else` 가지가 `r`을 통째로 버리고
`loadCalStatus()`만 부른다. **그 둘은 설계상 prefs에 흔적을 안 남기므로**(*"실패가 아니다"*)
다시 그린 줄은 **저장 누르기 전과 글자 하나 안 다르다.**

### ③ (잠복) `sent === 0`을 성공으로 말한다

`r.ok && r.sent === 0`이면 **초록 토스트 `캘린더 0건을 맞췄어요`**가 뜬다.
**휴일 캘린더만 고르면 바로 이 모양이다** — T-43이 `0건`과 로그인 HTML을 가른 그 자리와 같다.

### ④ ★ `cal/` 셋에 `Log` 호출이 0건이다

**화면이 조용하면 로그라도 남아야 하는데 둘 다 없었다.** `guard/`는 `noteFire`로 흔적을 남긴다 —
**같은 문제를 이미 한 번 겪은 자리다.**

## 할 일

### ★ 원칙 하나로 묶는다 — 시도는 언제나 흔적을 남긴다

```
성공 · 스킵 · 실패  →  셋 다 "마지막 시도의 결과"로 남는다
```

⚠️ **지금은 `lastOkAt`·`lastError`·`lastCount` 셋뿐이라 `skipped`가 갈 곳이 없다.**
그것이 ②의 뿌리다 — **prefs에 자리가 없으니 화면도 못 읽는다.**

### ① 빈 선택 — 막거나 말한다

**담당이 고른다. 근거를 보고에 적는다.**

```
(a) 저장을 막고 그 자리에서 말한다        "하나 이상 골라 주세요"
(b) 저장은 허용하되 결과를 말한다         "선택을 해제했어요 — 이제 아무것도 안 가져와요"
```

⚠️ **(b)를 고르면 "해제"가 의도된 행동으로 남는다** — 그것도 사용자가 할 수 있는 일이다.
어느 쪽이든 **시트가 조용히 닫히는 지금의 모양은 안 된다.**

### ② 결과를 화면까지

`calSyncNow`가 `r`을 버리지 않는다. **`skipped`·`sent`·`upserted`가 사용자에게 닿는 경로를 만든다.**

⚠️ **상태 줄(`#td-cal`)과 섞지 마라.** 그것은 *"지금 어떤 상태인가"*이고, 이건 *"방금 한 행동의 결과"*다.
**T-53이 `calStatusLine` 하나로 상태를 정한 구조는 그대로 둔다** — 두 곳에서 정하면 갈라진다.

### ③ `sent === 0`은 성공이 아니다

```
sent 0 · ok true   →  "가져올 일정이 없었어요 (대상 N개 · 창 M일)"   ← 초록 아님
sent 5 · ok true   →  "일정 5개를 맞췄어요"
```

**0이 왜 0인지를 함께 말한다** — 대상 수와 창을 보이면 *"휴일 캘린더만 골랐다"*가 그 자리에서 드러난다.

### ④ ★ `cal/`에 흔적

**`guard/`의 `noteFire`와 같은 급으로.** 최소한 **마지막 시도의 사유가 `Cal.status()`에 실려야** 한다 —
그래야 화면이 안 보여도 CDP 한 줄로 갈린다.

⚠️ **`Log`만 늘리는 것으로 끝내지 마라.** logcat은 개발자만 보고, **이 결함의 피해자는 사용자다.**

## 범위

```
android/.../cal/CalSync.kt · CalPlugin.kt    시도 결과 기록 · status 노출
public/app.js · index.html                  빈 선택 · 결과 표시
test/front.mjs                              검사
```

**서버 무변경 · 마이그레이션 없음.**

⚠️ **`calStatusLine`의 상태 넷(`noperm`·`notarget`·`error`·`ok`)을 늘리지 마라.**
결과는 상태가 아니다 — 섞으면 T-53이 세운 것이 무너진다.

⚠️ **`guard/` 아래를 안 건드린다.** T-53의 `GuardSync.kt` 한 줄은 그대로 둔다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 빈 선택을 조용히 저장 | **①이 이 티켓의 시작점**이다 |
| `sent === 0`에 초록 토스트 | **0건과 실패가 안 갈린다**(T-43) |
| 결과를 상태 줄에 합치기 | 상태와 행동 결과는 다른 것이다 |
| `calStatusLine` 상태 늘리기 | 넷이 곧 `CAL_ACT`의 넷이다. 구조가 무너진다 |
| `Log` 만 늘리고 끝내기 | **피해자는 사용자다.** logcat 은 안 본다 |
| A(빈 목록) 를 "고치려" 들기 | **결함이 아니다.** B 를 고치면 다음번에 드러난다 |
| 경합이 있는 신호로 검사 짜기 | ⚠️ 토스트가 그것이다 — 담당이 직전 커밋에서 물렸다 |

## 완료 조건

```
typecheck 통과 · smoke 385(변화 없음) · front 377 → 382 이상 · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

**검사**

```
1  빈 선택으로 저장하면 그 사실이 사용자에게 닿는다
2  ★ 하나 이상 고르면 닿지 않는다                        ← 1의 짝
3  ★ sent === 0 이 성공 문구로 안 나온다
4  ★ sent > 0 은 성공 문구로 나온다                      ← 3의 짝
5  ★ skipped(no_target) 가 화면까지 온다 — 저장 전후로 화면이 달라진다
6  Cal.status() 에 마지막 시도의 사유가 실린다
7  ★ 상태 줄은 넷 그대로다 (결과가 섞이지 않았다)         ← 없는 것을 세는 검사
```

**1·2와 3·4가 각각 짝이다.** 1만 보면 *"항상 경고하는 구현"*이, 3만 보면
*"성공도 실패처럼 말하는 구현"*이 통과한다.

**5가 이 티켓의 본체다.** *"저장 전후로 화면이 달라진다"*를 세라 — **글자가 같으면 실패다.**

⚠️ **검사 신호에 토스트를 쓰지 마라.** `until`이 `refreshToday()`의 DOM 쓰기를 보고 먼저 빠져나와
**던지기 전에 읽는다** — 담당이 직전 커밋에서 실측했다. **호출을 세거나 상태를 세라.**

**변이**
- 빈 선택 경고를 뺀다 → **1만** 죽는다
- 항상 경고한다 → **2만** 죽는다
- `sent 0`에 성공 문구 → **3만** 죽는다
- `sent > 0`에도 실패 문구 → **4만** 죽는다
- `calSyncNow`의 `else`에서 `r`을 다시 버린다 → **5만** 죽는다
- `status`에서 사유를 뺀다 → **6만** 죽는다
- 결과를 `calStatusLine`에 넣는다 → **7만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

```
□ 설정 → 폰 캘린더 → 아무것도 안 고르고 [저장하고 지금 동기화]
   ★ 그 자리에서 무언가 말한다 (조용히 닫히지 않는다)
□ 하나 고르고 저장 → 일정이 들어오고 "N개를 맞췄어요"
□ ★ 아무것도 안 넣었는데 오늘 화면에 무언가 있다        ← T-53 이 못 채운 목적
□ 휴일 캘린더만 골라 보기 → "가져올 일정이 없었어요 (대상 1개 · 창 60일)"
```

**★ 그리고 셋째 줄이 되면 T-53의 §확인 절차를 마저 밟는다** — 반복 인스턴스 · 읽기 전용 · 삭제 반영.
