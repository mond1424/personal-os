# T-39 — 판정이 flush를 앞질러도 살아남는다

**발행** Cowork · 2026-08-20 · **담당** Claude Code · **작음**
**T-37이 넓힌 창을 닫는다. T-38이 만든 칸을 실제로 채운다.**

---

## 무엇이 어긋났나

**판정이 도착하기 전에 `flush()`가 돌면 그 판정은 영영 사라진다.**

```
발동 → 화면 → (백그라운드) verify … 최악 16초
                              ↓
사용자가 반응 → GuardAlertActivity:224 flush()  ← 큐에서 행이 빠진다
                              ↓
        amendFire: firstOrNull{…} ?: return     ← 조용히 지나간다
```

**두 곳이 함께 막혀 있다.**

| 자리 | 지금 | 문제 |
|---|---|---|
| `GuardEventQueue.amendFire:113` | `?: return` | 큐에 없으면 **버린다** |
| `src/services/guard.ts` `record()` dup 경로 | `if (!dup.reaction && input?.reaction)` | 뒤늦게 온 항목에서 **`reaction`만 채운다.** `ai_verdict`·`ai_used`·`ai_reason`은 무시된다 |

**기기를 고쳐도 서버가 안 받는다. 서버를 고쳐도 기기가 안 보낸다.** 둘 다여야 한다.

## 왜 지금

**① T-37이 창을 6초에서 최악 16초로 넓혔다.** 담당이 그 사실을 주석으로 남겼고 맞다 —
원래 있던 위험이지만 **세 배 가까이 넓어졌다.** 그리고 새벽에 알람으로 깬 사람이
16초 안에 화면을 치우는 것은 **드문 일이 아니라 기본값**이다.

**② T-38이 만든 칸이 바로 이 경로로 온다.** `ai_reason`은 `amendFire`가 나른다.
**T-38이 되찾으려던 `deny` 사유가 가장 흔한 상황에서 유실된다** —
관측을 늘리는 티켓을 통과시켜 놓고 그 관측이 도달하지 못하는 자리를 남기는 셈이다.

**③ 9~11월이 전례를 쌓는 기간이다.** 사라진 판정은 소급해서 못 만든다.

## 할 일

### ① 기기 — `recordReaction`과 같은 모양으로

**같은 파일에 이미 정답이 있다**(`GuardEventQueue.kt:124`):

> 이미 밀어 올려 큐에서 빠졌으면 **반응만 담은 항목을 새로 넣는다** —
> 서버가 client_id로 찾아 반응만 채운다(record()의 upsert 경로).

`amendFire`도 같게 한다. **새 패턴을 만들지 않는다.**

### ② 서버 — dup 경로가 판정도 채운다

**`NULL → 값`만 채운다.** 이미 값이 있는 것은 덮지 않는다 —
불변성 트리거가 강제하는 규칙과 같은 모양이고(`record()` 주석이 이미 그렇게 적고 있다),
재시도가 판정을 뒤집으면 안 된다.

```
채운다      ai_verdict · ai_used · ai_unavailable_reason · ai_reason
```

⚠️ **`level`은 이 티켓에서 정하지 않는다.** `NOT NULL`이라 *"NULL → 값"* 규칙에 안 맞고
불변성 트리거에 걸릴 수 있다. **먼저 걸리는지 확인하고, 걸리면 별건으로 올린다** —
격상 구간 판정은 기기가 `GuardLevel4.note()`로 따로 들고 있으므로(ADR-035 ③)
서버의 `level`이 3에 머물러도 **동작은 안 바뀐다. 기록만 덜 남는다.**

### ③ 검사 — 끊기는 자리를 직접 본다

T-38의 보고가 배운 것을 그대로 쓴다: **서버로 직접 POST하는 검사는 기기가 무엇을 하든 초록이다.**

```
1  flush 뒤에 도착한 판정이 서버에 실린다        ← 이 티켓의 본체
2  이미 값이 있으면 덮지 않는다                  ← 1의 짝
3  기기가 fallback 항목을 만드는가 (배선)         ← Kotlin 소스를 직접 본다
4  ★ 3의 스캐너가 살아 있는가                     ← 주석을 걷어내고 본다 (T-38이 물린 자리)
```

## 범위

```
android/.../guard/GuardEventQueue.kt   amendFire 의 ?: return → fallback 항목
src/services/guard.ts                  record() dup 경로가 ai_* 를 NULL→값으로 채운다
test/smoke.ts                          검사 4건
```

**마이그레이션 없다.** 0017의 칼럼을 쓰는 것뿐이다.
**`GuardVerify`·타임아웃 상수 무변경** — T-37이 정한 값은 그대로 둔다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 타임아웃을 다시 줄여 창을 좁히기 | T-37을 되돌리는 것이다. **창은 좁히는 게 아니라 안전하게 만든다** |
| `flush()`를 판정까지 기다리게 하기 | 반응 기록이 최악 16초 늦어진다. **개입 경로에 네트워크를 넣지 않는다**(ADR-021) |
| 이미 있는 값 덮어쓰기 | 재시도가 판정을 뒤집는다. `NULL → 값`만 |
| `level`을 함께 밀어 넣기 | `NOT NULL`이라 규칙이 다르다. §할 일 ② |
| 새 큐·새 저장소 만들기 | `recordReaction`이 이미 그 길을 갔다. 두 벌 두면 갈라진다 |

## 완료 조건

```
typecheck 통과 · smoke 317 → 321 이상 · front 291(변화 없음) · 실패 0 · verify exit 0
Kotlin: assembleRelease BUILD SUCCESSFUL
```

**변이**

| 변이 | 기대 |
|---|---|
| 서버 dup 경로를 되돌린다 (`reaction`만) | 1이 죽고 3은 산다 |
| 기기 fallback을 주석 처리한다 | **3만 죽는다** — 1·2는 서버 직접 POST라 초록이다 |
| 스캐너를 눈멀게 한다 | 3은 초록으로 남고 ★만 죽는다 |

**둘째가 이 티켓의 핵심이다.** 서버만 고치고 기기를 안 고쳐도 1·2가 통과한다 —
그것이 T-38에서 실제로 일어난 일이고, 이번엔 처음부터 짝을 둔다.
