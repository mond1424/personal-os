# T-56 — 뒤에 또 깨어 있었으면 묻지 않아도 안다

**발행** Cowork · 2026-09-03 · **담당** Claude Code · **작음**
**근거** [ADR-044](../../APP-ADR.md#adr-044) · **마이그레이션 없음 · APK 무관**

---

## 무엇을 만드나

Today 상단의 **잘 했어요 / 못 했어요**가 대부분 답 없이 남는다 — 묻는 때가 다음 날 낮이고,
그때는 그 밤이 이미 멀다.

**답이 없어도 알 수 있는 밤이 있다.**

```
개입 뒤에 같은 밤의 발동이 또 있었다   →  그 사이에 자지 않았다
```

`GuardWatch`는 `continuousScreenOnMin`으로 발동한다 — **화면이 켜져 있어야 뜬다.**
다음 발동의 존재는 추측이 아니라 **관측된 사실**이다.
여섯 밤 관측에서 L3에는 매번 재발동이 뒤따랐으므로, **대부분의 밤이 답 없이 채워진다.**

## ★ 저장하지 않는다 — 이 티켓의 전부가 여기에 걸린다

⚠️ **`outcome`에 자동으로 `failure`를 쓰면 안 된다.**

```sql
outcome  TEXT CHECK (outcome IN ('success','failure'))
trg_guard_event_immutable:
  OR (OLD.outcome IS NOT NULL AND IFNULL(NEW.outcome,'') != OLD.outcome)
```

**append-only다.** 시스템이 먼저 박으면 사용자가 나중에 *"그건 잤다가 깬 거였다"* 라고
**고칠 길이 DB 층에서 막힌다.** 그리고 §6.5가 전례를 읽을 때
*"사용자가 그렇게 말했다"* 와 *"시스템이 그렇게 추론했다"* 가 **한 칸에 섞인다.**

**컬럼도 더하지 않는다.** *"뒤에 발동이 또 있었나"* 는 `guard_events`를 보면 **언제든 나온다** —
**아키텍처 원칙 1: 파생값은 저장하지 않는다.** 저장하면 닫힌 `CHECK`와 트리거를 상대해야 하고
얻는 것이 없다.

## 할 일

### ① 조회할 때 계산한다

그 발동보다 **뒤**이고 **같은 귀속일(`on_date`)**인 `guard_events`가 있으면 `inferred`다.
**레벨은 가리지 않는다** — L2도 화면이 켜져 있어야 뜨므로 증거로는 같다(ADR-044 ③).

⚠️ **귀속일 경계에 시각을 적지 마라.** `on_date`가 이미 그 판정을 담고 있다.

### ② 화면이 셋을 갈라 말한다

```
답이 있다                    그 답을 보인다 — 물음이 사라진다
답 없고 · 뒤에 발동 있다      "못 한 것으로 보여요"   ★ 버튼은 남는다
답 없고 · 뒤에 발동 없다      묻는다 (지금 모양)
```

⚠️ **둘째 줄에서 버튼을 없애지 마라.** 자동 판정은 **사용자의 답을 대체하지 않고 자리를 대신
채운다** — `outcome`이 비어 있으므로 트리거가 안 막고, **사용자가 누르면 그 답이 이긴다.**

⚠️ **문구를 단정하지 마라.** *"못 했어요"*가 아니라 *"못 한 것으로 보여요"* 다 —
관측의 강도가 다르고, 그 차이가 사용자에게 **고칠 수 있다는 신호**가 된다.

## 범위

```
src/db/index.ts     뒤따른 발동 여부 (조회에 얹는다)
src/services/       또는 여기 — 도메인 판단이므로
public/app.js       셋을 가르는 표시
test/smoke.ts · test/front.mjs
```

**마이그레이션 없음 · APK 무관 · `guard/` 무변경.**

⚠️ **`services/guard.ts`의 발동 경로를 건드리지 않는다** — 이 티켓은 **읽는 쪽**이다.
**위임 금지 영역이 아니다**(발동 경로가 아니라 조회다). **Antigravity 위임 가능.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| `outcome`에 자동 기입 | **사용자가 못 고친다**(append-only). ADR-044 ★ |
| 새 컬럼·마이그레이션 | **파생값은 저장하지 않는다**(원칙 1) |
| 추론된 것에서 버튼 제거 | 관측이 사람의 답을 이기는 구조가 된다 |
| *"못 했어요"* 로 단정 | 관측의 강도가 다르다. 고칠 수 있다는 신호를 지운다 |
| 레벨로 거르기 | L2도 화면이 켜져야 뜬다(ADR-044 ③) |
| 귀속일 경계에 시각 적기 | 설정값이다. `on_date`가 이미 담고 있다 |

## 완료 조건

```
typecheck 통과 · smoke 385 → 389 이상 · front 385 → 387 이상 · 실패 0 · verify exit 0
```

**검사**

```
1  뒤에 발동이 있으면 추론이 붙는다
2  ★ 뒤에 발동이 없으면 안 붙는다                     ← 1의 짝
3  ★ 사용자 답이 있으면 추론이 그것을 덮지 않는다      ← 이 티켓의 핵심
4  ★ 추론이 붙어도 outcome 은 여전히 NULL 이다         ← 없는 것을 세는 검사
5  ★ 추론이 붙은 뒤에도 사용자가 답을 쓸 수 있다       ← 4의 실물. 트리거가 안 막는가
6  다른 귀속일의 발동은 세지 않는다
7  L2 가 뒤따라도 추론이 붙는다
```

**4와 5가 이 티켓의 회귀 검사다.** 4만 보면 *"계산은 맞는데 아무 데도 안 쓰이는 구현"*이 통과하고,
5만 보면 *"쓰기는 되는데 추론이 안 도는 구현"*이 통과한다.

⚠️ **5는 실제로 `POST`(또는 그 경로)를 태워라.** 트리거가 막는지는 **API를 거쳐야 알 수 있고**,
막는다면 이 설계가 틀린 것이므로 **멈추고 보고한다.**

⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).

**변이**
- 뒤따른 발동 조회를 뺀다 → **1만** 죽는다
- 항상 추론을 붙인다 → **2만** 죽는다
- 추론이 사용자 답을 덮는다 → **3만** 죽는다
- 추론을 `outcome`에 쓴다 → **4·5** 죽는다
- 귀속일 조건을 뺀다 → **6만** 죽는다
- `level >= 3` 으로 거른다 → **7만** 죽는다
