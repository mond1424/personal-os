# T-06 — Codex 환경에서 `npm run front`가 돌게 한다

**발행** Cowork · 2026-07-30 · **담당** Claude Code · **상태** ✅ **닫힘 (2026-07-31)** — Codex 셸에서 193 · 실패 0

> 권한을 적용한 환경에서 `npm run front` → **통과 193 · 실패 0 · front 검사 75.2초 · 정리 완료.**
> 기본 환경의 `.wrangler` EPERM 메커니즘은 **미해결로 남긴다** — 리포 밖이고 프로젝트를 막지 않는다.
> 재발하면 러너가 어디서 막혔는지 이름을 말한다(§배제 목록부터 본다).

---

## 목표

`npm run front`가 **어느 셸에서든** 자기 숫자를 낼 수 있게 한다.

**왜** — T-01(EPERM) · T-03(미측정) · T-05(300초 초과)로 **세 번 연속** Codex가 front 숫자를 못 냈고,
매번 Claude Code가 대신 재실행했다. 보고 형식의 절반이 늘 비어 오면 **검토가 성립하지 않는다** —
그 층이 자기 작업을 검증하지 못한 채 넘기는 것이고, 다음 층이 대신 돌리면
"구현자가 자기 검사를 통과시킨다"를 막으려던 §8이 다른 방향으로 무너진다.

세 번은 우연이 아니다.

## 관찰된 증상

| 티켓 | 증상 |
|---|---|
| T-01 | `C:\Users\LG\AppData\Roaming\xdg.config\.wrangler\logs` 쓰기 권한 오류(EPERM) 후 60초 종료 |
| T-03 | 미측정 |
| T-05 | 로컬 D1 마이그레이션 단계에서 300초 시간 초과 — 검사 본문에 도달하지 못함 |

**Claude Code 셸에서는 세 번 다 재현되지 않았다.** 같은 리포·같은 명령이므로
차이는 **환경 변수와 그로 인한 로그·상태 경로**다(`XDG_CONFIG_HOME` 계열).

## 방향 — 환경에 기대지 않게 만든다

셸마다 환경을 맞추라고 하는 것은 지시로 해결하는 방법이고, 그건 다음 셸에서 또 깨진다.
**`e2e.mjs`(또는 npm 스크립트)가 자기 로그·상태 경로를 스스로 정하게 한다.**

- 격리 러너는 이미 임시 D1을 쓴다 — **wrangler의 로그·설정 경로도 같은 임시 디렉터리로** 몰아넣는다
- 그러면 사용자 홈의 권한 상태와 무관해지고, 실 `.wrangler/state` 불변이라는 성질도 유지된다
- 300초 초과가 로그 실패의 2차 증상인지, 별개의 마이그레이션 지연인지는 **재현해서 가른다** —
  추측으로 둘 다 고치려 하지 않는다

## 범위

```
test/e2e.mjs        로그·상태 경로 격리
package.json        필요하면 스크립트 조정
```

`src/`·`public/`·`migrations/`는 건드리지 않는다. **검사의 내용은 바뀌지 않는다** —
같은 검사가 같은 숫자를 내야 한다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 실 `.wrangler/state`를 쓰게 하는 것 | 격리 러너의 전제다(함정 8). 실 DB는 불변이어야 한다 |
| 타임아웃을 늘려서 덮는 것 | 300초가 모자란 것이 원인이라는 근거가 아직 없다 |
| 검사를 줄이거나 건너뛰는 것 | 숫자가 의미를 잃는다 |

## 읽을 것

- `CLAUDE.md` 함정 8 — `e2e.mjs`는 격리 임시 D1이고 끝의 `spawnSync ETIMEDOUT`은 무해하다
- `STATE.md` — `CI=true`를 넣은 경위(wrangler 4.1x 프롬프트). 같은 종류의 환경 대응이다

### 진짜 원인 — `front.mjs`가 끝나지 않았다

실패 경로엔 `process.exit(1)`이 있는데 **성공 경로엔 종료 호출이 없었다.**
`pretendToBeVisual` jsdom이 **두 개**(부팅 복구 검사용 두 번째 포함) 살아 있고 rAF 타이머가
계속 돌아 이벤트 루프가 비지 않는다 → 요약을 찍고도 프로세스가 살아 있었다.

그래서 `e2e.mjs`의 **안전망 SIGKILL(180초)이 유일한 종료 수단**이었고,
검사가 193건 전부 통과해도 `npm run front`는 **exit 1**이었다.
옛 실행의 3분 15초 중 **~105초가 순수 hang**이다(75초 검사 + 105초 대기 + 마이그레이션·기동).

**함정 8의 "끝의 `spawnSync ETIMEDOUT`은 무해하다"가 이 결함의 흔적이다.**
숫자를 눈으로 읽는 사람에게는 무해하지만, **종료 코드를 믿는 셸·에이전트에는 매번 실패로 보인다.**
Codex가 세 번 연속 숫자를 못 낸 이유로 가장 유력하다.

### 범위 밖 한 줄 — `test/front.mjs`

티켓 범위는 `test/e2e.mjs`·`package.json`인데, hang이 `front.mjs`에 있어 **e2e만 고쳐서는
티켓의 목표("어느 셸에서든 자기 숫자를 낸다")에 도달할 수 없다.** `AGENT-CHAIN.md` §5 세 조건:

- ① **새 결정이 아니다** — 티켓의 목표 자체가 요구하는 것이고, 실패 경로의 `process.exit(1)`과
  대칭을 맞춘 것뿐이다
- ② **최소** — 한 줄. 검사를 줄이거나 건너뛰지 않았다(금지 3번). 요약을 찍은 **뒤**에 끝낸다
- ③ 이 절이 ③이다

파이프로 나가는 stdout은 비동기라 `write` 콜백에서 종료한다 — 그냥 `exit`하면 요약이 잘려
**숫자를 잃을 수 있다.**

### e2e.mjs — 환경에 기대지 않게

- wrangler의 **로그·설정·캐시를 임시 폴더로** 몬다: `WRANGLER_LOG_PATH` · `XDG_CONFIG_HOME` ·
  `XDG_CACHE_HOME` · `XDG_DATA_HOME` · `XDG_STATE_HOME` · `WRANGLER_SEND_METRICS=false`.
  T-01이 물린 `%APPDATA%\xdg.config\.wrangler\logs`는 **wrangler의 기본 전역 설정 위치**다
  (`XDG_CONFIG_HOME`이 설정돼 있었다는 증거가 아니다 — Windows 기본값이 그렇다).
  격리 러너가 임시 D1을 쓰면서 로그만 홈에 남길 이유가 없다.
  두 knob이 실제로 지원되는지 wrangler 4.112 번들에서 확인했다(`WRANGLER_LOG_PATH`가 전역 경로
  계산을 건너뛰고, `XDG_CONFIG_HOME`은 `~/.wrangler`가 디렉터리로 있으면 legacy 폴백에 밀린다 →
  **로그는 `WRANGLER_LOG_PATH`가 져야 한다**)
- 마이그레이션 단계에 상한 **120초**. 금지 2번("타임아웃을 늘려서 덮는 것")과 반대 방향이다 —
  없던 상한을 **새로** 두어 막힘이 스스로 이름을 말하게 한다. 실측 11.5초라 오발동 여지가 없고,
  걸리면 "느린 것이 아니라 막힌 것"이라고 로그 경로까지 짚어 준다
- 안전망 180 → **420초**. 이제 순수 hang 방지다. **실제 소요를 매 실행 찍는다** — 늘어나는 것이 보이게
- 실패했을 때 어디에 쓰려 했는지 두 줄로 찍는다 — T-01의 진단을 대신한다

**`.wrangler/state`는 그대로다**(금지 1번) — `--persist-to`는 손대지 않았다.

### 결정적 사실 — 마이그레이션 상한이 발동하지 않았다

1차에서 넣은 120초 상한이 안 떴다. 마이그레이션 자식이 돌고 있었다면
"마이그레이션이 120초 안에 끝나지 않았다(정상 ~12초)"가 출력됐어야 한다.
**Codex의 진단("마이그레이션 단계 미완료")은 그 출력과 어긋난다.**

그래서 원인을 더 추정하지 않고 **러너 안의 모든 대기에 상한을 채웠다** —
목적은 빠르게 만드는 것이 아니라 **다음 실패가 스스로 이름을 말하게** 하는 것이다.

### 상한이 없던 자리 둘

1. **헬스 대기의 `fetch`.** 반복 120회 × 250ms라 "최대 30초"처럼 보였지만, 서버가 포트만 열고
   응답하지 않으면 **그 한 번의 `fetch`가 영원히 걸린다** — 횟수로 감싼 상한은 상한이 아니다.
   `AbortSignal.timeout(2000)`으로 매 시도를 끊고, 실패 메시지에 포트와 로그 경로를 실었다
2. **`seedFixtures`**(`seed.mjs:14`에 상한 없는 `fetch`). `seed.mjs`를 고치지 않고
   **호출부에서** 60초로 씌웠다(실측 ~2초)

### 진단을 가르는 한 줄

마이그레이션 직후 러너가 `[e2e] 마이그레이션 완료 N초`를 찍는다.
표는 wrangler가 찍고 이 줄은 러너가 찍는다:

| 다음 실행에서 | 뜻 |
|---|---|
| 표는 있고 이 줄이 없다 | 마이그레이션 자식이 표를 찍고도 끝나지 않았다 (+ 120초 상한이 안 먹은 것도 별도 문제) |
| 이 줄 뒤 30초에 "dev 서버가…" | wrangler dev가 안 뜬다 |
| "워커 기동" 뒤 60초에 "픽스처 시드가…" | 워커가 요청에 응답하지 않는다 |
| **어느 상한도 안 걸리고 또 15분** | 막힌 곳이 대기가 아니라 **출력 자체**다 → 리포 밖 |

### 1차에서 넓힌 것을 되돌렸다

`XDG_CACHE_HOME`·`XDG_DATA_HOME`·`XDG_STATE_HOME`을 뺐다. 관측된 실패는 설정 디렉터리 쓰기(로그)
하나였는데 캐시까지 매 실행 비우게 해 뒀었다 — **근거 없이 넓힌 통제가 새 실패를 만든다.**
`WRANGLER_LOG_PATH`·`XDG_CONFIG_HOME`·`WRANGLER_SEND_METRICS`만 남겼다.

### 남은 가설 (리포 밖)

이제 러너 안에 상한 없는 대기가 없다. 그래도 **아무 메시지 없이** 15분을 돌면
`stdio: "inherit"`으로 나가는 stdout이 **소비되지 않는 파이프에서 막히는 것**이 가장 유력하다 —
마이그레이션 표가 520줄이고 출력이 정확히 거기서 끊겼다. 대처는 **파일로 리다이렉트**:
`npm run front > front.log 2>&1`. 확정되면 `AGENTS.md`에 넣도록 Cowork에 올린다(이 층 소유가 아니다).

기준선: typecheck 통과 · smoke 233(무변경) · front 193(무변경) · 실패 0 · verify exit 0

**wrangler가 찍은 것이 전부 사라졌다** — "30초 안에 응답 없음"만 남고 원인은 안 남는 구조다.
이 티켓이 "어느 셸에서든 자기 숫자를 낸다"를 목표로 하는데, 실패했을 때 이유를 못 내면 절반이다.

  기각한 가설이지만 여기서는 내가 만들 수 있는 함정이다). 실패 보고에 그 출력을 붙인다
- **앞 40줄 + 뒤 20줄**을 남긴다. 뒤쪽만 남기면 헬스 프로브의 접근 로그가 버퍼를 채워
  **기동 로그를 밀어낸다** — 처음 60줄 유지로 만들었다가 실제로 그렇게 돼서 고쳤다.
  "왜 안 떴나"의 답은 앞쪽에 있다
- dev 서버가 **일찍 죽으면 30초를 기다리지 않는다** — 종료 코드·시그널과 출력을 들고 즉시 끝낸다
- **실패하면 임시 폴더를 남긴다.** 지우면서 로그 경로를 알려 주는 건 아무 말도 안 하는 것과 같다 —
  실제로 3차 보고가 가리킨 `wrangler-logs`는 **이미 삭제된 폴더**였다

### 진단을 실제로 돌려서 확인했다

사본(`e2e.probe.mjs`)에서 헬스 URL을 틀리게 만들어 실패 경로를 강제했다.
`wrangler 4.112.0` 배너 · 바인딩 표 · `⎔ Starting local server...`가 보고에 붙는 것을 확인하고
사본과 잔여 임시 폴더를 지웠다. **진단이 비어 나오면 아무것도 만들지 않은 것이므로 이 확인이 필요했다.**

## 4차 — 근본 원인 확정 · 리포 밖으로 올림 (Claude Code · 07-30)

3차 진단이 답을 잡아 왔다:

```
✘ [ERROR] EPERM: operation not permitted, mkdtemp
          'C:\dev\personal-os-worker\worker\.wrangler\tmp\dev-XXXXXX'
✘ [ERROR] The expression evaluated to a falsy value: (this.#tmpDir)
```

`wrangler dev`가 **리포 안** `.wrangler/tmp/`에 임시 디렉터리를 못 만든다.
그 오류로 죽지 않고 `#tmpDir`이 falsy인 채 살아 있어서 헬스가 30초를 채운다.

### 확인한 것

- `.wrangler`·`.wrangler/tmp`의 **속성·ACL 정상**(Authenticated Users에 Modify, ReadOnly 아님).
  이 셸에서는 같은 자리에 잘 만들어진다
- Codex는 **리포 루트에는 쓸 수 있다** — `front.log`(49KB)가 실제로 써졌다. `.wrangler/` 아래만 막힌다
- ⇒ 파일시스템이 아니라 **Codex 샌드박스의 경로 정책**

### 왜 리포 안에서 못 고치나

wrangler는 `.wrangler`를 **설정 파일이 있는 디렉터리**에서 계산한다:

```
getWranglerHiddenDirPath(projectRoot) = join(projectRoot, ".wrangler")
projectRoot = dirname(config.userConfigPath)
```

그 디렉터리를 옮기려면 **`wrangler.toml`을 임시 폴더에 복제**하고 `main`·`migrations_dir`·
`[assets] directory` 세 상대 경로를 절대 경로로 고쳐야 한다. 가능하다 — 그런데
**검사가 진짜 설정을 안 보게 된다.** 나중에 바인딩·호환 플래그가 추가되면 러너만 조용히 옛 설정으로
돈다. 테스트 하네스에서 "실물과 다른 설정으로 통과하는 검사"의 대가는 크다.

### 그래서 위로 올린다 (§7)

**고칠 곳은 Codex 샌드박스의 쓰기 허용 목록이다** — `<repo>/.wrangler/`.
한 줄이면 `wrangler dev`만이 아니라 앞으로의 모든 로컬 wrangler 명령이 함께 풀리고 유지 비용이 0이다.

T-06의 방향("환경에 기대지 않게 만든다")은 **로그·상태까지는 통했다**(1·2차) —
`.wrangler/tmp`에서 끝난다. 티켓의 전제가 여기서 다한 것이고, 판단은 위층 몫이다.

샌드박스를 못 고친다는 답이 오면 `wrangler.toml` 복제안을 구현한다. 그때는 위 대가를 감수하는
명시적 결정이므로 티켓에 적고 들어가야 한다.

### 5차 — Codex 자신의 A/B로 확정 (07-30)

`wrangler.toml` 복제안을 꺼내기 전에, 원인이 정말 권한인지 Codex 셸에서 직접 갈랐다:

| probe | 결과 |
|---|---|
| `mkdtemp('<repo>\.wrangler\tmp\dev-')` — 기본 환경 | **EPERM** |
| 같은 것 — 추가 권한 환경 | **성공** (`dev-dwtlHS`) |
| `mkdtemp(os.tmpdir()+'\dev-')` | 성공 |
| `node -v` · `where node` | v24.14.1 · `C:\Program Files\nodejs\node.exe` — **이 셸과 동일** |

**같은 바이너리·같은 버전·같은 연산이 환경 권한에 따라서만 갈린다.** 변수가 하나다.
"권한 문제가 아니라 실행 환경 오류"라는 진단은 **Codex 자신의 실험으로 반증됐다.**

**확정된 조치**: Codex **기본 환경**에 `C:\dev\personal-os-worker\worker\.wrangler` **쓰기** 허용.
추가 권한 환경에서만 되는 것으로는 부족하다 — `npm run front`가 기본 환경에서 돈다.

**그래서 `wrangler.toml` 복제안은 구현하지 않는다.** 4차에서 "샌드박스를 못 고친다는 답이 오면
구현한다"고 적었는데, 고칠 수 있다는 것이 증명됐으므로 그 대가(검사가 진짜 설정을 안 보게 되는 것)를
치를 이유가 없다. 리포 쪽에서 더 할 일은 없다.

### 곁에서 드러난 것

`e2e.mjs`가 매 실행 `<repo>/.wrangler/tmp/bundle-*`를 남긴다 — **59개 쌓여 있었다.**
러너 헤더의 "흔적 0"은 `--persist-to` 임시 DB에 대해서만 참이고 wrangler의 번들 임시 폴더는 리포에 남는다.
정리해 뒀다. 삭제는 wrangler 자신의 sweep이 하는 일이라 러너에 넣지 않았다 —
돌고 있는 다른 wrangler가 쓰는 폴더를 지울 위험이 있다.
