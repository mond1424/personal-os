## ★★★ 무엇이 어긋났나 — 게이트와 재료가 한 `if` 에 묶여 있다

**`GuardWatch.kt` 114~123:**

```kotlin
if (level == 2) {
    val w = GuardSync.nextWake(...)
    val fire = w.state != NONE
    noteL2Gate(ctx, w, now, fire)
    if (!fire) return false                            // ★ 게이트 — L3 가 타면 안 된다
    if (w.state == OK) wakeLine = wakeSentence(now, w) // ⚠️ 재료 — L3 가 못 쓸 이유가 없다
}
```

**주석이 ②의 근거를 정확히 적어 뒀다:**

> Level 3·4 는 **데드라인·보호 일정이 근거**이므로 여기를 타지 않는다 —
> 태우면 **시험 전날 밤에 Guard 가 통째로 조용해진다.**

★★★★ **그 근거는 *"안 뜨게 하지 마라"* 이지 *"아침을 말하지 마라"* 가 아니다.**
**게이트를 안 태우려다 재료까지 버렸다.**

### ⚠️⚠️ 대가 — L3 가 L2 보다 아는 것이 적다

```
L2   지금 자면 6시간 30분 — 8시 기상 · 10시 양자물리및연습2    ★ 가장 구체적인 사실
L3   (그 줄이 아예 없다)
```

**그리고 L3 는 그 자리를 매일 같은 말 둘로 감싸고 있다** (스크린샷 · 소스 확인):

```
지금 자야 합니다             ⚠️ 매일 같다 — ADR-047 ①이 L2 에서 없앤 바로 그 명령
오늘 밤 8번째예요.            ★ 다르다
00:30 이후 135분 …           ★ 다르다
내일이 무너집니다.            ⚠️ 매일 같다 — 예언이고, 틀린 날이 오면 신뢰를 깎는다
```

★★★ **①은 *"매일 같은 앞부분"* 을 경계했는데 여기는 앞뒤가 둘 다 같다.**
**그래서 가운데를 안 읽는다** — 사용자 판정이 정확히 그것이다.

⚠️ **T-76 §결함 ②는 `title` 만 지목했다. 담당이 꼬리(178줄)를 찾아 목록을 채웠다** — **둘이다.**

## ★★ 할 일 — 셋. 순서가 있다

### ① 게이트와 재료를 가른다 (본체)

```kotlin
val w = GuardSync.nextWake(...)          // 레벨과 무관하게 부른다
if (level == 2) {
    val fire = w.state != NONE
    noteL2Gate(ctx, w, now, fire)
    if (!fire) return false              // ★ 게이트는 L2 에만
}
if (w.state == OK) wakeLine = wakeSentence(now, w)   // ★ 재료는 둘 다
```

⚠️ **`noteL2Gate`를 L3 에서 부르지 마라** — 이름 그대로 L2 게이트의 관측이고,
L3 가 함께 쓰면 **게이트가 안 걸린 밤과 걸린 밤이 같은 표에 섞인다**(T-70 과 같은 모양).
⚠️ **`return false` 를 L3 로 넓히지 마라** — ②가 막은 바로 그것이다. **시험 전날 밤이 조용해진다.**

★ **`nextWake` 호출이 레벨마다 한 번씩 늘어난다** — 비싸면 보고해라(고치지 말고).

### ② 꼬리를 뺀다 — *" 내일이 무너집니다."*

**`GuardWatch.kt:178` · `if (level >= 3)` 무조건.**

⚠️ **예언이다.** 안 무너진 날이 한 번만 와도 다음부터 안 믿는다 — ADR-047 이
*명령을 사실로* 바꾼 이유(*"틀린 사실은 명령보다 빨리 신뢰를 깎는다"*)가 그대로 걸린다.
**그리고 매일 같아서 정보가 0이다.**

★ **대체 문장을 새로 짓지 마라. 그냥 뺀다.** ①이 그 자리에 **사실**을 넣는다.

### ②-b ⚠️ **`0분`을 말하지 않는다** (2026-09-17 실측 추가)

**사용자 스크린샷 — 창 시작 직후에 뜬 L2:**

```
지금 자면 7시간 29분 — 8시 기상 · 10시 전자기및연습1.
★ 00:30 이후 0분 화면을 켜 두셨어요.
```

★★★★ **값은 정확한데 문장이 발동 이유를 설명하지 않는다.**

```
발동이 읽는 값   usedMin      마지막 screen_off 이후 연속 — ★ 창 밖에서부터 이어진 시간을 포함한다
문구가 말하는 값  windowMin    창 시작 이후만 센다 — ⚠️ 00:30 발동이면 0
```

★★ **T-69 가 그 둘을 *일부러* 갈랐다**(*"두 번째 개입부터 세 시간을 써도 늘 15분째"* 를
고치려고). **그 대가가 창 시작 직후에 극단으로 드러난 것이다** — 평소엔 두 값이
비슷해서 안 보였다. ⚠️ **T-69 를 되돌리지 마라. 그 갈라 놓음은 옳다.**

**바꿈 — `windowMin`이 0이면 그 조각을 통째로 뺀다:**

```
지금   00:30 이후 0분 화면을 켜 두셨어요.     ⚠️ 정보가 0이고, "왜 떴지?"를 만든다
바꿈   ★ (그 문장 없음)
```

★ **L2 에는 이미 사실이 있다** — *"지금 자면 7시간 29분 — 8시 기상 · 10시 전자기및연습1."*
**0분 줄이 빠져도 잃는 것이 없다.**

⚠️ **`usedMin` 으로 바꾸지 마라** — T-69 가 그것을 문구에서 뺀 이유가 그대로 남아 있다.
⚠️ **1분 미만을 반올림해 *"1분"* 이라 쓰지 마라** — **거짓이고, 0을 숨기는 것이다.**

### ③ 제목 — ⚠️ **이건 이 티켓에서 안 한다**

`title = if (level == 2) "아직 깨어 있네요" else "지금 자야 합니다"`

**①·②가 본문을 바꾼 뒤에 제목이 여전히 비는지 다시 본다.** 본문이 사실을 되찾으면
제목은 **레벨 표시로만 남아도 된다**(화면에 이미 `LEVEL 3` 배지가 따로 있다).
⚠️ **지금 정하면 바뀐 본문을 못 보고 정하는 것이다.**

★ 그래서 **검사 0** 이 합성 조각 하나를 먹여 **네 결과를 실제로 가르는지 먼저 증명**하고 시작한다.

**구현 상태**가 *"못 뽑았다"* 와 같은 모양이 돼 **검사 아홉이 한꺼번에 죽는다.** 그건 검사 3 하나의 몫이다.

### 변이 — 열. 전부 front 검사 하나씩만 죽인다

```
M1  게이트를 L3 에도 태운다              → front 2          (+ smoke 5 · T-60 7)
M2  게이트를 통째로 지운다                → front 3          (+ smoke 5 · T-60 7 ×2)
M3  wakeLine 대입을 다시 if 안으로        → front 1          (+ smoke 5b)
M4  꼬리를 레벨 무관하게 되살린다          → front 4
M5  다른 위협 문장을 level >= 3 에        → front 4b
M6  L2 에서 기상 줄을 뺀다                → front 5
M7  noteL2Gate 를 가지 밖으로 뺀다         → front 6          (+ smoke T-60 7)
M8  noteL2Gate 호출을 지운다              → front 6b
M9  windowMin > 0 조건을 지운다           → front 7
M10 공백을 앞에 붙이는 꼴로 되돌린다       → front 8
```

**티켓의 여섯에 넷을 더했다.** M5 를 더한 이유는 티켓이 *"꼬리를 되살린다 → 4 만 죽는다"* 로
하나만 뒀는데 **검사 4와 4b 가 서로 다른 명제**라 변이도 둘이어야 했기 때문이다
(M4 는 리터럴을, M5 는 레벨 의존을 문다). M8·M9·M10 도 같은 이유다.

⚠️⚠️ **★ M1 이 처음엔 검사 *셋*(2·4·8)을 죽였다 — 그게 이 배터리가 실제로 잡은 결함이다.**
검사 4와 8이 두 번째 표본으로 **"아침이 없는 L3 밤의 본문"** 을 쓰고 있었는데, 그 본문은
**검사 2의 명제(*"그 밤에 L3 가 뜬다"*)가 참일 때만 존재한다.** 게이트를 L3 에 태우자
그 밤이 안 뜨고 → 본문이 `null` → **문구를 세는 검사 둘이 게이트 때문에 죽었다.**
★ **둘 다 게이트를 안 타는 표본(`t76Mk(3, …)`)으로 바꿔** 좁혔고, 다시 돌리니 M1 은 검사 2만 죽인다.
★★ **티켓 §변이의 마지막 경고가 가리킨 것과 같은 자리인데 방향이 반대다** — 거기는
*"한 검사가 두 명제를 담으면 변이가 절반을 안 태운다"* 였고, 여기는
***"한 검사가 남의 명제를 업고 있으면 변이 하나가 여러 검사를 죽인다"*** 였다.

⚠️ **smoke 쪽이 함께 죽는 것은 좁힐 수 없고 그래야 한다** — T-60 4·5·5b·7 은 **스캐너**이고
front [T-77] 은 같은 게이트를 **돌려서** 본다. 한 결함을 두 방식이 보는 짝이지 중복이 아니다
(T-60 4의 주석이 *"앞만 보면 기기 쪽에서 조건을 태운 구현이 서버 검사를 통과한다"* 고 적어 둔 그 배치).

### ⚠️ 남겨 둔 것 — 본문이 빌 수 있는 밤이 하나 있다

②-b 가 조각을 조건부로 만들면서 **모든 조각이 동시에 빠지는 조합**이 하나 생긴다:
**L2 · 재료가 `NO_DATA`/`STALE`**(→ 기상 줄 없음) **· `windowMin == 0`**(→ 창 조각 없음) **·
`UsageProbe.currentApp` 이 `null`**(→ 앱 줄 없음) **· `n < watchTallyFrom`**(→ 순번 없음).
그러면 `body` 가 `""` 이고 알림엔 **제목만** 남는다.

★ **고치지 않았다** — 메우려면 **대체 문장을 새로 지어야 하고**, 그것이 티켓 §금지의 첫 줄이다.
그리고 그 조합은 *"말할 사실이 하나도 없다"* 가 실제로 참인 밤이라 **빈 본문이 거짓은 아니다.**
⚠️ L3 에서는 안 난다 — `l2done` 이 참이면 `n >= 2` 이고 `watchTallyFrom` 의 하한이 2라 **순번이 항상 붙는다.**
