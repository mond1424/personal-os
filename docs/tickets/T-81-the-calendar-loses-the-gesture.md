★★★★★ **②를 먼저 한다.** 사용자가 *"스파이크 쓰고 싶다"* 고 말한 근거가 ②인데,

## ② 느린 곳을 먼저 가른다 — ⚠️ 고치기 전에

```

(d) WebView 가 프레임을 못 낸다        ★ 그때만 Compose 가 후보가 된다
```

### 할 일 — **읽기와 계측만. 아직 아무것도 안 고친다**

```
□ ★ 달을 넘기는 경로가 네트워크를 타는가 (weeksOf · 캐러셀 렌더 경로를 코드로)

□ ★ transform 의 transition 지속 시간이 얼마인가 (CSS 원문)
□ ★★ 위 셋으로 설명이 안 되면 → (d) 후보. 그때 폰 계측이 필요하다
```

★★ **①(제스처)은 이 단계에서 안 건드린다.** 둘을 같이 만지면
*"무엇이 좋아졌나"* 를 못 가른다.

⚠️ **사용자에게 물을 것이 생기면 한 줄로 만들어 올려라** — *"넘어가는 데 시간이 걸리나,

답이 쓸모 있다**(`CLAUDE.md` §작업 방식 — 확인 절차를 제시하고 결과를 받는다).

## 근거 ① — 한 칸 넘길 때 기다리는 것은 **두 칸 뒤의 달**이다

`renderCalendar` 는 언제나 `[-2 … +2]` 다섯 달을 창으로 잡는다(`app.js:2170`).
한 칸 넘기면 창이 한 칸 밀리므로 **캐시에 없는 달은 새 가운데 기준 `+2`** 하나다.

```
넘기기 전   c-2  c-1  [c]  c+1  c+2          ← 다섯 다 캐시에 있다
넘긴 뒤     c-1   c  [c+1] c+2  c+3          ← c+3 하나만 없다
                        ↑              ↑
                  지금 보이는 칸     기다리는 칸 (두 칸 뒤)
```

- 창: `app.js:2170` `const months = [-2,-1,0,1,2].map(...)`
- 빠진 달만 고른다: `missingCalendarSegments` `app.js:2104-2112` — 캐시는 **비우기 전까지 안 줄어든다**(`calendarMonthCache` `app.js:2089`, 지우는 곳은 `invalidateCalendarCache` `app.js:2097` 하나 = **쓰기 뒤에만**)
- 그 하나를 **`await` 한다**: `app.js:2173` `const [cal, plist] = await calendarDataFor(dataMonths)` → `Api.calendar` `app.js:2149`
- 새로 조립하는 pane 은 `targetIndex = 4`(또는 `0`) = **그 `c+3` 칸**이다: `app.js:2253·2258`

★★ **보이는 칸(`c+1`)의 DOM 도 데이터도 이미 다 있다.** 손을 뗀 순간 화면은 끝나 있다.
그런데도 **`c+3` 의 응답이 올 때까지 다음 제스처가 통째로 막힌다.**

## 근거 ② — 막는 것은 `calBusy` 이고, 그것을 푸는 것은 그 응답이다

```
app.js:4195   calBusy = true                       ← 손을 뗀 순간
app.js:4211   trackSet(…, CENTER+dir, true, …)     ← 300ms CSS 전환 시작
app.js:4208   transitionend → finish()             ← ≈300ms 뒤

app.js:4218   blocked: (e) => … || calBusy || …    ← pointerdown 에서 통째로 버린다
```

⚠️ **`blocked` 는 `commit` 이 아니라 `pointerdown` 에서 본다**(`bindCarousel` `app.js:4114`).
그래서 그동안은 *"넘어가다 말았다"* 가 아니라 **손가락이 아예 안 따라온다** — 죽은 것처럼 보인다.

## 근거 ④ — (c) 는 300ms 고정 바닥이다

```
app.js:140    const TRACK_MS = 300, TRACK_EASE = "cubic-bezier(.22,.61,.36,1)"
app.js:156    el.style.transition = animate ? `transform ${TRACK_MS}ms ${TRACK_EASE}` : "none"
```

지속 시간은 **인라인으로 `trackSet` 이 한 곳에서 정한다**(CSS 원문엔 `transition` 이 없다).

위 셋으로 죽은 시간이 전부 설명된다(300ms 전환 + 0.5초 이상 왕복). 프레임을 못 내는 증상

⚠️ **다만 이것은 코드가 하는 말이지 폰이 하는 말이 아니다.** §확인 절차의 한 줄이 그것을 가른다 —
*"되돌아갈 때도 똑같이 느리다"* 가 오면 그때 (c)/(d) 가 열리고, **그때 폰 계측 절차를 짠다.**
