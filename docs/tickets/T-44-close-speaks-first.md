# T-44 — 마감 화면이 먼저 말한다

**발행** Cowork · 2026-08-22 · **담당** Claude Code · **작음**
**근거** [ADR-040](../../APP-ADR.md#adr-040) · **프런트만 · 서버 무변경 · 마이그레이션 없음 · APK 무관**

---

## 무엇이 어긋났나

**일일 기록이 계속 밀린다.** 2026-08-21 실측: `daily` 없음 · `logs 0` · `feelings []`.

**그런데 마찰은 이미 낮다** — `closeDay`는 `score`도 `feelings`도 요구하지 않는다.
버튼 하나면 닫힌다. **원인이 입력 비용이 아니다**(ADR-040 §맥락).

지금 마감 화면은 **백지다**:

```
SELF-DAILY SCORE
오늘에 점수를 매긴다면
—
```

**시스템이 그날을 이미 알고 있는데 아무 말도 안 한다.**

## 할 일 — 한 줄 추가가 전부다

**`S.today`가 이미 가진 것으로 만든다. 서버를 부르지 않는다.**

```
todo      남은 것
done      한 것
reassign  이월된 것
periods   진행 중인 기간
```

문장 예 (실제 문구는 담당이 정한다):

```
오늘 3개 했고 2개 남았어요. 이월 1개.
오늘 한 것이 없어요. 남은 것 2개.
오늘 담긴 것이 없는 날이에요.
```

### ★ 판단하지 않는다 — 이 티켓의 핵심

**센 것만 말한다.** 평가어를 쓰지 않는다:

```
✅  "3개 했고 2개 남았어요"
❌  "잘하고 있어요" · "아쉬운 하루였네요" · "평소보다 적어요"
```

**평가하는 순간 점수가 오염된다.** 이 앱은 거울이지 심판이 아니다(§6.3의 이탈이
잔소리에서 온다는 것과 같은 자리). **ADR-040 §결정이 명시적으로 금지한다.**

### 위치 — 점수 **앞**에 둔다

읽고 나서 매기는 것이 이 티켓의 전부다. 뒤에 두면 통보가 된다.

⚠️ **다만 앵커링을 감수하고 두는 것이다**(ADR-040 §감수하는 비용).
**순서만 바꾸면 되도록** 만들어라 — 재검토 트리거가 그것이다.

## 범위

```
public/index.html   마감 시트에 한 줄 (빈 요소)
public/app.js       숫자를 세어 문장을 만든다
test/front.mjs      검사
```

**서버 무변경 · 마이그레이션 없음 · APK 무관.**
새 API 없다 — `S.today`를 읽을 뿐이다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 평가어 쓰기 | **점수가 오염된다.** 거울이지 심판이 아니다 |
| AI 호출 | 매일 도는 것에 AI를 넣지 않는다(ADR-024와 같은 방향). 재료가 이미 결정론이다 |
| 서버 호출 추가 | `S.today`에 다 있다. 부르면 마감이 네트워크에 걸린다 |
| 세 줄 넘기기 | 읽을 것이 늘면 열기 싫어진다(ADR-040 §감수하는 비용) |
| 어제와 비교하기 | 어제 데이터를 또 불러야 하고, **비교는 평가로 미끄러진다.** v2 |
| 요약 실패가 마감을 막기 | T-33 §금지 1행과 같다. **기록의 봉인이 우선이다** |
| 빈 날에 아무것도 안 쓰기 | *"오늘 담긴 것이 없는 날"*도 사실이다. 침묵은 고장과 구별이 안 된다 |

## 완료 조건

```
typecheck 통과 · smoke 354(변화 없음) · front 305 → 309 이상 · 실패 0 · verify exit 0
```

**검사**

```
1  한 것·남은 것·이월이 실제 숫자로 나온다
2  ★ 아무것도 없는 날에도 문장이 나온다        ← 1의 짝. "침묵하지 않는다"를 세는 검사
3  평가어가 없다                               ← 없는 것을 세는 검사 (스캐너)
4  ★ 3의 스캐너가 살아 있는가                   ← 합성 문구를 실제로 잡는가
5  요약이 던져도 마감 버튼이 동작한다
```

**2와 5가 짝이다.** 1·3만 보면 *"빈 날엔 아예 안 쓰는 구현"*과
*"요약이 죽으면 마감도 죽는 구현"*이 둘 다 통과한다 —
T-33·T-38·T-39·T-41·T-43에서 **다섯 번** 물린 자리다.

⚠️ **검사 3의 금지어 목록을 코드와 검사 두 곳에 두지 마라.** 한 곳에서 읽는다 —
두 벌이 되면 갈라지고, 갈라진 쪽이 통과시킨다.

**변이**
- 빈 날에 문장을 안 쓴다 → **2만** 죽는다
- 평가어를 하나 심는다 → **3만** 죽는다
- 스캐너를 눈멀게 한다 → **3은 초록 · 4만** 죽는다
- 요약을 던지게 한다 → **5만** 죽는다

ADR-040의 재검토 트리거가 그 자리다.

**실제 문구 — 갈래 전부 · 문자열 그대로** (소스의 `closeSummaryText`를 그대로 평가해 뽑았다)

```
done=0 todo=0 reassign=0  →  "오늘 담긴 할 일이 없는 날이에요."
done=3 todo=2 reassign=0  →  "오늘 3개 했고 2개 남았어요."
done=3 todo=2 reassign=1  →  "오늘 3개 했고 2개 남았어요. 재배정 대기 1개."
done=3 todo=0 reassign=0  →  "오늘 3개 했고 남은 것이 없어요."

done=0 todo=0 reassign=2  →  "오늘 담긴 할 일이 없어요. 재배정 대기 2개."
```

실측 화면(검사 트리)에 뜬 줄: `오늘 한 것이 없어요. 남은 것 1개.`

**'이월'이라는 말을 안 썼다 — 티켓의 예시 문구에서 벗어난 유일한 곳이다.**
같은 화면의 TODO 행이 `defer_count`를 이미 **`N회 이월`**로 부르고 있어서,
`reassign`까지 이월이라 하면 **한 화면에서 한 단어가 두 가지를 뜻한다.**
재배정 대기는 그 행이 이미 쓰는 이름(`Missed 확정 — 재배정 대기`) 그대로 썼다. **재료는 티켓 그대로 `reassign`이다.**

**`periods`는 쓰지 않았다** — 헤더 칩(`#td-chips`)이 같은 것을 이미 그리고 있어
한 줄을 두 벌로 만들 뿐이다(세 줄 상한의 취지와 반대 방향).

**금지어 목록의 자리**

`public/app.js`의 `CLOSE_JUDGING_WORDS` **하나**(31개 · 칭찬/질책 · 비교 · 독려 셋으로 나뉜다).
`test/front.mjs`는 `ev("CLOSE_JUDGING_WORDS")`로 **그것을 읽어서** 스캔한다 —
검사가 자기 목록을 들면 두 벌이 되고 갈라진 쪽이 통과시킨다.

**변이 넷 — 실측 (각 변이마다 `npm run front` 전량 실행)**

| 변이 | 결과 | 죽은 검사 |

| 빈 날에 문장을 안 쓴다 (`else s = ""`) | 311 → **310** | **②만** — `빈 날 "" · 복구 "오늘 한 것이 없어요. 남은 것 1개."` |
| 평가어 하나 심기 (`… 잘하고 있어요.`) | 311 → **310** | **③만** — `잘하@오늘 3개 했고 2개 남았어요. 잘하고 있어요.` |

⚠️ **넷째만 티켓의 표와 다르다 — 그리고 처음엔 검사가 아니라 러너가 죽었다.**
`renderToday`가 던지자 `askClose`의 `refreshToday()`(await 없음)가 **처리되지 않은 거절**이 되어
node가 프로세스를 통째로 죽였다: raw 스택만 남고 **통과/실패 요약이 아예 안 찍혔다 — 숫자를 잃었다.**
T-06이 hang에서 없앤 것과 같은 실패 모양이라 `front.mjs`에 `process.on("unhandledRejection")`을 달아
**errors에 이름을 남기고 계속 가게** 했다. 그 뒤로는 위 표대로 `⑤`가 자기 이름을 말한다.
같이 죽는 「콘솔 오류 없음」은 **덤이 아니라 그 변이의 두 번째 진짜 증상**이다(실제로 거절이 샌다).

**⑤는 확인 모달까지가 아니라 실제 마감 경로에 태웠다.** 요약이 던지는 채로
`btn-close → cf-yes → daily.status === "closed"`까지 간다. 그리고 재렌더 전에 `#bchart`를 **비운다** —
옛 막대가 남아 있으면 렌더가 요약에서 죽어도 14칸이 보여 검사가 거짓 통과한다.

⚠️ **§범위의 *"마감 시트"*는 없다 (Cowork 확인).** 마감은 시트가 아니라 **Today 화면의
`SELF-DAILY SCORE` 카드**에서 버튼(`#btn-close`)으로 한다 — `.sheet`에 마감용은 하나도 없다.
시트를 새로 만들지 않고 **그 카드의 점수 앞**에 넣었다: 확인 절차의
*"하루 마감을 열면 점수 위에 한 줄"*이 가리키는 자리가 거기다.

**순서만 바꾸면 되게 뒀다.** 요약은 `.scorehead`의 **형제 한 줄**(`#close-summary`)이라
재검토 트리거가 걸리면 `index.html`에서 그 `<p>`를 `.scorehead` 뒤로 옮기는 것이 전부다.
`app.js`는 `$("#close-summary")`만 알고 위치를 모른다.
