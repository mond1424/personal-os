# T-95 — 수집 과제의 삭제 대신 기록 보존과 취소를 안내한다

**발행** 설계층 · 2026-10-08 · **담당** 감독층 · **상태** ⬜ 대기 · 사용자 승인 2026-10-08
**근거** ADR-050 2026-10-08 개정 · ADR-048 · T-88 ①-d 둘째
**착수 조건:** T-94 코드 커밋·설계 검토·종료 후. **서버 + 웹 · 마이그레이션 없음 · APK 변경 없음**

---

## 목표

수집 원장이 참조하는 할 일은 삭제할 수 있다는 약속을 하지 않는다. 사용자가 삭제 확인창까지 거친 뒤
일반 FK 오류만 받던 경로를 고치고, 실행 가능한 기존 취소 동작을 알려 준다. 알림 이관 뒤에도 기존 기록에 남는 문제다.
신규 과제 수락을 종료한 뒤에도 기존 참조는 보존하므로 이 티켓은 유효하다(사용자 승인 2026-10-08 · T-97).

## 범위 — 이 파일들만 고친다

```
src/db/index.ts              collected_items의 task_id 참조 존재 조회
src/services/tasks.ts       getTask의 참조 표시·deleteTask의 명시적 거절
public/app.js               openTask의 삭제 버튼/안내와 오래된 화면의 오류 처리
public/index.html           task 시트의 설명 자리
test/smoke.ts               API·참조 보존·상태별 오류 검사
test/front.mjs              상태별 버튼/안내와 실제 API 응답 짝 검사
docs/api-surface.md         응답 필드·409 계약 반영
```

범위 밖은 고치지 말고 보고한다. 일반 종료 문서와 커밋은 감독층 규칙을 따른다.

## 할 일

1. `GET /api/tasks/:id`에 **`collected_ref: boolean`**을 추가한다. `collected_items.task_id = id`인 행의 존재로
   조회 시 계산한다. state 필터로 FK 참조를 숨기지 않고, 제목·과목명으로 추정하지 않는다. DB 칼럼은 추가하지 않는다.
2. task 시트는 `collected_ref=true`면 모든 상태에서 삭제 버튼을 숨긴다. 가까운 설명 자리에
   `수집한 과제는 기록 연결 때문에 삭제할 수 없어요.`를 표시한다.
   - 미완료: `목록에서 빼려면 취소를 눌러 주세요.`를 덧붙이고 기존 **취소** 버튼을 쓴다.
   - 완료: `완료 기록으로 남겨요.` — 취소를 권하지 않는다.
   - 취소: `취소 기록으로 남겨요.` — 기존 취소 해제는 유지한다.
   손 할 일을 이어 열면 버튼·설명이 되돌아와야 한다. 일반 할 일의 삭제 정책은 그대로다.
3. 직접 DELETE나 옛 화면에서도 같은 참조를 확인해 **409**와 수집 기록이 막는다는 이유를 반환한다.
   미완료에만 `suggest:"cancel"`을 싣는다. 완료·취소에는 실행 불가능한 취소 제안을 싣지 않는다.
   참조된 task는 일반 마감/Guard 거절 분기보다 먼저 이 안내로 처리해 상태별 행동이 갈리지 않게 한다.
   참조 없는 task의 기존 마감·Guard 거절과 삭제 동작은 보존한다. FK는 최종 방어선으로 남긴다.
4. `collected_items.task_id`·event 연결은 보존하고, 취소는 기존 API를 호출한다.
   Tasks.org에 완료·삭제·취소 요청을 보내거나 그 상태를 읽지 않는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| FK 해제·CASCADE·task_id NULL 처리 | 비어 있는 연결은 「이미 했어요」의 뜻이며 이력을 잃는다 |
| 모든 409에 취소 제안 붙이기 | 완료·취소된 일에는 실행 불가능하다 |
| 삭제 오류를 성공 토스트로 덮기 | 기록은 남았는데 삭제됐다고 말하게 된다 |
| 일반 task 삭제·마감 트리거·Tasks.org 상태 변경 | 이번 결함의 범위가 아니다 |

## 읽을 것

- T-88 ①-d 보고, ADR-048, ADR-050 개정, T-80의 「이미 했어요」 의미
- `docs/schema-current.sql`의 collected_items.task_id 참조
- `tasks.getTask/deleteTask/cancelTask`, `public/app.js`의 `openTask`·`#tk-delete`·`execCancel`

## 완료 조건

```
typecheck 통과 · smoke A → B · front C → D · 실패 0 · schema 일치 · verify exit 0
```

- 미완료·완료·취소의 수집 task 모두 API `collected_ref=true`, DELETE 409, 원장 연결·task 행 불변.
  미완료만 cancel 힌트가 있고 기존 취소 API가 성공한다. 완료·취소에는 힌트가 없다.
- 같은 제목의 손 task는 `collected_ref=false`이고 기존 조건이 허용하면 삭제된다.
  복수 수집 행이 한 task를 참조해도 응답이 불어나지 않는다.
- 실제 API에 새 필드가 있다는 검사와 화면 상태별 검사를 짝으로 둔다. 서버가 필드를 빼면 화면 픽스처만 초록이어서는 안 된다.
- 수집 task → 손 task → 취소된 수집 task 순서로 열어 삭제 버튼과 안내가 남의 상태를 물려받지 않음을 확인한다.
- 변이: 참조 판정 무시 / 완료에도 cancel 힌트 / 버튼 항상 표시를 각각 넣어 담당 검사가 실패하는지 보고한다.

## 확인 절차 (사용자)

1. 배포 후 기존 수집 과제 시트를 연다. 삭제 버튼 대신 기록 보존 설명과 가능한 취소 행동이 보인다(할 일 2).
2. 완료·취소 과제에는 잘못된 취소 권유가 없고, 손 할 일을 이어 열면 종전 삭제 버튼이 보인다(할 일 2).
3. 필요 없는 미완료 시험 과제를 취소하면 pOS에서만 취소되고 기록은 남는다(할 일 4).
