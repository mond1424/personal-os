# T-74 — 과목은 제목이 아니라 `CATEGORIES`가 안다

**발행** Cowork · 2026-09-15 · **담당** Claude Code · **보통**
**근거** [ADR-037](../../APP-ADR.md#adr-037) §재검토 트리거 — *"개강 첫 실제 과제 이벤트에서 강좌 구분이 안 되면"* ·
2026-09-15 사용자 실측(iCal 원문 · 앱 화면)
**서버 층 + 마이그레이션 · APK 무관 · 프런트는 ②까지 무변경**

---

## ★★ 무엇이 어긋났나 — 제목이 거짓말을 한다

**2026-09-15, 사용자가 원문과 실제를 대조했다:**

```
SUMMARY      1주차 연습. 벡터대수학 기한             ⚠️ 틀렸다
실제 과목    전자기및연습1                            ← 사용자가 안다
CATEGORIES   전자기및연습1 (2026-20\, 45004_01_U)     ★ 맞다
```

★★★ **교수가 Moodle 에서 과제 이름을 잘못 지었고, 그것이 `SUMMARY`에 그대로 실린다.**
**`CATEGORIES`는 Moodle 이 강좌에서 자동으로 붙이므로 사람이 틀릴 자리가 없다.**

⚠️ **그래서 `SUMMARY`로 과목을 읽으면 안 된다.** `ADR-037 §실측`이 못 박은 그대로다 —
***"이름을 믿는 순간 그것이 해석이고, 개강 첫날 틀린다."*** **진짜로 틀렸다.**

★ **그리고 이것이 ADR-037 §재검토 트리거를 발화시켰다** —
*"개강 첫 실제 과제 이벤트에서 강좌 구분이 안 되면 `DESCRIPTION`·`SUMMARY`로 되는지 보고…"*
**답: `SUMMARY`로는 안 되고 `CATEGORIES`로는 된다.**

---

## ★★ 할 일 — 먼저 전수를 세고, 그다음 저장한다

### ① 전수 확인 — ⚠️ 본 것은 5건 중 1건뿐이다

**이 티켓의 전제는 *"과제 이벤트에는 `CATEGORIES`가 있다"* 인데, 근거가 표본 하나다.**

```
지금 collected_items 의 5건 각각에 대해 라이브 iCal 원문에서
  · CATEGORIES 가 있는가 · 없으면 몇 건인가
  · 형식이 같은가 (과목명 + 괄호 안 학기·코드)
  · ★ 다중값(이스케이프 안 된 쉼표로 둘 이상)이 실제로 오는가
```

⚠️ **없는 건이 하나라도 있으면 멈추고 보고해라.** 그러면 *"과목을 항상 안다"* 가 거짓이고,
**모를 때 무엇을 보여줄지**가 설계 질문이 된다(Cowork 자리).
⚠️ **`UCLASS_ICAL_URL`을 출력하지 마라.**

### ② 저장 — 원문 그대로. **쪼개지 않는다**

**마이그레이션 하나로 `collected_items`에 칸을 추가한다.**

```
categories   TEXT   ★ 원문 그대로. 언이스케이프만 한다
```

★★ **언이스케이프는 해석이 아니라 복원이다** — RFC 5545 가 정한 `\,` `\;` `\\` `\n` 넷을
원래 글자로 되돌리는 것뿐이고, **되돌리지 않으면 저장된 값이 원문이 아니다.**
⚠️ **그 이상은 하지 마라.** 과목명·학기·코드로 쪼개는 것은 **해석이고 표시할 때 한다.**
`docs/schema-current.sql:78`이 `summary`에 *"원문 그대로. 해석 금지"* 라고 적어 둔 것과 같은 규칙이다.

⚠️ **다중값을 지금 다루지 않는다** — ①이 *"실제로 온다"* 를 보여주면 그때 별도로 정한다.
**한 칸에 원문 그대로 넣으면 다중값이 와도 잃는 것이 없다.**

### ③ 표시 — 제안·목록에서 과목을 함께 보여준다

```
지금   1주차 연습. 벡터대수학 기한
바꿈   ★ 전자기및연습1
         1주차 연습. 벡터대수학 기한
```

⚠️ **제목을 고치지 마라. 지우지도 마라.** 원문이 틀렸다는 것 자체가 사실이고,
**사용자가 uclass 에서 그 제목으로 찾는다.** 과목을 **위에 얹기만** 한다.

★ **괄호 안(학기·코드)은 화면에 안 보여준다** — 저장은 하되 표시는 과목명까지다.
⚠️ **그러려면 쪼개야 하는데, 그 쪼개기는 표시하는 쪽에 둔다**(저장은 원문 그대로 §②).

**검사**

```
1  ★ CATEGORIES 가 있는 VEVENT 를 파싱하면 categories 가 원문으로 저장된다
2  ★ \, 가 쉼표로 복원된다 (\; \\ \n 도)                    ← 언이스케이프
3  ★ CATEGORIES 가 없는 VEVENT 도 죽지 않는다 (null 로 남는다)  ← 짝
4  ★ 쪼개지 않았다 — 저장값에 괄호·학기·코드가 그대로 있다    ← 해석 금지 스캐너
5     summary 는 그대로다 (제목을 안 고쳤다)                   ← 회귀
6  ★ 다중값 CATEGORIES 도 통째로 들어간다 (잃지 않는다)
```

⚠️ **2는 *"쉼표가 있다"* 가 아니라 *"백슬래시가 없다"* 도 함께 본다** — 한쪽만 세면
`\,` 를 `,` 로 바꾸는 대신 `,` 를 덧붙이는 구현이 통과한다.
⚠️ **픽스처에 고정 날짜를 쓰지 마라**(함정 12).
⚠️ **훑기가 0건을 내면 스캐너에 물어야 하는 것 하나를 먹여 보고 넘어가라**(함정 17·18).

**변이**

```
언이스케이프를 지운다              → 2 만 죽는다
categories 를 안 싣는다            → 1 만 죽는다
CATEGORIES 없는 건에서 던진다      → 3 만 죽는다
괄호 앞에서 잘라 저장한다          → 4 만 죽는다 (1은 초록 — 값이 있으니)
summary 를 categories 로 덮어쓴다  → 5 만 죽는다
다중값의 둘째부터 버린다           → 6 만 죽는다
```

⚠️ **넷째 변이가 1을 안 죽이는 것이 4의 존재 이유다** — *"실렸다"* 만 세면
**해석해서 잘라 넣은 구현이 통과한다.**

### 변이 — 6 + 2

```
1 언이스케이프를 지운다              죽은 검사 [1,2,3,4,6]   (기대 [2] — 과잉)
2 categories 를 안 싣는다            죽은 검사 [1,2,3,4,6]   (기대 [1] — 과잉)
3 CATEGORIES 없는 건에서 던진다      ⚠️ 요약을 못 냈다 (아래)
4 괄호 앞에서 잘라 저장한다          죽은 검사 [4,6]         ★ 1은 초록 — 티켓이 4를 둔 이유가 그대로 섰다
5 summary 를 categories 로 덮어쓴다  죽은 검사 [5]           OK
6 다중값의 둘째부터 버린다           죽은 검사 [6]           OK
A(표시) 쪼개기를 지운다              죽은 검사 [과목, 괄호]  (기대 [괄호] — 과잉)
B(표시) 없어도 빈 배지를 그린다      죽은 검사 [짝]          OK
```

**1·2가 과잉인 것은 설계상 불가피하다** — 값이 없거나 복원이 안 되면 **원문과 비교하는 검사는 전부**
죽는다. 과소 검출이 아니라 과잉 검출이다. ★ **티켓이 특히 못 박은 것(4가 1을 안 죽인다)은 그대로 섰다.**

⚠️⚠️ **변이 6은 처음에 아무것도 안 죽였는데, 코드가 아니라 내 변이가 틀린 것이었다.**
`indexOf(",")`가 **이스케이프된 쉼표**(`2026-20\,`)를 먼저 집어서 자를 자리를 못 찾았다 —
**변이가 아무 일도 안 하고 초록이 났다.** 그 앞 회차엔 **heredoc 이 `(?<!\),` 의 백슬래시를 삼켜**
`(?<!\),` 가 되어 `SyntaxError` 로 죽었다(**함정 17 을 이 티켓에서 다시 물었다** — 스크립트를
`Write` 로 파일에 쓰고서야 살았다). ★ **변이가 초록이면 구현이 아니라 변이를 먼저 의심한다.**

### ⚠️ 닫지 못한 것 — 변이 3이 요약을 못 낸다 (Cowork 자리)

`parseIcal`이 던지게 만들면 **smoke 가 요약도 개수도 못 내고 죽는다.** 세 번 쫓았다:

```
smoke.ts:1829  T-41 의 첫 파싱          → parse() 헬퍼로 번역했다
smoke.ts:1848  접힌 줄 파싱             → 같은 헬퍼로 번역했다
smoke.ts:1869  await uclass.collect(…)  → ★ 여기는 못 막았다
```

**`collect()`가 *안에서* 부르는 파싱은 헬퍼를 안 지난다.** 그 던짐은 최상위 `await`의 거절로 가고,
그것이 **요약 없는 죽음**이다(함정 8 · `runner-exit` 규약이 막으려던 바로 그 모양).
닫으려면 **T-41 블록의 `collect()` 호출 전부**를 감싸야 해서 **T-74 범위 밖으로 뒀다.**

★ **대신 헬퍼 주석에 경계를 적어 뒀다** — *"여기가 막는 것은 검사가 직접 부르는 파싱까지다"*.
⚠️ **그 주석이 없으면 다음 사람이 "다 막았다"로 읽는다.** 반만 막은 가드가 다 막은 얼굴을 하는 것이
이 리포가 반복해서 물린 모양이다(함정 15).
