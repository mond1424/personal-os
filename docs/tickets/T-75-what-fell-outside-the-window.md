# T-75 — 창 밖으로 떨어진 것을 볼 자리가 없다

**발행** Cowork · 2026-09-21 · **담당** Claude Code · **보통**
**근거** 2026-09-21 사용자 실측(T-79 §확인 절차 넷째를 *"대기가 없어서"* 못 했다) ·
2026-09-15 실측(`collected_items` 5건 중 `new` 가 남아 있는데 화면에 아무것도 없다) ·
[T-42 결정 ①](T-42-*.md)(7일 창) · [T-78](T-78-accepted-homework-becomes-a-task.md) · ADR-048
**서버 + 프런트 · 마이그레이션 없음 · APK 무관**

---

## ★★★ 무엇이 어긋났나 — 제안은 **밀어 주는 것**뿐이고, **가서 보는 자리**가 없다

```
GET /api/collected/pending   state='new' AND starts_at ∈ [now, +7일]
```

**7일 밖의 과제는 화면 어디에도 없다.** 11월 마감짜리는 **11월이 되어서야 처음 보인다.**

⚠️ **그 사이 사용자는 그것이 수집됐다는 사실조차 모른다** — 알림함엔
*"파일이 등록되었습니다"* 만 남고 **내용이 없다.**

★★★★ **T-79의 확인 절차 넷째가 그것에 막혔다.** *"accept 토스트가 '캘린더와 대기'를
말하는가"* 를 재려는데 **누를 것이 화면에 없었다.** `new`는 DB에 남아 있다.

### ★★ 그런데 창을 넓히는 것은 답이 아니다

```
창을 넓힌다   ⚠️ 11월 과제가 9월부터 매일 뜬다 — ADR-047 의 "항상 뜨는 것은 정보가 0"
창을 둔다     ★ 7일 창은 "지금 결정할 값이 있는가" 를 재는 것이고, 그 판단은 맞다
```

★★★★★ **갈라야 할 것은 창이 아니라 *길*이다.**

```
밀어 주는 것 (push)   ★ 7일 창. 지금 결정할 값이 있는 것만.   ← 그대로 둔다
가서 보는 것 (pull)   ⚠️ 없다.                                 ← 이 티켓이 만드는 것
```

⚠️ **ADR-048 그대로다** — *"모르는 버튼은 없는 버튼"* 이 여기서는
***"볼 자리가 없는 것은 없는 것이다."***

## 할 일

### ① 먼저 확인한다 — ⚠️ 이 티켓의 전제다

```
□ ★ collected_items 에 state='new' 가 지금 몇 건인가
□ ★ 그 각각의 starts_at 이 7일 창 안인가 밖인가
□ GET /api/collected/pending 이 지금 실제로 몇 건을 주는가
□ 제안 시트(sh-coll)는 지금 무엇으로 열리는가 — 스스로 뜨나, 입구가 있나
```

⚠️ **`new`가 0건이면 이 티켓의 근거가 다르다.** 그때는 멈추고 보고해라 —
*"창 밖이라 안 보인다"* 가 아니라 *"수집이 안 되고 있다"* 이고, **고칠 곳이 다른 층이다.**
★ 세 번째가 `new` 수와 같으면 창이 안 막고 있다는 뜻이다 — 그것도 멈출 자리다.

### ② 서버 — 목록은 창을 안 쓴다. **`pending`은 손대지 않는다**

```
GET /api/collected/pending   ★ 그대로. 7일 창 그대로            ← 밀어 주는 길
GET /api/collected/list      ★ 새로. state='new' 전체, 창 없음  ← 가서 보는 길
```

⚠️ **같은 엔드포인트에 파라미터로 두지 마라.** 두 뜻이 한 이름을 쓰면
**어느 쪽을 검사했는지가 흐려지고**, 한쪽이 틀렸을 때 다른 쪽이 그것을 덮는다
(함정 15의 `#cal-list` 와 같은 자리 — **이름을 공유하면 그 이름의 오류를 못 센다**).

★ **응답 모양은 `pending`과 같게 한다**(`categories` 포함 — T-74). 화면이 같은 시트를 쓴다.
⚠️ **정렬은 `starts_at` 오름차순** — 가까운 마감이 위다.

### ③ 프런트 — **새 목록을 만들지 않는다. 입구만 만든다**

**Works 탭 · 대기 칸 바로 위에 한 줄:**

```
들어온 것 3개                    ← 누르면 기존 제안 시트(sh-coll)가 열린다
```

★★★ **자리를 Works 로 정한 근거는 T-78 이다** — 수락하면 **대기에 들어간다.**
**들어오는 것과 들어온 것이 같은 칸의 앞뒤**여야 흐름이 한 줄로 읽힌다.

⚠️ **새 시트·새 탭·새 목록을 만들지 마라.** 시트는 이미 있고, ①의 넷째가 그 여는 법을 말한다.
★ **수가 보이는 것이 ADR-048 의 요구다** — *"3개"* 가 있어야 존재를 안다.

⚠️ **0건이면 그 줄이 아예 없다.** *"들어온 것 0개"* 는 매일 자리를 차지하면서
아무것도 말하지 않는다 — **T-79가 방금 걷어낸 그것이다.**

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
★ ①의 확인 결과가 §보고에 있다 — new 몇 건, 그중 창 밖 몇 건
```

**검사**

```
1  ★ list 가 7일 창 밖의 new 를 준다                      ← 본체
2  ★ pending 은 여전히 창 밖을 안 준다                     ← 1의 짝. 회귀
3  ★ list 가 accepted·dismissed 를 안 준다                 ← 경계
4  ★ list 가 starts_at 오름차순이다
5  ★ Works 입구가 N 을 말한다 (N>0)
6  ★ N=0 이면 그 줄이 없다                                 ← 5의 짝
7  ★ 그 줄을 누르면 기존 시트가 열린다 (새 DOM 을 안 만든다)
8  ★ 시트에서 수락하면 event 와 task 가 둘 다 생긴다        ← T-78 회귀
```

⚠️ **2가 없으면 *"창을 없앴다"* 는 구현이 통과한다** — `list`가 창 밖을 주니 1은 초록이다.
**이 티켓에서 제일 쉬운 잘못이고, 정확히 §금지의 첫 줄이다.**
⚠️ **6이 없으면 5가 *"항상 띄운다"* 로도 통과한다.**
⚠️ **7은 *새 DOM 을 안 만든다*까지 세라** — 시트를 복제한 구현은 화면이 같아 보인다.
⚠️ **픽스처에 고정 날짜를 쓰지 마라**(함정 12). **창 안팎은 `now` 기준 상대로 잡는다.**

**변이**

```
list 에 7일 창을 건다              → 1 만 죽는다
pending 의 창을 뺀다               → ★ 2 만 죽는다 (1은 초록 — list 는 여전히 주니까)
list 의 state 필터를 뺀다          → 3 만 죽는다
정렬을 뒤집는다                    → 4 만 죽는다
입구가 수를 안 쓴다                → 5 만 죽는다
0건에도 입구를 띄운다              → ★ 6 만 죽는다 (5는 초록)
입구를 span 으로 되돌린다          → 7 만 죽는다
accept 에서 task 를 안 만든다      → 8 만 죽는다
```

★★ **둘째·여섯째가 짝의 존재 이유다.** 돌려 보고 안 태워진 절반이 있으면 변이를 늘려라.
★★★ **변이가 *붙었는지*와 *되돌아갔는지*를 둘 다 본다**(함정 16 — T-78·T-79가 양쪽으로 물렸다).

## ★ 이 티켓이 안 하는 것

- **`pending`의 창을 안 바꾼다.** ★ 밀어 주는 길의 판단은 맞다.
- **알림함 문구(*"파일이 등록되었습니다"*)를 안 고친다** — Android 알림이고 별건이다.
- **자동 수락을 안 만든다.** ⚠️ 수락은 사람의 판단이고, T-78 이 그 산물을 정했다.
- **놓친 것을 다시 밀어 주지 않는다** — 이 티켓은 *가서 보는 길*만 만든다.
  **한 번 놓친 것을 또 미는 것은 ADR-047 이 경계한 반복 개입이다.**
- **Guard 쪽은 한 줄도 안 건드린다.**

#### ① 확인 결과 — **둘 다 멈출 자리가 아니다**

원격 `collected_items` (2026-09-21 15:33 KST · 읽기만):

```
new 4건          ⚠️ 0건이 아니다 → 수집은 돌고 있다. 층이 다르지 않다
pending 0건      ⚠️ new 수와 다르다 → 창이 실제로 막고 있다
```

**`new` 4건의 창 판정:**

```
20260914-001  09-14 13:10  ★ 과거   벡터대수학 2주차 연습문제 제출 기한
20260921-001  09-21 13:15  ★ 과거   벡터대수학 3주차연습문제 제출 기한   (오늘이지만 15:33 기준 지났다)
20260904-001  11-30 23:59  ★ 창 밖  중간고사대체과제 기한
20260904-002  11-30 23:59  ★ 창 밖  학기과제 기한
```

★★★ **티켓이 못 본 것 하나 — 가려지는 것이 위아래 둘 다다.**
티켓은 *"7일 밖"* 만 말했는데 **절반은 과거다.** `starts_at >= t.now` 라는 **아래 끝**이
그만큼을 가린다. `list`는 창이 없으므로 넷 다 준다 — 고칠 것은 없고, **근거가 티켓보다 넓다.**

**④ 시트 여는 법**: `#td-coll-open`의 `onclick`이 `renderCollected(rows); openSheet("sh-coll")`.
⚠️ **그 버튼은 Today 카드 안에 있고, 그 카드는 `pending 0`이라 `display:none`이다** —
즉 **지금 시트는 도달 불가**다. 티켓의 전제가 화면에서 그대로 확인된다.

#### ②③ 무엇을 했나

```
GET /api/collected/pending   손대지 않았다. 7일 창 그대로        ← 밀어 주는 길
GET /api/collected/list      새로. state='new' 전부 · 창 없음     ← 가서 보는 길
Works · 대기 위              "들어온 것 N개" → 기존 시트를 연다
```

⚠️ **`db`의 함수 이름이 `collectedList`가 아니다 — `collectedNewAll`이다.**
`collectedList(env, limit)`가 **이미 있었고 원장 전체 덤프**(모든 state)다.
★ 같은 이름을 쓰면 **이 티켓이 방금 세운 원칙을 그 줄이 깬다** — 뜻이 다르면 이름도 다르다.
(밖에서 보는 이름은 `/api/collected/list`가 맞다.)

★ **담당이 정한 것 하나**: `starts_at IS NULL`은 **이 목록에도 안 넣는다.**
`pending`과 같은 이유다 — `accept`가 `events` 행을 못 만들고 **400으로 죽는다**.
**누를 수 없는 것을 보여주는 것은 보여주는 것이 아니다.** 검사가 그 규칙을 진다.
⚠️ 그래서 이 목록의 수와 `state='new'` 전체 수가 갈릴 수 있다. 실측 원장엔 그런 행이 없다(`no_date` 0).

★ **수락 뒤 Works를 다시 그린다** — 시트가 Today만 갱신하고 있었다. **수락은 대기에 task를
만드는데**(T-78) 바로 뒤의 대기 목록이 안 바뀌고 입구의 수도 안 줄었다.

#### ★★ 변이 배터리 — **N7이 붙고도 아무것도 안 죽였다**

```
N1 list 에 7일 창을 건다        → ★ 1 만
N2 pending 의 창을 뺀다         → 2 + 기존 pending 검사    (같은 계약의 두 각도)
N3 list 의 state 필터를 뺀다     → ★ 3 만
N4 정렬을 뒤집는다              → ★ 4 만
N5 입구가 수를 안 쓴다           → ★ 5 만
N6 0건에도 입구를 띄운다         → ★ 6 만
N7 입구가 시트를 안 연다         → ★ 7 만   ← ⚠️ 처음엔 **0건이었다**
N8 accept 에서 task 를 안 만든다 → ★ T-78 검사 1 만 (= 검사 8)
```

⚠️⚠️ **N7이 처음에 `494 · 실패 0`을 냈다 — 앵커는 1로 붙었는데.**
★★★ **그 화면은 *"검사가 튼튼하다"* 와 같다**(함정 16 · `AGENT-CHAIN` §8의 *"살아남는 검사"*).
**검사 7의 두 조각이 둘 다 저절로 참이었다:**

```
① 열렸나   `|| $("#sh-coll").style.display !== "none"`
           인라인 display 가 빈 문자열이라 **늘 참**. 계약은 classList.contains("on") 하나다
② 몇 줄인가 개수만 셌는데 #coll-list 엔 **앞 블록(T-74)이 남긴 줄 둘**이 그대로 있었다
```

★ **고친 것 셋**: 먼저 `closeAll()`(이미 열려 있으면 *"열었다"* 가 뜻이 없다) ·
`classList.contains("on")` 하나로 · **내 id(`t75-a`·`t75-b`)로** 묻는다.
고친 뒤 N7은 `493 · 실패 1`로 **7만** 죽인다.

⚠️ **N1도 처음엔 1과 4를 함께 죽였다** — 검사 4가 `먼 것`의 **존재**에 매달려 있었고,
그건 정렬이 아니라 검사 1의 몫이다. **전수 오름차순 하나로 줄이자 N4에서만 죽는다.**
★ 그 앞서 검사 4는 `l1[0]`을 고정했다가 죽기도 했다 — **앞선 fixture가 남긴 `new` 행이
더 있었다**(8/18짜리 둘). 정렬은 맞았고 **내 고정이 틀렸다.**

#### ⚠️ 안 한 것

- **`pending`의 7일 창을 한 글자도 안 건드렸다.** 검사 2가 그것을 진다.
- **알림함 문구·자동 수락·다시 밀어 주기**는 안 만들었다(§안 하는 것).
- **밀린 4건을 소급 처리하지 않았다** — 배포 뒤 사용자가 그 줄에서 처리한다.
