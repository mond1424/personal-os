# T-42 — 수집한 것을 제안 카드로 꺼낸다

**발행** Cowork · 2026-08-21 · **담당** Claude Code · **보통**
**근거** [ADR-030](../../APP-ADR.md#adr-030) 본체 · [ADR-037](../../APP-ADR.md#adr-037)
**마이그레이션 없음 · APK 무관 · 서버 + 프런트**

---

## 무엇을 만드나

T-41이 `collected_items`에 쌓는다. **그것을 꺼내 1탭으로 `events`에 넣는 자리가 없다.**

```
cron → collected_items (state='new')        ← T-41 이 여기까지
                    ↓
        Today 제안 카드 → [추가 / 무시]      ← 이 티켓
                    ↓
                 events
```

**T-33의 outcome 카드와 같은 모양을 쓴다.** `#td-guard`가 이미 그 자리에 있고,
`data-state`로 `ask`/`none`/`error`를 가르며 `catch`가 화면을 안 막는다.
**새 패턴을 만들지 않는다.**

## ★ 결정 ① — 앞으로 7일 것만 묻는다

**개강 첫 수집에서 학기 전체가 한꺼번에 들어온다.** 4월 캘린더 실측이 주당 3~5건이었으므로
한 학기면 **60건 이상**이고, 창이 `+365일`이라 그것이 전부 첫 수집에 `new`로 앉는다.

**60건을 하나씩 묻는 것은 적극성 문제를 푸는 게 아니라 만드는 것이다.**

```
starts_at 이 앞으로 7일 안  →  제안한다
그 밖                       →  state='new' 그대로 두고 때가 되면 올라온다
starts_at 이 과거           →  묻지 않는다 (지난 것이다)
```

**한 번에 3~5건으로 줄어든다.** 그리고 *"지금 필요 없는 것을 왜 묻나"*도 함께 없어진다.

⚠️ **7일은 v1의 값이고 설계가 아니다.** 2주 뒤 발표 준비처럼 **미리 알아야 하는 것**이
분명히 있다 — 그것은 보호 규칙 제안(ADR-030의 나머지 절반)이 다룰 일이고,
**실사용이 요구하면 넓힌다.** 지금 넓히면 첫 수집이 다시 60건이 된다.

## ★ 결정 ② — "마감"이라고 쓰지 않는다

**`DTSTART`가 마감 시각인지 아직 모른다**(ADR-037 §실측의 ❌ 셋째).
T-41이 칼럼을 `starts_at`이라 지은 것도 그래서다.

```
✅  "9/3(수) 23:00 · 5주차 과제"        ← 원문과 시각만
❌  "마감: 5주차 과제"                   ← 이름을 믿었다
❌  "과제 5 제출"                        ← 원문을 다듬었다
```

**`summary` 원문을 그대로 보여주고 그대로 `events.title`에 넣는다.**
다듬는 순간 그것이 해석이고, 개강 첫날 틀린다.

## 할 일

### ① 서버 — 셋

```
GET  /api/collected/pending        state='new' 이고 starts_at 이 [지금, +7일] 인 것
POST /api/collected/:id/accept     events 생성 → state='accepted' · event_id 연결
POST /api/collected/:id/dismiss    state='dismissed'
```

**`accept`가 만드는 것은 `events` 행 하나다.** `title = summary` 원문,
`date`·`time` = `starts_at`에서. **보호 규칙은 붙이지 않는다** — 그것은 별개의 결정이고
ADR-030의 나머지 절반이다.

⚠️ **`accept`는 멱등이어야 한다.** 이미 `accepted`면 `events`를 또 만들지 않는다 —
느린 네트워크에서 두 번 눌리는 것이 이 카드의 기본 조건이다.

⚠️ **`dismissed`는 다시 묻지 않는다.** `last_modified`가 바뀌어도 그대로다
(T-41이 *"state는 건드리지 않는다"*로 이미 정했다). **거절한 것을 다시 묻는 것이 잔소리다.**

### ② 프런트 — 카드 하나, 열면 목록

```
카드    "새로 들어온 일정 3건"          ← Today 위 한 줄. T-33의 #td-guard 자리
누르면  시트에 셋이 나열된다
각각    [추가]  [무시]
```

**"전부 추가"를 두지 않는다.** 개강 첫 수집에 무엇이 들어오는지 아직 아무도 못 봤다 —
**보고 나서 정한다.** 지금 만들면 오수집을 한 번에 캘린더에 붓는 버튼이 된다.

`data-state`는 T-33과 같게 셋: `ask` · `none` · `error`.
**`none`과 `error`가 화면에서 똑같이 안 보이는 것**도 같고, 그래서 **둘을 가르는 검사가 짝**이다.

## 범위

```
src/services/collected.ts   (신규 또는 uclass.ts 확장) pending · accept · dismiss
src/db/index.ts             SQL
src/index.ts                라우트 셋
public/api.js               래퍼 셋
public/app.js               카드 + 시트
test/smoke.ts               서버 검사
test/front.mjs              화면 검사
```

**마이그레이션 없다** — 0018의 `state`·`event_id`를 쓰는 것뿐이다.
**기기 무변경 · APK 무관.**

## 금지

| 하지 말 것 | 왜 |
|---|---|
| "마감"·"제출" 같은 단어 쓰기 | `DTSTART`의 뜻을 모른다. **이름을 믿는 순간 해석이다** |
| `summary` 다듬기 | 같은 이유. 원문 그대로 `title`에 넣는다 |
| "전부 추가" 버튼 | 첫 수집에 무엇이 오는지 아직 못 봤다. **보고 나서 정한다** |
| 7일을 넓히기 | 첫 수집이 60건이 된다. 넓히는 것은 실사용이 요구할 때 |
| 보호 규칙을 함께 붙이기 | 별개의 결정이다. ADR-030의 나머지 절반 |
| `dismissed`를 다시 묻기 | 거절한 것을 또 묻는 것이 잔소리다 |
| 카드를 여러 개 늘어놓기 | *"대충 눌러 치우게 되고, 그런 것은 없는 것보다 나쁘다"*(`app.js:452`) |
| `catch`에서 화면 막기 | 수집이 없는 상태에서도 Today가 떠야 한다(T-33 §금지 1행) |
| 새 시트·새 닫기 경로 | `closeSheet`·`handleBack`이 이미 있다(T-34) |

## 완료 조건

```
typecheck 통과 · smoke 335 → 341 이상 · front 291 → 297 이상 · 실패 0 · verify exit 0
```

**검사 — T-33이 배운 것을 그대로 쓴다**

```
서버
1  pending 이 7일 밖·과거·dismissed 를 안 준다      ← 셋을 각각 넣고 확인
2  accept 가 events 를 만들고 state·event_id 를 잇는다
3  ★ accept 를 두 번 불러도 events 가 하나다        ← 2의 짝 (멱등)
4  dismiss 뒤에는 pending 에 안 나온다

화면
5  대기가 있으면 카드가 뜬다 · state='ask'
6  하나를 처리하면 남은 수가 준다
7  대기가 없으면 안 뜬다 · state='none'
8  ★ 조회가 실패하면 안 뜬다 · state='error'         ← 7의 짝
```

**3과 8이 짝이다.** 1·2·4·5·6·7만 보면 *"두 번 누르면 두 개 생기는 구현"*과
*"조회가 항상 실패해도 초록인 검사"*가 둘 다 통과한다 — T-33·T-38·T-39·T-41에서 **네 번** 물린 자리다.

**변이**
- `accept`의 멱등 가드를 뗀다 → **3만** 죽는다
- `catch`도 `none`으로 만든다 → **8만** 죽는다
- 7일 필터를 뗀다 → **1만** 죽는다

## 확인 절차 (사용자)

**시크릿을 넣기 전까지 카드가 안 뜬다** — `pending`이 비어 `state='none'`이다.

넣은 뒤 (개강 후):

```
□ Today 위에 "새로 들어온 일정 n건" 이 뜬다
□ 눌러서 하나 [추가] → 캘린더에 그 제목 그대로 들어간다
□ [무시] 한 것은 다시 안 나온다
□ 카드 문구에 "마감" 같은 단어가 없다        ← 결정 ②가 지켜졌는지 눈으로
```

⚠️ **첫 수집 뒤에 `collected_items`를 한 번 훑어봐 달라.** 7일 밖에 몇 건이 쌓였는지,
`summary`가 실제로 어떤 문장인지가 **개강 후 해석 단계(별건)의 유일한 재료**다.
