# T-58 — 한 번 붙여넣으면 학기가 채워진다

**발행** Cowork · 2026-09-05 · **담당** Claude Code · **큼**
**근거** [ADR-045](../../APP-ADR.md#adr-045) · **마이그레이션 하나 · 위임 금지 · APK 무관**

---

## 무엇을 만드나

**9/3 Today는 `todo 0 · 일정 0`이었다.** T-52·53·54·55가 배관을 끝까지 놓았는데도 —
**원천에 든 것이 60일에 8건, 그중 넷이 공휴일**이었다.

```
시간표 한 번 입력  →  학기 내내 매일 3~6시간이 화면에 있다
```

**이 프로젝트에서 입력 한 번의 수익률이 이만큼 높은 데이터는 없다.**

## ★ 자동 수집은 불가능하다 — 실측으로 확인됐다

```
uclass iCal      개강 이틀째에도 VEVENT 0. Moodle 캘린더엔 과제·퀴즈 마감만 실린다
폰 캘린더        사용자가 시간표를 넣어 두지 않았다 (반복 일정 15개를 손으로 만드는 일이다)
포털 그리드      ★ 시작 칸만 그린다 — 길이를 말하지 않는다
```

⚠️ **포털을 긁어도 안 된다는 것이 이 티켓의 전제다.** 2026-09-05에 포털의 `schedule-days`
그리드(7열 × 15행)를 실제로 읽었더니 `월 10:00 전자기및연습1` 처럼 **시작 교시 한 칸**만 있었다.
실제로는 **같은 과목이 월 3시간 · 목 2시간**이다. **그리드는 그 차이를 담고 있지 않다.**

## 입력 — 사용자가 이미 쓰는 형식 그대로

**2026-09-05에 사용자가 실제로 준 것:**

```
월요일 10시-13시 전자기및연습1, 14시-16시 역학및연습2
화요일 공강
수요일 10시-13시 양자물리및연습2, 14시-17시 수리물리1
목요일 10시-12시 전자기및연습1, 14시-17시 역학및연습2
금요일 10시-12시 양자물리및연습2, 14시-17시 인간과인공지능
```

⚠️ **이 형식을 규격으로 굳히지 마라.** 다음 학기에 사용자가 다르게 쓸 수 있고,
**그때 조용히 어긋나면 이 티켓이 무의미해진다.** 그래서 ②가 필요하다.

### ① 붙여넣기 → 파싱

**정규식으로 충분하다** — `<요일> <시>시-<시>시 <과목>` 의 반복.
`공강`·빈 줄은 건너뛴다. ⚠️ **모델을 부르지 마라**(비결정론 · 비용 · 오프라인).

### ② ★ 파싱 결과를 보여 주고 고치게 한다 — 이 티켓의 핵심

```
읽은 것을 표로 보인다  →  틀린 칸을 그 자리에서 고친다  →  저장
```

⚠️ **파서가 못 읽은 줄을 조용히 버리지 마라.** *"3줄 중 2줄만 읽었어요"* 가 보여야 한다 —
T-54·T-55가 두 번 배운 그 자리다. **못 읽은 원문을 그대로 보여 주면 사용자가 손으로 고친다.**

### ③ 규칙을 저장하고 날짜는 전개한다

```sql
-- 저장한다 (규칙)
과목명 · 요일 · 시작시각 · 종료시각 · 학기 시작일 · 학기 종료일
```

⚠️ **15주치 행을 만들지 마라**(원칙 1). 학기가 바뀌거나 시각이 틀리면 그 전부를 손봐야 한다.
`CalendarContract.Instances`가 하는 일과 같은 모양이고, **T-53이 이미 그 판단을 따랐다.**

**전개는 조회하는 창만큼**이고, Today·캘린더가 그것을 읽는다.

### ④ 학기 범위

**포털 학사일정의 `[대학] 개강일 09-01~12-21`이 그 값이다**(2026-09-05 확인).
⚠️ **코드에 박지 마라** — 사용자가 입력할 때 함께 받는다. 다음 학기에 또 바뀐다.

## 범위

```
migrations/00NN_timetable.sql   (신규) — ★ 위임 금지 영역
src/db/index.ts                 규칙 CRUD · 창 전개 SQL
src/services/                   전개 규칙 (도메인)
src/index.ts                    엔드포인트
public/app.js · index.html      붙여넣기 · 확인 표 · 표시
test/smoke.ts · test/front.mjs  검사 · 스키마 목록에 파일명
docs/api-surface.md · schema-current.sql   재생성
```

**APK 무관 · `guard/` 무변경.**

⚠️ **마이그레이션이 있으므로 Antigravity 위임 불가**(`AGENT-CHAIN` §4). 직접 한다.
⚠️ **`periods`를 고쳐 쓰지 마라** — 그것은 기간 하나이고 반복이 없다. **새 테이블이다.**
⚠️ **`events`에 넣지 마라** — 그러면 15주치 행이 되고 원칙 1을 어긴다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 인스턴스를 저장 | **파생값은 저장하지 않는다**(원칙 1) |
| 파싱에 모델 사용 | 비결정론 · 오프라인에서 안 돈다. 정규식으로 된다 |
| 못 읽은 줄을 조용히 버리기 | **T-54·T-55가 두 번 배운 자리다** |
| 확인 없이 바로 저장 | 형식이 다음 학기에 바뀐다. **고칠 자리가 있어야 한다** |
| 학기 범위를 코드에 박기 | 매 학기 바뀐다. 입력으로 받는다 |
| 휴강·보강 예외 | ADR-045 ④ — 사용자가 학교 앱 알림으로 안다 |
| `periods` 재사용 | 반복이 없다. 기간과 시간표는 다른 것이다 |
| 폰 캘린더에 쓰기 | ADR-045 ① — 갈라짐을 열지 않는다 |

## 완료 조건

```
typecheck 통과 · smoke +N · front +N · 실패 0 · verify exit 0
```

⚠️ **기준선은 `STATE.md` §기준선이 원장이다** — 착수 시점 숫자를 거기서 읽고 보고에 적는다.

**검사**

```
1  붙여넣은 텍스트가 규칙으로 파싱된다 (9칸 · 5과목 · 화요일 0)
2  ★ 못 읽은 줄이 사용자에게 보인다                     ← 조용히 버리지 않는가
3  ★ 확인 화면에서 고친 값이 저장된다                    ← 2의 짝
4  ★ 규칙이 창 범위만큼 전개된다 (인스턴스가 DB에 없다)   ← 없는 것을 세는 검사
5  ★ 4의 짝 — 전개된 수가 맞다 (한 주에 9칸)
6  같은 과목이 요일마다 다른 길이를 갖는다               ← 월 3h · 목 2h
7  학기 범위 밖 날짜에는 안 뜬다
8  ★ 학기 범위가 입력에서 온다 (코드에 상수가 없다 · 스캐너)
```

**4와 5가 짝이다.** 4만 보면 *"아무것도 전개 안 하는 구현"*이 통과한다.

**6이 이 티켓이 존재하는 이유다** — 포털 그리드로는 못 얻는 값이고,
**같은 길이로 뭉개는 구현이 통과하면 시간표가 틀린 채 학기를 간다.**

⚠️ **검사 신호에 토스트나 `until`을 쓰지 마라**(함정 14).
⚠️ **fixture에 고정 날짜를 쓰지 마라**(함정 12) — 학기 범위도 상대로 잡는다.

**변이**
- 파싱을 안 한다 → **1만** 죽는다
- 못 읽은 줄을 버린다 → **2만** 죽는다
- 확인 화면의 수정을 무시한다 → **3만** 죽는다
- 인스턴스를 DB에 저장한다 → **4만** 죽는다
- 전개를 안 한다 → **5만** 죽는다
- 요일별 길이를 첫 칸으로 통일 → **6만** 죽는다
- 학기 범위를 무시한다 → **7만** 죽는다
- 범위를 코드에 박는다 → **8만** 죽는다

```powershell
npx wrangler d1 migrations apply personal-os --local
npx wrangler d1 migrations apply personal-os --remote
npm run deploy
```

```
□ 설정에서 시간표를 붙여넣는다 (아래 원문 그대로)
□ ★ 읽은 결과가 표로 뜨고, 틀린 칸을 고칠 수 있다
□ ★★ 오늘이 평일이면 Today 에 수업이 뜬다        ← T-52~55 가 못 닿은 그 목적

□ 화요일에는 수업이 없다
```

**★ 셋째 줄이 이 프로젝트가 8/19 이래 겨눠 온 것이다** — *아무것도 안 넣어도 볼 것이 있다.*
