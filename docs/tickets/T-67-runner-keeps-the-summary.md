# T-67 — 러너는 무엇이 던져도 요약을 낸다

## 무엇이 어긋났나 — 배터리를 못 믿게 됐다

**T-66이 M5를 재려는 순간 러너가 죽었다:**

```
Error: 응답이 안 와요 — 잠시 뒤 다시 해 주세요     ← T-57 의 15초 fetch 상한
    at Timeout.task (jsdom/browser/Window.js:552)  ← jsdom 타이머 콜백에서 던진다
Node.js v24.14.1                                   ← 프로세스가 죽고 요약을 잃는다
```

**`front.mjs`는 `unhandledRejection`만 받는다.** 이 거절은 **타이머 콜백**에서 올라온
`uncaughtException`이라 **아무도 안 받는다.**

⚠️ **함정 8이 *"러너의 모든 대기에 상한이 있으므로 실패는 이름을 말한다"* 고 적는데,
이 죽음은 이름 대신 침묵을 남긴다.** 배터리는 요약이 없는 것을 *"아무도 안 죽었다"* 로 읽고,
**그 순간 변이표 전체가 근거를 잃는다**(§8이 이미 경고한 자리 — 이번엔 변이가 아니라 환경이 죽였다).

## ★ 둘은 한 쌍이다 — 따로 고치면 증상만 옮긴다

**T-66 담당이 가드를 넣어 봤고 되돌렸다. 그 실측이 이 티켓의 설계를 정한다:**

```
①  uncaughtException 을 안 받는다        →  죽는다. 요약이 없다
①만 고친다 (가드를 넣는다)               →  ★ 420초 hang 으로 바뀐다. 요약은 여전히 없다
②  front.mjs:2336 의 await ev(Api.task(…)) 에 상한이 없다   ← hang 이 사는 자리
```

**①은 죽음을 멈추고 ②는 그 자리에서 빠져나오게 한다.** 하나만 하면
*"프로세스가 죽는다"* 가 *"영원히 안 끝난다"* 로 바뀔 뿐이고, **화면에서 둘은 같다.**

## 할 일

### ① 러너가 `uncaughtException`도 받는다 — 그 검사만 빨간불로

```
지금   unhandledRejection 만
바꿈   uncaughtException 도 · ★ 받아서 "그 검사 실패"로 기록하고 계속 간다
```

⚠️ **삼키지 마라.** 조용히 지나가면 T-54가 없앤 부류가 검사 층에 생긴다 —
**던진 것의 메시지와 스택 첫 줄이 실패 사유에 남아야 한다.**
⚠️ **전역 상태를 오염시킨 예외는 다음 검사도 죽일 수 있다.** 그때는 **연쇄로 빨간불이 나는 것이
맞다** — 요약이 나오면 사람이 읽고 가른다. **요약을 잃는 것보다 낫다.**

### ② 상한 없는 대기를 메운다

**`front.mjs:2336`의 `await ev(Api.task(...))`.** 함정 8이 *"모든 대기에 상한이 있다"* 고
적는데 **여기 하나가 비어 있다.**

⚠️ **상한 값을 이 티켓에 적지 않는다** — 담당이 정하고 §보고에 근거를 적는다.
⚠️ **다른 `await ev(...)`도 같은 모양인지 한 번 훑는다.** 있으면 **이름만** 올린다(고치지 마라) —
T-64 §훑기와 같은 규칙이다.

### ③ ★ 원인은 이 티켓이 안 고친다

**19:15 이후 T-47 검사 넷이 계속 실패하는 것**(같은 날 18:50엔 442/0)은 **범위 밖이다.**

```
이 티켓이 사는 것   요약이 나온다  →  무엇이 몇 개 죽었는지 읽힌다
안 사는 것          왜 T-47 이 죽나
```

⚠️ **순서가 이렇다.** 요약이 없으면 원인을 잴 자가 없다. **먼저 자를 고친다.**

## 범위

test/e2e.mjs        (필요하면) 자식 종료 코드 해석

⚠️ **T-47의 검사를 고치지 마라** — 원인 미상이다. 고치면 증상을 지우고 원인을 잃는다.

빼면 배터리가 가벼워진다.

**변이**
- `uncaughtException` 핸들러 제거 → **1·2** 죽는다 (포함 관계 — 죽으면 요약도 없다)

- 상한 초과에 이름을 안 붙인다 → **5만** 죽는다

⚠️ **첫 변이가 둘을 죽이는 것은 예상이다.** 나머지가 하나씩 죽는 것이 증거다.

## ★ 실측이 티켓의 전제 둘을 정정했다

**환경을 기다리지 않고 세 경로를 직접 쏘아 봤다**(node 24.14.1 · jsdom):

```
jsdom 타이머가 throw    →  virtualConsole 의 jsdomError 로 간다 · ★ 프로세스는 산다
떠돌이 Promise.reject   →  unhandledRejection (front.mjs 가 이미 받고 있었다)
최상위 await 거절       →  ★ uncaughtException 으로 온다 — T-66이 죽은 자리는 여기다
```

**① 티켓은 둘을 한 경로로 적었는데 아니었다.** *"타이머 콜백에서 던진다"* 는 이미 잡히고 있었고
(그래서 그것만 막았으면 아무것도 안 고쳐졌다), 실제로 죽인 것은 **최상위 `await`의 거절**이다.
그래서 검사도 **1(타이머)과 1b(최상위 await)로 갈랐다.**

**② 더 중요한 정정 — 가드만 달면 더 나빠진다.**

```
지금            죽는다 · 요약 없음                       ← 빨간불로는 보인다
가드만 단다     ★ 모듈은 죽은 채 프로세스가 exit 0       ← 요약 없이 **초록**이다
 (jsdom rAF가 살아 있으면)  ★ 420초 hang · 요약 없음     ← T-66이 실제로 본 그 모양
```

⚠️ **최상위 `await`가 거절하면 모듈 본문은 이미 끝난 것**이라 *"기록하고 계속 간다"* 가
성립하지 않는다. 계속 갈 곳이 없다. **그래서 가드는 계속 가는 장치가 아니라 요약을 내는
장치로 만들었다** — 티켓 ①의 문구와 다르고, 그 근거가 위 실측이다.

## 넣은 것

### ① 가드 — 사유를 남기고 · 코드를 못 박고 · 죽었으면 요약을 낸다

```
① errors 에 사유(메시지 + 스택 첫 줄)를 남긴다      조용히 안 지나간다
② process.exitCode = EXIT_ABORTED 로 못 박는다      나중에 정상 종료해도 초록이 안 된다
③ 60초 안에 검사가 하나도 안 늘면 요약을 내고 끝낸다  러너가 살아 있으면 아무것도 안 한다
```

**판정을 "검사 수가 늘었는가"로 했다** — 관측(토스트·DOM)이 아니라 **러너 자신의 계수**다(함정 14).
**60초**는 앱의 상한(15초)보다 넉넉히 길어 **느린 왕복 하나를 죽음으로 오해하지 않고**,
e2e 안전망(420초)보다 훨씬 짧다.

**요약을 내는 자리를 하나로 모았다**(`emitSummary`). 전에는 정상 끝에서 직접 찍었고, 그러면
중단 경로가 생길 때 **자리가 둘이 되어 한쪽만 낡는다.** 부팅 실패도 같은 자리를 지나게 했다 —
예전엔 `exit(1)`이라 *"요약 없이 죽은 런"* 과 **종료 코드가 같았다.**
마지막 방벽으로 `process.on("exit")`을 뒀다 — **어떤 이유로 나가든 요약은 남는다.**

★ **중단 줄이 "마지막으로 지난 검사"를 말한다.** 함정 8의 계약(*"실패는 어디서 막혔는지
이름을 말한다"*)이 이 경로에선 반쪽이었다 — 앱의 상한 문구만 있고 **어느 자리인지**가 없었다.
`ok()`가 이름을 한 칸 들고 있게 해서 메웠다. 실제로 이것으로 다음 막힘 자리를 짚었다(아래 §훑기).

### ② 상한 없는 대기를 메웠다 — `capped`

**`capped(이름, 프라미스, ms)`.** `until`과 다르다: `until`은 **조건**을 폴링하고 이것은
**프라미스**를 기다린다 — 프라미스가 영영 안 정산되면 `until`은 도움이 안 된다.

**상한은 30초** (근거): 앱 자신의 상한(`api.js`의 `REQ_TIMEOUT_MS` 15초)의 **두 배**다.
그래야 **앱의 이름 붙은 거절이 항상 먼저 도착하고**(*"응답이 안 와요"*), 이 상한은 프라미스가
**아예 정산되지 않는** 경우만 잡는다. 앱보다 짧으면 이쪽이 먼저 터져 **원인을 가린다.**

⚠️ **⑧의 단언은 한 글자도 안 고쳤다.** 들여쓰기만 들어갔다(try/catch 안이 됐다).
답이 안 오면 **이름 붙은 빨간불을 대신 세운다** — `{entries:[]}` 같은 값을 만들어 넘기면
⑧이 *"안 옮겨갔다"* 로 **조용히 초록이 된다.** 그게 더 나쁘다.

### ③ e2e 가 요약 줄을 직접 본다

**`spawnSync` → `spawn` + tee.** 자식의 stdout을 **흘려보내면서 동시에 모은다.**
`spawnSync`+pipe 는 200초 동안 화면이 침묵하고, `stdio:"inherit"` 는 부모가 못 읽는다 —
둘 다 포기할 수 없었다.

⚠️ **종료 코드만으로는 부족하다.** *"코드는 내고 줄은 안 내는"* 구현을 코드만 보고는 못 가른다.
**줄과 코드를 둘 다 본다**: 줄은 *"냈는가"*, 코드는 *"어떤 끝이었나"*.

**`test/runner-exit.mjs` 를 새로 뒀다** (근거): 코드를 `front.mjs`가 내고 `e2e.mjs`가 읽으므로
**두 파일에 같은 숫자가 박히면 반드시 갈라진다**(CLAUDE.md의 그 규칙). 한 곳에 뒀다.

```
0  요약을 냈다 · 실패 0
2  요약을 냈다 · 실패 N          ← 정상적인 빨간불
3  요약을 냈다 · 다만 도중까지다  (중단)
그 밖 = 요약을 못 냈다          ← e2e 가 이름 붙인다
```

⚠️ **1을 안 쓴다.** node 가 죽을 때 기본으로 내는 값이 1이라, 1을 '검사 실패'에 쓰면
**요약을 낸 빨간불과 요약도 못 낸 죽음이 같은 값**이 된다 — T-66에서 배터리가 거짓말을 한
자리가 정확히 그것이다.

1b ★ 최상위 await 거절이 오는 자리를 가드가 받는다 (코드가 '중단' · 감시가 걸린다)

4  ★ 4의 스캐너가 살아 있다                              4의 짝

실제로 이 티켓이 티켓의 전제 하나를 그렇게 정정했다. 빼면 그 정정을 아무도 다시 못 센다.

★ **스캐너가 자기 자신을 읽어 한 번 빨간불이 됐다** — 짝의 합성 문자열
(`t47After = await ev(`)을 스캐너가 **자기 소스에서** 찾았다. 찾을 꼴을 쪼개서 조립했다
(`"t47After = await " + "ev("`). T-55(검사와 구현이 같은 이름을 공유한다)의 사촌이고,
**검사가 자기 자신을 대상으로 읽는 자리**라 한 칸 더 조심해야 한다.

## 변이 — 하나씩 죽는다

| 변이 | 결과 |
|---|---|
| M1 `uncaughtException` 핸들러를 없앤다 | **1b·3** — 포함 관계 |
| M2 요약 줄을 안 낸다 | ★ **요약 없음 · 코드 1 · e2e 게이트가 잡는다** (= 검사 2) |
| M3 사유를 안 남긴다 | **3만** |
| M4 T-47 앞의 상한을 뺀다 | **4만** |
| M5 상한에 이름을 안 붙인다 | **5만** |
| M6 가드가 검사까지 실패로 센다 | **6만** |

**M1이 둘을 죽이는 것은 필연이다** — 3이 세는 것(`errors`에 사유가 남는가)의 **대상이 그
핸들러 안에 산다.** 핸들러가 없으면 남길 자리가 없다. 티켓도 첫 변이의 포함 관계를 예상했다
(다만 티켓은 *"1·2"* 로 봤고 실제는 **1b·3**이다 — 정상 런에서는 아무것도 안 던져서
핸들러가 없어도 요약이 나오기 때문이다. 포함 관계는 **중단되는 런에서만** 1·2로 성립한다).

★ **처음엔 6이 1b·3에 딸려 죽었다 — 좁혔다.** 6의 자가 `fails.length`였는데 그것은
**같은 블록의 다른 검사가 실패하면 같이 움직이는 값**이다(T-64가 고친 그 모양).
**가드가 만지는 순간의 값**으로 바꿨다(`t67Guard.failsAfter`). 실측이 그것을 확인한다:
좁히기 전 M1이 **1b·3·6 셋**을 죽였고, 좁힌 뒤 **1b·3 둘**만 죽는다.

## 남은 빚

- **T-47 넷의 원인은 여전히 미상이다** — 이 티켓은 자만 고쳤다(티켓 ③).
  이번 측정 창에서는 그 실패가 **재현되지 않았다**(기준선 450/0). 시각 의존이 남는다.
- **상한 없는 대기 79곳**은 그대로다. 이제 막히면 **요약과 이름이 남으므로** 다음에 고를 수 있다.
- **`process.on("exit")`의 요약은 동기 출력이다** — 파이프로 나갈 때 잘릴 수 있다.
  정상·중단 경로는 write 콜백을 쓰므로 안 잘린다. 이건 **마지막 방벽에만 남은 위험**이다.
