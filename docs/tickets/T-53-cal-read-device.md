# T-53 — 폰 캘린더가 Today 를 채운다

**발행** Cowork · 2026-08-28 · **담당** Claude Code · **큼**
**근거** [ADR-029](../../APP-ADR.md#adr-029) · [ADR-028](../../APP-ADR.md#adr-028) · **APK 필요 · T-52 선행**

---

## 무엇을 만드나

**아무것도 안 넣어도 오늘 화면에 무언가 있다.**

```
폰 캘린더  →  CalendarContract 읽기  →  POST /api/cal/sync  →  Today
```

**이것이 이 프로젝트에서 "넣을 것이 없다"를 처음 공략하는 티켓이다.**
위젯 셋은 *넣기의 비용*을 깎았고, 이건 *넣지 않아도 되게* 한다.

## ★ 상한 — 여기서 멈춘다

```
✅  권한 · 대상 캘린더 선택 · 창 읽기 · 보내기 · 읽기 전용 표시
❌  쓰기 방향 (앱 → 캘린더)        ← 9월. 갈라짐을 물리적으로 차단한다
❌  보호 제안 카드                 ← ADR-030. 다음 티켓
❌  위치·참석자·알림 필드           ← 제목·날짜·시각/종일만
❌  충돌 해소 UI                   ← LWW 하나다
```

## 할 일

### ① 권한 — `READ_CALENDAR`

런타임 권한이다. **유도 UI가 필요하다.**

### ② ★ 권한이 없으면 조용하지 않다 — 이 티켓의 핵심

⚠️ **2026-08-28에 실제로 겪었다**: 알림 권한을 끄자 Guard 가 통째로 멈췄고,
**앱을 다시 켜도 아무도 그것을 말해 주지 않았다.**

```
권한 없음 · 대상 캘린더 미선택 · 마지막 동기화 실패
   →  Today 에 한 줄로 보인다 (제안 카드가 아니라 상태 표시)
```

**같은 실패를 캘린더에서 반복하지 않는다.** 권한이 빠지면 **일정이 조용히 사라지고**,
그건 *"넣을 게 없다"* 와 화면상 구별이 안 된다 — **이 티켓이 고치려는 바로 그 증상으로 되돌아간다.**

### ③ 대상 캘린더 선택

⚠️ **전체 동기화는 잡동사니다**(§함정). 계정이 여럿이다(구글 다중·삼성).

```
설정 어딘가에 캘린더 목록 → 체크 → settings 에 저장
```

**선택 전에는 아무것도 안 가져온다** — ②의 상태 표시가 그것을 말한다.

### ④ 읽기 — 창과 반복

```
창        오늘(열린 날) ~ +N일 (기본 60 · settings)
반복      CalendarContract.Instances 로 창 범위만 전개
식별      ext_uid = '<eventId>:<날짜>'  (인스턴스 단위)
멀티데이  시작일 1건으로 축약 (v1)
```

⚠️ **반복을 빼면 개강 후 수업이 통째로 안 들어온다.** 이 티켓에서 가장 값이 큰 부분이다.

### ⑤ 시점

```
앱 열 때  +  하루 1회 보호 일정 pull 직전  +  수동 새로고침
```

⚠️ **pull 직전이라는 순서를 지킨다** — 뒤집히면 **캘린더의 시험이 그날 알람 예약을 놓친다**(§함정).

### ⑥ 화면 — devcal 일정은 읽기 전용

앱에서 수정·삭제할 수 없다. **수정은 캘린더에서.** 쓰기 방향이 붙기 전까지 갈라짐을 물리적으로 막는다.

### ★ ②의 세 상태를 어디에 어떻게 띄웠나 · 문구가 갈리는가

**Today의 한 줄 `#td-cal`이고, 판정은 순수 함수 `calStatusLine(st)` 하나가 한다.**
**네이티브는 사실만 준다**(`permission`·`targets`·`lastError`) — **이름과 문구를 정하지 않는다.**
두 곳에서 상태를 정하면 그 둘이 갈라지고, 갈라진 쪽이 조용한 문구를 고른다.

```
noperm     폰 캘린더를 못 읽어요 — 캘린더 권한이 꺼져 있어요     [허용하기]
notarget   가져올 캘린더를 아직 안 골랐어요                      [고르기]
error      캘린더 동기화가 실패했어요 — <서버·네트워크 원문>      [다시 시도]
ok / off   안 뜬다
```

**판정 순서가 곧 사용자가 할 일의 순서다**: 권한 → 대상 → 동기화. 권한이 없으면 목록 자체를
못 읽으므로 뒤의 것을 말해도 **할 수 있는 일이 없다.**

- **사유를 문장으로 뭉개지 않는다**(T-43과 같은 판단). `HTTP 401`과 `timeout`은 지금은 할 일이
  같지만, 뭉개 두면 **다음에 다른 사유가 와도 같은 문장**이 된다.
- **`off`(네이티브 없음)는 실패가 아니다** — 브라우저에는 폰 캘린더가 없다. `ok`와 화면에서 같고
  `data-state`에서만 갈린다(T-33이 `none`/`error`를 가른 그 모양).
- **행동이 있는 상태만 보인다.** `CAL_ACT`에 있는 셋이 곧 뜨는 셋이라, 문구만 늘리고 버튼을
  안 붙이는 실수가 구조적으로 안 생긴다.

⚠️ **설정에도 한 줄을 뒀다**(`#set-cal`, 학사 캘린더 줄 **아래**). Today 줄은 정상이면 사라지므로
**대상을 다시 고를 입구가 없어진다.** 둘을 합치지 않은 이유는 서로 다른 것이기 때문이다 —
학사 캘린더는 **서버가 iCal을 긁는 것**(T-41), 폰 캘린더는 **기기가 CalendarContract를 읽는 것**이다.

### 반복을 Instances 로 전개했는가 · ext_uid 모양

**전개했다.** `CalendarContract.Instances.CONTENT_URI`에 창의 시작·끝(ms)을 붙여 질의한다 —
provider가 RRULE을 창 범위만큼 이미 펼쳐 준다. `Events`는 **한 번도 질의하지 않는다**(검사 ⑦).

```
ext_uid = "<eventId>:<날짜>"      예: 1873:2026-09-03
```

- **취소된 인스턴스는 건너뛴다**(`STATUS_CANCELED`). 캘린더 화면에 없는 것이 미러에 남으면 유령이다.
- **같은 uid가 두 번 나오면 앞의 것으로 접는다** — 서버의 키가 uid라 뒤엣것은 어차피 덮어쓴다.
- ⚠️ **종일 일정의 `BEGIN`은 UTC 자정이다.** 날짜 포맷의 시간대를 종일 여부로 가르지 않으면
  **KST에서 하루가 밀린다.** 9월 시간표 전체가 이 한 줄에 달려 있다.
- **멀티데이는 시작일 1건**(v1, 티켓 ④ 그대로). 창 앞에서 시작해 창 안으로 걸친 일정은 빠진다.
- **`ext_updated`는 '기기가 이 상태를 본 시각'이다.** CalendarContract에는 이식 가능한 *수정 시각*이
  없다(`DIRTY`·`LAST_DATE`는 다른 뜻이다). 관측 시각을 실으면 **늦게 도착한 옛 배치가 새 상태를
  덮는 것**을 서버 LWW가 막는다 — 그 값이 없으면(`null`) LWW가 아무것도 안 한다.

### 동기화 시점 셋을 어디에 걸었나 · pull 직전 순서를 어떻게 보장했나

```
앱 열 때          웹 boot → Guard.sync → GuardSync.syncNow → (여기서 캘린더) → pull
하루 1회 pull 직전  알람 → AlarmReceiver → GuardSync.syncNow → (같은 자리)
수동              설정 시트 [저장하고 지금 동기화] · Today 줄 [다시 시도] → Cal.sync
```

★ **순서를 '한 자리'로 보장했다.** `GuardSync.syncNow()`의 `GET /api/guard/schedule` **바로 앞**에
`CalSync.syncNow(ctx)` 한 줄을 넣었다. 세 시점이 전부 이 함수를 지나므로 **웹이 없는 새벽에도
같은 순서**다. 별도 알람으로 *"2분 먼저"* 를 흉내 내는 안은 버렸다 — 그것은 순서 보장이 아니라
**우연**이고, 어긋나는 밤이 바로 시험 전날일 수 있다.

**실패해도 계속 간다**(`runCatching`). 캘린더가 안 와도 **서버가 이미 아는 보호 일정은 예약돼야
한다** — 동기화 실패가 예약을 인질로 잡으면 그날 밤 Guard가 통째로 없어진다.

검사가 **위치로** 센다(존재만 보면 순서가 뒤집혀도 초록이다):
`indexOf("CalSync.syncNow") < indexOf("/api/guard/schedule")`.

### ⚠️ guard/ 를 읽기만 했는가 — **아니다. 한 줄 썼다.**

**티켓 §범위가 *"읽기만 하고, 고쳐야 할 것 같으면 멈추고 보고한다"* 고 했다. 고쳤고, 여기 적는다.**

```kotlin
runCatching { dev.mond1424.personalos.cal.CalSync.syncNow(ctx) }   // GuardSync.kt · pull 바로 앞
```

**Cowork 확인 대기.** 근거는 위 절이다 — ⑤의 *"pull 직전"* 을 **보장**하는 자리가 여기뿐이다.
나머지 guard/ 접촉은 전부 읽기다: `GuardSync.baseUrl`·`token`(자격증명 재사용) ·
`boundaryHm`(창의 시작을 '열린 날'로 잡는다). **자격증명을 두 벌 두지 않은 이유**는
`GuardEventQueue`가 같은 값을 쓰는 이유와 같다 — 웹이 건네는 통로가 둘이면 한쪽만 갱신된 밤이 온다.

### ⚠️ 범위 밖 파일 하나 — `cal/CalSync.kt`

티켓 §범위는 `cal/` 아래 **둘**(Reader·Plugin)을 적었고 *"보내기"* 를 Plugin에 뒀다.
**그러면 ⑤의 가운데 시점이 통째로 빈다** — 알람이 깨우는 경로에는 `PluginCall`이 없어
플러그인 메서드를 부를 수 없다. 그래서 보내기·설정을 object로 내리고 Plugin은 부르기만 한다
(`GuardSync`/`GuardPlugin`이 서 있는 자리와 같은 모양). **파일이 하나 는 것이지 층이 는 것은 아니다.**

| C 실패해도 아무 표시 안 함 | 374 | ④ · ★셋이 갈린다 |
| D devcal 에도 수정 버튼을 켠다 | 375 | **⑤만** |

| G ⑦의 스캐너를 눈멀게 한다 | 375 | **⑧만** (⑦은 초록) |

**A가 ③까지 죽인 것은 결함이 아니라 ③의 정의다** — 티켓이 ③을 *"②의 짝 · 2와 다른 문구"* 로
적었으므로, ③은 **자기 문구가 ②와 다른가**를 센다. 권한 갈래가 사라지면 두 문구가 같아진다.
**★은 셋을 한꺼번에 보는 검사라 A·B·C 모두에서 죽는 것이 맞다** — 그것이 없으면
*"셋을 같은 문자열로 만드는 변이"* 가 ②③④를 각각 통과한다(셋 다 '뜬다'만 세므로).
**신호는 여전히 갈린다**: `②③★` / `③★` / `④★` / `⑤` / `⑥+기존` / `⑦` / `⑧`.

**E가 기존 검사도 죽였다** — *"일정 줄에 삭제(×)"*. ⑥의 방향을 지키는 검사가 이미 있었다는 뜻이고,
읽기 전용을 넓게 거는 실수는 **두 곳에서** 잡힌다.

⚠️ **1차 배터리가 깨졌다 — 백업이 Windows 경로에서 조용히 실패해 변이가 누적됐다**(`join()`이
역슬래시를 주는데 basename을 `/`로 잘랐다). `from`에 개행을 넣은 둘은 **CRLF 트리에서 빗나갔다.**
누적분을 되돌리고 **깨끗한 트리에서 다시 쟀다** — 위 표가 그 숫자다.
