# T-53 — 폰 캘린더가 Today 를 채운다

**발행** Cowork · 2026-08-28 · **담당** Claude Code · **큼**
**근거** [ADR-029](../../APP-ADR.md#adr-029) · [ADR-028](../../APP-ADR.md#adr-028) · **APK 필요 · T-52 선행**

---

## 무엇을 만드나

**아무것도 안 넣어도 오늘 화면에 무언가 있다.**

```
폰 캘린더  →  CalendarContract 읽기  →  POST /api/cal/sync  →  Today
```

**이것이 이 프로젝트에서 "넣을 것이 없다"를 처음 공략하는 티켓이다.**
위젯 셋은 *넣기의 비용*을 깎았고, 이건 *넣지 않아도 되게* 한다.

## ★ 상한 — 여기서 멈춘다

```
✅  권한 · 대상 캘린더 선택 · 창 읽기 · 보내기 · 읽기 전용 표시
❌  쓰기 방향 (앱 → 캘린더)        ← 9월. 갈라짐을 물리적으로 차단한다
❌  보호 제안 카드                 ← ADR-030. 다음 티켓
❌  위치·참석자·알림 필드           ← 제목·날짜·시각/종일만
❌  충돌 해소 UI                   ← LWW 하나다
```

## 할 일

### ① 권한 — `READ_CALENDAR`

런타임 권한이다. **유도 UI가 필요하다.**

### ② ★ 권한이 없으면 조용하지 않다 — 이 티켓의 핵심

⚠️ **2026-08-28에 실제로 겪었다**: 알림 권한을 끄자 Guard 가 통째로 멈췄고,
**앱을 다시 켜도 아무도 그것을 말해 주지 않았다.**

```
권한 없음 · 대상 캘린더 미선택 · 마지막 동기화 실패
   →  Today 에 한 줄로 보인다 (제안 카드가 아니라 상태 표시)
```

**같은 실패를 캘린더에서 반복하지 않는다.** 권한이 빠지면 **일정이 조용히 사라지고**,
그건 *"넣을 게 없다"* 와 화면상 구별이 안 된다 — **이 티켓이 고치려는 바로 그 증상으로 되돌아간다.**

### ③ 대상 캘린더 선택

⚠️ **전체 동기화는 잡동사니다**(§함정). 계정이 여럿이다(구글 다중·삼성).

```
설정 어딘가에 캘린더 목록 → 체크 → settings 에 저장
```

**선택 전에는 아무것도 안 가져온다** — ②의 상태 표시가 그것을 말한다.

### ④ 읽기 — 창과 반복

```
창        오늘(열린 날) ~ +N일 (기본 60 · settings)
반복      CalendarContract.Instances 로 창 범위만 전개
식별      ext_uid = '<eventId>:<날짜>'  (인스턴스 단위)
멀티데이  시작일 1건으로 축약 (v1)
```

⚠️ **반복을 빼면 개강 후 수업이 통째로 안 들어온다.** 이 티켓에서 가장 값이 큰 부분이다.

### ⑤ 시점

```
앱 열 때  +  하루 1회 보호 일정 pull 직전  +  수동 새로고침
```

⚠️ **pull 직전이라는 순서를 지킨다** — 뒤집히면 **캘린더의 시험이 그날 알람 예약을 놓친다**(§함정).

### ⑥ 화면 — devcal 일정은 읽기 전용

앱에서 수정·삭제할 수 없다. **수정은 캘린더에서.** 쓰기 방향이 붙기 전까지 갈라짐을 물리적으로 막는다.

## 범위

```
android/.../cal/CalendarReader.kt      (신규) CalendarContract · Instances
android/.../cal/CalPlugin.kt           (신규) 권한 · 목록 · 읽기 · 보내기
android/app/src/main/AndroidManifest.xml   READ_CALENDAR
public/app.js · index.html             대상 선택 · 상태 한 줄 · 읽기 전용 표시
test/front.mjs                         검사
```

**서버 무변경**(T-52가 이미 세웠다) **· 마이그레이션 없음.**

⚠️ **`guard/` 아래를 고치지 않는다.** 새 디렉터리(`cal/`)를 쓴다 — 다만 ⑤의 *"pull 직전"*은
Guard 쪽 스케줄과 맞물리므로 **읽기만 하고, 고쳐야 할 것 같으면 멈추고 보고한다.**

⚠️ **`MainActivity`에 플러그인 등록이 필요하다**(T-48에서 배운 것). **범위에 넣어 둔다.**

**Codex 위임 가능** — `AndroidManifest.xml`·플러그인 등록·②의 실패 경로는 직접.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 권한 없음을 조용히 넘기기 | **②가 이 티켓의 핵심.** 8/28에 알림에서 겪은 그 실패다 |
| 전체 캘린더 동기화 | 잡동사니가 된다. **대상 선택이 선행** |
| 반복을 마스터 이벤트 1건으로 | 개강 후 수업이 통째로 빠진다 |
| 귀속일 재계산 | 캘린더 벽시계 그대로(ADR-029) |
| 앱에서 devcal 일정 수정 | 쓰기 방향은 9월이다 |
| pull 뒤에 동기화 | 그날 알람 예약을 놓친다 |
| `protect_*` 를 캘린더로 | 앱 전용이다 |
| 새 서버 엔드포인트 | T-52의 `/api/cal/sync` 하나다 |

## 완료 조건

```
typecheck 통과 · smoke 385(변화 없음) · front 363 → 368 이상 · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

**검사**

```
1  대상 캘린더가 선택돼 있으면 창 범위를 보낸다 (스캐너 + 배선)
2  ★ 권한이 없으면 Today 에 그 사실이 뜬다
3  ★ 대상 미선택이면 그 사실이 뜬다 (2와 다른 문구)          ← 2의 짝. 원인이 갈린다
4  ★ 동기화 실패도 뜬다 (성공하면 안 뜬다)                    ← 없는 것을 세는 검사
5  devcal 일정은 앱에서 수정·삭제 버튼이 없다
6  ★ 앱이 만든 일정은 그대로 수정된다                          ← 5의 짝
7  반복 인스턴스가 개별로 들어온다 (스캐너 — Instances 를 쓰는가)
8  ★ 7의 스캐너가 살아 있는가
```

**2·3·4가 셋으로 갈려 있어야 한다.** 하나로 뭉치면 *"뭔가 안 된다"*만 남고
**무엇을 고쳐야 하는지 화면이 말하지 않는다** — 8/28에 알림 권한에서 겪은 것이 정확히 그 모양이다.

**5와 6도 짝이다.** 5만 보면 *"모든 일정의 수정을 막는 구현"*이 통과한다.

⚠️ **Kotlin 쪽은 jsdom 이 못 본다.** 1·7은 스캐너이고 **진짜 판정은 실측이다.**

**변이**
- 권한 확인을 빼고 바로 읽는다 → **2만** 죽는다
- 미선택과 권한없음을 같은 문구로 → **3만** 죽는다
- 실패해도 아무 표시 안 함 → **4만** 죽는다
- devcal 에도 수정 버튼을 켠다 → **5만** 죽는다
- 모든 일정의 수정을 막는다 → **6만** 죽는다
- `Events` 로 읽는다(Instances 대신) → **7만** 죽는다
- 스캐너를 눈멀게 한다 → **7은 초록 · 8만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

```
□ 앱을 열면 캘린더 권한을 묻는다
□ 거부하면 Today 에 그 사실이 한 줄로 뜬다        ← ②
□ 허용 후 대상 캘린더를 고르면 일정이 들어온다
□ ★ 아무것도 안 넣었는데 오늘 화면에 무언가 있다   ← 이 티켓의 목적
□ 반복 일정(주간 수업 등)이 날짜별로 들어온다
□ devcal 일정은 앱에서 못 고친다 · 앱이 만든 것은 고쳐진다
□ 캘린더에서 하나 지우고 새로고침 → 앱에서도 사라진다
□ ★ 앱에서 만든 일정은 그대로 남아 있다           ← T-52 검사 7의 실물
```

**★ 그리고 한 주 뒤에 답해 달라:**

```
앱을 여는 횟수가 늘었나
열었을 때 볼 것이 있었나
```

**둘째가 이 티켓의 진짜 판정이다.** 도착지가 채워졌는지는 검사가 못 센다.
