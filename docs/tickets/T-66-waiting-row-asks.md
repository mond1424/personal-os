# T-66 — 대기 한 줄이 무엇을 하라는지 말하고, 그 자리에서 된다

**발행** Cowork · 2026-09-08 · **담당** Claude Code · **작음**
**근거** [ADR-048](../../APP-ADR.md#adr-048) · 2026-09-08 사용자 답 ·
**APK 무관 · 마이그레이션 없음 · 서버 무관**

## 무엇이 어긋났나 — 17일 동안 안 눌린 버튼

```
대기 1 — 밤 실측 #3 — adb tcpip 검증 후  17일째        일정 정하기 ›
```

**떠 있었고 색도 이미 최댓값이었다**(`ageClass`는 15일부터 `age3`). **17일 동안 한 번도 안 눌렸다.**

> **잘 몰라서 그냥 안 누름.** 그리고 중요하게 표시되지 않기도 하고 — 사용자, 2026-09-08

**셋이 겹쳐 있다** (`index.html:88-91` · `app.js:519-525`):

```
①  onclick="goInbox()"        Works 탭 → 대기 세그로 이동. 일정은 거기서 두 걸음 더
    라벨 "일정 정하기 ›"       ★ 하는 일과 다르다
②  행동이 var(--faint)         본문은 --sub. ★ 누를 곳이 화면에서 가장 흐리다
③  age3 가 "17일째"에만        줄 전체는 안 변한다
```

⚠️ **바로 위 재배정 행은 한 걸음이다** — `pickReassign` → `startPick({mode:"defer"})`.
**같은 화면에 한 걸음짜리와 세 걸음짜리가 나란히 있고, 세 걸음짜리가 더 직접적으로 말한다.**

## 할 일

### ① ★ 라벨이 아니라 동작을 맞춘다 — 한 걸음으로

```
지금   goInbox()                          Works 로 이동 (그다음 두 걸음)
바꿈   startPick({ mode:"schedule", … })  ★ 그 자리에서 날짜를 정한다
```

**`openTask`가 이미 `t.is_waiting`이면 `startPick({mode:"schedule"})`을 부른다** — 같은 함수를 쓴다.
⚠️ **새 경로를 만들지 마라.** 재배정 행(`pickReassign`)과 **같은 모양**이 이미 있다.

⚠️ **라벨을 낮춰서 맞추지 마라**(*"대기 목록 ›"*). 문구는 참이 되지만 **걸음 수가 그대로다** —
옆줄이 하나인데 이쪽만 셋일 이유가 없다(ADR-048 ①).

### ② 목록으로 가는 길은 남는다

**대기가 여럿이면 전체를 보고 고르고 싶다.** `W.n > 1`일 때 그 입구가 사라지면 안 된다 —
⚠️ **어디에 둘지는 담당이 정하고 근거를 적는다.** 줄을 둘로 쪼개도 되고, `대기 N` 부분만
목록으로 보내도 된다. **한 걸음 경로를 없애지 않는 것만 지킨다.**

### ③ 문구가 무엇을 하면 되는지 말한다

```
지금   "대기 1 — 밤 실측 #3 … 17일째"          ← 관측이다
바꿈   ★ 무엇을 하면 이 줄이 사라지는지가 읽힌다
```

⚠️ **문구를 여기 적지 않는다** — 화면 말은 담당이 쓰고 §보고에 적는다.
**다만 상태만 말하고 끝나면 안 된다**(ADR-048). 지금 줄은 *"17일째"* 까지만 말하고
**그래서 뭘 하라는 건지**는 흐린 글씨의 라벨 하나에 맡긴다.

### ④ 누를 곳이 읽을 곳보다 흐리지 않다

**`var(--faint)`를 행동에 쓰지 않는다.** 이것은 *"더 세게 하기"* 가 아니다 —
ADR-047 ③이 막은 것은 **개입의 강도**(소리·진동·빈도)이고 여기는 **한 화면 안의 위계**다.

### ① 라벨이 아니라 동작을 맞췄다 — 한 걸음

```
전   onclick="goInbox()"                 Works 대기 세그 → 거기서 두 걸음 더
후   onclick="return pickWaitTop()"      pickSchedule → startPick({mode:"schedule"})
```

**새 경로를 안 만들었다.** `pickSchedule`은 Works 대기 목록의 *"일정 정하기"* 칩이 이미 쓰던
함수이고, **`works`가 안 실린 화면에서는 `S.today.waiting.top`으로 폴백**하도록 전부터 적혀
있었다 — Today 에서 부를 준비가 이미 돼 있었다. `pickWaitTop`은 그 위의 세 줄짜리 어댑터이고
**재배정 행의 `pickReassign`과 같은 모양**이다(대상을 찾아 `startPick`에 넘긴다).

⚠️ **인라인 `onclick`에 `return`을 붙였다**(함정 14 · T-63). 지금 두 핸들러는 동기라 안 물리지만,
`onclick="f()"` 의 본문은 그대로 함수 몸이라 **왕복이 붙는 순간** 프라미스가 버려진다.

### ② 목록으로 가는 길 — **`대기 N`이 그대로 진다** (담당 결정 · 근거)

```
[ 대기 3 › ]  밤 실측 #3 — adb tcpip 검증 후          [ 날짜 정하기 → ]
              17일째 미배정 — 날짜를 정하면 이 줄이 없어져요
   └ goInbox()                                          └ 그 자리에서 날짜
```

1. **화면에 버튼이 늘지 않는다.** `대기 N`은 이 줄이 **원래 이미 들고 있던 글자**다
   (`대기 1 — 제목 …`). 자리를 옮겨 누를 수 있게 했을 뿐이라 위계(②)가 흐려지지 않는다.
2. **입구가 사라질 수가 없다.** `W.n > 1`을 조건으로 걸지 않았다 — 걸면 *"하나뿐일 때 목록이
   없어도 되는가"* 를 매번 다시 물어야 하고, 티켓이 지키라 한 것은 **길이 남는 것** 하나다.
3. **줄을 둘로 쪼개는 안은 버렸다.** 한 줄짜리 알림에 두 행을 두면 *"어느 쪽이 본체인가"* 가
   다시 흐려진다 — 이 티켓이 없앤 바로 그 모양이다.

### ③ 문구가 무엇을 하면 되는지 말한다

```
전   대기 1 — 밤 실측 #3 — adb tcpip 검증 후  17일째        ← 관측으로 끝난다
후   밤 실측 #3 — adb tcpip 검증 후
     17일째 미배정 — 날짜를 정하면 이 줄이 없어져요           ← 상태 + 무엇을 하면 + 그 결과
```

**상태를 지우지 않았다** — `N일째`도 `ageClass`도 그대로다. 더한 것은 **조건절과 결과**다.

### ④ 누를 곳이 읽을 곳보다 흐리지 않다

```
전   본문 --sub  ·  행동 --faint     ★ 누를 곳이 화면에서 가장 흐렸다
후   제목 --ink · 본문 --sub · 행동 .deferchip(--brick)   ← 재배정 행의 '미루기 →'와 같은 칩
```

**새 CSS를 안 만들었다** — 옆줄이 쓰는 클래스를 그대로 쓴다. `#today-wait` 블록 안에
`--faint`는 이제 **한 번도 안 나온다.**
⚠️ **임계는 한 글자도 안 건드렸다** — `WAIT_LIMIT`(21) · `ageClass`(8/15). 검사 6이 센다.
