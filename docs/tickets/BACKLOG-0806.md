**Level 4 게이트의 비대칭 (T-29에서 알고 남긴 것).**
같은 "오늘로는 안 된다"인데 두 자리가 사용자에게 요구하는 단계 수가 다르다:

| 막힌 자리 | 그다음 | 단계 |
|---|---|---|
| `assignDate` (피커) | 피커가 그대로 떠 있고 오늘 칸만 흐려진다 → **바로 다른 날 탭** | 1 |
| `dfx-ok` (미루기 시트) | 시트가 남는다. 거기서 `to`를 바꿀 수 없으므로 **취소 → 피커 → 다시 고름** | 3 |

시트를 남긴 것은 **맥락이 갑자기 사라지지 않게** 하려는 것이다 — 무엇을 어디로 옮기려
했는지가 토스트 한 줄만 남기고 지워지는 것과, 그대로 있는 채로 "오늘은 안 된다"는 말을
듣는 것은 다르다. **사유가 보존되지는 않는다**(`openDeferSheet`가 비운다).

**실사용에서 이 한 단계가 답답하면 막힐 때 시트를 닫고 피커로 돌려보낸다.**
지금 바꾸지 않는 이유는 새벽에 미루기가 오늘로 막히는 빈도를 아직 모르기 때문이다 —
드물면 맥락 유지가 낫고, 잦으면 단계 수가 이긴다. **밤 실측 뒤에 정한다.**

**`testNotify`의 제목이 요청 level을 말한다 (2026-08-17 낮 실측에서 실제로 헷갈렸다).**

```
GuardPlugin.kt:164        title = "Guard 테스트 · Level $level"       ← 요청한 값
GuardNotifications.kt:151 fireLevel = if (level >= 4) 3 else level   ← 실제로 발동한 값
```

**Level 4를 요청하면 알림 제목엔 `4`가 뜨는데 화면·기록·알림 ID는 전부 `3`이다.**
ADR-024대로 Level 4 후보는 먼저 Level 3으로 나가므로 **발동 쪽이 옳고 제목이 거짓말**이다.
낮 실측에서 이것 때문에 *"4가 떴는데 왜 화면은 3인가"*를 한 번 되짚었다 —
그날은 `cap`이라 격상도 없었으므로 제목이 유일하게 4를 말하는 자리였다.

**응답도 발동 level을 안 준다** — `reached`·`posted`·`shown`·`canPost`·`canOverlay`뿐이라
콘솔에서도 몇으로 났는지 알 수 없다. 고칠 방향은 둘이고 **함께여도 된다**:
제목을 `fireLevel`로 바꾸거나(요청과 발동이 다르면 그 사실이 제목에 보이게), 응답에 발동 level을 싣거나.

**지금 고치지 않는 이유는 네이티브라 APK 재빌드가 필요해서다** — 다음 빌드에 묶는다.
**실사용 경로가 아니라 시험 도구의 표시 문제이므로 급하지 않다**(발동·기록은 이미 옳다).

**루프의 마지막 조각인데 프런트 검사가 한 건도 없다.** `#td-guard`·`loadGuardOutcome`·

서버 쪽은 검사 3건이 있다(`smoke.ts` — 200 · 재확정 409 · 잘못된 값 400).

**그리고 이 카드는 실패하면 조용히 사라진다** (`app.js:476`):

```js
} catch { bar.style.display = "none"; }   // Guard가 아직 없거나 조회 실패 — 화면을 막지 않는다
```

화면을 안 막는 것은 옳다. 문제는 **그 침묵이 회귀와 구별되지 않는다**는 것이다 —
카드가 안 떠도 앱은 멀쩡해 보이고, 검사도 271/0이고, `outcome`만 영영 안 쌓인다.
**§6.5 자기 보정의 입력이 그 `outcome`이다.** 없으면 "이 규칙이 과했나"를 판정할 재료가 없다.

**T-01의 교훈이 여기 그대로 있다** — "구현을 잘못했다면 이 검사가 빨간불이 되는가."
지금은 카드를 통째로 지워도 초록이다.

크기는 검사만이라 작다. 볼 것: 미확정 발동이 있으면 **카드가 뜨는가** ·
버튼 둘이 각각 `success`/`failure`를 보내는가 · 확정 후 **다음 것을 이어 묻는가**(`:471`) ·
없으면 안 뜨는가. **조회가 실패했을 때와 확정할 게 없을 때가 지금 같은 모양인 것**도
이 자리에서 갈라야 한다 — 앞은 회귀이고 뒤는 정상이다.
