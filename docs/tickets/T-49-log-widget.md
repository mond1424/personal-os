# T-49 — 홈에 로그 한 줄

**발행** Cowork · 2026-08-27 · **담당** Claude Code · **작음**
**근거** [ADR-043](../../APP-ADR.md#adr-043) 연장 · **APK 필요 · 서버 무변경 · 마이그레이션 없음**

---

## 무엇을 만드나

**3×1 위젯 하나. 검색창처럼 생겼고, 탭하면 앱의 로그 입력줄로 간다.**

```
┌──────────────────────────────────────┐
│  ✎   지금 뭐 하고 있나요              │
└──────────────────────────────────────┘
```

**딥링크는 이미 있다** — `add-log`가 `DEEPLINK_ACTIONS`에 서 있다(T-48).
**이 티켓은 위젯 하나와 그 배선이 전부다.**

## 왜 지금인가 — 어포던스를 잰다

**T-48 최대 크기에 로그 버튼이 이미 있는데 왜 또 만드나:**

```
T-48 의 로그 버튼   최대 크기로 늘린 사람만 닿는다
T-46 의 "+"        아이콘 하나라 무엇을 하는지 안 읽힌다
이것               가로로 길고 "쓰는 곳"처럼 생겼다
```

**T-46과 이 위젯은 같은 물건이다** — 탭 → 딥링크 → 앱 입력창. **다른 것은 옷뿐이다.**
그래서 **둘 중 어느 쪽이 눌리는지가 "위젯이 안 눌리는 이유가 어포던스인가"를 답한다.**
ADR-043 §재검토가 묻는 것에 대조군이 하나 생긴다.

## ★ 상한 — 여기서 멈춘다

```
✅  3×1 위젯 · 검색창 모양 · 탭 → add-log 딥링크
❌  위젯 안에서 타이핑             ← RemoteViews 에 EditText 가 없다. Android 가 안 준다
❌  오늘 로그 개수·마지막 로그 그리기  ← 데이터를 그리면 다리·갱신이 따라온다
❌  add-log 액션 손보기            ← T-48 이 세웠다. 재사용만 한다
❌  ScaleWidget · AddTaskWidget 손대기  ← 별개 위젯 셋이다
```

**데이터를 안 그리므로 `WidgetPlugin` 다리도, 토큰도, 갱신 스케줄도 필요 없다** —
T-46과 같은 부류다(ADR-041 §맥락).

## 할 일

```
AppWidgetProvider 하나 · 3×1 · RemoteViews = 아이콘 + 힌트 텍스트
전체를 하나의 PendingIntent → personalos://add-log
```

**모양**

- 둥근 모서리 · 옅은 배경 · 옅은 글씨 — **입력줄로 읽혀야 한다**
- ⚠️ **placeholder 처럼 보이되 실제로 못 친다.** 탭하면 앱이 열리는 것이 전부이고,
  그것은 Google 검색 위젯과 같은 계약이라 **거짓말이 아니다**
- 색은 `values/` ↔ `values-night/` **짝**(함정 5의 Android판). T-46이 세운 그 자리다
- 문자열은 `strings.xml`. **레이아웃에 리터럴을 박지 않는다**

**⚠️ 주석에 `/api/…/*` 꼴을 적지 마라** — `/*`가 Kotlin 블록 주석을 새로 연다.
**T-46·T-48이 두 번 물렸고 `verify`가 초록인 채로 `assembleRelease`만이 잡았다**(함정 13).

## 범위

```
android/.../widget/LogWidget.kt          (신규)
res/layout/widget_log.xml                (신규)
res/xml/widget_log_info.xml              (신규 · minWidth 3칸 · minHeight 1칸)
res/values{,-night}/widget_log_colors.xml (신규)
res/values/strings.xml                   힌트·라벨
AndroidManifest.xml                      receiver 하나
test/front.mjs                           검사
```

**서버 무변경 · 마이그레이션 없음 · smoke 무변경 · `public/app.js` 무변경.**

⚠️ **`app.js`를 안 고치는 것이 이 티켓의 조건이다.** `add-log`가 이미 있으므로
**고칠 것이 있다면 그것은 이 티켓이 아니다** — 멈추고 보고하라.

⚠️ `guard/` 아래·`WidgetPlugin`·다른 두 위젯을 건드리지 않는다.

**Codex 위임 가능** — `AndroidManifest.xml`만 직접.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 위젯 안 텍스트 입력 시도 | `RemoteViews`에 `EditText`가 없다 |
| 로그 개수·마지막 로그 그리기 | 다리·토큰·갱신이 따라온다. **이 위젯은 여는 물건이다** |
| `add-log` 액션 수정 | T-48이 세웠다. 고칠 게 있으면 이 티켓이 아니다 |
| `app.js` 수정 | 위와 같다 — 범위가 Android 뿐이다 |
| 다크모드 색 한 벌만 | 짝이 없으면 안 보인다 |
| 주석에 `/*`를 만드는 경로 적기 | **함정 13. 두 번 물렸다** |
| `exported="false"` | `APPWIDGET_UPDATE`는 system_server가 보낸다(T-46이 판단한 자리) |

## 완료 조건

```
typecheck 통과 · smoke 370(변화 없음) · front 351 → 354 이상 · 실패 0 · verify exit 0
assembleRelease BUILD SUCCESSFUL · npx cap sync android 성공
```

**검사**

```
1  위젯이 add-log 딥링크를 던진다 (스캐너 — 스킴·액션 이름이 app.js 의 대장과 일치)
2  ★ 그 액션이 DEEPLINK_ACTIONS 에 실제로 있다      ← 1의 짝. 이름만 맞고 없는 경우
3  values-night 색이 짝으로 있다 (한쪽에만 있는 이름 0)
4  레이아웃이 색 리터럴(`#…`)·문자열 리터럴을 안 쓴다
5  ★ 1의 스캐너가 살아 있는가                        ← 주석을 걷어내고 본다
```

**1과 2가 짝이다.** 1만 보면 *"`add-logs`처럼 한 글자 틀린 딥링크"*가 통과한다 —
그러면 `resolveAction`이 `null`을 주고 **위젯을 눌러도 Today만 뜬다.**
T-46이 세운 폴백이 이 결함을 **조용하게** 만든다는 것이 이 짝의 이유다.

**변이**
- 딥링크 액션 이름을 한 글자 바꾼다 → **2만** 죽는다
- 스캐너를 눈멀게 한다 → **1은 초록 · 5만** 죽는다
- `values-night`를 지운다 → **3만** 죽는다
- 레이아웃에 색을 박는다 → **4만** 죽는다

## 확인 절차 (사용자) — APK 설치 후

```
□ 위젯 목록에 "로그 쓰기"가 있고, 놓으면 가로 3칸을 차지한다
□ 탭하면 앱이 열리고 로그 입력줄에 커서가 있다
□ 앱이 이미 떠 있어도 같다                     ← 더운 시작
□ 다크모드에서 힌트 글씨가 보인다
□ ★ 마감된 날에 탭하면 — 그 줄이 memo 로 간다(입력줄이 그렇게 동작한다)
```

**★ 그리고 한 주 동안 셋을 나눠 세어 달라:**

```
"+"(T-46)  /  "오늘 찍기"(T-48)  /  "로그 쓰기"(T-49)
```

**T-46과 T-49는 같은 물건에 다른 옷이다.** 그 둘의 비가 ADR-043 §재검토의
*"접근성이 원인이었나"*를 **어포던스 축에서** 갈라 준다.
