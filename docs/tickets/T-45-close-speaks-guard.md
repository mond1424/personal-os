# T-45 — 마감 요약이 Guard도 말한다

**발행** Cowork · 2026-08-23 · **담당** Claude Code · **보통**
**근거** [ADR-040](../../APP-ADR.md#adr-040) 연장 · 마이그레이션 없음 · APK 무관 · 서버 + 프런트

---

## 무엇이 어긋났나

**T-44의 요약은 사람이 넣어야 생기는 것만 말한다.**

```
done · todo · reassign   →  전부 사용자가 넣어야 채워진다
넣은 게 없으면            →  "오늘 담긴 할 일이 없는 날이에요."
```

**그 문장이 나흘 연속 떴다**(2026-08-19~22 `daily` 없음 · `logs 0`). 그리고 그 나흘 동안
**Guard는 매일 무언가를 알고 있었다** — `guard_events` 60건, `watch:bedtime` 22건.

**시스템이 아는 것이 있는데 마감이 그것을 말하지 않는다.** ADR-040이 고치려던 바로 그 모양이,
사용자 입력이 0인 날에 **그대로 남아 있다.**

## 왜 지금인가

**빈 시스템에서 마감할 이유가 없다는 것이 이 앱의 첫 벽이다.**

```
넣은 게 없다 → 요약이 "없는 날" → 마감할 이유가 없다 → 마감을 안 한다
             → daily 가 안 쌓인다 → 12월에 읽을 것이 없다
```

**Guard 쪽 재료는 사용자 입력과 무관하게 매일 생긴다.** 그것을 말하면
**넣은 게 0인 날에도 마감이 무언가를 돌려준다.**

## ★ 결정 ① — 주어는 시스템이다

**이 티켓에서 가장 위험한 자리다.** 같은 사실을 두 방향으로 쓸 수 있다:

```
✅  "새벽 2시에 두 번 알렸어요"        ← 시스템이 한 일
❌  "새벽 2시까지 깨어 있었어요"        ← 사용자를 서술한다
❌  "어젯밤 늦게 주무셨네요"            ← 평가어가 없어도 판단이다
```

**평가어를 안 써도 주어가 사용자면 판단이 된다.** T-44의 금지어 목록(`CLOSE_JUDGING_WORDS`)은
어휘를 막지 **문장의 주어를 못 막는다.**

**주어를 시스템으로 고정한다.** 그것이 이 티켓의 §금지 1행이고, 검사가 세는 것이다.

## ★ 결정 ② — 없으면 말하지 않는다

```
✅  "오늘 3개 했고 2개 남았어요."                     ← 개입이 없던 날. 그대로 끝
❌  "오늘 3개 했고 2개 남았어요. 알림은 없었어요."     ← 없는 것을 말하면 잔소리다
```

**T-44의 §금지 7행(*"빈 날에 아무것도 안 쓰기"*)과 헷갈리지 마라.** 그것은
**요약 전체가 침묵하는 것**을 막았다. 여기는 **한 조각이 없을 때 그 조각만 빼는 것**이고,
요약 자체는 여전히 나온다.

## 할 일

### ① 서버 — `today` 응답에 얹는다. 호출을 늘리지 않는다

⚠️ **T-44 §금지 3행이 *"서버 호출 추가"*를 막았다. 그 이유는 *"마감이 네트워크에 걸린다"*였다.**
**기존 `today` 응답에 얹으면 그 이유가 해소된다** — 화면이 이미 부르는 것이고 왕복이 안 는다.

`Api.today()`에 그날 귀속일의 Guard 집계를 얹는다 (이름은 담당이 정한다):

```
fired         그날 발동 수
last_at       마지막 발동 시각
ignored       반응 없이 지나간 수      ← finalizeIgnored 가 이미 만드는 상태다
```

⚠️ **집계는 조회 시 계산한다**(원칙 1). `guard_events`를 세는 것이지 새 칸을 만들지 않는다.

⚠️ **`level`·`ai_verdict`를 요약에 쓰지 않는다.** 사용자에게 Level 3/4는 뜻이 없고,
`deny`·`approve`는 T-38이 관측용으로 만든 것이지 화면에 낼 말이 아니다.

### ② 프런트 — 한 조각을 뒤에 붙인다

```
오늘 3개 했고 2개 남았어요. 새벽 2시에 두 번 알렸어요.
오늘 담긴 할 일이 없어요. 밤 1시에 한 번 알렸어요.
오늘 3개 했고 2개 남았어요.                          ← 개입 0. 아무 말 안 붙는다
```

**T-44의 문장 뒤에 붙인다.** 앞에 두면 Guard가 주인공이 되고, 이 앱은 Guard 앱이 아니다.
**세 줄 상한은 그대로다**(ADR-040 §감수하는 비용).

⚠️ **`ignored`를 어떻게 말할지 조심하라.** *"두 번은 답을 안 하셨어요"*는 사용자 서술이다.
말할 값이 없다고 판단되면 **v1에서는 빼라** — 보고에 그 판단을 적는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 주어를 사용자로 쓰기 | **평가어가 없어도 판단이 된다.** 결정 ① — 이 티켓의 핵심 |
| 개입이 0인 날에 "없었어요" 쓰기 | 없는 것을 말하면 잔소리다. 결정 ② |
| `level`·`ai_verdict`를 화면에 | 사용자에게 뜻이 없다. T-38의 재료는 관측용이다 |
| 새 API 호출 추가 | T-44 §금지 3행. **`today`에 얹어서 왕복을 안 늘린다** |
| 새 칼럼·새 저장소 | 조회 시 계산한다(원칙 1) |
| Guard 조각을 앞에 두기 | 이 앱은 Guard 앱이 아니다. 뒤에 붙인다 |
| 세 줄 넘기기 | ADR-040 §감수하는 비용 |
| 집계 실패가 마감을 막기 | T-44 검사 ⑤와 같다. **기록의 봉인이 우선이다** |

## 완료 조건

```
typecheck 통과 · smoke 354 → 358 이상 · front 311 → 315 이상 · 실패 0 · verify exit 0
```

**검사**

```
서버
1  그날 발동이 있으면 집계가 실제 수를 준다
2  ★ 발동이 0이면 집계가 0을 준다 (없는 게 아니라 0)      ← 1의 짝
3  귀속일 경계를 지킨다 — 어제 새벽 것이 어제로 간다      ← 06:00 경계

화면
4  개입이 있으면 문장 뒤에 조각이 붙는다
5  ★ 개입이 0이면 조각이 없다 (T-44 문장만 남는다)        ← 4의 짝. 결정 ②
6  ★ 주어가 시스템이다 — 사용자 서술 표현이 없다          ← 스캐너. 결정 ①
7  ★ 6의 스캐너가 살아 있는가                             ← 합성 문구를 잡는가
8  집계가 던져도 T-44 문장과 마감 버튼이 살아 있다
```

**5와 8이 짝이다.** 4·6만 보면 *"개입 0일 때도 뭔가 쓰는 구현"*과
*"Guard 집계가 죽으면 요약 전체가 죽는 구현"*이 둘 다 통과한다 —
T-33·T-38·T-39·T-41·T-43·T-44에서 **여섯 번** 물린 자리다.

⚠️ **검사 6의 금지 표현 목록은 `CLOSE_JUDGING_WORDS`와 별개다.** 그쪽은 어휘,
이쪽은 **주어**다. 합치지 마라 — 뜻이 다르고, 합치면 한쪽을 고칠 때 다른 쪽이 딸려 간다.
다만 **각각은 한 곳에만 둔다**(T-44가 세운 규칙).

**변이**
- 개입 0일 때도 조각을 쓴다 → **5만** 죽는다
- 주어를 사용자로 바꾼다 → **6만** 죽는다
- 스캐너를 눈멀게 한다 → **6은 초록 · 7만** 죽는다
- 집계를 던지게 한다 → **8만** 죽는다

```
티켓: T-45
바꾼 파일: src/db/index.ts · src/services/daily.ts · public/app.js
          test/smoke.ts · test/front.mjs · docs/api-surface.md   (마이그레이션 없음 · APK 무관)
기준선: typecheck 통과 · smoke 354 → 359 · front 311 → 316 · 실패 0 · verify exit 0
```

**집계를 어디에 얹었나**

`GET /api/today` 응답의 **`guard`** — `assembleToday`의 `Promise.all`에 `db.guardDayTally` 하나를 더했다.
**왕복이 안 는다**(화면이 이미 부르는 응답이다). SQL은 `db/index.ts` 한 곳:
`COUNT(*) · MAX(fired_at) · SUM(reaction='ignored')` — **새 칼럼도 새 저장소도 없다**(원칙 1).

```
guard = { fired, last_at, ignored }      집계를 읽었다
guard = null                             집계를 못 읽었다
```

⚠️ **`null`과 `fired: 0`을 갈라 뒀다.** 화면에서는 둘 다 침묵이지만(결정 ②) **응답에서는 다르다** —
T-43이 `last_seen_count`로 세운 자리와 같다. 그래서 `guardDayTally`에만 `.catch(() => null)`이 붙는다:
집계는 보조이고, 그것이 죽었다고 Today 전체가 죽으면 **마감 자체를 못 한다**(§금지 8행).

**귀속일 경계를 어느 시계로 쟀나**

**아무 시계로도 안 쟀다 — `guard_events.on_date`를 그대로 쓴다.** 그 값은 기록 시점에
`record()`가 `attributionOfIso(fired_at, t.boundary)`로 확정한 것이다(ADR-011).
집계에서 `fired_at`을 다시 자르면 **경계 설정을 바꿀 때 과거가 따라 움직인다** — 두 벌이 되는 자리다.
검사 ③이 그것을 센다: `오늘 02:00` 발동은 `on_date = D_1`이라 **오늘 집계에 안 들어온다.**

**`ignored`는 말하지 않았다 (응답에는 싣는다)**

근거 둘이고, **뒤엣것이 결정적이다.**

1. 어떻게 써도 주어가 사용자로 넘어간다. *"두 번은 답을 안 하셨어요"*는 물론이고
   *"두 번은 답을 못 받았어요"*도 가리키는 것은 사용자의 무반응이다 — 결정 ①에 걸린다.
2. ★ **마감 시점에는 구조적으로 늘 0이다.** `finalizeIgnored`의 유예가 **36시간**이라
   (기기가 오프라인이면 발동과 반응을 함께 늦게 올린다 — ADR-023), 오늘 발동이 `ignored`로
   확정되는 것은 **모레**다. 그때 그 날은 이미 닫혀 있다. **말할 값이 아예 없다.**

응답에는 남겼다 — 같은 한 문장으로 나오고, 관측이 가능해야 나중에 판단이 된다(검사 ④가 센다).

**실제 문구 — 문자열 그대로** (소스의 함수를 그대로 평가해 뽑았다)

```
개입 있음
  2건 02:10  →  "오늘 3개 했고 2개 남았어요. 새벽 2시에 두 번 알렸어요."
  1건 23:40  →  "오늘 담긴 할 일이 없는 날이에요. 밤 11시에 한 번 알렸어요."
  5건 01:05  →  "오늘 한 것이 없어요. 남은 것 2개. 새벽 1시에 5번 알렸어요."
  3건 19:30  →  "오늘 3개 했고 남은 것이 없어요. 재배정 대기 1개. 저녁 7시에 세 번 알렸어요."

개입 없음 (셋 다 같다 — 조각이 없다)
  fired 0     →  "오늘 3개 했고 2개 남았어요."
  guard null  →  "오늘 3개 했고 2개 남았어요."     ← 집계 실패
  키 자체 없음 →  "오늘 3개 했고 2개 남았어요."     ← 옛 배포. 화면을 인질로 잡지 않는다

집계가 던짐
  throw       →  "오늘 3개 했고 2개 남았어요."     ← 앞 문장이 살아남는다
```

시각 표현 전 구간: `00 밤 12시 · 01~05 새벽 · 06~11 아침 · 12~17 낮 · 18~22 저녁 · 23 밤 11시`.
`Date`를 안 거치고 `fired_at` 문자열의 시(hour)를 읽는다 — 이미 로컬 오프셋으로 정규화돼 있다(T-41).
⚠️ 티켓 예시의 *"밤 1시"*는 **"새벽 1시"**로 갔다(01시는 새벽이 표준이다). 나머지는 예시 그대로다.

**주어 스캐너의 목록**

`public/app.js`의 **`CLOSE_USER_SUBJECT_MARKS`** 하나(25개 · ①높임 어미 ②사용자 지칭 ③상태·행동 서술).
`front.mjs`가 `ev("CLOSE_USER_SUBJECT_MARKS")`로 읽는다 — T-44가 세운 규칙 그대로 **한 곳**이다.
**`CLOSE_JUDGING_WORDS`와 합치지 않았고, 검사 ⑦이 교집합 0을 센다.**
⑦은 한 가지를 더 본다: 합성 문구(*"어젯밤 늦게 주무셨네요…"*)를 **주어 목록은 3건 잡고 어휘 목록은 0건 잡는다** —
그 두 숫자가 **왜 합치면 안 되는지의 증거**다. 합치는 순간 이 구분이 사라진다.

**변이 넷 — 실측 (각 변이마다 `npm run front` 전량 실행)**

| 변이 | 결과 | 죽은 검사 |
|---|---|---|
| 개입 0일 때도 조각을 쓴다 | 316 → **315** | **⑤만** — `0 "…남았어요. 알림은 없었어요."` |
| 주어를 사용자로 (`알렸어요`→`깨셨어요`) | 316 → **315** | **⑥만** — `셨@…새벽 2시에 두 번 깨셨어요.` 외 4갈래 |
| 스캐너 눈멀게 (목록 비움) | 316 → **315** | **⑦만** — ⑥은 초록. `주어 적중 []` |
| 집계를 던지게 (try/catch 제거) | 316 → **315** | **⑧만** — `render true · btn true · 모달 true · 줄 ""` |

⚠️ **첫 변이가 처음엔 ⑤가 아니라 ④를 죽였다 — 그래서 검사를 고쳤다.**
기대값 `t45Base`를 `closeSummaryText(3,2,0)`으로 **함수를 거쳐** 잡고 있었다. 조각이 새는 변이에서는
**기준선까지 같이 오염돼** ⑤는 통과하고 ④가 대신 죽었다 — *어느 결함이 무엇을 죽였는지 못 읽게 된다*
(T-43 ①·T-44에서 고친 것과 같은 자리). 기대값을 문장 리터럴로 독립시키자 ⑤만 죽었다.

⚠️ **④도 함께 고쳤다 — 문구를 통째로 박지 않고 자리와 재료를 본다**(`startsWith(T-44 문장)` ·
`새벽 2시` · `두 번`). 그러지 않으면 **주어만 바꾼 변이가 ④까지 죽인다.** 문구는 ⑥·⑦이 지킨다.

**⑧이 ⑤(T-44)와 다른 자리를 지킨다.** 변이 D에서 `render true · btn true`인데 `줄 ""`이었다 —
**렌더도 마감도 멀쩡한데 사용자가 넣은 것까지 조각과 함께 사라진 상태**다. T-44 ⑤는 이걸 못 본다.
