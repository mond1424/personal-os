# T-45 — 마감 요약이 Guard도 말한다

**발행** Cowork · 2026-08-23 · **담당** Claude Code · **보통**
**근거** [ADR-040](../../APP-ADR.md#adr-040) 연장 · 마이그레이션 없음 · APK 무관 · 서버 + 프런트

---

## 무엇이 어긋났나

**T-44의 요약은 사람이 넣어야 생기는 것만 말한다.**

```
done · todo · reassign   →  전부 사용자가 넣어야 채워진다
넣은 게 없으면            →  "오늘 담긴 할 일이 없는 날이에요."
```

**그 문장이 나흘 연속 떴다**(2026-08-19~22 `daily` 없음 · `logs 0`). 그리고 그 나흘 동안
**Guard는 매일 무언가를 알고 있었다** — `guard_events` 60건, `watch:bedtime` 22건.

**시스템이 아는 것이 있는데 마감이 그것을 말하지 않는다.** ADR-040이 고치려던 바로 그 모양이,
사용자 입력이 0인 날에 **그대로 남아 있다.**

## 왜 지금인가

**빈 시스템에서 마감할 이유가 없다는 것이 이 앱의 첫 벽이다.**

```
넣은 게 없다 → 요약이 "없는 날" → 마감할 이유가 없다 → 마감을 안 한다
             → daily 가 안 쌓인다 → 12월에 읽을 것이 없다
```

**Guard 쪽 재료는 사용자 입력과 무관하게 매일 생긴다.** 그것을 말하면
**넣은 게 0인 날에도 마감이 무언가를 돌려준다.**

## ★ 결정 ① — 주어는 시스템이다

**이 티켓에서 가장 위험한 자리다.** 같은 사실을 두 방향으로 쓸 수 있다:

```
✅  "새벽 2시에 두 번 알렸어요"        ← 시스템이 한 일
❌  "새벽 2시까지 깨어 있었어요"        ← 사용자를 서술한다
❌  "어젯밤 늦게 주무셨네요"            ← 평가어가 없어도 판단이다
```

**평가어를 안 써도 주어가 사용자면 판단이 된다.** T-44의 금지어 목록(`CLOSE_JUDGING_WORDS`)은
어휘를 막지 **문장의 주어를 못 막는다.**

**주어를 시스템으로 고정한다.** 그것이 이 티켓의 §금지 1행이고, 검사가 세는 것이다.

## ★ 결정 ② — 없으면 말하지 않는다

```
✅  "오늘 3개 했고 2개 남았어요."                     ← 개입이 없던 날. 그대로 끝
❌  "오늘 3개 했고 2개 남았어요. 알림은 없었어요."     ← 없는 것을 말하면 잔소리다
```

**T-44의 §금지 7행(*"빈 날에 아무것도 안 쓰기"*)과 헷갈리지 마라.** 그것은
**요약 전체가 침묵하는 것**을 막았다. 여기는 **한 조각이 없을 때 그 조각만 빼는 것**이고,
요약 자체는 여전히 나온다.

## 할 일

### ① 서버 — `today` 응답에 얹는다. 호출을 늘리지 않는다

⚠️ **T-44 §금지 3행이 *"서버 호출 추가"*를 막았다. 그 이유는 *"마감이 네트워크에 걸린다"*였다.**
**기존 `today` 응답에 얹으면 그 이유가 해소된다** — 화면이 이미 부르는 것이고 왕복이 안 는다.

`Api.today()`에 그날 귀속일의 Guard 집계를 얹는다 (이름은 담당이 정한다):

```
fired         그날 발동 수
last_at       마지막 발동 시각
ignored       반응 없이 지나간 수      ← finalizeIgnored 가 이미 만드는 상태다
```

⚠️ **집계는 조회 시 계산한다**(원칙 1). `guard_events`를 세는 것이지 새 칸을 만들지 않는다.

⚠️ **`level`·`ai_verdict`를 요약에 쓰지 않는다.** 사용자에게 Level 3/4는 뜻이 없고,
`deny`·`approve`는 T-38이 관측용으로 만든 것이지 화면에 낼 말이 아니다.

### ② 프런트 — 한 조각을 뒤에 붙인다

```
오늘 3개 했고 2개 남았어요. 새벽 2시에 두 번 알렸어요.
오늘 담긴 할 일이 없어요. 밤 1시에 한 번 알렸어요.
오늘 3개 했고 2개 남았어요.                          ← 개입 0. 아무 말 안 붙는다
```

**T-44의 문장 뒤에 붙인다.** 앞에 두면 Guard가 주인공이 되고, 이 앱은 Guard 앱이 아니다.
**세 줄 상한은 그대로다**(ADR-040 §감수하는 비용).

⚠️ **`ignored`를 어떻게 말할지 조심하라.** *"두 번은 답을 안 하셨어요"*는 사용자 서술이다.
말할 값이 없다고 판단되면 **v1에서는 빼라** — 보고에 그 판단을 적는다.

## 금지

| 하지 말 것 | 왜 |
|---|---|
| 주어를 사용자로 쓰기 | **평가어가 없어도 판단이 된다.** 결정 ① — 이 티켓의 핵심 |
| 개입이 0인 날에 "없었어요" 쓰기 | 없는 것을 말하면 잔소리다. 결정 ② |
| `level`·`ai_verdict`를 화면에 | 사용자에게 뜻이 없다. T-38의 재료는 관측용이다 |
| 새 API 호출 추가 | T-44 §금지 3행. **`today`에 얹어서 왕복을 안 늘린다** |
| 새 칼럼·새 저장소 | 조회 시 계산한다(원칙 1) |
| Guard 조각을 앞에 두기 | 이 앱은 Guard 앱이 아니다. 뒤에 붙인다 |
| 세 줄 넘기기 | ADR-040 §감수하는 비용 |
| 집계 실패가 마감을 막기 | T-44 검사 ⑤와 같다. **기록의 봉인이 우선이다** |

## 완료 조건

```
typecheck 통과 · smoke 354 → 358 이상 · front 311 → 315 이상 · 실패 0 · verify exit 0
```

**검사**

```
서버
1  그날 발동이 있으면 집계가 실제 수를 준다
2  ★ 발동이 0이면 집계가 0을 준다 (없는 게 아니라 0)      ← 1의 짝
3  귀속일 경계를 지킨다 — 어제 새벽 것이 어제로 간다      ← 06:00 경계

화면
4  개입이 있으면 문장 뒤에 조각이 붙는다
5  ★ 개입이 0이면 조각이 없다 (T-44 문장만 남는다)        ← 4의 짝. 결정 ②
6  ★ 주어가 시스템이다 — 사용자 서술 표현이 없다          ← 스캐너. 결정 ①
7  ★ 6의 스캐너가 살아 있는가                             ← 합성 문구를 잡는가
8  집계가 던져도 T-44 문장과 마감 버튼이 살아 있다
```

**5와 8이 짝이다.** 4·6만 보면 *"개입 0일 때도 뭔가 쓰는 구현"*과
*"Guard 집계가 죽으면 요약 전체가 죽는 구현"*이 둘 다 통과한다 —
T-33·T-38·T-39·T-41·T-43·T-44에서 **여섯 번** 물린 자리다.

⚠️ **검사 6의 금지 표현 목록은 `CLOSE_JUDGING_WORDS`와 별개다.** 그쪽은 어휘,
이쪽은 **주어**다. 합치지 마라 — 뜻이 다르고, 합치면 한쪽을 고칠 때 다른 쪽이 딸려 간다.
다만 **각각은 한 곳에만 둔다**(T-44가 세운 규칙).

**변이**
- 개입 0일 때도 조각을 쓴다 → **5만** 죽는다
- 주어를 사용자로 바꾼다 → **6만** 죽는다
- 스캐너를 눈멀게 한다 → **6은 초록 · 7만** 죽는다
- 집계를 던지게 한다 → **8만** 죽는다

## 확인 절차 (사용자)

```
npm run deploy
```

```
□ 개입이 있던 날 마감 → 문장 뒤에 조각이 붙는다
□ 개입이 없던 날 마감 → T-44 문장만 나온다
□ ★ 그 조각이 "시스템이 한 일"로 읽히는가, "나를 평가한 것"으로 읽히는가
```

**마지막 줄이 이 티켓의 진짜 판정이다.** 검사는 표현 목록만 세지 **읽히는 방식은 못 센다.**
불편하면 말해 달라 — 그때는 조각을 빼는 것이 맞고, ADR-040 §재검토 트리거가 그 자리다.
